GenApp Insurance Application — PL/I on z/OS

A comprehensive wiki for the General Insurance (GenApp) sample application built in Enterprise PL/I for z/OS, covering architecture, program inventory, domain analysis, and operational guidance.

Application Documentation
Overview
Project Overview High-level introduction to the GenApp insurance application: purpose, technology stack (CICS, DB2, VSAM, PL/I), and key functional domains covering customer management and insurance policy lifecycle operations. Domain Map Visual and descriptive mapping of the GenApp business domains — customer and policy subdomains (motor, endowment, house, commercial) — and how they relate to each other and to the underlying infrastructure.
Architecture
System Architecture Detailed architectural description of GenApp: CICS transaction flow, layered program design (front-end handlers → business logic → DB2/VSAM back-ends), use of CICS LINK, communication areas, named counters, temporary storage queues, and IBM ODM integration. CRUD Matrix A cross-reference matrix showing which programs perform Create, Read, Update, and Delete operations against each DB2 table and VSAM dataset in the GenApp system. Customer Domain Analysis In-depth analysis of the customer domain: data model, key programs, transaction flows for customer inquiry, addition, and update, and how customer data is kept consistent across DB2 and VSAM stores. Customer Domain Migration Analysis Analysis of considerations, risks, and strategies for migrating the customer domain from its current PL/I on z/OS implementation, including data access patterns, CICS dependencies, and modernisation options.
Program Inventory
Program Inventory A complete inventory of all PL/I programs in GenApp, listing each program name, its transaction ID (where applicable), its role (terminal handler, business logic, DB2 back-end, VSAM back-end, batch, utility), and its primary domain.
Customer Domain Programs
Customer Business Logic Programs Covers the business-logic layer programs for customer operations: LGACUS01 (add customer, policy offer, transfer, delete), LGICUS01 (customer inquiry with MQ routing), and LGUCUS01 (customer update), including their COMMAREA contracts, validation rules, and downstream LINK chains. Customer DB2 Back-End Programs Details the DB2-layer programs for the customer domain: LGACDB01 (insert new customer), LGACDB02 (insert customer security record), LGICDB01 (retrieve customer profile), and LGUCDB01 (update customer record), including SQL table targets, host variables, return codes, and error handling. Customer VSAM Back-End Programs Covers the VSAM KSDS (KSDSCUST) access layer for the customer domain: LGACVS01 (write new customer record), LGICVS01 (random customer number selection via GTEQ browse), and LGUCVS01 (update existing customer record), including key construction, ENQ/DEQ serialization, and abend behaviour on failure.
Policy Domain Programs
Policy Business Logic Programs Covers the business-logic orchestration layer for insurance policy operations: LGAPOL01 (add policy, ODM integration for endowment), LGIPOL01 (inquire policy), LGUPOL01 (update policy), and LGDPOL01 (delete policy), including COMMAREA validation, policy-type routing, return code contracts, and downstream LINK chains to DB2 and VSAM back-ends. Policy Terminal Menu Handlers Documents the four CICS interactive terminal programs that present BMS screens and route user input to back-end services: LGTESTP1 (motor, SSP1), LGTESTP2 (endowment, SSP2), LGTESTP3 (house, SSP3), and LGTESTP4 (commercial, SSP4), covering screen maps, option routing, COMMAREA population, and pseudo-conversational flow. Policy DB2 Back-End Programs Details the DB2 persistence layer for insurance policies: LGAPDB01 (insert with premium surcharge, bundling discount, broker commission, and peril surcharge rules), LGIPDB01 (multi-variant policy inquiry across five policy-type tables), LGUPDB01 (update with lost-update timestamp guard), and LGDPDB01 (delete with referential integrity cascade), including SQL table joins, host variables, and error-code conventions. Policy VSAM Back-End Programs Covers the VSAM KSDS (KSDSPOLY) access layer for insurance policies: LGAPVS01 (write new 64-byte policy record with composite key), LGIPVS01 (GTEQ browse for policy lookup), LGUPVS01 (read-update / rewrite with abend on failure), and LGDPVS01 (delete by composite key), including key structure, CICS file commands, response-code handling, and abend codes.
Infrastructure & Utilities
Statistics & Monitoring Explains the GenApp statistics pipeline: LGASTAT1 (event-processing adapter that increments named counters per transaction type and outcome) and LGWEBST5 (self-rescheduling CICS statistics collector that harvests counters every minute, computes deltas, and writes results to TSQs for dashboard consumption), covering counter naming conventions, TSQ layout, and the SSST transaction scheduling loop. Logging & Error Handling Documents the shared LGSTSQ error-logging utility used across all GenApp programs: how it accepts diagnostic messages via COMMAREA or terminal input, writes entries prefixed with the CICS SYSID to the CSMT transient data queue and to application-specific TSQs (GENAERRS / GENAnnnn), and how calling programs construct timestamped error messages including SQLCODE, RESP codes, and raw COMMAREA snapshots. Batch Programs Covers the non-CICS batch programs in GenApp: LGBATCH (customer report generator reading CUSTIN and writing CUSTRPT via DB2 SELECTs), LGBATCHF (report-line formatting subroutine), LGBATDB2 (standalone DB2 test driver), and LGMOTOUT (motor policy extract writing formatted 132-byte records to MOTOROUT from the DB2 MOTOR table), including file DD names, return codes, and error display conventions. Environment Setup & Initialisation Describes LGSETUP, the operator-invoked CICS PL/I program that bootstraps the entire GenApp environment: tearing down and recreating the four TSQs (control, statistics, start, errors), writing the customer number range to the control queue, redefining the GENACUSTNUM named counter, and zeroing all 36 transaction statistics counters to establish a clean starting state.
