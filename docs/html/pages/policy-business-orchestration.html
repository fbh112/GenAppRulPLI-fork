Policy Business Logic & Operation Orchestration

1. Overview

The GenApp insurance application exposes a clean, layered CICS architecture for all insurance policy operations. The business logic front-end layer is composed of four PL/I programs — LGAPOL01 (Add), LGIPOL01 (Inquire), LGUPOL01 (Update), and LGDPOL01 (Delete) — each responsible for a single CRUD operation across all supported policy lines: Endowment, House, Motor, and Commercial.

These orchestration programs share a consistent behavioral contract:

  • Accept a structured 32,500-byte CICS COMMAREA carrying a request identifier (CA_REQUEST_ID), a customer number, a policy number, and policy-type-specific fields.
  • Validate the COMMAREA’s presence and minimum length before any business processing begins.
  • Delegate all DB2 persistence to a paired back-end database program (LGAPDB01, LGIPDB01, LGUPDB01, LGDPDB01) via EXEC CICS LINK.
  • Return a standardized CA_RETURN_CODE to the caller: '00' (success), '98' (COMMAREA too short), or '99' (unrecognized request type).
  • Write timestamped diagnostic records to a CICS Transient Data Queue (TDQ) through the shared logging utility LGSTSQ when fatal errors occur.

None of the four front-end programs contain direct SQL. They act purely as orchestrators and safety gates, ensuring that only well-formed, correctly-sized requests ever reach the database tier.

3. COMMAREA Contract & Request Identifier Scheme

3.1 Request Identifier Design

Every operation is identified by a 6-character CA_REQUEST_ID field in the COMMAREA. The identifier encodes both the operation type (A=Add, I=Inquire, U=Update, D=Delete) and the policy line (END=Endowment, HOU=House, MOT=Motor, COM=Commercial).

01AEND Add Endowment LGAPOL01 LGAPDB01
01AHOU Add House LGAPOL01 LGAPDB01
01AMOT Add Motor LGAPOL01 LGAPDB01
01ACOM Add Commercial LGAPOL01 LGAPDB01
01IMOT Inquire Motor LGIPOL01 LGIPDB01

3.2 COMMAREA Header Layout

All programs share a fixed 28-byte COMMAREA header:

Field Type Length Description
CA_REQUEST_ID CHAR(6) 6 Operation and policy-type routing key
CA_RETURN_CODE PIC '99' 2 Status: 00=OK, 98=too short, 99=unknown type
CA_CUSTOMER_NUM PIC '9999999999' 10 Customer identifier
CA_POLICY_NUM PIC '9999999999' 10 Policy identifier

Beyond the header, CA_POLICY_REQUEST holds common policy fields (issue/expiry dates, broker ID, payment) followed by a UNION of policy-type-specific sub-structures (CA_ENDOWMENT, CA_HOUSE, CA_MOTOR, CA_COMMERCIAL, CA_CLAIM).

3.3 Return Code Convention

CA_RETURN_CODE Meaning Set By
'00' Success Front-end (initial default)
'98' COMMAREA too short for requested policy type Front-end
'99' Unrecognized CA_REQUEST_ID Front-end
Non-zero (other) DB2 / backend processing failure DB2 back-end program

4. Add Policy — LGAPOL01

4.1 Purpose & Scope

LGAPOL01 is the Add Policy orchestrator. It handles creation of Endowment, House, Motor, and Commercial policies. It is the only front-end program that conditionally invokes a third-party component — the IBM Operational Decision Manager (ODM) business rules program LGAPBR01 — before delegating to the database tier.
