Customer Add & Onboarding

1. Overview

Customer onboarding in the General Insurance application creates a new customer in three places. The customer is written to DB2, mirrored to a VSAM file, and given an initial security record. The four programs involved are:

Program Role in onboarding
LGACUS01 PL/I orchestrator for customer and policy operations. Its ONBOARD_CUSTOMER branch drives the full onboarding sequence.
LGACDB01 CICS PL/I program dedicated to adding a customer. It assigns the customer number, inserts into DB2 CUSTOMER, then links to the VSAM and security programs.
LGACDB02 Adds the customer’s security row to the DB2 CUSTOMER_SECURE table (request 02ACUS).
LGACVS01 Writes the customer record to the VSAM KSDS file KSDSCUST, keyed on the 10-digit customer number.

A shared error utility, LGSTSQ, receives diagnostic messages from every program in the flow.

The flow has these steps:

  1. Validate the COMMAREA, which must be at least 90 bytes (an 18-byte header plus a 72-byte customer section).
  2. Obtain a customer number from the CICS named counter GENACUSTNUM in pool GENA. If the counter is unavailable, fall back to the DB2 identity column.
  3. Insert the customer row into DB2.
  4. Mirror the record to VSAM through LGACVS01.
  5. Create the security record through LGACDB02.
  6. Return CA_RETURN_CODE and CA_CUSTOMER_NUM to the caller.

Important runtime note: In LGACUS01, ACTION_CODE is initialised to '0' and never changed. The ONBOARD_CUSTOMER branch ('1') is therefore never selected at runtime. This is a documented porting artifact. LGACDB01 implements the same onboarding sequence directly and without a routing switch.

2.2 Component Responsibilities

Component Type Mechanism Responsibility
LGACUS01 CICS PL/I program EXEC CICS LINK target Validates input, routes by ACTION_CODE, and runs onboard, offer, transfer and delete operations.
LGACDB01 CICS PL/I program EXEC CICS LINK target Validates input, obtains the customer number, inserts into DB2, then links to LGACVS01 and LGACDB02.
LGACDB02 CICS PL/I program EXEC SQL INSERT Inserts one row into CUSTOMER_SECURE.

LGSTSQ Shared utility EXEC CICS LINK Writes error messages and COMMAREA snapshots to a queue.
GENACUSTNUM / GENA CICS named counter EXEC CICS GET COUNTER Provides sequential customer numbers.

2.3 Common Program Structure

All four programs use the same entry convention. Each is entered as Proc(COMM_AREA_PTR) Options(Main) and addresses the shared COMM_AREA layout from the LGCMAREA include. Each captures EIBTRNID, EIBTRMID and EIBTASKN into a working-storage header for diagnostics. Each routes errors through a local WRITE_ERROR_MESSAGE procedure.

3.2 Input Validation

Both orchestrating programs run the same two checks before any business work:

  • No COMMAREA (EIBCALEN = 0): an error message is written, then EXEC CICS ABEND ABCODE('LGCA') NODUMP is issued.
  • COMMAREA too short: the required length is the header (18) plus the customer section (72), which is 90 bytes. A shorter COMMAREA sets CA_RETURN_CODE = '98' and returns immediately, with no DB2 or downstream calls.
PLI 
WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_CUSTOMER_LEN;   /* 18 + 72 = 90 */
IF (WS_CALEN < WS_REQUIRED_CA_LEN) THEN DO;
   CA_RETURN_CODE = '98';
   EXEC CICS RETURN;
END;

3.3 Customer Number Assignment

OBTAIN_CUSTOMER_NUMBER requests the next value from the named counter. If the response is anything other than NORMAL, the program sets LGAC_NCS = 'NO' and zeroes DB2_CUSTOMERNUM_INT. This tells INSERT_CUSTOMER to let DB2 assign the number.

PLI 
EXEC CICS GET COUNTER(GENACOUNT)
               POOL(GENAPOOL)
               VALUE(LASTCUSTNUM)
               RESP(WS_RESP);

IF (WS_RESP ^= DFHRESP(NORMAL)) THEN DO;
   LGAC_NCS = 'NO';
   DB2_CUSTOMERNUM_INT = 0;
END;
ELSE
   DB2_CUSTOMERNUM_INT = LASTCUSTNUM;
Counter outcome LGAC_NCS CUSTOMERNUMBER in INSERT Number retrieval
Success ON :DB2_CUSTOMERNUM_INT Counter value
Failure NO DEFAULT IDENTITY_VAL_LOCAL() after the insert

3.4 DB2 Insert (INSERT_CUSTOMER)

INSERT_CUSTOMER sets EM_SQLREQ = ' INSERT CUSTOMER' and then takes one of two paths:

  • Named counter path (ON): inserts all ten columns using the counter value.
  • Identity path (NO): inserts DEFAULT for CUSTOMERNUMBER. On success it runs SET :DB2_CUSTOMERNUM_INT = IDENTITY_VAL_LOCAL() to retrieve the generated number.

In both paths a non-zero SQLCODE sets CA_RETURN_CODE = '90', calls WRITE_ERROR_MESSAGE and issues EXEC CICS RETURN. On success, CA_CUSTOMER_NUM receives the final customer number.

PLI 
IF (LGAC_NCS = 'ON') THEN DO;
   EXEC SQL INSERT INTO CUSTOMER
        ( CUSTOMERNUMBER, FIRSTNAME, LASTNAME, DATEOFBIRTH,
          HOUSENAME, HOUSENUMBER, POSTCODE,
          PHONEMOBILE, PHONEHOME, EMAILADDRESS )
        VALUES ( :DB2_CUSTOMERNUM_INT, :CA_FIRST_NAME, :CA_LAST_NAME,
                 :CA_DOB, :CA_HOUSE_NAME, :CA_HOUSE_NUM, :CA_POSTCODE,
                 :CA_PHONE_MOBILE, :CA_PHONE_HOME, :CA_EMAIL_ADDRESS );
END;
ELSE DO;
   EXEC SQL INSERT INTO CUSTOMER
        ( CUSTOMERNUMBER, FIRSTNAME, LASTNAME, DATEOFBIRTH,
          HOUSENAME, HOUSENUMBER, POSTCODE,
          PHONEMOBILE, PHONEHOME, EMAILADDRESS )
        VALUES ( DEFAULT, :CA_FIRST_NAME, :CA_LAST_NAME,
                 :CA_DOB, :CA_HOUSE_NAME, :CA_HOUSE_NUM, :CA_POSTCODE,
                 :CA_PHONE_MOBILE, :CA_PHONE_HOME, :CA_EMAIL_ADDRESS );
   /* on SQLCODE = 0 */
   EXEC SQL SET :DB2_CUSTOMERNUM_INT = IDENTITY_VAL_LOCAL();
END;
CA_CUSTOMER_NUM = DB2_CUSTOMERNUM_INT;

3.5 VSAM Mirror Write (LGACVS01)

After the DB2 insert, the orchestrator links to LGACVS01 with the COMMAREA and a fixed length of 225:

PLI 
EXEC CICS LINK PROGRAM(LGACVS01)
               COMMAREA(COMM_AREA)
               LENGTH(225);

LGACVS01 sets WS_Commarea_Len = EIBCALEN and writes the record, keyed on the 10-byte customer number:

PLI 
EXEC CICS WRITE FILE('KSDSCUST')
               FROM(CA_Customer_Num)
               LENGTH(WS_Commarea_Len)
               RIDFLD(CA_Customer_Num)
               KEYLENGTH(10)
               RESP(WS_RESP);

Two behaviors to note:

  • The record image begins at CA_CUSTOMER_NUM, not at CA_REQUEST_ID.
  • A non-NORMAL response, such as a duplicate key, sets CA_RETURN_CODE = '80', logs the failure and abends the task with LGV0. See Section 7.

3.6 Security Record Creation (LGACDB02)

The orchestrator then prepares the security commarea (CDB2AREA) and links to LGACDB02 with a length of 32500:

CDB2AREA field Value
D2_CUSTOMER_NUM The newly assigned customer number
D2_REQUEST_ID '02ACUS'
D2_CUSTSECR_COUNT '0000'
D2_CUSTSECR_STATE 'N'

LGACDB01 also supplies D2_CUSTSECR_PASS, which is a fixed hashed literal. As a result, every newly onboarded customer starts with the same initial credential value.

PLI 
D2_CUSTOMER_NUM   = DB2_CUSTOMERNUM_INT;
D2_REQUEST_ID     = '02ACUS';
D2_CUSTSECR_COUNT = '0000';
D2_CUSTSECR_STATE = 'N';

EXEC CICS LINK PROGRAM(LGACDB02)
               COMMAREA(CDB2AREA)
               LENGTH(32500);

IF (CA_RETURN_CODE ^= '00') THEN
   EXEC CICS RETURN;

Inside LGACDB02, a SELECT (CA_REQUEST_ID) accepts only '02ACUS'. It converts CA_CUSTOMER_NUM and CA_CUSTSECR_COUNT to FIXED BIN(31) host variables and calls INSERT_CUSTOMER_PASSWORD:

PLI 
EXEC SQL INSERT INTO CUSTOMER_SECURE
     ( customerNumber, customerPass, state_indicator, pass_changes )
     VALUES ( :DB2_CUSTOMERNUM_INT, :CA_CUSTSECR_PASS,
              :CA_CUSTSECR_STATE,   :DB2_CUSTOMERCNT_INT );

4. Component Details

4.1 LGACUS01 – Customer and Policy Orchestrator

LGACUS01 is the multi-purpose controller. After validation it dispatches on ACTION_CODE:

ACTION_CODE CA_REQUEST_ID set Procedure
'1' 01ICUS ONBOARD_CUSTOMER
'2' 02OCUS OFFER_CUSTOMER
'3' 02UCUS TRANSFER_CUSTOMER
'4' 02DCUS DELETE_CUSTOMER
Other – No action, then EXEC CICS RETURN

For onboarding, ONBOARD_CUSTOMER does the following in order:

  1. Zeroes DB2_OUT_INTEGERS.
  2. Calls OBTAIN_CUSTOMER_NUMBER.
  3. Calls INSERT_CUSTOMER.
  4. Links to LGACVS01.
  5. Builds CDB2AREA.
  6. Links to LGACDB02.
  7. Checks CA_RETURN_CODE.

The policy operations in the same program write to the POLICY table. That table has a foreign key to CUSTOMER, and SQLCODE -530 maps to CA_RETURN_CODE = '70'. Those operations are outside the onboarding flow.

4.2 LGACDB01 – Add Customer DB2 Backend

LGACDB01 is the dedicated add-customer program. Its main body performs validation, calls OBTAIN_CUSTOMER_NUMBER and INSERT_CUSTOMER in sequence, then links to LGACVS01 and LGACDB02. It contains no routing switch. The named counter name GENACUSTNUM and pool GENA are hardcoded.

4.3 LGACDB02 – Customer Security

Item Detail
Accepted request CA_REQUEST_ID = '02ACUS' only
DB2 target CUSTOMER_SECURE
Success CA_RETURN_CODE = '00'
DB2 failure '98', with the error logged
Unrecognised request '99', with no logging and no DB2 access

4.4 LGACVS01 – VSAM Write

LGACVS01 has a single purpose. It writes one KSDS record and has no DB2 interaction. Its only data store is the CICS file KSDSCUST, defined over a VSAM KSDS with a 10-byte key.

5.2 Data Flow of the Customer Number

graph LR NCS[(Named Counter)] -->|LASTCUSTNUM| H[DB2_CUSTOMERNUM_INT] IDV[IDENTITY_VAL_LOCAL] -->|fallback| H H --> C[(CUSTOMER row)] H --> CA[CA_CUSTOMER_NUM
returned to caller] CA --> V[LGACVS01 RIDFLD] H --> D2[D2_CUSTOMER_NUM] D2 --> S[(CUSTOMER_SECURE row)]

The customer number is generated only on the server side, never taken from the caller. The same value flows to DB2, VSAM, the security table and the caller, which keeps the three stores consistent.

6. Error Logging Pattern

Each program has its own WRITE_ERROR_MESSAGE with the same structure:

graph TD A[Error detected] --> B[Save SQLCODE or RESP codes
into ERROR_MSG] B --> C[EXEC CICS ASKTIME] C --> D[EXEC CICS FORMATTIME
MMDDYYYY and TIME] D --> E[LINK LGSTSQ with ERROR_MSG] E --> F{EIBCALEN > 0} F -- No --> Z([Return]) F -- Yes --> G{EIBCALEN < 91} G -- Yes --> H[CA_DATA = LEFT COMM_AREA_RAW, EIBCALEN] G -- No --> I[CA_DATA = LEFT COMM_AREA_RAW, 90] H --> J[LINK LGSTSQ with CA_ERROR_MSG] I --> J J --> Z
PLI 
EXEC CICS ASKTIME ABSTIME(WS_ABSTIME);
EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME)
                     MMDDYYYY(WS_DATE) TIME(WS_TIME);
EXEC CICS LINK PROGRAM('LGSTSQ')
               COMMAREA(ERROR_MSG)
               LENGTH(STG(ERROR_MSG));

The error record content differs by program:

  • LGACUS01, LGACDB01 and LGACDB02 record the program name, the EM_SQLREQ label and the SQLCODE. LGACUS01 and LGACDB02 also carry customer and policy number fields.
  • LGACVS01 records the customer number, RESP and RESP2.
  • Every program also logs up to 90 bytes of the raw COMMAREA as a second record.

7. Return Codes and Error Handling

7.1 Return Code Summary

Code Set by Meaning
00 All Success.
70 LGACUS01 (policy insert) Referential integrity violation (SQLCODE -530). Not part of the customer insert.
80 LGACVS01 VSAM write to KSDSCUST failed.
90 LGACUS01, LGACDB01 DB2 insert into CUSTOMER failed (any non-zero SQLCODE).
98 LGACUS01, LGACDB01 COMMAREA shorter than 90 bytes.
98 LGACDB02 DB2 insert into CUSTOMER_SECURE failed.
99 LGACDB02 Unrecognised request ID.

Code 98 appears in two contexts. In the orchestrators it means a short COMMAREA. In LGACDB02 it means a DB2 failure. Callers should interpret it according to which program set it.

7.2 Failure Scenarios

graph TD S[Onboarding step] --> A{Failure point} A -->|No COMMAREA| A1[ABEND LGCA, no dump] A -->|COMMAREA under 90 bytes| A2[RC 98, immediate RETURN] A -->|Named counter unavailable| A3[Silent fallback to DB2 identity] A -->|CUSTOMER insert fails| A4[RC 90, logged, RETURN
no VSAM and no security] A -->|KSDSCUST write fails| A5[RC 80, logged, ABEND LGV0] A -->|CUSTOMER_SECURE insert fails| A6[RC 98, logged, orchestrator checks RC]

Notes:

  • The named counter failure is not reported to the caller. The identity column silently takes over.
  • A failed CUSTOMER insert stops processing before LGACVS01 and LGACDB02 are reached.
  • LGACVS01 terminates the task with abend LGV0 (NODUMP) after logging. This is the only onboarding failure besides the missing COMMAREA that abends rather than returning a code.
  • The CUSTOMER row is already inserted when the VSAM or security step fails. The documentation describes no compensating rollback or delete.
  • After linking to LGACDB02, the orchestrator tests CA_RETURN_CODE and returns if it is not '00'.

8. Constraints and Design Considerations

8.1 Sequencing

  1. Validation must complete before any business logic.
  2. The customer number must be obtained before the DB2 insert.
  3. The DB2 insert must precede the VSAM write, which must precede the security add.
  4. IDENTITY_VAL_LOCAL() must be read immediately after the insert that generated the value.

8.2 Sizes and Formats

Item Constraint
COMMAREA minimum 90 bytes (18 header + 72 customer)
COMMAREA maximum 32,500 bytes (COMM_AREA_RAW)
LGACVS01 link length 225 bytes, fixed
LGACDB02 link length 32,500 bytes, fixed
CA_CUSTOMER_NUM PIC '9999999999', 10 digits
DB2_CUSTOMERNUM_INT FIXED BIN(31), maximum 2,147,483,647
CA_RETURN_CODE PIC '99'
Error COMMAREA dump At most 90 bytes
VSAM key 10 bytes, unique in KSDSCUST

8.3 Design Observations

  • Dual-write consistency: DB2 and VSAM are written in the same task, but without a documented compensating action for partial failure.
  • Shared initial credential: the hardcoded initial password hash in LGACDB01 means all new customers start with the same value, so it should be changed on first use.
  • Dead branch in LGACUS01: because ACTION_CODE is fixed at '0', LGACDB01 is the effective onboarding path.
  • Fixed request ID: D2_REQUEST_ID is always '02ACUS' and cannot be changed by the caller.
  • Silent truncation: CHAR fields longer than their declared length are truncated by PL/I assignment. CA_REQUEST_ID is limited to 6 characters.

9. Examples

9.1 Successful Onboarding with the Named Counter Available

Input customer data:

Field Value
CA_FIRST_NAME John
CA_LAST_NAME Smith
CA_DOB 1980-05-12
CA_HOUSE_NAME Maple House
CA_HOUSE_NUM 42
CA_POSTCODE SW1A 1AA
CA_PHONE_MOBILE 07700900123
CA_PHONE_HOME 02071234567
CA_EMAIL_ADDRESS john.smith@email.com

Processing:

  1. EIBCALEN is at least 90, so validation passes and CA_RETURN_CODE = '00'.
  2. The named counter returns 1042, so DB2_CUSTOMERNUM_INT = 1042.
  3. INSERT INTO CUSTOMER runs with CUSTOMERNUMBER = 1042, and CA_CUSTOMER_NUM = 1042.
  4. LGACVS01 writes record key 0000001042 to KSDSCUST.
  5. LGACDB02 inserts (1042, <initial password>, 'N', 0) into CUSTOMER_SECURE.

Result:

Field Value
CA_RETURN_CODE 00
CA_CUSTOMER_NUM 0000001042

9.2 Named Counter Unavailable

  1. GET COUNTER returns a non-NORMAL response, so LGAC_NCS = 'NO' and DB2_CUSTOMERNUM_INT = 0.
  2. INSERT INTO CUSTOMER ... VALUES (DEFAULT, ...) runs.
  3. IDENTITY_VAL_LOCAL() returns, for example, 5001, which becomes CA_CUSTOMER_NUM.
  4. The VSAM write and security add proceed with 5001.

Result: CA_RETURN_CODE = '00', CA_CUSTOMER_NUM = 0000005001.

9.3 COMMAREA Too Short

With EIBCALEN = 10, the check 10 < 90 is true. The program sets CA_RETURN_CODE = '98' and returns. No counter, DB2, VSAM or security calls are made.

9.4 VSAM Duplicate Key

If KSDSCUST already holds key 0000000042:

  1. The WRITE FILE returns a non-NORMAL response, for example DUPREC.
  2. WS_RESP2 is taken from EIBRESP2 and CA_RETURN_CODE = '80'.
  3. LGSTSQ receives two records. The first carries the date, time, customer number and RESP/RESP2. The second carries up to 90 bytes of the COMMAREA, prefixed with COMMAREA=.
  4. The task abends with LGV0 and no dump. The security step is never reached.

9.5 Security Insert Failure (Duplicate Customer)

If CUSTOMER_SECURE already contains customer 12345:

  1. The insert returns a non-zero SQLCODE, for example -803.
  2. LGACDB02 sets CA_RETURN_CODE = '98', logs the error with EM_SQLREQ = ' INSERT SECURITY' and returns.
  3. The orchestrator sees CA_RETURN_CODE <> '00' and returns that error to its caller.
