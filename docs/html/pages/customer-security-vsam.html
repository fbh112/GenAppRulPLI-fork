Customer Security & VSAM Layer

1. Overview

The Customer Security & VSAM Layer is a foundational subsystem of the General Insurance Application (GenApp) responsible for two closely related concerns: persisting new customer security credentials into the DB2 CUSTOMER_SECURE table, and maintaining the VSAM KSDS customer file (KSDSCUST) that serves as the application’s primary flat-file customer store.

This layer is composed of four PL/I programs running under CICS:

Program Role
LGACDB02 Inserts a new customer security record into the DB2 CUSTOMER_SECURE table
LGACVS01 Adds (writes) a new customer record to the VSAM KSDS file KSDSCUST
LGUCVS01 Updates (reads and rewrites) an existing customer record in KSDSCUST
LGICVS01 Randomly selects a valid customer number from KSDSCUST using a configured range

All four programs communicate via a shared COMMAREA structure defined in the LGCMAREA include member. Errors are logged to a CICS Transient Storage queue via the shared utility program LGSTSQ, which ensures a consistent, centralised diagnostic trail across the entire layer.

LGACDB01 is the top-level Add Customer backend: it calls both LGACDB02 (to write the security record into DB2) and LGACVS01 (to mirror the new customer into the VSAM file). LGUCVS01 and LGICVS01 are called independently by their respective orchestrators. All error conditions route diagnostic messages through LGSTSQ to a CICS Transient Storage queue.

3. LGACDB02 — Customer Security Record Insertion

3.1 Purpose

LGACDB02 is a CICS-linked PL/I program that inserts a new row into the DB2 CUSTOMER_SECURE table. It is invoked by LGACDB01 and receives the customer’s number, password, state indicator, and password-change count through the shared COMMAREA. A default MD5 password of NewPass is used if no password is supplied. The program validates the COMMAREA, routes on the request identifier 02ACUS, performs the DB2 INSERT, and returns a structured return code to its caller.

3.2 COMMAREA Interface

Field Type Direction Description
CA_REQUEST_ID CHAR(6) In Must equal 02ACUS to trigger processing
CA_CUSTOMER_NUM PIC 9(10) In 10-digit customer number; mapped to DB2_CUSTOMERNUM_INT
CA_CUSTSECR_PASS CHAR(32) In Customer password (MD5); inserted as customerPass
CA_CUSTSECR_STATE CHAR(1) In Activation state (e.g., N); inserted as state_indicator
CA_CUSTSECR_COUNT CHAR(4) In Password-change count; mapped to DB2_CUSTOMERCNT_INT
CA_RETURN_CODE CHAR(2) Out 00 = success, 98 = DB2 error, 99 = unknown request

3.3 DB2 Table — CUSTOMER_SECURE

erDiagram CUSTOMER_SECURE { int customerNumber "FK - customer identifier" string customerPass "length 32 - password MD5 or caller-supplied" string state_indicator "length 1 - activation state e.g. N" int pass_changes "number of password changes" }

The single INSERT statement executed by LGACDB02 maps COMMAREA fields directly to CUSTOMER_SECURE columns:

SQL 
EXEC SQL INSERT INTO CUSTOMER_SECURE
    (customerNumber, customerPass, state_indicator, pass_changes)
VALUES
    (:DB2_CUSTOMERNUM_INT, :CA_CUSTSECR_PASS, :CA_CUSTSECR_STATE, :DB2_CUSTOMERCNT_INT)
END-EXEC

3.5 Error Handling

LGACDB02 applies a uniform three-tier return code contract and logs all failures via the WRITE_ERROR_MESSAGE internal procedure:

Condition CA_RETURN_CODE Abend
Successful INSERT 00 None
No COMMAREA (EIBCALEN = 0) N/A LGCA (NODUMP)
DB2 INSERT failure (SQLCODE ≠ 0) 98 None — caller notified via return code
Unrecognized CA_REQUEST_ID 99 None — caller notified via return code

When WRITE_ERROR_MESSAGE is invoked it:

  1. Saves SQLCODE into EM_SQLRC immediately (before any other CICS call can overwrite it).
  2. Obtains a timestamp via EXEC CICS ASKTIME / EXEC CICS FORMATTIME.
  3. Links the fully populated ERROR_MSG structure to LGSTSQ.
  4. Conditionally links a raw COMMAREA snapshot (up to 90 bytes) in a second call to LGSTSQ.

A diagnostic eyecatcher 'LGACDB02------WS' is embedded in working storage for rapid identification in memory dumps.

3.6 Code Example — INSERT_CUSTOMER_PASSWORD Procedure

PLI 
INSERT_CUSTOMER_PASSWORD: PROCEDURE;
  EM_SQLREQ = ' INSERT SECURITY';
  EXEC SQL INSERT INTO CUSTOMER_SECURE
           (customerNumber,
            customerPass,
            state_indicator,
            pass_changes)
    VALUES (:DB2_CUSTOMERNUM_INT,
            :CA_CUSTSECR_PASS,
            :CA_CUSTSECR_STATE,
            :DB2_CUSTOMERCNT_INT);
  IF SQLCODE ^= 0 THEN DO;
    CA_RETURN_CODE = '98';
    CALL WRITE_ERROR_MESSAGE;
    EXEC CICS RETURN;
  END;
END INSERT_CUSTOMER_PASSWORD;

4. LGACVS01 — Add Customer to VSAM

4.1 Purpose

LGACVS01 is a CICS PL/I program that writes a new customer record to the VSAM KSDS file KSDSCUST. It is called by LGACDB01 as the VSAM mirror write for every new customer also stored in DB2. The 10-digit customer number serves as both the data anchor and the KSDS record key. On failure it sets CA_RETURN_CODE = '80', logs diagnostics via LGSTSQ, and issues a CICS ABEND LGV0.

4.2 COMMAREA Interface

Field Direction Description
CA_CUSTOMER_NUM In / Key 10-digit VSAM KSDS record key; FROM and RIDFLD for the CICS WRITE
CA_FIRST_NAME … CA_EMAIL_ADDRESS In Customer demographic fields written as part of the record
CA_RETURN_CODE Out Set to '80' on VSAM write failure; unchanged on success

4.3 Processing Flow

graph TD classDef startEnd fill:#d5e8d4,stroke:#82b366,color:#000 classDef process fill:#dae8fc,stroke:#6c8ebf,color:#000 classDef decision fill:#fff2cc,stroke:#d6b656,color:#000 classDef error fill:#f8cecc,stroke:#b85450,color:#000 A([Start LGACVS01]):::startEnd B[WS_Commarea_Len = EIBCALEN]:::process C[EXEC CICS WRITE FILE KSDSCUST\nRIDFLD = CA_CUSTOMER_NUM\nLENGTH = WS_Commarea_Len\nKEYLENGTH = 10]:::process D{{WS_RESP =\nDFHRESP NORMAL}}:::decision E([Return to caller — Success]):::startEnd F[WS_RESP2 = EIBRESP2\nCA_RETURN_CODE = 80]:::error G[Call WRITE_ERROR_MESSAGE\nTimestamp + ERROR_MSG + COMMAREA dump\nvia LGSTSQ]:::error H[EXEC CICS ABEND ABCODE LGV0 NODUMP\nEXEC CICS RETURN]:::error A --> B --> C --> D D -- Yes --> E D -- No --> F --> G --> H

The record written to KSDSCUST starts at CA_CUSTOMER_NUM and spans exactly EIBCALEN bytes — the same size as the inbound COMMAREA — ensuring the complete customer profile is stored.

4.4 Error Handling

Condition Return Code Abend
VSAM WRITE succeeds Unchanged (caller’s 00) None
VSAM WRITE fails (WS_RESP ≠ NORMAL) 80 LGV0 (NODUMP)

Both the primary CICS response code (WS_RESP) and the secondary code (EIBRESP2) are captured and forwarded to LGSTSQ in the ERROR_MSG structure along with the failing customer number.

4.5 Code Example — VSAM Write and Error Path

PLI 
WS_Commarea_Len = EIBCALEN;

EXEC CICS WRITE FILE('KSDSCUST')
     FROM(CA_Customer_Num)
     LENGTH(WS_Commarea_Len)
     RIDFLD(CA_Customer_Num)
     KEYLENGTH(10)
     RESP(WS_RESP);

IF WS_RESP ^= DFHRESP(NORMAL) THEN DO;
  WS_RESP2       = EIBRESP2;
  CA_RETURN_CODE = '80';
  CALL WRITE_ERROR_MESSAGE;
  EXEC CICS ABEND ABCODE('LGV0') NODUMP;
  EXEC CICS RETURN;
END;

5. LGUCVS01 — Update Customer in VSAM

5.1 Purpose

LGUCVS01 updates an existing customer record in KSDSCUST. It issues a CICS READ with UPDATE intent to obtain an exclusive lock, then immediately rewrites the record with the updated data from the COMMAREA. Distinct abend codes (LGV1 for read failure, LGV2 for rewrite failure) allow operations staff to pinpoint exactly which step failed.

5.2 COMMAREA Interface

Field Direction Description
CA_CUSTOMER_NUM In / Key 10-digit VSAM KSDS key; used in both READ and REWRITE
CA_FIRST_NAME … CA_EMAIL_ADDRESS In Updated customer fields rewritten to KSDSCUST
CA_RETURN_CODE Out 81 = read failure, 82 = rewrite failure

5.3 VSAM Record Layout

erDiagram KSDSCUST { string CA_CUSTOMER_NUM "10 digits — KSDS primary key" string CA_FIRST_NAME "length 10" string CA_LAST_NAME "length 20" string CA_DOB "length 10" string CA_HOUSE_NAME "length 20" string CA_HOUSE_NUM "length 4" string CA_POSTCODE "length 8" string CA_NUM_POLICIES "PIC 999" string CA_PHONE_MOBILE "length 20" string CA_PHONE_HOME "length 20" string CA_EMAIL_ADDRESS "length 100" string CA_POLICY_DATA "length 32267" }

5.4 Processing Flow

The read-then-rewrite pattern is mandatory: CICS requires a successful READ … UPDATE to establish the exclusive record lock before a REWRITE can be accepted for the same record in the same task.

graph TD classDef startEnd fill:#b5ead7,stroke:#4a9e7f,color:#000 classDef process fill:#c7ceea,stroke:#5a67a0,color:#000 classDef decision fill:#ffdac1,stroke:#c47a3a,color:#000 classDef error fill:#ffb7b2,stroke:#c0504d,color:#000 A([Start LGUCVS01]):::startEnd B[WS_Commarea_Len = EIBCALEN\nWS_Commarea_LenF = EIBCALEN]:::process C[EXEC CICS READ FILE KSDSCUST\nINTO WS_Customer_Area\nRIDFLD = CA_CUSTOMER_NUM\nUPDATE]:::process D{{READ RESP\n= NORMAL}}:::decision E[CA_RETURN_CODE = 81\nWS_RESP2 = EIBRESP2\nCall WRITE_ERROR_MESSAGE]:::error F[EXEC CICS ABEND ABCODE LGV1 NODUMP\nEXEC CICS RETURN]:::error G[EXEC CICS REWRITE FILE KSDSCUST\nFROM CA_CUSTOMER_NUM\nLENGTH WS_Commarea_LenF]:::process H{{REWRITE RESP\n= NORMAL}}:::decision I[CA_RETURN_CODE = 82\nWS_RESP2 = EIBRESP2\nCall WRITE_ERROR_MESSAGE]:::error J[EXEC CICS ABEND ABCODE LGV2 NODUMP\nEXEC CICS RETURN]:::error K([Return to caller — Success]):::startEnd A --> B --> C --> D D -- Yes --> G D -- No --> E --> F G --> H H -- Yes --> K H -- No --> I --> J

5.5 Error Handling

Condition Return Code Abend
Both READ and REWRITE succeed Unchanged (00) None
READ UPDATE fails 81 LGV1 (NODUMP)
REWRITE fails 82 LGV2 (NODUMP)

The two distinct abend codes are an important operational signal: LGV1 means the record could not be located or locked, while LGV2 means the record was found and locked but the update itself failed. Both are logged through WRITE_ERROR_MESSAGE before the abend fires.

5.6 Code Example — Read-Update-Rewrite Sequence

PLI 
WS_Commarea_Len  = EIBCALEN;
WS_Commarea_LenF = EIBCALEN;

EXEC CICS READ FILE('KSDSCUST')
     INTO(WS_Customer_Area)
     LENGTH(WS_Commarea_Len)
     RIDFLD(CA_CUSTOMER_NUM)
     KEYLENGTH(10)
     UPDATE
     RESP(WS_RESP);

IF WS_RESP ^= DFHRESP(NORMAL) THEN DO;
  WS_RESP2       = EIBRESP2;
  CA_RETURN_CODE = '81';
  CALL WRITE_ERROR_MESSAGE;
  EXEC CICS ABEND ABCODE('LGV1') NODUMP;
  EXEC CICS RETURN;
END;

EXEC CICS REWRITE FILE('KSDSCUST')
     FROM(CA_CUSTOMER_NUM)
     LENGTH(WS_Commarea_LenF)
     RESP(WS_RESP);

IF WS_RESP ^= DFHRESP(NORMAL) THEN DO;
  WS_RESP2       = EIBRESP2;
  CA_RETURN_CODE = '82';
  CALL WRITE_ERROR_MESSAGE;
  EXEC CICS ABEND ABCODE('LGV2') NODUMP;
  EXEC CICS RETURN;
END;

6. LGICVS01 — Inquire Random Customer Number

6.1 Purpose

LGICVS01 randomly selects a valid customer number from KSDSCUST. It reads the GENACNTL CICS Temporary Storage queue (protected by ENQ/DEQ serialization) to obtain the configured lower and upper boundaries of the customer number range, generates a random number within that range seeded by EIBTASKN, and then performs a GTEQ read against KSDSCUST to resolve the nearest real customer key. Results are returned either via COMMAREA (when invoked by CICS LINK) or via a terminal SEND TEXT (when invoked interactively).

6.2 COMMAREA and Data Store Interfaces

erDiagram KSDSCUST { string CA_CUSTOMER_NUM "length 10 — KSDS key returned to caller" string CA_REST "length 215 — remaining customer data" } GENACNTL_TS_QUEUE { string EYECATCHER "length 20 — GENAPP CNTL marker" string LOW_CUSTOMER_LABEL "length 13 — LOW CUSTOMER=" decimal LOW_CUSTOMER_VALUE "length 10 — numeric low boundary" string HIGH_CUSTOMER_LABEL "length 14 — HIGH CUSTOMER=" decimal HIGH_CUSTOMER_VALUE "length 10 — numeric high boundary" }

The GENACNTL queue defaults both boundaries to 1000001 on first invocation. Once written, the boundaries persist for the lifetime of the CICS region.

6.3 Invocation Modes

LGICVS01 supports two invocation modes resolved at startup:

Mode Detection Input Source Output Destination
COMMAREA (WS_FLAG = 'C') INVOKINGPROG not blank or STARTCODE begins with 'D' COMMAREA via COMM_AREA_PTR COMMA_DATA_HIGH in caller’s COMMAREA
Terminal (WS_FLAG = 'R') Neither of the above EXEC CICS RECEIVE EXEC CICS SEND TEXT to 3270 terminal

6.5 Random Customer Number Generation

The formula used to generate the random customer number is:

PLI 
WS_RANDOM_NUMBER = FLOOR(
    RANDOM(EIBTASKN) * FLOAT(WS_CUST_HIGH - WS_CUST_LOW) + WS_CUST_LOW
);

EIBTASKN seeds the RANDOM built-in, producing a different result per CICS task. Because RANDOM returns a value in [0, 1), the result falls within [WS_CUST_LOW, WS_CUST_HIGH). The subsequent GTEQ read then resolves it to the nearest real customer key in KSDSCUST, so even if the exact random number is not a valid VSAM key the program always returns a genuine customer record.

6.6 GENACNTL Queue Initialization Logic

The three flag variables (WS_FLAG_TSQE, WS_FLAG_TSQL, WS_FLAG_TSQH) default to 'Y' on every invocation. They are cleared to ' ' only when the corresponding record is found in the TS queue during the sequential scan. This pessimistic-default strategy ensures that any missing control record is automatically written on the first invocation where it is absent:

PLI 
/* Conditionally write missing TS queue records */
IF WS_FLAG_TSQE = 'Y' THEN
  EXEC CICS WRITEQ TS QUEUE(STSQ_NAME)
       FROM(WRITE_MSG_E) LENGTH(20) NOSUSPEND;

IF WS_FLAG_TSQL = 'Y' THEN
  EXEC CICS WRITEQ TS QUEUE(STSQ_NAME)
       FROM(WRITE_MSG_L) LENGTH(23) NOSUSPEND;

IF WS_FLAG_TSQH = 'Y' THEN
  EXEC CICS WRITEQ TS QUEUE(STSQ_NAME)
       FROM(WRITE_MSG_H) LENGTH(24) NOSUSPEND;

6.7 Error Handling

LGICVS01 uses a non-abending, graceful degradation strategy — unlike the other three programs in this layer:

Condition Behaviour
GENACNTL queue absent on READQ TS All three flags stay 'Y'; defaults (1000001) are used and written
READQ TS NEXT returns non-NORMAL Loop exits cleanly; partial data already extracted is used
KSDSCUST GTEQ read returns non-NORMAL WRITE_MSG_HIGH retains the raw random number; no abend issued
WRITEQ TS fails (NOSUSPEND) Silently continues; WS_RESP is captured but not branched on

ENQ/DEQ serialization protects against race conditions where multiple concurrent tasks could simultaneously determine that the control queue is absent and write duplicate records.

7. Shared Error Logging Pattern

All three programs that perform file or database writes (LGACDB02, LGACVS01, LGUCVS01) share an identical WRITE_ERROR_MESSAGE internal procedure pattern. The sequence below shows the common steps executed on any error:

sequenceDiagram participant Program as Failing Program participant CICS as CICS Runtime participant LGSTSQ as LGSTSQ Logger participant TSQ as Transient Storage Queue Program->>CICS: EXEC CICS ASKTIME ABSTIME(WS_ABSTIME) CICS-->>Program: Absolute timestamp Program->>CICS: EXEC CICS FORMATTIME ABSTIME → WS_DATE / WS_TIME CICS-->>Program: Formatted date and time Program->>Program: Populate ERROR_MSG\n(date, time, prog name, customer num,\nSQLCODE or RESP/RESP2) Program->>LGSTSQ: EXEC CICS LINK PROGRAM(LGSTSQ)\nCOMMAPEA(ERROR_MSG) LGSTSQ->>TSQ: Write structured error message alt EIBCALEN > 0 Program->>Program: Extract up to 90 bytes\nfrom COMM_AREA_RAW into CA_DATA Program->>LGSTSQ: EXEC CICS LINK PROGRAM(LGSTSQ)\nCOMMAPEA(CA_ERROR_MSG) LGSTSQ->>TSQ: Write raw COMMAREA snapshot end

Key design points shared across all three programs:

  • SQLCODE / RESP is captured as the very first statement in WRITE_ERROR_MESSAGE, before any subsequent CICS call can overwrite it.
  • COMMAREA snapshot is capped at 90 bytes regardless of the actual EIBCALEN value, matching the fixed CA_DATA CHAR(90) field.
  • Two separate CICS LINK calls to LGSTSQ are issued per error event: first the structured ERROR_MSG, then the raw CA_ERROR_MSG snapshot.
  • NODUMP is specified on all CICS ABENDs — the TS queue log is the sole diagnostic artefact; no system dump is produced.

8. COMMAREA Return Code Summary

The table below consolidates the return codes written back to callers across all four programs, providing a single reference for any orchestrating program interpreting the COMMAREA on return:

Program Return Code Meaning
LGACDB02 00 Customer security record inserted successfully
LGACDB02 98 DB2 INSERT into CUSTOMER_SECURE failed (non-zero SQLCODE)
LGACDB02 99 Unrecognized CA_REQUEST_ID (not 02ACUS)
LGACVS01 00 (unchanged) New customer record written to KSDSCUST successfully
LGACVS01 80 CICS WRITE FILE to KSDSCUST failed
LGUCVS01 00 (unchanged) Customer record read and rewritten successfully
LGUCVS01 81 CICS READ UPDATE of KSDSCUST failed
LGUCVS01 82 CICS REWRITE of KSDSCUST failed
LGICVS01 N/A Returns resolved customer number via COMMA_DATA_HIGH; no explicit error return code
