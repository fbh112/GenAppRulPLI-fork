Project Overview & Program Inventory

1. Overview

1.1 Purpose

GenApp is a general insurance application for z/OS. This page documents the PL/I implementation at application level: how it is layered, which programs exist, and how they relate to each other and to the data stores.

CICS online transactions manage customers and four kinds of insurance policy: Motor, Endowment, House and Commercial. Batch programs handle reporting and data extraction. The PL/I source is in two libraries:

  • /pli/ holds 35 programs.
  • /plinc/ holds 6 include files.

2. System Architecture

2.1 Three-Tier Layering

The online application follows a strict three-tier layering:

  1. Tier 1, Presentation. BMS menu programs receive control from CICS transactions, present maps and collect input.
  2. Tier 2, Orchestration. Business logic programs validate the COMMAREA and dispatch to a backend program with EXEC CICS LINK, usually through a program-name variable.
  3. Tier 3, Backend. Db2 programs perform the embedded SQL, and VSAM programs perform CICS File Control I/O.

2.3 Programming Conventions

The programs share a few conventions.

  • COMMAREA-driven. Almost every CICS program includes LGCMAREA and exchanges data through a COMM_AREA_PTR parameter.
  • Centralised error handling. Programs call LGSTSQ with EXEC CICS LINK to log errors.
  • Dynamic dispatch. Most orchestrators link to a backend through a variable holding the program name. LGUPOL01 is the exception and uses a hard-coded literal.

Typical entry-point declarations:

PLI 
/* Tier 1 menu programs (LGTESTP1-4, LGTESTC1) */
Proc(DFHEIPTR, COMM_AREA_PTR) Options(Main, Reentrant)

/* Orchestrators and most backends */
Proc(COMM_AREA_PTR) Options(Main)

/* Statistics collector and setup utility (no COMMAREA) */
Proc Options(Main)

/* Batch subroutine called statically by LGBATCH and LGBATDB2 */
LGBATCF: Proc(CUSTNUMBER, COMM_PTR, LS_LINE)

Include conventions differ between CICS and batch programs:

PLI 
%INCLUDE LGCMAREA            /* CICS programs               */
%INCLUDE SSMAP               /* BMS menu programs only      */

EXEC SQL INCLUDE SQLCA       /* Batch Db2 programs          */
EXEC SQL INCLUDE LGCMAREA

3.1 UI — Presentation / BMS Menu Programs

These programs present BMS maps, collect user input and dispatch to the orchestration tier with EXEC CICS LINK. None of them access Db2 or VSAM directly.

Program Screen / Map Operations Programs Linked
LGTESTP1 Motor policy menu (SSMAPP1), transaction SSAM Inquire, Add, Delete, Update LGIPOL01, LGAPOL01, LGDPOL01, LGUPOL01
LGTESTP2 Endowment policy menu (SSMAPP2) Inquire, Add, Delete, Update LGIPOL01, LGAPOL01, LGDPOL01, LGUPOL01

3.3 Db2 Backend Programs

The Db2 backends perform all embedded SQL for policies and customers and communicate only through the COMMAREA.

Program Function Db2 Tables / Operations Also Calls
LGAPDB01 Add Policy POLICY, ENDOWMENT, HOUSE, MOTOR, COMMERCIAL, CLAIM (INSERT) LGAPVS01, LGSTSQ
LGIPDB01 Inquire Policy CUSTOMER, POLICY, ENDOWMENT, HOUSE, MOTOR, COMMERCIAL, CLAIM (SELECT via Cust_Cursor, Zip_Cursor, CusClaim_Cursor) LGSTSQ
LGDPDB01 Delete Policy POLICY (DELETE) LGDPVS01, LGSTSQ
LGUPDB01 Update Policy POLICY (cursor POLICY_CURSOR with hold, UPDATE), ENDOWMENT, HOUSE, MOTOR (UPDATE) LGUPVS01, LGSTSQ
LGACDB01 Add Customer CUSTOMER (INSERT) LGACVS01, LGACDB02, LGSTSQ
LGACDB02 Add Customer Security CUSTOMER_SECURE (INSERT) LGSTSQ
LGICDB01 Inquire Customer CUSTOMER (SELECT) LGSTSQ
LGUCDB01 Update Customer CUSTOMER (UPDATE) LGUCVS01, LGSTSQ

LGDPDB01 is declared Proc(DFHEIPTR, COMM_AREA_PTR) Options(Main, Reentrant). The other Db2 backends use Proc(COMM_AREA_PTR) Options(Main).

3.4 VSAM Backend Programs

The VSAM programs use CICS File Control against two KSDS datasets: KSDSPOLY for policies and KSDSCUST for customers.

Program Function Dataset CICS Operation
LGAPVS01 Add Policy KSDSPOLY WRITE
LGIPVS01 Inquire Policy (browse) KSDSPOLY READ GTEQ generic key browse
LGDPVS01 Delete Policy KSDSPOLY DELETE
LGUPVS01 Update Policy KSDSPOLY READ UPDATE followed by REWRITE
LGACVS01 Add Customer KSDSCUST WRITE
LGICVS01 Inquire Customer KSDSCUST READ GTEQ, after reading the GENACNTL TS queue
LGUCVS01 Update Customer KSDSCUST READ UPDATE followed by REWRITE

Notes on specific programs:

  • LGIPVS01 is declared Proc(COMMA_PTR) Options(Main), includes no copybooks and calls no other program. It accepts a partial policy key (type plus customer number) from a COMMAREA or terminal input.
  • LGICVS01 can be invoked by CICS LINK or started as a transaction.
  • Every other VSAM backend calls LGSTSQ on error.

3.5 Supporting CICS Programs

Program Type Responsibility Resources
LGSTSQ Shared service Central error message writer. Accepts up to 90 bytes of text in the COMMAREA. Writes to the TDQ and the TSQ, or to a custom queue if started with Q=nnnn. CSMT (TDQ), GENAERRS (TSQ)
LGASTAT1 Event Processing adapter Reads the request ID and return code from the DFHEP.DATA.00001 and DFHEP.DATA.00002 containers, or from the COMMAREA. Increments the matching counter GENA<request><rc>. GENA named counter pool, GENASTRT TSQ (read)
LGWEBST5 Statistics daemon Queries the GENA counters, computes per-minute rates as current minus previous, and stores the values in GENA<code>V. Restarts itself every minute through transaction SSST. It is a PL/I port of the COBOL version and drives 34 counter blocks from an internal table. GENA counters (QUERY), GENA<code>V TSQs
LGSETUP Administrative utility One-time environment initialisation. Deletes and recreates the GENAERRS and GENASTRT TS queues and 36 named counters. Accepts the high customer number from terminal input (default 11). GENA counters, GENAERRS, GENASTRT, GENACNTL

3.6 Batch Programs and Utilities

The batch programs run outside CICS and contain no EXEC CICS statements.

Program Type Description Inputs / Outputs
LGBATCH Main Reads customer numbers from CUSTIN, selects each customer from Db2 CUSTOMER, and formats an 80-byte report line through the static call to LGBATCHF. In: CUSTIN (FB, RECSIZE 10). Out: CUSTRPT (FB, RECSIZE 80)
LGBATDB2 Main Minimal Db2 connectivity test. Selects customer 1 and displays the line built by LGBATCHF. Out: console (DISPLAY)
LGMOTOUT Main Extracts every row of the Db2 MOTOR table through cursor MOTOR_CSR into 132-byte records. Out: MOTOROUT (FB, RECSIZE 132)
LGBATCHF Subroutine Formats first name, last name and customer number into the report line. Its internal entry label is LGBATCF. Parameters: customer number, COMMAREA pointer, 80-byte buffer

LGMOTOUT sets these return codes:

RC Meaning
0 Success
8 Fetch error
12 Open or cursor error

4.1 Add Policy

A policy add passes through all three tiers. The business-rules step is optional, and the VSAM write mirrors the Db2 insert.

4.2 Add Customer

LGACUS01 inserts the CUSTOMER and POLICY rows itself, then mirrors the customer to VSAM and creates the security record. LGACDB01 performs the same mirroring and security calls for its own CUSTOMER insert.

4.3 Update and Delete Policy Propagation

Update and delete operations follow the same pattern. The Db2 backend changes Db2 first, then links to the VSAM program so both stores stay aligned.

Operation Orchestrator Db2 Backend VSAM Follow-up
Delete LGDPOL01 LGDPDB01 (DELETE POLICY) LGDPVS01 (DELETE KSDSPOLY)
Update LGUPOL01 LGUPDB01 (UPDATE POLICY and sub-type) LGUPVS01 (REWRITE KSDSPOLY)
Customer update LGUCUS01 LGUCDB01 (UPDATE CUSTOMER) LGUCVS01 (REWRITE KSDSCUST)

9. Design Observations

  • Dual persistence. Db2 is the primary store and VSAM mirrors it. Customer data is mirrored to KSDSCUST and policy data to KSDSPOLY. The Db2 backends link to the matching VSAM program after their SQL.
  • Shared sub-services. LGACVS01 and LGACDB02 are each called by both LGACDB01 and LGACUS01.
  • Dispatch styles. Most orchestrators link through a variable program name. LGUPOL01 hard-codes 'LGUPDB01'.
  • Add Customer paths. LGACUS01 does its own CUSTOMER and POLICY inserts, while LGACDB01 is a separate Db2 backend with the same VSAM and security fan-out. The inventory lists no caller for LGACDB01.
  • Entry points with no listed caller. LGIPVS01 and LGICVS01 have no listed callers. They are reached by LINK or by direct transaction start.
  • Menu feature gap. The Commercial policy menu (LGTESTP4) offers no Update operation, and LGUPDB01 only updates Endowment, House and Motor sub-types.
  • Batch reuse. LGBATCH and LGBATDB2 share LGBATCHF and the LGCMAREA structure with the online code.
