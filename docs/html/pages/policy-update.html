Policy Update

1. Overview

The Policy Update flow changes existing insurance policies (Endowment, House or Motor) in the General Insurance Application (GenApp). Three CICS-hosted Enterprise PL/I programs implement it:

Program Role Data store
LGUPOL01 Business-logic front-end. Validates the COMMAREA and request type, then delegates. None (no direct I/O)
LGUPDB01 DB2 back-end. Updates the policy and policy-type tables, with optimistic locking on a timestamp. DB2: POLICY, ENDOWMENT, HOUSE, MOTOR
LGUPVS01 VSAM back-end. Updates the matching record in the policy KSDS. VSAM KSDS KSDSPOLY

The programs cooperate as follows:

  • LGUPOL01 checks that a COMMAREA exists. It also checks that the COMMAREA is long enough for the requested policy type, and then links to LGUPDB01.
  • LGUPDB01 protects against lost updates. It locks the POLICY row with a cursor and compares the caller’s CA_LASTCHANGED timestamp with the value held in DB2. If they match, it updates the policy-type table and then the POLICY table, which gets a new CURRENT TIMESTAMP. It then links to LGUPVS01.
  • LGUPVS01 keeps the VSAM copy of the policy in step with DB2. It does a READ UPDATE followed by a REWRITE on KSDSPOLY.
  • LGSTSQ, a shared logging utility, receives diagnostic messages from all three programs.

Results are returned to the caller in CA_RETURN_CODE in the shared COMMAREA.

The layers are:

  • Orchestration layer (LGUPOL01). It is not a transaction entry point. It is always reached through EXEC CICS LINK, and it contains no SQL.
  • Persistence layer (LGUPDB01, LGUPVS01). DB2 is the system of record. VSAM holds a secondary copy that is updated after DB2.
  • Cross-cutting layer. LGSTSQ handles diagnostics. The LGCMAREA include defines COMM_AREA, which is shared by all three programs. LGPOLICY defines the DB2 host variables used by LGUPDB01.

4. LGUPOL01 — Validation and Delegation

4.1 Responsibilities

LGUPOL01 is the front-end gatekeeper. It is declared Proc(COMM_AREA_PTR) Options(Main). It captures EIBTRNID, EIBTRMID and EIBTASKN into its working-storage eyecatcher area (WS_HEADER), which helps with dump diagnostics. It then validates the request and delegates the update.

4.2 Processing Flow

graph TD A([LGUPOL01 invoked]) --> B{EIBCALEN = 0?} B -- Yes --> C[WRITE_ERROR_MESSAGE
NO COMMAREA RECEIVED] C --> D[ABEND LGCA NODUMP] B -- No --> E[CA_RETURN_CODE = 00
Save EIBCALEN, customer and policy num] E --> F{CA_REQUEST_ID} F -- 01UEND --> G{EIBCALEN < 152?} F -- 01UHOU --> H{EIBCALEN < 158?} F -- 01UMOT --> I{EIBCALEN < 165?} F -- Other --> J[CA_RETURN_CODE = 99] G -- Yes --> K[CA_RETURN_CODE = 98
EXEC CICS RETURN] H -- Yes --> K I -- Yes --> K G -- No --> L[UPDATE_POLICY_DB2_INFO] H -- No --> L I -- No --> L J --> L L --> M[LINK LGUPDB01] M --> N([EXEC CICS RETURN])

4.3 Key Behaviours

  1. COMMAREA presence. If EIBCALEN = 0, the program logs NO COMMAREA RECEIVED and abends with LGCA (NODUMP).
  2. Default result. CA_RETURN_CODE is set to '00'. The customer and policy numbers are copied to EM_CUSNUM and EM_POLNUM so any later error message already carries them.
  3. Length check. The required length is WS_CA_HEADER_LEN (28) plus the full length for the policy type: 124, 130 or 137. A shorter COMMAREA gives return code '98' and an immediate RETURN, so no update is attempted.
  4. Unknown request. The OTHERWISE branch sets '99' but does not return early. Control falls through to the LGUPDB01 link.
  5. Delegation. UPDATE_POLICY_DB2_INFO links to LGUPDB01 with the whole raw COMMAREA.

4.4 Code Examples

Request routing and length validation (as described for the SELECT on CA_REQUEST_ID):

PLI 
SELECT (CA_REQUEST_ID);
  WHEN ('01UEND') DO;
    WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_ENDOW_LEN;  /* 28 + 124 */
    IF EIBCALEN < WS_REQUIRED_CA_LEN THEN DO;
      CA_RETURN_CODE = '98';
      EXEC CICS RETURN;
    END;
  END;
  /* 01UHOU uses WS_FULL_HOUSE_LEN (130); 01UMOT uses WS_FULL_MOTOR_LEN (137) */
  OTHERWISE
    CA_RETURN_CODE = '99';
END;
CALL UPDATE_POLICY_DB2_INFO;
EXEC CICS RETURN;

Delegation to the DB2 back-end:

PLI 
EXEC CICS LINK Program('LGUPDB01')
               Commarea(COMM_AREA_RAW)
               LENGTH(32500);

5. LGUPDB01 — DB2 Update with Timestamp Lost-Update Protection

5.1 Responsibilities

LGUPDB01 performs the DB2 update. It combines two protections:

  • Pessimistic row lock. POLICY_CURSOR is declared WITH HOLD FOR UPDATE, which locks the fetched row.
  • Optimistic timestamp check. CA_LASTCHANGED is the timestamp the user originally read. The update only proceeds if it equals the LASTCHANGED value just fetched from DB2.

On entry it converts CA_CUSTOMER_NUM and CA_POLICY_NUM to binary host variables (DB2_CUSTOMERNUM_INT, DB2_POLICYNUM_INT). If EIBCALEN = 0, it abends with LGCA.

5.2 Processing Flow

Call UPDATE_POLICY_DB2_INFO] D --> E[OPEN POLICY_CURSOR] E --> F{SQLCODE} F -- 0 --> G[FETCH_DB2_POLICY_ROW] F -- "-913 or other" --> H[RC 90, log error, RETURN] G --> I{FETCH SQLCODE} I -- 100 --> J[RC 01 not found] I -- other non-zero --> K[RC 90, log error] I -- 0 --> L{CA_LASTCHANGED =
DB2_LASTCHANGED?} L -- No --> M[RC 02 conflict] L -- Yes --> N{CA_REQUEST_ID} N -- 01UEND --> O[UPDATE_ENDOW_DB2_INFO] N -- 01UHOU --> P[UPDATE_HOUSE_DB2_INFO] N -- 01UMOT --> Q[UPDATE_MOTOR_DB2_INFO] O --> R{RC = 00?} P --> R Q --> R R -- No --> S[CLOSE_PCURSOR, RETURN] R -- Yes --> T[UPDATE POLICY

RC 90, log error] V -- Yes --> X[CLOSE_PCURSOR] J --> X K --> X M --> X W --> X X --> Y[LINK LGUPVS01] Y --> Z([EXEC CICS RETURN])

5.3 Lost-Update Protection in Detail

  1. Lock. OPEN POLICY_CURSOR and FETCH read the current LASTCHANGED (DB2_LASTCHANGED) for the customer and policy.
  2. Compare. IF (CA_LASTCHANGED = DB2_LASTCHANGED) decides whether the update is allowed.
  3. Reject on mismatch. If the values differ, CA_RETURN_CODE = '02'. Neither the policy-type table nor the POLICY table is touched, and no error message is logged. This is a business rejection, not a system error.
  4. Issue a new token. On a match, the POLICY update sets LASTCHANGED = CURRENT TIMESTAMP. A follow-up SELECT LASTCHANGED INTO :CA_LASTCHANGED returns the new token to the caller for its next request.
  5. Ordering for consistency. The policy-type table is updated first. The POLICY header (and its timestamp) is updated only if that succeeded.

5.4 Per-Type Update Procedures

Procedure Table Conversions Return codes on failure
UPDATE_ENDOW_DB2_INFO ENDOWMENT CA_E_TERM → SMALLINT, CA_E_SUM_ASSURED → INTEGER 100 → 01; other → 90 + log
UPDATE_HOUSE_DB2_INFO HOUSE CA_H_BEDROOMS → SMALLINT, CA_H_VALUE → INTEGER 100 → 01; other → 01 + log (differs from the others)
UPDATE_MOTOR_DB2_INFO MOTOR CA_M_CC → SMALLINT; value, premium and accidents → INTEGER 100 → 01; other → 90 + log

For endowments, WS_VARY_LEN = EIBCALEN - WS_REQUIRED_CA_LEN is calculated. If it is greater than 0, the overflow data in CA_E_PADDING_DATA is placed in WS_VARY_CHAR (up to 3,900 characters). The update then uses the variable-length path. Otherwise only the fixed fields are updated.

5.5 Code Examples

Positioned update of the policy header, which generates the new timestamp:

SQL 
EXEC SQL UPDATE POLICY
   SET ISSUEDATE        = :CA_ISSUE_DATE,
       EXPIRYDATE       = :CA_EXPIRY_DATE,
       LASTCHANGED      = CURRENT TIMESTAMP,
       BROKERID         = :DB2_BROKERID_INT,
       BROKERSREFERENCE = :CA_BROKERSREF
   WHERE CURRENT OF POLICY_CURSOR;

Retrieval of the new concurrency token:

SQL 
EXEC SQL SELECT LASTCHANGED
           INTO :CA_LASTCHANGED
           FROM POLICY
          WHERE POLICYNUMBER = :DB2_POLICYNUM_INT;

Timestamp comparison and rejection:

PLI 
IF ( CA_LASTCHANGED = DB2_LASTCHANGED ) THEN DO;
  /* dispatch to the type-specific update, then update POLICY */
END;
ELSE
  CA_RETURN_CODE = '02';   /* another user changed the row */

Rollback on a policy-header failure:

PLI 
EXEC CICS SYNCPOINT ROLLBACK;
CA_RETURN_CODE = '90';
CALL WRITE_ERROR_MESSAGE;

VSAM synchronisation, issued after the DB2 routine returns:

PLI 
EXEC CICS LINK Program('LGUPVS01')
               Commarea(COMM_AREA)
               LENGTH(225);

5.6 Cursor Close Behaviour

CLOSE_PCURSOR treats SQLCODE 0 as success. SQLCODE -501 (cursor not open) is also treated as non-fatal, giving '00' and an immediate RETURN. Any other SQLCODE gives '90', logs an error and returns.

5.7 Return Codes Produced by LGUPDB01

Code Meaning
00 Update completed
01 Row not found on fetch or update (and non-100 failures on the house table)
02 Timestamp mismatch (concurrent update detected)
90 DB2/system error: cursor open failure (including -913), fetch error, or policy update failure (with rollback)

6. LGUPVS01 — VSAM Update

6.1 Responsibilities

LGUPVS01 updates the corresponding record in the VSAM KSDS KSDSPOLY. It is linked from LGUPDB01 with the first 225 bytes of the COMMAREA. This limit is a constraint of the link and applies to everything LGUPVS01 can see.

6.2 Key Construction and Field Mapping

The fourth character of CA_REQUEST_ID selects the policy type and becomes the first byte of the 21-byte composite key:

Key component Source Length
WF_Request_ID SUBSTR(CA_REQUEST_ID,4,1) 1
WF_Customer_Num CA_CUSTOMER_NUM 10
WF_Policy_Num CA_POLICY_NUM 10

A SELECT on this byte copies the relevant fields into a UNION overlay (WF_Policy_Data):

Value Type Fields mapped
C Commercial Postcode, status, customer
E Endowment With-profits, equities, managed fund, fund name, life assured
H House Property type, bedrooms, value, postcode, house name
M Motor Make, model, value, registration number
Other n/a WF_Policy_Text blanked

Some fields are truncated in the VSAM record. CA_H_HOUSE_NAME (20 characters) is kept as 9, and CA_B_Customer (255 characters) is kept as 31.

6.3 Processing Flow

graph TD A([LGUPVS01 called]) --> B[Capture EIBCALEN
Extract 4th char of CA_REQUEST_ID] B --> C[Copy customer and policy num to key] C --> D{WF_Request_ID} D -- C --> E1[Map commercial fields] D -- E --> E2[Map endowment fields] D -- H --> E3[Map house fields] D -- M --> E4[Map motor fields] D -- Other --> E5[Blank WF_Policy_Text] E1 --> F[Re-copy CA_POLICY_NUM to key] E2 --> F E3 --> F E4 --> F E5 --> F F --> G[READ FILE KSDSPOLY UPDATE
KEYLENGTH 21] G --> H{RESP NORMAL?} H -- No --> I[RC 81, WRITE_ERROR_MESSAGE
ABEND LGV3] H -- Yes --> J[REWRITE FILE KSDSPOLY
LENGTH 64] J --> K{RESP NORMAL?} K -- No --> L[RC 82, WRITE_ERROR_MESSAGE
ABEND LGV4] K -- Yes --> M([RETURN])

6.4 Code Examples

PLI 
EXEC CICS READ FILE('KSDSPOLY')

EXEC CICS REWRITE FILE('KSDSPOLY')

7. Error Handling and Diagnostics

7.1 Error Logging Pattern

All three programs have a WRITE_ERROR_MESSAGE internal procedure with the same shape:

sequenceDiagram participant P as Program participant CICS as CICS Time Services participant L as LGSTSQ participant Q as TDQ P->>CICS: ASKTIME ABSTIME P->>CICS: FORMATTIME MMDDYYYY, TIME P->>P: Build ERROR_MSG (date, time, program, cust, policy, SQL/CICS codes) P->>L: LINK COMMAREA(ERROR_MSG) L->>Q: Write error record alt EIBCALEN between 1 and 90 P->>P: CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN) else EIBCALEN >= 91 P->>P: CA_DATA = first 90 bytes end P->>L: LINK COMMAREA(CA_ERROR_MSG) L->>Q: Write COMMAREA snapshot

Each log therefore has two parts: a structured, human-readable message and a raw COMMAREA snapshot of at most 90 bytes.

7.2 Consolidated Return Codes

Code Set by Meaning
00 LGUPOL01, LGUPDB01 Success
01 LGUPDB01 Policy or policy-type row not found
02 LGUPDB01 Timestamp mismatch (lost-update protection)
81 LGUPVS01 VSAM read failure (abend LGV3)
82 LGUPVS01 VSAM rewrite failure (abend LGV4)
90 LGUPDB01 DB2 or system error
98 LGUPOL01 COMMAREA too short
99 LGUPOL01 Unrecognised request ID

7.3 Abend Codes

Abend Program Cause
LGCA LGUPOL01, LGUPDB01 No COMMAREA received (EIBCALEN = 0)
LGV3 LGUPVS01 VSAM READ UPDATE failure
LGV4 LGUPVS01 VSAM REWRITE failure

7.4 Behaviours to Be Aware Of

  • Unknown requests still reach LGUPDB01. LGUPOL01 sets '99' and links anyway. In LGUPDB01 the type-specific SELECT has no matching branch for an unknown ID. The policy header could still be updated, and CA_RETURN_CODE may be reset by later processing.
  • LGUPVS01 is always linked. LGUPDB01 issues the link regardless of CA_RETURN_CODE, including after 01, 02 or 90.
  • Return code retention. LGUPVS01 does not write a success code. A VSAM failure produces an abend rather than a graceful return.
  • House update return code. UPDATE_HOUSE_DB2_INFO returns '01' for any non-zero SQLCODE, unlike the Endowment and Motor procedures, which use '90' for other errors.
  • Short CLOSE_PCURSOR path. -501 leads to an immediate RETURN.

8.3 Size Limits

  • COMM_AREA_RAW is CHAR(32500).
  • LGUPOL01 links to LGUPDB01 with the full 32,500 bytes.
  • LGUPDB01 links to LGUPVS01 with 225 bytes.
  • LGUPVS01 rewrites 64 bytes.
  • Error dumps are capped at 90 bytes of COMMAREA.
  • The endowment variable-length buffer WS_VARY_CHAR is capped at 3,900 characters.

9. Worked Examples

9.1 Successful House Update

Input

Field Value
CA_REQUEST_ID 01UHOU
CA_CUSTOMER_NUM 0000000042
CA_POLICY_NUM 0000000007
CA_LASTCHANGED 2023-06-01-10.30.00.000000 (matches DB2)
CA_H_PROPERTY_TYPE Detached
CA_H_BEDROOMS 004
CA_H_VALUE 00250000
EIBCALEN ≥ 158

Flow

  1. LGUPOL01 confirms that EIBCALEN is at least 158 and links to LGUPDB01.
  2. LGUPDB01 opens and fetches the cursor. The timestamps match.
  3. UPDATE HOUSE ... WHERE POLICYNUMBER = :DB2_POLICYNUM_INT runs.
  4. UPDATE POLICY ... WHERE CURRENT OF POLICY_CURSOR sets a new LASTCHANGED, and the new value is read back.
  5. The cursor is closed and LGUPVS01 rewrites the KSDSPOLY record.

Result: CA_RETURN_CODE = '00', and CA_LASTCHANGED holds the new timestamp.

9.2 COMMAREA Too Short (Endowment)

CA_REQUEST_ID = '01UEND' and EIBCALEN = 100. The required length is 28 + 124 = 152. LGUPOL01 sets CA_RETURN_CODE = '98' and returns. LGUPDB01 and LGUPVS01 are never called.

9.3 Concurrent Modification (Motor)

CA_REQUEST_ID = '01UMOT' and CA_LASTCHANGED = 2023-05-01-09.00.00.000000, which is stale. The FETCH returns a newer timestamp. LGUPDB01 sets CA_RETURN_CODE = '02' and does not update MOTOR or POLICY. The caller must re-read the policy and retry.

9.4 Policy Not Found

CA_POLICY_NUM = 0000009999 does not exist in POLICY. The FETCH returns SQLCODE 100, so CA_RETURN_CODE = '01'. The cursor is closed, and an error message is logged through LGSTSQ.

9.5 VSAM Record Missing

If LGUPDB01 succeeds but KSDSPOLY has no record for the 21-byte key, the READ UPDATE fails. LGUPVS01 sets CA_RETURN_CODE = '81', logs the failure with the RESP and RESP2 codes, and abends with LGV3.
