Environment Setup (LGSETUP)

The LGSETUP program is a CICS PL/I administrative utility that initializes or re-initializes the runtime environment for the General Insurance Application (GenApp). When invoked via a terminal transaction (such as LGSE), it accepts an optional upper bound for customer numbering, tears down and reconstructs all GenApp Temporary Storage (TS) queues, initializes the environment control queue (GENACNTL) with valid customer number boundaries, defines the customer numbering sequence counter (GENACUSTNUM), and resets all 36 transaction statistics counters in the CICS Named Counter pool GENA to zero.

1. Overview

The primary function of LGSETUP is to bring the GenApp CICS environment to a known, consistent baseline state. This setup is crucial prior to running transactional workloads, performance benchmarks, or automated tests.

Key actions executed by LGSETUP:

  • Terminal Input Capture: Reads an optional upper limit for the customer numbering sequence from the initiating terminal. If omitted, it applies a default value of 11.
  • Temporary Storage Queue Teardown & Reconstruction: Purges existing GenApp TS queues (GENAERRS, GENASTRT, GENASTAT, and GENACNTL) and writes initial control records to GENACNTL.
  • Customer Counter Initialization: Resets and defines the named counter GENACUSTNUM in the GENA counter pool seeded with the resolved upper customer number bound.
  • Transaction Statistics Reset: Iterates through a fixed set of 36 transaction statistics counters (representing success and failure metrics for Customer, Motor, Endowment, House, and Commercial policy operations) and sets their values to zero.
  • Terminal Confirmation: Returns a formatted message (HIGH CUSTOMER=...) to confirm the active upper boundary.

4. Resource Definitions and Structures

4.1 Temporary Storage Queues

LGSETUP manages four CICS Temporary Storage Queues:

Queue Name Variable Name Purpose Records Written by LGSETUP
GENACNTL STSQ_NAME Environment configuration & customer ID range store 3 fixed-length records (Eyecatcher, Low Customer, High Customer)
GENAERRS STSQ_ERRS Application error logging Purged only (0 records written)
GENASTRT STSQ_STRT Transaction start/heartbeat tracking Purged only (0 records written)
GENASTAT STSQ_STAT Transaction execution statistics Purged only (0 records written)

Control Queue (GENACNTL) Record Layout

The three records written to GENACNTL follow strict byte layouts:

classDiagram class Record1_Eyecatcher { +CHAR(20) WRITE_MSG_E = '**** GENAPP CNTL ' } class Record2_LowCustomer { +CHAR(13) Label = 'LOW CUSTOMER=' +PIC(10)9 WRITE_MSG_LOW = 0000000001 } class Record3_HighCustomer { +CHAR(14) Label = 'HIGH CUSTOMER=' +PIC(10)9 WRITE_MSG_HIGH = e.g. 0000000011 }
  • Record 1 (20 bytes): Environment identification string '**** GENAPP CNTL '.
  • Record 2 (23 bytes): Lower boundary string 'LOW CUSTOMER=' concatenated with WRITE_MSG_LOW (hardcoded to 1, formatted as 0000000001).
  • Record 3 (24 bytes): Upper boundary string 'HIGH CUSTOMER=' concatenated with WRITE_MSG_HIGH (formatted as a 10-digit number based on LASTCUSTNUM).

4.2 Named Counters (Pool GENA)

All named counters are maintained within the dedicated CICS counter pool named GENA.

  1. Customer Sequence Counter (GENACUSTNUM):

    • Re-defined with VALUE(LASTCUSTNUM).
    • Used by customer creation routines to assign sequential customer IDs.

  2. 36 Transaction Statistics Counters:

    • Organized as a static array COUNTER_TABLE mapped via COUNTER_ARRAY.
    • Represents operations across 5 entity types (Customer, Motor, Endowment, House, Commercial) and 4 CRUD operations (Inquire/Insert, Add, Delete, Update).
    • Tracks success (00 suffix) and failure (99 suffix) outcomes (e.g., GENA01ICUS00, GENA01ICUS99, GENA01UMOT00, etc.).
    • All 36 counters are re-defined with VALUE(0).

5. Implementation Code Examples

The following pseudo-code snippets demonstrate the core logic implemented in PL/I with embedded CICS commands.

5.1 Terminal Receive and High Customer Override

PLI 
/* Read up to 80 bytes from the terminal */
EXEC CICS RECEIVE 
     INTO(WS_RECV) 
     LENGTH(WS_RECV_LEN) 
     RESP(WS_RESP);

/* If data was entered beyond the 5-char TranID, extract LASTCUSTNUM */
IF WS_RECV_LEN > 5 THEN DO;
    WS_RECV_LEN = WS_RECV_LEN - 5;
    LASTCUSTNUM = SUBSTR(WS_RECV_DATA, 1, WS_RECV_LEN);
END;
ELSE DO;
    LASTCUSTNUM = 11; /* Compile-time default */
END;

5.2 Temporary Storage Queue Deletion and Control Queue Population

PLI 
/* Delete all existing TS queues */
EXEC CICS DELETEQ TS QUEUE('GENAERRS') RESP(WS_RESP);
EXEC CICS DELETEQ TS QUEUE('GENASTRT') RESP(WS_RESP);
EXEC CICS DELETEQ TS QUEUE('GENASTAT') RESP(WS_RESP);
EXEC CICS DELETEQ TS QUEUE('GENACNTL') RESP(WS_RESP);

/* Format control records */
WRITE_MSG_LOW  = FRSTCUSTNUM; /* Value = 1 */
WRITE_MSG_HIGH = LASTCUSTNUM; /* Value = 11 or override */

/* Write initial records to GENACNTL */
EXEC CICS WRITEQ TS QUEUE('GENACNTL') 
     FROM(WRITE_MSG_E) 
     LENGTH(20) 
     NOSUSPEND 
     RESP(WS_RESP);

EXEC CICS WRITEQ TS QUEUE('GENACNTL') 
     FROM(WRITE_MSG_L) 
     LENGTH(23) 
     NOSUSPEND 
     RESP(WS_RESP);

EXEC CICS WRITEQ TS QUEUE('GENACNTL') 
     FROM(WRITE_MSG_H) 
     LENGTH(24) 
     NOSUSPEND 
     RESP(WS_RESP);

5.3 Named Counter Reset

PLI 
/* Reset customer numbering counter */
EXEC CICS DELETE COUNTER('GENACUSTNUM') POOL('GENA') RESP(WS_RESP);
EXEC CICS DEFINE COUNTER('GENACUSTNUM') POOL('GENA') 
     VALUE(LASTCUSTNUM) 
     RESP(WS_RESP);

/* Reset all 36 statistics counters */
DO COUNTER_IDX = 1 TO COUNTER_COUNT; /* COUNTER_COUNT = 36 */
    EXEC CICS DELETE COUNTER(COUNTER_NAME(COUNTER_IDX)) 
         POOL('GENA') 
         RESP(WS_RESP);

    EXEC CICS DEFINE COUNTER(COUNTER_NAME(COUNTER_IDX)) 
         POOL('GENA') 
         VALUE(0) 
         RESP(WS_RESP);
END;

/* Send confirmation to terminal and return */
EXEC CICS SEND TEXT 
     FROM(WRITE_MSG_H) 
     LENGTH(24) 
     TERMINAL 
     WAIT 
     ERASE 
     FREEKB;

EXEC CICS RETURN;

6. Constraints and Error Handling Strategy

6.1 Constraints

  • Single Procedure Structure: LGSETUP is written as a single, linear PL/I procedure (LGSETUP: Proc Options(Main)) without sub-routines or paragraphs.
  • Fixed Buffer Sizing: Terminal input is captured in an 80-byte buffer (WS_RECV). Trailing data beyond byte 80 is truncated.
  • Lower Customer Limit: FRSTCUSTNUM is statically fixed to 1 and cannot be modified via runtime input.
  • Data Conversion: The override string from WS_RECV_DATA is converted directly to LASTCUSTNUM (FIXED BIN(31)). Non-numeric input will cause a runtime PL/I conversion condition.
  • Counter Table Boundaries: Sized statically to 36 entries. Any change to tracked metrics requires recompilation of the static table and loop limits.
  • No Database Interaction: LGSETUP does not issue EXEC SQL commands and does not interact directly with DB2.

6.2 Error Handling Behavior

  • Passive Response Capture: Every CICS statement specifies RESP(WS_RESP), which suppresses standard CICS condition raising and abends.
  • Tolerance of Missing Resources: When issuing DELETEQ TS or DELETE COUNTER, missing resources (e.g., QIDERR or NOTFND) are captured in WS_RESP but ignored, allowing clean execution during initial system installation when queues or counters do not yet exist.
  • Non-blocking Queue Writes: WRITEQ TS commands use NOSUSPEND to prevent task hanging if auxiliary storage is temporarily constrained.
  • Implicit Success Feedback: The transaction issues no diagnostic error logs; the display of the confirmation message HIGH CUSTOMER=... on an erased 3270 screen serves as the visual indicator to the operator that all queues and counters have been successfully rebuilt.
