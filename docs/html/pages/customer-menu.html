Customer CICS Interactive Menu (LGTESTC1)

LGTESTC1 is a CICS-based PL/I program that serves as the interactive customer maintenance menu for the General Insurance (GenApp) application. Running under CICS transaction SSC1, it presents a BMS-mapped terminal screen (map SSMAPC1, mapset SSMAP) through which users can perform three customer record operations: inquiry (option 1), add (option 2), and update (option 4). The program delegates all data-access work to dedicated backend programs via EXEC CICS LINK, manages state across pseudo-conversational transaction cycles using a shared 32,500-byte COMMAREA, and serializes post-add control queue updates using CICS ENQ/DEQ on the GENACNTL temporary storage queue.

1. System Architecture

LGTESTC1 sits at the boundary between the terminal user and the GenApp backend services. It is purely a presentation and orchestration layer — it owns no database access logic itself, delegating all persistence operations to three backend programs.

The program operates in a pseudo-conversational model: after each user interaction it issues EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA) to suspend itself, passing the full COMMAREA forward so that all state is preserved when the user next presses a key. This design keeps CICS storage overhead minimal while delivering a conversational user experience.

3. Inputs

3.1 BMS Terminal Screen Input

All customer data is received from the terminal via EXEC CICS RECEIVE MAP('SSMAPC1') MAPSET('SSMAP') INTO(SSMAPC1I) ASIS TERMINAL. The ASIS option preserves raw data without attribute stripping.

First name ENT1FNAI CHAR(10) Options 2, 4
Last name ENT1LNAI CHAR(20) Options 2, 4
Date of birth ENT1DOBI CHAR(10) Options 2, 4
House name ENT1HNMI CHAR(20) Options 2, 4
House number ENT1HNOI CHAR(4) Options 2, 4
Postcode ENT1HPCI CHAR(8) Options 2, 4 (uppercased before link)
Home phone ENT1HP1I CHAR(20) Options 2, 4

3.2 CICS COMMAREA

The COMM_AREA is a 32,500-byte UNION structure defined by the LGCMAREA copybook, addressed via COMM_AREA_PTR. It is the sole interface contract between LGTESTC1 and all backend programs.

Field Type Description
CA_REQUEST_ID CHAR(6) Set before each LINK: 01ICUS, 01ACUS, 01UCUS
CA_RETURN_CODE PIC '99' Return code from backend — non-zero triggers error path
CA_CUSTOMER_NUM PIC '9999999999' 10-digit customer identifier
CA_REQUEST_INITIALISER CHAR(32482) Bulk overlay — cleared to spaces between operations
CA_FIRST_NAME CHAR(10) Customer first name
CA_LAST_NAME CHAR(20) Customer last name
CA_DOB CHAR(10) Date of birth
CA_HOUSE_NAME CHAR(20) House name
CA_HOUSE_NUM CHAR(4) House number
CA_POSTCODE CHAR(8) Postcode (forced uppercase)
CA_PHONE_HOME CHAR(20) Home phone
CA_PHONE_MOBILE CHAR(20) Mobile phone
CA_EMAIL_ADDRESS CHAR(100) Email address
COMM_AREA_RAW CHAR(32500) Byte-level overlay for bulk null-to-space translation

3.3 CICS Temporary Storage Queue (External State)

The GENACNTL TS queue (referenced via variable STSQ_NAME = 'GENACNTL') is read inside WRITE_GENACNTL after a successful customer add. It holds control records that track the high-water customer number range:

Record Content Purpose
**** GENAPP CNTL Header record (20 bytes)
LOW CUSTOMER=nnnnnnnnnn Lowest assigned customer number (23 bytes)
HIGH CUSTOMER=nnnnnnnnnn Highest assigned customer number (24 bytes)

3.4 Program Entry Parameters

Parameter Description
DFHEIPTR CICS-supplied pointer for EIB addressability (required by CICS macro preprocessor)
COMM_AREA_PTR Pointer to the CICS COMMAREA; on first call (EIBCALEN=0) points at local BASE_COMM_AREA

4. Outputs

4.1 BMS Screen Output

EXEC CICS SEND MAP('SSMAPC1') MAPSET('SSMAP') is issued in every processing path. The content varies by outcome:

Scenario Key Output Fields
Initial display (EIBCALEN=0) ENT1CNOO = '0000000000'; blank screen with ERASE
Option 1 success All customer detail fields populated from COMMAREA
Option 2 success ENT1CNOI ← new CA_CUSTOMER_NUM; ERRFLDO = 'New Customer Inserted'
Option 4 success ENT1CNOI ← CA_CUSTOMER_NUM; ERRFLDO = 'Customer details updated'
Invalid option ERRFLDO = 'Please enter a valid option'; ENT1OPTL = -1 (cursor to option field)
Inquiry error ERRFLDO = 'No data was returned.'
Add error ERRFLDO = 'Error Adding Customer'
Update error ERRFLDO = 'Error Updating Customer'
CLEAR key Map sent MAPONLY (blank screen repaint)
PF3 / MAPFAIL EXEC CICS SEND TEXT — 'Transaction ended' with ERASE FREEKB

4.2 CICS RETURN (Transaction Continuation)

At label ENDIT_STARTIT, the program issues:

PLI 
EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA);

This suspends the current task and re-schedules transaction SSC1, passing the full COMMAREA forward so that all customer state and the last request ID/return code persist into the next interaction cycle.

4.3 CICS LINK Outputs

LINK Target Request ID Sent Data Returned
LGICUS01 01ICUS All CA_CUSTOMER_REQUEST fields + CA_RETURN_CODE
LGACUS01 01ACUS CA_CUSTOMER_NUM (assigned) + CA_RETURN_CODE
LGUCUS01 01UCUS CA_RETURN_CODE

4.4 CICS Temporary Storage Queue Output (GENACNTL)

After a successful customer add, WRITE_GENACNTL writes to the GENACNTL TS queue in one of two modes:

  • Update existing — EXEC CICS WRITEQ TS REWRITE ITEM(WS_ITEM_COUNT) overwrites the HIGH CUSTOMER record in-place with the new customer number (24 bytes).
  • New queue initialisation — Three items are written sequentially with NOSUSPEND:
    1. Header record WRITE_MSG_E (20 bytes)
    2. LOW CUSTOMER= record WRITE_MSG_L (23 bytes)
    3. HIGH CUSTOMER= record WRITE_MSG_H (24 bytes)

4.5 CICS ENQ/DEQ Side Effect

EXEC CICS ENQ RESOURCE('GENACNTL') and EXEC CICS DEQ RESOURCE('GENACNTL') bracket all TS queue activity inside WRITE_GENACNTL. Any concurrent transaction attempting the same ENQ will block until the lock is released.

5. Processing Logic

The overall program flow follows a classic pseudo-conversational pattern: the very first invocation initialises state and paints the screen; every subsequent invocation re-enters at label A_GAIN, reads the user’s input, dispatches on the option code, performs the requested operation, and returns control to CICS.

    START(["Program Entry"]) --> EIBCHECK{"EIBCALEN = 0?"}
    EIBCHECK -- "Yes (first call)" --> INIT["Initialise COMMAREA & Map\nSend SSMAPC1 with ERASE"]
    EIBCHECK -- "No (subsequent call)" --> AGAIN

    INIT --> AGAIN(["A_GAIN\n(main re-entry)"])

    AGAIN --> HANDLES["Register AID Handlers\nCLEAR→CLEARIT, PF3→ENDIT\nMAPFAIL→ENDIT"]
    HANDLES --> RCVMAP["EXEC CICS RECEIVE MAP\n(SSMAPC1I ASIS TERMINAL)"]

    RCVMAP --> SELECT{"SELECT ENT1OPTO"}

    SELECT -- "'1'" --> OPT1["Option 1: Inquiry\nCA_REQUEST_ID='01ICUS'\nLINK LGICUS01"]
    SELECT -- "'2'" --> OPT2["Option 2: Add\nCA_REQUEST_ID='01ACUS'\nTranslate nulls, UPPERCASE postcode\nLINK LGACUS01"]
    SELECT -- "'4'" --> OPT4["Option 4: Update\n(Two-Phase)"]
    SELECT -- "OTHER" --> INVALID["Set ERRFLDO\n'Please enter a valid option'\nENT1OPTL=-1"]

    OPT1 --> RC1{"CA_RETURN_CODE > 0?"}
    RC1 -- "Yes" --> NODATA["NO_DATA\nERRFLDO='No data was returned.'"]
    RC1 -- "No" --> SEND1["Map inquiry result\nSEND MAP"]
