Customer Domain Migration Risk Assessment

This document provides a comprehensive technical risk assessment for modernizing and migrating the Customer Domain of the GenApp PL/I mainframe application. It identifies architectural, structural, and operational risks across the dual-store persistence layer (Db2 and VSAM), infrastructure dependencies (CICS Named Counters and Temporary Storage Queues), security record provisioning, shared monolithic interface contracts (LGCMAREA), and cross-domain database coupling.

1. Overview

The Customer Domain encompasses core Customer Lifecycle Management capabilities, including onboarding, inquiry, profile updates, credential provisioning, and relationship archiving. While functionally cohesive from a business standpoint, the underlying PL/I and CICS implementation exhibits tight coupling across data stores, shared infrastructure, and cross-domain business boundaries (specifically the Policy domain).

1.1 Scope Definition

The scope of this assessment includes all core assets directly supporting or tightly coupled with the Customer domain:

Component Type Components in Scope Operational / Architectural Role
Db2 Relational Tables CUSTOMER, CUSTOMER_SECURE Core customer profile entity and write-only security credential store.
CICS Presentation LGTESTC1 (Transaction SSC1) 3270 BMS menu orchestrating inquiry, updates, and navigation.
CICS Orchestrators LGICUS01, LGACUS01, LGUCUS01 Core business logic coordinating persistence and domain workflows.
Db2 Persistence Handlers LGACDB01, LGICDB01, LGUCDB01, LGACDB02 Dedicated SQL execution programs for CRUD and credential management.
VSAM Shadow Persistence LGACVS01, LGICVS01, LGUCVS01 File Control programs maintaining the KSDSCUST VSAM dataset.
Shared PL/I Includes LGCMAREA.inc, LGPOLICY.inc Universal 32,500-byte COMMAREA and host variable structure definitions.
Infrastructure Resources GENACUSTNUM (Named Counter), GENACNTL (TS Queue) Distributed sequence generator and cross-program runtime state store.

External consumers crossing the boundary include batch report programs (LGBATCH, LGBATDB2), the policy persistence layer (LGAPDB01, POLICY table), and shared error logging utilities (LGSTSQ).

3.2 Primary Hot-Spot: LGACUS01

LGACUS01 is the single highest-risk asset in the Customer domain. It merges customer account setup with downstream policy lifecycle actions.

3.2.1 Multi-Operation Scope

The program spans 774 lines of PL/I code with 13 internal procedures. It handles four distinct business operations: Onboard Customer, Offer Policy, Transfer Customer, and Delete Customer.

3.2.2 Procedure Decomposition Matrix

3 out of 13 procedures directly execute SQL DML against the POLICY table, violating domain boundaries.

3.2.3 Dual Include Dependencies

LGACUS01 imports both LGCMAREA and LGPOLICY:

PLI 
/* Cross-Domain Include in LGACUS01 */
%INCLUDE LGCMAREA;
EXEC SQL INCLUDE LGPOLICY;

This forces a compile-time dependency on all Policy domain table structures (House, Motor, Endowment, Commercial, Claim).

3.3 Presentation Layer Hot-Spot: LGTESTC1

LGTESTC1 manages the 3270 user interface via BMS mapset SSMAPC1. It contains several patterns that complicate target-state migration:

  1. Stateful Pseudo-Conversational Lifecycle: Session state is carried across transaction boundaries using EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA).
  2. Atomic Rollback in Presentation: Issues EXEC CICS SYNCPOINT ROLLBACK at line 790 upon detecting an Add failure, controlling transactional integrity from the UI layer.
  3. Inquire-Then-Update Pattern (Option 4): Executes an inquiry and update in a single transaction turn, relying on COMMAREA buffers to retain pre-populated entity fields.
  4. Concurrency Locks: Employs explicit EXEC CICS ENQ RESOURCE('GENACNTL') and DEQ operations during menu interactions.
  5. Unstructured Control Flow: Relies extensively on legacy GO TO branch points (GO TO NO_DATA, GO TO NO_UPD, GO TO NO_ADD, GO TO ERROR_OUT, GO TO ENDIT_STARTIT).

3.4 Persistence Path Complexity: LGACDB01

LGACDB01 serves as a direct Db2 add program, duplicating significant portions of LGACUS01:

  • Redundant Logic: Contains duplicate implementations of OBTAIN_CUSTOMER_NUMBER and INSERT_CUSTOMER. Any modification to customer sequence generation or column defaults must be synchronized across both programs.
  • Fallback Behavior Discrepancy: If GENACUSTNUM is unavailable, it switches customer number generation from an explicit counter value to Db2 DEFAULT identity columns, causing behavioral variance depending on CICS runtime state.

3.5 Operational Anomaly: LGICVS01

LGICVS01 functions as an anomalous hybrid component:

  • Dual Invocation Handling: Inspects WS_STARTCODE to determine whether it was initiated via EXEC CICS LINK or directly from a terminal transaction (CICS RECEIVE).
  • Random Key Discovery: Reads customer bounds from the GENACNTL TS Queue, generates a random number, and executes EXEC CICS READ FILE('KSDSCUST') GTEQ to find the nearest physical key.
  • Direct Terminal I/O: Contains an unreferenced EXEC CICS SEND TEXT path that writes directly to 3270 screens.

4.2 Cross-Domain Include: LGPOLICY.inc

LGPOLICY.inc defines host variable records (DB2_CUSTOMER, DB2_POLICY, DB2_HOUSE, DB2_MOTOR, etc.). LGACUS01 includes this structure directly, establishing a compile-time dependency between customer lifecycle orchestration and the Policy schema.

4.3 Logging Subsystem: LGSTSQ and WRITE_ERROR_MESSAGE

Error reporting across all Customer programs relies on a common pattern:

  • Duplicated Code: An identical 31-line WRITE_ERROR_MESSAGE internal procedure is duplicated across 9 Customer domain programs (LGACDB01, LGACDB02, LGACUS01, LGICDB01, LGICUS01, LGUCDB01, LGUCUS01, LGACVS01, LGUCVS01).
  • CICS Transient Data Coupling: Each procedure formats timestamps and invokes EXEC CICS LINK PROGRAM('LGSTSQ') twice to log errors into a CICS TD Queue.
PLI 
/* Standard Pattern Duplicated Across 9 Programs */
WRITE_ERROR_MESSAGE: PROCEDURE;
    DCL ERROR_MSG CHAR(80);
    /* Format message and timestamp */
    EXEC CICS LINK PROGRAM('LGSTSQ')
              COMMAREA(ERROR_MSG)
              LENGTH(80);
END WRITE_ERROR_MESSAGE;

4.4 Distributed State and Sequence Generation

4.4.1 GENACUSTNUM Named Counter

Customer number generation is offloaded to a CICS Named Counter server:

PLI 
/* Named Counter Invocation in LGACUS01 and LGACDB01 */
EXEC CICS GET COUNTER(GENACOUNT)
          POOL(GENAPOOL)
          VALUE(LASTCUSTNUM)
          RESP(WS_RESP);

Named Counters provide atomic, distributed increments across CICS regions without database record locking. Migrations off CICS must replace this with a relational sequence, identity column, or distributed ID generation service.

4.4.2 GENACNTL Temporary Storage Queue

LGTESTC1 and LGICVS01 coordinate runtime customer number ranges using an unbacked CICS TS Queue (GENACNTL). Both programs serialize updates using explicit CICS ENQ and DEQ operations:

PLI 
/* Concurrency Lock Pattern in LGTESTC1 */
EXEC CICS ENQ RESOURCE('GENACNTL');
EXEC CICS READQ TS QUEUE('GENACNTL') INTO(WS_CNTL_REC) NUMITEMS(WS_ITEMS);
/* Update Range Logic */
EXEC CICS WRITEQ TS QUEUE('GENACNTL') FROM(WS_CNTL_REC) REWRITE;
EXEC CICS DEQ RESOURCE('GENACNTL');

Because the TS Queue is memory-resident, uncommitted state is lost during CICS region recycles unless defined as recoverable.

5. Shared Data and Persistence Risks

5.1 CUSTOMER Table Multi-Path Access

The CUSTOMER relational table is updated through multiple independent paths:

Consumer Component Domain / Layer Access Type SQL Operations / Notes
LGACDB01 Customer (Data) Write INSERT INTO CUSTOMER
LGACUS01 Customer (Orchestrator) Write INSERT INTO CUSTOMER
LGICDB01 Customer (Data) Read SELECT ... FROM CUSTOMER WHERE CUSTOMERNUMBER = ?
LGUCDB01 Customer (Data) Write UPDATE CUSTOMER SET ... WHERE CUSTOMERNUMBER = ?
LGBATCH Batch Reporting Read Standalone report query
LGBATDB2 Batch Reporting Read Direct batch read utility

5.2 CUSTOMER_SECURE Security Record Coupling

CUSTOMER_SECURE stores user credentials generated during customer creation (LGACDB02).

  • Hardcoded MD5 Digest: LGACUS01 and LGACDB01 provision initial accounts with a hardcoded MD5 password hash (5732fec825535eeafb8fac50fee3a8aa).
  • Write-Only Anomaly: No CICS or Batch program in this codebase issues a SELECT against CUSTOMER_SECURE. It is consumed by an external authentication subsystem outside the scanned repository.

5.3 KSDSCUST VSAM Dual-Store Shadow and 2PC Gap

The KSDSCUST VSAM KSDS dataset acts as a parallel shadow store for customer records.

CODE 
Add/Update Event Flow:
[Db2 CUSTOMER Table]  <--- 1. INSERT/UPDATE Committed via DB2 Resource Manager
        │
        └───> [VSAM KSDSCUST]  <--- 2. EXEC CICS WRITE/REWRITE (No 2PC Coordination)

Consistency Vulnerability: CICS does not coordinate Db2 and VSAM updates under a unified Two-Phase Commit protocol. If LGACVS01 fails (e.g., dataset out of space, file disabled), the Db2 transaction remains committed, causing data drift between the relational and VSAM layers.

5.4 Cross-Domain Writes to POLICY Table

LGACUS01 contains direct SQL operations on the POLICY table, breaking encapsulation with the Policy Domain:

Program Domain INSERT UPDATE SELECT DELETE
LGACUS01 Customer ✅ (2 procedures) — ✅ (1 procedure) ✅ (1 procedure)
LGAPDB01 Policy ✅ ✅ ✅ —
LGDPDB01 Policy — — — ✅
LGIPDB01 Policy — — ✅ —

5.5 Db2 Referential Integrity Constraints

Db2 enforces a foreign key constraint linking policies to customers: $\text{POLICY.CUSTOMERNUMBER} \longrightarrow \text{CUSTOMER.CUSTOMERNUMBER}$

  • Attempting to insert a policy without an existing customer yields SQLCODE -530 (handled in LGACUS01.INSERT_CUSTOMER_POLICY).
  • Deleting a customer with active policies violates referential integrity unless cascading deletes are handled by application logic.
  • Splitting Customer and Policy data across independent microservice databases requires replacing relational foreign keys with application-level validation and distributed saga compensation.

  • Monolithic Interface Contract (LGCMAREA): The absence of domain-scoped Data Transfer Objects (DTOs) makes it difficult to extract Customer capabilities as standalone microservices without refactoring caller interfaces.
  • Incomplete MQ Path (LGICUS01): LGICUS01 checks the GENAWMQC TS Queue for an MQHIT= record and branches to program AAAAAAAA (a placeholder stub). This represents an incomplete asynchronous messaging path that must be reconciled during modernization.

Because LGACUS01 bridges the Customer and Policy domains, choosing a decomposition strategy is a critical path decision for migration planning.
