Policy DB2 Persistence & Rating Engine

The Policy DB2 Persistence & Rating Engine is the relational data-access layer of the GenApp General Insurance application. Four CICS-hosted Enterprise PL/I programs handle the full lifecycle of policy and claim records in DB2:

  • LGAPDB01 adds policies and claims.
  • LGIPDB01 inquires on them.
  • LGUPDB01 updates them.
  • LGDPDB01 deletes them.

LGAPDB01 also embeds the rating rules. These cover premium surcharges, multi-policy bundling discounts and broker commission. LGUPDB01 enforces optimistic locking through a timestamp comparison on the POLICY row.

1. Overview

1.1 Purpose

This layer persists and retrieves five record types: Endowment, House, Motor, Commercial and Claim. It does this through a shared POLICY parent table and type-specific child tables. Each program is invoked by an orchestrator through EXEC CICS LINK. Each exchanges data through a COMMAREA, or a channel container in the inquiry case, and returns a two-digit CA_RETURN_CODE.

Program Function Request IDs Main DB2 operations
LGAPDB01 Add policy or claim, apply rating rules 01AEND, 01AHOU, 01AMOT, 01ACOM, 01ACLM INSERT, SELECT COUNT/SUM, conditional UPDATE
LGIPDB01 Inquire on policy or claim 01IEND, 01IHOU, 01IMOT, 01ICOM, 02ICOM, 03ICOM, 05ICOM, 01ICLM, 02ICLM Joined SELECT, cursors
LGUPDB01 Update with optimistic locking 01UEND, 01UHOU, 01UMOT Cursor FOR UPDATE, UPDATE
LGDPDB01 Delete policy (cascade) 01DEND, 01DHOU, 01DCOM, 01DMOT DELETE

1.2 Key Business Capabilities

  • Premium surcharges
    • House policies in postcodes 600000–699999 are loaded by property value band.
    • Motor premiums are loaded by accident count.
    • Commercial flood and weather premiums get a 15% surcharge in high-peril postcodes.
  • Bundling discount: customers with more than two active motor and house policies receive 15% off the payment.
  • Broker commission
    • The rate is tiered from 0% to 5% by the broker’s active policy count.
    • Commission is halved when a policy has more than three claims in the current year.
  • Optimistic locking: updates are rejected with return code 02 when CA_LASTCHANGED does not match the DB2 value.
  • Transactional integrity: SQL failures in secondary inserts trigger EXEC CICS ABEND ABCODE('LGSQ'), which backs out the whole unit of work.
  • Dual-store synchronisation: each program links to a VSAM counterpart after the DB2 work (LGAPVS01, LGUPVS01, LGDPVS01).

The orchestrators call the four DB2 programs. Each program writes to or reads from DB2 and calls its VSAM counterpart where one exists. Every program uses the shared LGSTSQ utility to log errors to a transient data queue.

2.2 Shared Infrastructure

Element Description
LGCMAREA Pointer-based COMM_AREA union covering all request types. Maximum size is 32,500 bytes.
LGPOLICY DB2 host-variable structures and length constants for Customer, Policy, Endowment, House, Motor, Commercial and Claim.
DCLPOLIC, DCLENDOW DCLGEN declarations for the POLICY and ENDOWMENT tables.
SQLCA Supplies SQLCODE after every SQL statement.
LGSTSQ Writes the ERROR_MSG record and up to 90 bytes of COMMAREA to the CSMT TDQ.

2.3 Common Entry Pattern

Every program performs the same start-up steps:

  1. Capture EIBTRNID, EIBTRMID and EIBTASKN into the working-storage header.
  2. Test EIBCALEN = 0. If true, log the error and abend LGCA with NODUMP.
  3. Initialise CA_RETURN_CODE to '00'.
  4. Convert CA_CUSTOMER_NUM and CA_POLICY_NUM to FIXED BIN(31) host variables.
  5. Dispatch on CA_REQUEST_ID with a PL/I SELECT/WHEN.

3.1 Entity Relationships

POLICY is the parent table. Endowment, House, Motor and Commercial rows are children keyed by POLICYNUMBER. Claims also reference POLICY. The delete program relies on foreign-key cascade to remove child rows.

4.2 Request Routing and Length Validation

Request ID Policy type DB2_POLICYTYPE Added to required COMMAREA length
01AEND Endowment E 124
01AHOU House H 130
01AMOT Motor M 137
01ACOM Commercial C none
01ACLM Claim X none

The base header length is 28 bytes. If EIBCALEN is shorter than the computed minimum, the program sets CA_RETURN_CODE = '98' and returns without any database work. An unrecognised request ID gives '99'.

4.3 Insert Sequence

The sequence below applies to a non-claim request:

sequenceDiagram participant Orch as Orchestrator participant ADD as LGAPDB01 participant DB2 as DB2 participant VS as LGAPVS01 Orch->>ADD: LINK with COMMAREA ADD->>DB2: SELECT COUNT (bundling) DB2-->>ADD: Active M and H count ADD->>DB2: SELECT COUNT (broker commission) DB2-->>ADD: Broker active policies ADD->>DB2: INSERT INTO POLICY DB2-->>ADD: SQLCODE 0 ADD->>DB2: IDENTITY_VAL_LOCAL and SELECT LASTCHANGED DB2-->>ADD: Policy number and timestamp ADD->>DB2: INSERT INTO type table DB2-->>ADD: SQLCODE 0 ADD->>VS: LINK (32500 bytes) ADD-->>Orch: RC 00 and CA_POLICY_NUM

INSERT_POLICY runs the rating rules in this order:

  1. The house surcharge, for house requests only.
  2. BUNDLING_DISCOUNT.
  3. CALCULATE_COMMISSION.
  4. The POLICY insert.

The POLICY insert uses DEFAULT for POLICYNUMBER and CURRENT TIMESTAMP for LASTCHANGED. IDENTITY_VAL_LOCAL() then returns the generated policy number, which goes back to the caller in CA_POLICY_NUM.

PLI 
SET :DB2_POLICYNUM_INT = IDENTITY_VAL_LOCAL()

5.2 House Premium Loading

This applies only when the house postcode is in the range 600000–699999.

Property value Surcharge on DB2_PAYMENT_INT
> 10,000,000 and < 15,000,000 +20%
> 15,000,000 and < 20,000,000 +40%
> 20,000,000 +50%

5.3 Bundling Discount

BUNDLING_DISCOUNT counts the customer’s currently active policies of type M or H. If the count is greater than 2, the payment is reduced by 15%.

PLI 
EXEC SQL SELECT COUNT(POLICYNUMBER) ... 
  WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT
    AND POLICYTYPE IN ('M','H')
    AND ISSUEDATE < CURRENT DATE AND EXPIRYDATE > CURRENT DATE;

An SQL error here sets CA_RETURN_CODE = '90' and abends LGSQ.

5.4 Broker Commission Tiers

CALCULATE_COMMISSION counts the broker’s active policies. WS_COMMISSION is then set as a percentage of DB2_PAYMENT_INT and stored in the COMMISSION column.

Active broker policies Commission rate
0 0%
1 1%
2 2%
3 3%
4 4%
5 or more 5%

5.5 Motor Accident Loading

INSERT_MOTOR applies the multiplier to CA_M_PREMIUM before the MOTOR row is inserted.

CA_M_ACCIDENTS Multiplier
0–2 ×1.00
3–5 ×1.20
6–8 ×1.50
> 8 ×3.00

5.6 Commercial Peril Surcharge

VALIDATE_PREV_PERIL runs two independent queries against active COMMERCIAL rows with the same ZIPCODE. One sums FLOODPERIL and the other sums WEATHERPERIL. If a sum is greater than 3, the matching flag is set to 'Y'. INSERT_COMMERCIAL then raises that premium by 15%.

sequenceDiagram participant IC as INSERT_COMMERCIAL participant VP as VALIDATE_PREV_PERIL participant DB2 as DB2 COMMERCIAL IC->>VP: CALL VP->>DB2: SELECT SUM(FLOODPERIL) by ZIPCODE DB2-->>VP: Sum VP->>DB2: SELECT SUM(WEATHERPERIL) by ZIPCODE DB2-->>VP: Sum VP-->>IC: WS_FLOOD_FLG and WS_WEATHER_FLG IC->>DB2: INSERT with adjusted premiums

5.7 Claim-Frequency Commission Reduction

Before a CLAIM row is inserted, UPDATE_BROKER_COMM counts claims for the policy where YEAR(CLAIMDATE) = YEAR(CURRENT DATE). If the count is greater than 3, it halves the commission:

PLI 
UPDATE POLICY SET COMMISSION = (COMMISSION / 2)
  WHERE POLICYNUMBER = :DB2_C_Policynum_INT

5.8 Worked Examples

Motor policy with four accidents

  • Input values: CA_REQUEST_ID = 01AMOT, CA_PAYMENT = 1200, CA_M_PREMIUM = 800, CA_M_ACCIDENTS = 4.
  • Result:
    • Return code 00.
    • The MOTOR row stores PREMIUM = 960 (800 × 1.20).
    • The POLICY row keeps PAYMENT = 1200 because there is no bundling discount.

House policy with surcharge, discount and top-tier commission

  • Input values: CA_PAYMENT = 2000, postcode 650000, value 12000000. Assumed database state: the customer holds 3 active motor/house policies and the broker holds 5 active policies.
  • Result:
    1. The postcode surcharge gives 2000 + 20% = 2400.
    2. The bundling discount gives 2400 − 15% = 2040.
    3. Commission is 5% of 2040, which is 102.

Claim that halves commission

  • Input values: CA_REQUEST_ID = 01ACLM, CA_POLICY_NUM = 7891. Assumed database state: three claims already exist this year.
  • Result:
    • INSERT_POLICY is skipped.
    • The commission is halved.
    • The CLAIM row is inserted.

6. Policy and Claim Inquiry (LGIPDB01)

6.1 Input Channels and Dispatch

LGIPDB01 first tries EXEC CICS GET CONTAINER('ICOM-Data') CHANNEL('ICOM'). If that succeeds, the container supplies the COMMAREA pointer. Otherwise it falls back to the standard COMMAREA and abends LGCA if EIBCALEN = 0. The request ID is upper-cased before dispatch.

Request ID Procedure Selection criteria
01IEND GET_ENDOW_DB2_INFO Customer and policy
01IHOU GET_HOUSE_DB2_INFO Customer and policy
01IMOT GET_MOTOR_DB2_INFO Customer and policy
01ICOM GET_COMMERCIAL_DB2_INFO_1 Customer and policy
02ICOM GET_COMMERCIAL_DB2_INFO_2 Policy only
03ICOM GET_COMMERCIAL_DB2_INFO_3 All commercial policies for a customer, via Cust_Cursor, maximum 20
05ICOM GET_COMMERCIAL_DB2_INFO_5 By ZIP code, via Zip_Cursor
01ICLM GET_CLAIM_DB2_INFO_1 Claim number
02ICLM GET_CLAIM_DB2_INFO_2 All claims for a customer, via CusClaim_Cursor

6.2 Single-Row Retrieval Pattern

graph TD S[Joined SELECT POLICY + type table] --> Q{SQLCODE} Q -- 0 --> L{EIBCALEN >= required} Q -- 100 --> NF[RC 01 not found] Q -- Other --> ER[RC 90 and log] L -- No --> SM[RC 98] L -- Yes --> MV[Convert integers
Skip NULL-flagged fields
Copy data and write FINAL marker]
  • Nullable columns (BROKERID, BROKERSREFERENCE, PAYMENT, PADDINGDATA) are fetched with indicator variables and copied only when the indicator is not -1.
  • The required COMMAREA length is the 33-byte header/trailer plus a type constant: endowment 124, house 130, motor 137, commercial 1174, claim 618. For endowment, the actual padding length is added when PADDINGDATA is not NULL.
  • A 'FINAL' sentinel marks the end of the returned data.

7. Policy Update with Optimistic Locking (LGUPDB01)

7.1 Concurrency Model

LGUPDB01 uses a cursor declared WITH HOLD FOR UPDATE on the POLICY row. The caller supplies the LASTCHANGED timestamp it originally read in CA_LASTCHANGED. The program compares it with the timestamp it fetches from DB2:

PLI 
IF ( CA_LASTCHANGED = DB2_LASTCHANGED ) THEN
   /* proceed with update */
ELSE
   CA_RETURN_CODE = '02';

On a mismatch, no update is made. The caller must re-read the record and retry.

7.2 Update Sequence

sequenceDiagram participant Orch as Orchestrator participant UPD as LGUPDB01 participant DB2 as DB2 participant VS as LGUPVS01 Orch->>UPD: LINK with COMMAREA UPD->>DB2: OPEN POLICY_CURSOR UPD->>DB2: FETCH row DB2-->>UPD: LASTCHANGED alt Timestamps match UPD->>DB2: UPDATE type table by POLICYNUMBER UPD->>DB2: UPDATE POLICY WHERE CURRENT OF cursor UPD->>DB2: SELECT new LASTCHANGED DB2-->>UPD: New timestamp else Mismatch UPD->>UPD: RC 02 end UPD->>DB2: CLOSE POLICY_CURSOR UPD->>VS: LINK (225 bytes) UPD-->>Orch: RETURN

7.3 Ordering and Atomicity

  • The type-specific table (ENDOWMENT, HOUSE or MOTOR) is updated first. If it fails, the POLICY header is not touched.
  • The POLICY update sets LASTCHANGED = CURRENT TIMESTAMP. The new value is selected back into CA_LASTCHANGED, so the caller holds a fresh concurrency token.
  • If the POLICY update or the timestamp re-read fails, the program issues EXEC CICS SYNCPOINT ROLLBACK and sets return code 90.
  • If ENDOWMENT is updated and WS_VARY_LEN = EIBCALEN - WS_REQUIRED_CA_LEN is greater than 0, the extra bytes are treated as VARCHAR padding data.
  • CLOSE_PCURSOR treats SQLCODE -501 as harmless.

7.4 Return Codes

Code Meaning
00 Updated
01 Row not found
02 Timestamp mismatch (optimistic lock failure)
90 DB2 or lock error, including -913 on cursor open

The house update path sets '01' for any non-zero SQLCODE, unlike the endowment and motor paths, which set '90' for errors other than 100.

8. Policy Deletion (LGDPDB01)

LGDPDB01 validates the COMMAREA, accepts four delete codes (01DEND, 01DHOU, 01DCOM, 01DMOT) and issues one DELETE against POLICY. DB2 foreign-key cascade removes the child row.

PLI 
EXEC SQL DELETE FROM POLICY
  WHERE (CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT
    AND POLICYNUMBER   = :DB2_POLICYNUM_INT);
graph TD A([Start]) --> B{EIBCALEN = 0} B -- Yes --> C[Log and abend LGCA] B -- No --> D{EIBCALEN < 28} D -- Yes --> E[RC 98 Return] D -- No --> F{Request ID valid} F -- No --> G[RC 99] F -- Yes --> H[DELETE FROM POLICY] H --> I{SQLCODE not 0} I -- Yes --> J[RC 90, log, Return] I -- No --> K[LINK LGDPVS01] K --> L([RETURN]) G --> L

The code tests SQLCODE <> 0, so SQLCODE 100 (row not found) also takes the error path. The documentation describes 100 as an acceptable outcome. The coded test does not match that description.

99 Unrecognised request

9. Error Handling and Transaction Integrity

9.1 Error Handling Strategy

Mechanism Used when Effect
ABEND LGCA NODUMP No COMMAREA received Task terminated
ABEND LGSQ NODUMP SQL error in a secondary insert or rating query (LGAPDB01) CICS backs out the whole unit of work, including the POLICY row
RETURN with RC 70 or 90 Failure on the initial POLICY INSERT Clean return, since nothing needs to be backed out
SYNCPOINT ROLLBACK POLICY update failure (LGUPDB01) Explicit rollback with RC 90
Return code only Validation and business rejections (98, 99, 02, 01) Caller decides next step

On the POLICY INSERT, SQLCODE -530 (referential integrity violation, for example a non-existent customer) maps to CA_RETURN_CODE = '70'. Any other failure maps to '90'.

9.2 Centralised Logging

WRITE_ERROR_MESSAGE is present in every program:

  1. It captures SQLCODE into EM_SQLRC.
  2. It calls EXEC CICS ASKTIME and FORMATTIME to fill EM_DATE and EM_TIME.
  3. It links to LGSTSQ with the ERROR_MSG record, which holds the program name, customer number, policy number, SQL request label and SQLCODE.
  4. If EIBCALEN > 0, it links to LGSTSQ again with up to 90 bytes of raw COMMAREA.

Before each SQL statement, EM_SQLREQ is set to a short label such as ' INSERT POLICY', ' DELETE POLICY ' or 'BUNDLE DISCNT '. The log therefore identifies the failing operation.

11. Constraints and Design Considerations

  • Field sizes
    • The COMMAREA uses fixed-width pictures: CA_PAYMENT is 6 digits, CA_H_VALUE is 8 digits, CA_M_ACCIDENTS is 6 digits, and peril fields are 4 digits.
    • Larger values do not fit.
  • Sequencing in LGAPDB01
    • The POLICY insert must precede the type-specific insert.
    • Claims reference an existing policy and skip the POLICY insert.
  • Commission rounding
    • The commission is stored in a SMALLINT column, so large payments may not fit.
  • VSAM links are unconditional
    • LGUPDB01 links to LGUPVS01 regardless of CA_RETURN_CODE.
    • It passes only 225 bytes.
  • Repeated rating guard
    • Both LGAPDB01 request-ID checks reject unknown values.
    • The second check acts only as a fallback.
  • Endowment padding
    • PADDINGDATA is populated only when the COMMAREA is longer than the fixed portion.
    • The maximum COMMAREA is 32,500 bytes.
    • The update program caps the VARCHAR work area at 3,900 bytes.
  • Inquiry on container path
    • When data arrives via the container, CA_RETURN_CODE is not initialised to '00'.
