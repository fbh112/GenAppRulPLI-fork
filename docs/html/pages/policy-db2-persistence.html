1. Policy DB2 Persistence & Pricing Rules

1.1 Overview

This page documents the DB2 persistence layer of the General Insurance (GenApp) policy system. It covers four Enterprise PL/I programs that run under CICS. Each one handles one CRUD operation against the DB2 POLICY table and its policy-type child tables:

Program CRUD Role Request ID Family Key Behavior
LGAPDB01 Create (Add) 01AEND, 01AHOU, 01AMOT, 01ACOM, 01ACLM Applies pricing rules, then inserts policy and detail rows
LGIPDB01 Read (Inquire) 01IEND, 01IHOU, 01IMOT, 01ICOM, 02ICOM, 03ICOM, 05ICOM, 01ICLM, 02ICLM Single-row and cursor-based retrieval
LGUPDB01 Update 01UEND, 01UHOU, 01UMOT Optimistic locking on LASTCHANGED
LGDPDB01 Delete 01DEND, 01DHOU, 01DCOM, 01DMOT Deletes the parent row. DB2 referential integrity cascades to the children.

The insertion engine LGAPDB01 also holds the business pricing rules:

  • House location surcharges.
  • A 15% bundling discount.
  • Motor accident loading.
  • A 15% commercial flood and weather peril surcharge.
  • Tiered broker commission.
  • Commission halving when claim frequency is high.

Every program follows the same conventions:

  • The caller passes a CICS COMMAREA, and CA_RETURN_CODE reports the outcome.
  • Errors are logged to a transient data queue through LGSTSQ.
  • After the DB2 work, the program links to a VSAM counterpart (LGAPVS01, LGUPVS01, LGDPVS01) to keep the two stores in sync. LGIPDB01 has no VSAM counterpart.

1.2 Scope of the Page

  • DB2 CRUD operations for Endowment, House, Motor, Commercial and Claim records.
  • Referential cascades on delete and referential-integrity checks on insert.
  • Premium adjustments: house location loading, bundling discount, motor accident loading.
  • Peril surcharges for commercial flood and weather.
  • Broker commission calculation and claim-driven commission reduction.

The orchestrators call the four DB2 programs with EXEC CICS LINK. The DB2 programs write to the shared DB2 schema. The three programs that change data then call a VSAM counterpart, and every program logs failures through LGSTSQ.

3. Create Operations – LGAPDB01

3.1 Purpose

LGAPDB01 is the DB2 insertion engine. It supports five request types: Endowment, House, Motor, Commercial and Claim. Before each insert it applies the pricing rules. After a successful insert it returns the DB2-generated policy number to the caller in the COMMAREA, then links to LGAPVS01.

3.2 Request Routing and Validation

Request ID Policy Type (DB2_POLICYTYPE) Extra required length
01AEND E WS_FULL_ENDOW_LEN (124)
01AHOU H WS_FULL_HOUSE_LEN (130)
01AMOT M WS_FULL_MOTOR_LEN (137)
01ACOM C none
01ACLM X none
Other – CA_RETURN_CODE = '99' and return

The base header length is 28 bytes. If EIBCALEN is less than the computed minimum, the program sets CA_RETURN_CODE = '98' and returns without touching DB2. If EIBCALEN = 0, it abends with LGCA.
