Policy VSAM KSDS Data Persistence

1. Overview

The Policy VSAM KSDS Data Persistence layer is the data access tier for the insurance policy file KSDSPOLY. It is a CICS VSAM Key-Sequenced Data Set that holds Commercial, Endowment, House and Motor policy records in one fixed-format file. Four Enterprise PL/I programs make up the layer. Each handles one kind of file operation:

Program Operation CICS File Command Failure Return Code Abend Code
LGAPVS01 Add (write) a new policy record WRITE FILE 80 None
LGIPVS01 Generic key browse (inquiry) READ FILE GENERIC GTEQ Sentinel 13 in the returned key None
LGUPVS01 Update an existing policy record READ UPDATE followed by REWRITE 81 (read), 82 (rewrite) LGV3, LGV4
LGDPVS01 Delete a policy record DELETE FILE 81 None

All four programs share these design points:

  • Record layout. The record is 64 bytes. It has a 21-byte composite key followed by a 43-byte policy-type-specific payload.
  • Policy type. The 4th character of CA_REQUEST_ID selects the policy type: C (Commercial), E (Endowment), H (House) or M (Motor).
  • Interface. Callers pass a COMMAREA, described by the shared LGCMAREA layout. The programs signal failure back through CA_RETURN_CODE.
  • Error logging. Failures are logged by linking to the diagnostic program LGSTSQ.
  • No DB2. None of these programs use DB2. All persistence goes through CICS file control.

1.1 Record Key and Layout

Component Length Source
WF_REQUEST_ID 1 byte 4th character of CA_REQUEST_ID
WF_CUSTOMER_NUM 10 bytes CA_CUSTOMER_NUM
WF_POLICY_NUM 10 bytes CA_POLICY_NUM
WF_POLICY_DATA (UNION) 43 bytes Commercial, Endowment, House or Motor overlay
Total record 64 bytes Written with LENGTH(64), key length 21

2. System Architecture

Calling programs, such as the policy orchestrator LGAPOL01, pass a COMMAREA to one of the four VSAM programs. Each program builds the composite key and issues the matching CICS file control command against KSDSPOLY. Error diagnostics go to LGSTSQ.

2.1 Component Responsibilities

  • LGAPVS01 builds the composite key and the policy payload, then issues WRITE FILE. It returns 80 on failure.
  • LGIPVS01 accepts a partial key of policy type plus a customer number. It runs in two modes, COMMAREA (called by LINK) or terminal (RECEIVE), and does a single generic GTEQ read. It returns either the found key or a Policy Bad= indicator.
  • LGUPVS01 maps the new field values into the working record. It locks the record with READ UPDATE, then does a REWRITE. It returns 81 or 82 and abends with LGV3 or LGV4 on failure.
  • LGDPVS01 builds the key and issues DELETE. It returns 81 on failure.
  • LGSTSQ receives the formatted error message and, optionally, a snapshot of the COMMAREA.
  • LGCMAREA is the shared PL/I include. It defines the COMM_AREA UNION, 32,500 bytes in total, and its COMM_AREA_RAW overlay.

3. Data Model

3.1 Working Record Structure

The write, update and delete programs build the 21-byte key in working storage. The write and update programs also build the 43-byte payload. The payload is a PL/I UNION, so only the overlay for the active policy type holds data.

3.2 Field Truncation on Assignment

Some COMMAREA fields are longer than their record counterparts. PL/I truncates them on assignment, as shown below.

COMMAREA Field COMMAREA Length Record Field Stored Length
CA_B_Customer 255 WF_B_Customer 31
CA_E_LIFE_ASSURED 31 WF_E_LIFE_ASSURED 30
CA_H_HOUSE_NAME 20 WF_H_HOUSE_NAME 9 (documented for LGUPVS01)

3.3 Composite Key Construction

All programs that address a specific record build the key the same way:

CODE 
WF_Request_ID   = SUBSTR(CA_Request_ID,4,1);
WF_Policy_Num   = CA_Policy_Num;
WF_Customer_Num = CA_Customer_Num;

For a Motor policy for customer 0000001234 with policy number 0000009901, the key is M followed by 0000001234 and 0000009901. That is 21 bytes in total.

4. Add Policy Record (LGAPVS01)

4.1 Processing Flow

LGAPVS01 copies the key fields from the COMMAREA, then uses a SELECT on the policy type to fill the matching payload. It writes the 64-byte record and handles any non-normal response.

4.2 Write Command

The program writes a fixed 64-byte record. The 21-byte key is passed as RIDFLD, and the CICS response goes to WS_RESP.
