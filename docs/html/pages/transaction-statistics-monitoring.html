Transaction Statistics & Telemetry Pipeline

1. Overview

The Transaction Statistics & Telemetry Pipeline is the operational-metrics layer of the GenApp general insurance application. Two cooperating CICS PL/I programs implement it.

Program Role Trigger
LGASTAT1 Event-processing adapter. Classifies each business event by request type and outcome, and resolves the matching CICS named counter. Invoked per business event, either through the CICS Event Processing (EP) channel or with a COMMAREA.
LGWEBST5 Continuous background collector. Harvests named counters every minute and computes real-time delta rates. Self-scheduling transaction SSST.

Together they cover these business operations:

  • Customer inquiry and add.
  • Motor, endowment, house and commercial policy inquiry, add, update and delete.

Key characteristics:

  • Event-driven classification. LGASTAT1 builds a counter name of the form GENA<request><type> in the GENA counter pool. It normalizes request variants and collapses all failure codes into a single 99 bucket.
  • Time-driven harvesting. LGWEBST5 reads 35 named counters (1 customer-number counter, 17 success counters and 17 error counters). It stores a new / old / delta triple per counter in CICS Temporary Storage Queues (TSQs).
  • No database dependency. All state lives in CICS named counters and temporary storage. There are no DB2 tables.
  • Self-sustaining. LGWEBST5 restarts itself with EXEC CICS START TRANSID('SSST') AFTER MINUTES(1). Dashboards or monitors can read the TSQs for near-real-time throughput.

3. Event Classification with LGASTAT1

3.1 Purpose

LGASTAT1 is a CICS event-processing adapter target. Each time a business transaction finishes, it receives a request identifier (for example 01IMOT, Inquire Motor) and a return code. It maps these to a named counter and resolves that counter. The result is a running tally of business events, categorized by request type and by success or failure.

3.2 Inputs

Source Field Description
EP channel container DFHEP.DATA.00001 WS_DATA_REQ 6-character request identifier (primary source).
EP channel container DFHEP.DATA.00002 WS_DATA_RC 2-character return code (primary source).
COMMAREA (fallback) CA_REQUEST_ID 6-character request ID.
COMMAREA (fallback) CA_RETURN_CODE 2-digit return code (PIC '99').
EIB EIBCALEN, EIBTRNID, EIBTRMID, EIBTASKN Presence of a COMMAREA, plus diagnostic context.
TS queue GENASTRT — Initialization marker.
Counter pool GENA — Source of counter values.

3.4 Input Selection: Channel First, COMMAREA Fallback

The program issues two GET CONTAINER calls and tests only the final RESP. If the channel data is unavailable, it falls back to the COMMAREA. If there is no COMMAREA either, the task ends silently.

PLI 
IF EIBCALEN = 0 THEN
   EXEC CICS RETURN;

3.5 First-Use Initialization Marker

On first use, READQ TS against GENASTRT returns QIDERR. The program then stamps the current date and time into the queue. It never rewrites that record afterward.

Field Declaration / value Purpose
WS_QNAME CHAR(8) STATIC INIT('GENASTRT') Queue name.
WS_AREA_D 8 bytes Startup date.
WS_AREA_T 2-byte filler plus 6 bytes of time Startup time.
WS_QLEN STG(WS_QAREA) (16 bytes) Record length.

3.6 Counter Name Normalization

Normalization consolidates equivalent business events so statistics are not fragmented.

PLI 
IF GENACOUNTER = '02ACUS' THEN GENACOUNTER = '01ACUS';
IF GENACOUNTER = '02ICOM' | GENACOUNTER = '03ICOM' | GENACOUNTER = '05ICOM'
   THEN GENACOUNTER = '01ICOM';
IF GENATYPE ^= '00' THEN GENATYPE = '99';
Input request Normalized request Rationale
02ACUS 01ACUS Add Customer variants share one counter.
02ICOM, 03ICOM, 05ICOM 01ICOM Commercial inquiry variants share one counter.
Input return code Normalized type Meaning
00 00 Success.
Anything else 99 Generic failure bucket.

3.7 Counter Name Layout

The counter name is a fixed 16-character string. The overlay GENACOUNT_STR CHAR(16) is BASED on the GENACOUNT structure, so the normalized values are used automatically in the GET COUNTER call.

Offset Length Content
1 4 Literal GENA.
5 6 GENACOUNTER (normalized request).
11 2 GENATYPE (00 or 99).
13 4 Trailing spaces.

Example: GENA + 01ACUS + 99 + 4 spaces gives GENA01ACUS99 .

3.8 Behavior Note on GET COUNTER

The program text and purpose statements describe each invocation as counting the event, which matches the CICS behavior of GET COUNTER. It increments the named counter and returns the new value in TRANCOUNT. One internal note in the program analysis says the call only reads the value and that incrementing happens elsewhere. Verify this against the counter definition and the calling flow in your environment. The resulting value stays in working storage. No PUT CONTAINER or RETURN DATA is issued.

3.9 Worked Examples

Scenario Inputs Result
Channel input, motor inquiry success Containers 01IMOT / 00 Counter GENA01IMOT00 is resolved. No normalization applies.
COMMAREA fallback, failed add customer CA_REQUEST_ID='02ACUS', CA_RETURN_CODE='01', GENASTRT missing GENASTRT is created. The request becomes 01ACUS and the type becomes 99, so counter GENA01ACUS99 is resolved.
No channel, no COMMAREA EIBCALEN = 0 Immediate RETURN. No counter or queue is touched.

4. Continuous Collection with LGWEBST5

4.1 Purpose

LGWEBST5 runs as transaction SSST. It reads the cumulative counters that LGASTAT1 and the application maintain. It computes how much each changed since the previous run, and persists the results in TS queues. It then schedules its own next execution one minute later.

4.2 Counter Catalog

LGWEBST5 uses static, positionally aligned arrays. Index I selects the same operation in all four.

Array Size Content
CT_SUCCESS 17 Success counter names, GENA01<OP><ENT>00.
CT_ERROR 17 Error counter names, GENA01<OP><ENT>99.
CT_CODE 17 3-character code used to build the rate queue name GENA<code>V.
CT_OPS 17 chars Operation type per entry: I inquire, A add, U update, D delete.

Additionally, GENACUSTNUM is queried once as a stand-alone metric. It is not part of the success or error totals.

4.4 Interval Calculation (TRAN_RATE_INTERVAL)

This procedure runs first, so the restart is scheduled before any statistics work.

  1. Read item 1 of GENA000V, the previous HHMMSS. If the read is not NORMAL, default WS_OLDV to '120000'.
  2. Delete the queue and write the current HHMMSS as item 1.
  3. Convert both times to seconds since midnight (HH*3600 + MM*60 + SS).
  4. Compute ICOUNTVAL = ABS(NCOUNTVAL - OCOUNTVAL) and write it as item 2.
  5. Schedule the next run.
PLI 
EXEC CICS START TRANSID('SSST')
          AFTER MINUTES(1)
          RESP(WS_RESP);

4.5 Rate Tracking (TRAN_RATE_COUNTS)

This reusable routine produces the new / old / delta triple for any queue name in WS_TSQNAME. It serves individual counters and roll-up totals alike.

6. Dependencies

6.1 CICS Resources

Resource Used by Notes
Named counter pool GENA Both Must be defined in the region’s counter server configuration.
TS queue GENASTRT LGASTAT1 Hard-coded name.
TS queues GENA000V, GENA<code>V, GENAX00V–GENAX05V LGWEBST5 Global queues with static names.
Channel containers DFHEP.DATA.00001 / 00002 LGASTAT1 Must match the EP adapter configuration.
Transaction SSST LGWEBST5 Defined in the CSD and mapped to program LGWEBST5.
ASKTIME / FORMATTIME, EIB Both Time services and task context.

6.2 Includes

LGASTAT1 uses %INCLUDE LGCMAREA (plinc/LGCMAREA.inc). It supplies the shared COMM_AREA layout, including the customer, policy, endowment, house, motor, commercial and claim sub-structures. The COMM_AREA_RAW overlay is CHAR(32500).

6.3 Counter-Name Contract Between the Programs

The two programs agree on counter names only by convention.

  • LGASTAT1 builds names such as GENA01ACUS00 / GENA01ACUS99 (GENA + request + type).
  • LGWEBST5 queries the static list GENA01<OP><ENT>00 / 99.

The normalization rules in LGASTAT1 (02ACUS→01ACUS, 02ICOM/03ICOM/05ICOM→01ICOM, non-zero→99) are what keep the counter set bounded. They are also what lets LGWEBST5 use a fixed 17-entry catalog.

7. Constraints

7.1 Data Formats and Sizes

  • GENACOUNTER is CHAR(6) and GENATYPE is CHAR(2). The counter name is exactly 16 characters, and the pool is fixed at GENA.
  • NRATEVAL, ORATEVAL and DRATEVAL are PIC '999999999', so values above 999,999,999 overflow.
  • The WS_TSQDATA buffer is 9 characters. Interval values are 6 characters.
  • ICOUNTVAL is PIC '999999'.
  • Queue names are exactly 8 characters (GENA + code).

7.2 Sequencing

  • In LGASTAT1, containers are read before the COMMAREA fallback is evaluated. Normalization must precede GET COUNTER.
  • In LGWEBST5, TRAN_RATE_INTERVAL runs first. Accumulators are zeroed before the loop. The aggregate queues are written only after the loop completes.
  • Each run schedules exactly one successor. If a run fails before scheduling, the chain stops.

7.3 Known Edge Cases

Topic Behavior
Midnight crossing ABS() prevents a negative interval but gives the wrong elapsed time. Example: previous 235500, current 000100 gives ABS(60 - 86100) = 86040 seconds instead of the true 360.
First-run interval The default '120000' (noon) makes the first interval reflect time since noon.
CT_OPS values The SELECT has no OTHERWISE. Any character other than I, A, U or D is unhandled.
Missing counter QUERY COUNTER failures are not checked. A stale COUNTVAL may be accumulated.
Queue sharing TSQ names are static, so the queues are shared by all concurrent instances.
Restart interval Fixed at one minute and not configurable.
Failure granularity LGASTAT1 reports only 00 or 99. Per-error-code statistics are not available.

8. Error Handling

Both programs use RESP(...) on every CICS command, which suppresses default abends and keeps control in the program. Only a few responses are actually inspected.

Program Condition Handling
LGASTAT1 Container GET not NORMAL Fall back to the COMMAREA.
LGASTAT1 No COMMAREA (EIBCALEN = 0) Clean RETURN with no updates.
LGASTAT1 READQ TS returns QIDERR Create the GENASTRT marker record.
LGASTAT1 Unknown or failing return codes Collapsed to 99.
LGWEBST5 GENA000V read not NORMAL WS_OLDV = '120000'.
LGWEBST5 Rate queue read not NORMAL ORATEVAL = 0, so the first delta equals the full value.
LGWEBST5 DELETEQ, WRITEQ, START and QUERY COUNTER responses Captured but not evaluated (silent tolerance).
PLI 
/* Defensive default for a missing prior snapshot */
IF WS_RESP = DFHRESP(NORMAL) THEN
   ORATEVAL = WS_TSQDATA;
ELSE
   ORATEVAL = 0;

9. Operational Guidance

  • Reading the telemetry. Consumers should read items 1, 2 and 3 of each rate queue in order. Item 3 is the per-interval delta. Divide it by item 2 of GENA000V (elapsed seconds) to obtain a per-second rate.
  • Start-up. Define the GENA pool, the SSST transaction (program LGWEBST5) and the EP adapter. Start SSST once, and it perpetuates itself.
  • Monitoring the collector. If the rate queues stop updating, check whether SSST is still being scheduled. A failure before TRAN_RATE_INTERVAL completes breaks the chain.
  • Interpreting the first interval. Expect inflated first-cycle deltas and an anomalous first interval, because of the zero and 120000 defaults.
