Random Customer Selector (LGICVS01)

1. Overview

LGICVS01 is a CICS PL/I utility in the General Insurance Application (GenApp). It randomly selects a valid customer number from the VSAM KSDS customer file KSDSCUST.

The program works in these steps:

  1. It works out how it was invoked. A caller may have used EXEC CICS LINK with a COMMAREA, or a user may have started it from a terminal.
  2. It reads the GENACNTL temporary storage queue (TSQ) to get the lower and upper customer-number boundaries. An ENQ/DEQ pair serialises this access. If the control records are missing, the program writes them with defaults.
  3. It seeds PL/I RANDOM with the CICS task number (EIBTASKN) and computes a random number in the configured range.
  4. It issues a GTEQ read against KSDSCUST to find the nearest real customer key.
  5. It returns the resolved customer number in the COMMAREA (linked callers) or with EXEC CICS SEND TEXT (terminal users). It then issues EXEC CICS RETURN.

Characteristic Detail

3. Inputs

3.1 CICS Execution Environment (EIB Fields)

Field Use
EIBTASKN Task number. It seeds the PL/I RANDOM built-in.
EIBCALEN COMMAREA length. It is assigned to WS_RECV_LEN in COMMAREA mode.

3.2 CICS ASSIGN Values

Source Target Meaning
STARTCODE WS_STARTCODE (2 chars) A first character of 'D' means the program was not started interactively.
INVOKINGPROG WS_INVOKEPROG (8 chars) A non-blank value means the program was linked from another program.
SYSID WS_SYSID (4 chars) Local system ID. It is retrieved but not used in the logic.

3.3 Program Parameter (COMMAREA)

COMM_AREA_PTR points to the COMMA_DATA based structure:

Field Definition Description
COMMA_DATA_H 14 characters Header such as 'HIGH CUSTOMER='
COMMA_DATA_HIGH PIC '(10)9' Receives the resolved customer number
COMMA_DATA_FILL 60 characters Filler, blanked on return

3.4 Terminal Input

In terminal mode the program issues EXEC CICS RECEIVE INTO(WS_RECV). The 80-byte buffer holds WS_RECV_TRANID (5 characters) followed by WS_RECV_DATA (74 characters).

3.5 TS Queue GENACNTL

The program reads the queue sequentially and looks for these records:

  • LOW CUSTOMER is the lower bound (READ_CUST_LOW → WS_CUST_LOW). The default is 1000001.
  • HIGH CUSTOMER is the upper bound (READ_CUST_HIGH → WS_CUST_HIGH). The default is 1000001.

3.6 VSAM File KSDSCUST

The program reads this file with a GTEQ search into the 225-byte CA_AREA. The first 10 characters, CA_CUSTOMER_NUM, hold the actual customer key.

4. Outputs

4.1 TS Queue Writes (GENACNTL)

The program writes records only when they are missing:

Record Variable Length Written when
Eyecatcher **** GENAPP CNTL WRITE_MSG_E 20 bytes WS_FLAG_TSQE = 'Y' (queue absent)
LOW CUSTOMER= + value WRITE_MSG_L 23 bytes WS_FLAG_TSQL = 'Y'
HIGH CUSTOMER= + value WRITE_MSG_H 24 bytes WS_FLAG_TSQH = 'Y'

4.2 COMMAREA Return (WS_FLAG = 'C')

Field Content
COMMA_DATA_H 'HIGH CUSTOMER=' label from WRITE_MSG_H
COMMA_DATA_HIGH The resolved customer number (WRITE_MSG_HIGH)
COMMA_DATA_FILL 60 spaces

4.3 Terminal Output (WS_FLAG = 'R')

The program sends the 24-byte WRITE_MSG_H (label plus customer number) with EXEC CICS SEND TEXT, using ERASE, FREEKB and WAIT.

5.2 Sequence of Operations

The sequence below covers a call through CICS LINK when the queue is already populated.

5.3 Processing Steps

5.3.1 Determine Invocation Mode

The program issues three ASSIGN commands. If STARTCODE begins with 'D' or INVOKINGPROG is not blank, it sets WS_FLAG = 'C'. It then copies the COMMAREA header and takes the length from EIBCALEN. Otherwise it issues RECEIVE and sets WS_FLAG = 'R'.

PLI 
IF SUBSTR(WS_STARTCODE,1,1) = 'D' | WS_INVOKEPROG ^= ' ' THEN DO;
   WS_FLAG = 'C';
   WS_COMMAREA = COMMA_DATA_H;
   WS_RECV_LEN = EIBCALEN;
END;
ELSE DO;
   EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN);
   WS_FLAG = 'R';
   WS_COMMAREA = WS_RECV_DATA;
   WS_RECV_LEN = WS_RECV_LEN - 5;
END;

5.3.2 Initialise Range Defaults

WS_CUST_LOW and WS_CUST_HIGH both start at 1000001. All three TS-queue flags (WS_FLAG_TSQE, WS_FLAG_TSQH, WS_FLAG_TSQL) start as 'Y'. This means every record is assumed missing until the read proves otherwise.

5.3.3 Serialise and Read the Control Queue

The program takes an exclusive enqueue on GENACNTL, then reads item 1.

  • If item 1 is read normally, the queue exists. The program clears WS_FLAG_TSQE. It then loops with READQ TS NEXT until WS_RESP > 0.
  • A record starting with 'LOW CUSTOMER' sets WS_CUST_LOW and clears WS_FLAG_TSQL.
  • A record starting with 'HIGH CUSTOMER' sets WS_CUST_HIGH and clears WS_FLAG_TSQH.
PLI 
EXEC CICS ENQ RESOURCE(STSQ_NAME) LENGTH(STG(STSQ_NAME));
EXEC CICS READQ TS QUEUE(STSQ_NAME) INTO(READ_MSG) ITEM(1) RESP(WS_RESP);

5.3.4 Write Missing Control Records

The program writes any record whose flag is still 'Y', using NOSUSPEND. It then releases the enqueue.

Flag Record written Length
WS_FLAG_TSQE = 'Y' **** GENAPP CNTL 20
WS_FLAG_TSQL = 'Y' LOW CUSTOMER=nnnnnnnnnn 23
WS_FLAG_TSQH = 'Y' HIGH CUSTOMER=nnnnnnnnnn 24
PLI 
EXEC CICS DEQ RESOURCE(STSQ_NAME) LENGTH(STG(STSQ_NAME));

5.3.5 Generate the Random Customer Number

PLI 
WS_RANDOM_NUMBER = FLOOR(RANDOM(EIBTASKN) * FLOAT(WS_CUST_HIGH - WS_CUST_LOW)
                         + WS_CUST_LOW);

The task number seeds RANDOM, so different tasks usually get different numbers. The result goes into WRITE_MSG_HIGH, which is reused as the VSAM search key.

5.3.6 Resolve the Nearest Real Customer

PLI 
EXEC CICS READ FILE('KSDSCUST') INTO(CA_AREA) LENGTH(F82)
     RIDFLD(WRITE_MSG_HIGH) KEYLENGTH(F10) RESP(WS_RESP) GTEQ;

GTEQ returns the first record whose key is greater than or equal to the random value. On DFHRESP(NORMAL), CA_CUSTOMER_NUM replaces the random value in WRITE_MSG_HIGH.

5.3.7 Return the Result

PLI 
SELECT (WS_FLAG);
  WHEN ('C') DO;
     COMMA_DATA_H    = WRITE_MSG_H;
     COMMA_DATA_HIGH = WRITE_MSG_HIGH;
     COMMA_DATA_FILL = (60)' ';
  END;
  OTHERWISE
     EXEC CICS SEND TEXT FROM(WRITE_MSG_H) LENGTH(24)
          WAIT ERASE TERMINAL FREEKB;
END;
EXEC CICS RETURN;

5.4 Logical Phases (Paragraph Equivalents)

LGICVS01 has no sub-procedures. Its mainline divides into these logical phases:

Phase Purpose
Invocation Mode Detection ASSIGN calls, then WS_FLAG = 'C' or 'R'
TS Queue Initialisation and Reset Set defaults and flags
TS Queue Read ENQ, then READQ TS loop
TS Queue Write Conditional WRITEQ TS, then DEQ
Random Number Generation RANDOM/FLOOR computation
VSAM KSDS Read READ FILE GTEQ
Result Dispatch SELECT (WS_FLAG), then RETURN

5.5 External Interactions

Resource Commands Purpose
GENACNTL TSQ ENQ, READQ TS, WRITEQ TS, DEQ Read and initialise range control records
KSDSCUST READ FILE GTEQ Find the nearest real customer at or above the random key
Terminal RECEIVE, SEND TEXT Interactive input and output
COMMAREA Pointer-based read and write Return the result to the LINK caller

6. Dependencies

6.1 CICS Commands

Command Role
ASSIGN SYSID / STARTCODE / INVOKINGPROG Environment and mode detection
RECEIVE Terminal input
ENQ / DEQ Serialise access to GENACNTL
READQ TS / WRITEQ TS Read and initialise control records
READ FILE ... GTEQ Locate the nearest customer
SEND TEXT Terminal output
RETURN End of task

The program also uses DFHRESP(NORMAL), EIBCALEN and EIBTASKN.

6.2 Resources

  • VSAM: KSDSCUST, a KSDS with a 10-byte key and 225-byte records as read.
  • TS queue: GENACNTL (STSQ_NAME), holding the eyecatcher, LOW CUSTOMER and HIGH CUSTOMER records.

6.3 Invocation Interface

  • COMM_AREA_PTR points to the 84-byte COMMA_DATA structure.
  • WS_RECV is an 80-byte terminal buffer: 5 bytes of transaction ID plus 74 bytes of data.

6.4 PL/I Built-ins

Built-in Use
RANDOM(seed) Pseudo-random value in [0,1), seeded with EIBTASKN
FLOOR Truncate to an integer
FLOAT Convert the range width to floating point
SUBSTR Detect 'LOW CUSTOMER' and 'HIGH CUSTOMER' prefixes and the start code
STG Supply the length of STSQ_NAME for ENQ/DEQ

7. Constraints

7.1 Invocation Mode

  • The two modes are mutually exclusive, and the output path is fixed by WS_FLAG at detection time.
  • The program dereferences COMM_AREA_PTR without an EIBCALEN guard. An absent COMMAREA in LINK mode is therefore unsafe.
  • The terminal buffer is 80 bytes. Longer input is truncated, and at most 74 data characters remain after the transaction ID.

7.2 Serialisation

  • ENQ is issued before any access to the TS queue, and DEQ is issued after the last read or write.
  • The VSAM read and the output steps run outside the ENQ/DEQ bracket.
  • Reads must come before writes. The read determines whether the records already exist.

7.3 TS Queue Content

  • Each control record is written only when it is absent, so duplicates are avoided.
  • The read loop ends on the first non-NORMAL response, for example ITEMERR.
  • WRITEQ TS uses NOSUSPEND, and its response is not checked. A failed write can leave the queue partly initialised without any signal.

7.4 Customer Number Range

  • The default range is [1000001, 1000001], which is a zero-width range.
  • RANDOM returns a value in [0,1), so the result falls in [LOW, HIGH).
  • The seed is the task number, so the same task number always gives the same value.
  • There is no upper-bound guard. If the random key is above the highest key in KSDSCUST, the read returns a non-NORMAL response and the raw random value is returned.

7.5 VSAM Access

  • F82 is 225 bytes and must match the CA_AREA length.
  • F10 is the 10-byte key length and must match the cluster definition. A mismatch causes LENGERR.
  • Only CA_CUSTOMER_NUM is used. The other 215 bytes are ignored.

7.6 Output Format

  • The COMMAREA result is 84 bytes, so the caller must allocate at least that much.
  • The terminal send is fixed at 24 bytes and always uses ERASE and FREEKB.

8. Error Handling

Area Behaviour
RESP(WS_RESP) Most commands capture the response, so there are no implicit condition raises.
READQ TS ITEM(1) A normal response means the queue exists. Otherwise (for example QIDERR) the read loop is skipped and all flags stay 'Y'.
READQ TS NEXT loop A non-normal response ends the loop. Record extraction requires both a normal response and a matching prefix.
READ FILE GTEQ On NORMAL, the real key is adopted. Otherwise (for example NOTFND) the random value is kept. No abend or message is issued.
ASSIGN commands Responses are captured but never tested.
ENQ / DEQ These carry no RESP, so failures raise a CICS condition under default handling.
WRITEQ TS NOSUSPEND A failure returns immediately and is not tested.
SELECT (WS_FLAG) OTHERWISE is a catch-all that defaults to the terminal path.

9. Examples

9.1 First-Time Invocation via CICS LINK (Queue Does Not Exist)

Scenario: A program such as LGICUS01 links to LGICVS01. GENACNTL has never been written. KSDSCUST has a record with key 0001000050.

Variable Value
WS_INVOKEPROG 'LGICUS01'
WS_STARTCODE 'SD'
GENACNTL Does not exist
EIBTASKN 1234

Steps:

  1. INVOKINGPROG is non-blank, so WS_FLAG = 'C'.
  2. WS_CUST_LOW and WS_CUST_HIGH are set to 1000001.
  3. ENQ is issued. READQ TS ITEM(1) returns non-NORMAL, so all three flags stay 'Y'.
  4. Three WRITEQ TS calls create the queue:
    • Item 1 is **** GENAPP CNTL.
    • Item 2 is LOW CUSTOMER=0001000001.
    • Item 3 is HIGH CUSTOMER=0001000001.
  5. DEQ is issued.
  6. The range width is zero, so the random number is 1000001.
  7. READ FILE('KSDSCUST') GTEQ RIDFLD(1000001) returns CA_CUSTOMER_NUM = '0001000050'.
  8. The COMMAREA is returned to the caller.
COMMAREA field Value
COMMA_DATA_H 'HIGH CUSTOMER='
COMMA_DATA_HIGH 0001000050
COMMA_DATA_FILL 60 spaces

9.2 Interactive Terminal Invocation (Queue Already Populated)

Scenario: A user starts transaction LGIS at a 3270 terminal. GENACNTL holds LOW CUSTOMER=0001000001 and HIGH CUSTOMER=0001009999. KSDSCUST has a record at key 0001005500.

Variable Value
WS_INVOKEPROG Blank
WS_STARTCODE 'TC'
EIBTASKN 5678

Steps:

  1. Both conditions are false, so RECEIVE runs and WS_FLAG = 'R'.
  2. After ENQ, item 1 is read normally, so WS_FLAG_TSQE = ' '.
  3. The loop finds the LOW record (WS_CUST_LOW = 1000001) and the HIGH record (WS_CUST_HIGH = 1009999), and clears both flags.
  4. No WRITEQ TS runs. DEQ is issued.
  5. The program computes FLOOR(RANDOM(5678) × FLOAT(1009999 − 1000001) + 1000001). Assume this gives 1005482.
  6. READ FILE GTEQ RIDFLD(1005482) returns key 0001005500.
  7. SEND TEXT displays the result.

Terminal output:

CODE 
HIGH CUSTOMER=0001005500

The 24-character message is sent with ERASE and FREEKB. It clears the screen and unlocks the keyboard.
