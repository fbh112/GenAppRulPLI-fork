Policy Business Logic Programs

1. Overview

The Policy Business Logic Programs form the orchestration layer of the IBM General Insurance Application (GenApp) running on z/OS under CICS. This layer consists of four PL/I programs — LGAPOL01, LGIPOL01, LGUPOL01, and LGDPOL01 — each responsible for a single CRUD operation (Create, Read, Update, Delete) on insurance policies. Together they implement a consistent, contract-driven pattern: validate the incoming CICS COMMAREA, optionally apply business rules, delegate all DB2 persistence to a dedicated back-end program, and return a standardised return code to the caller.

Each program in this layer:

  • Runs as a CICS-hosted PL/I program, invoked via EXEC CICS LINK from a menu or orchestrating transaction
  • Accepts a single 32,500-byte COMMAREA (defined by the shared LGCMAREA copybook) carrying the request identifier, return code, customer/policy numbers, and policy-type-specific data
  • Performs COMMAREA presence and length validation before any business logic executes
  • Delegates all DB2 access to a paired back-end data program (LGAPDB01, LGIPDB01, LGUPDB01, LGDPDB01)
  • Returns one of three standardised return codes: '00' (success), '98' (COMMAREA too short), or '99' (unrecognised request identifier)
  • Writes structured diagnostic messages to a CICS Transient Data Queue (TDQ) via the shared logging utility LGSTSQ on error

3. LGAPOL01 — Add Policy

3.1 Purpose

LGAPOL01 orchestrates the addition of a new insurance policy — Endowment, House, Motor, or Commercial — for a given customer. It validates the COMMAREA, optionally invokes the IBM ODM business rules program LGAPBR01 for Endowment requests (controlled by the BUSINESS_RULES feature flag), and delegates DB2 persistence to LGAPDB01.

3.4 ODM Business Rules Feature Toggle

LGAPOL01 contains a compile-time/deployment-time feature flag BUSINESS_RULES, initialized to 'N'. When set to 'Y' and the request is CA_REQUEST_ID = '01AEND', the program invokes LGAPBR01 before the DB2 write:

PLI 
/* Feature toggle — set to 'Y' to enable ODM for Endowment */
DCL BUSINESS_RULES CHAR(1) INIT('N');

IF BUSINESS_RULES = 'Y' THEN DO;
   IF CA_REQUEST_ID = '01AEND' THEN DO;
      EXEC CICS LINK Program('LGAPBR01')
                    Commarea(COMM_AREA)
                    LENGTH(32500);
   END;
END;

This pattern allows ODM-based underwriting rules for Endowment policies to be activated without altering program flow.

4. LGIPOL01 — Inquire Policy

4.1 Purpose

LGIPOL01 is the business-logic front-end for full policy inquiry. It validates the COMMAREA, initialises the return code, and delegates all DB2 SELECT operations to LGIPDB01. The program itself contains no SQL — it is a pure orchestrator and safety gate.

4.5 Error Handling

LGIPOL01 implements a fail-fast strategy for missing COMMAREA and fully delegates post-DB2-call error handling to the caller via the return code:

PLI 
/* COMMAREA presence guard */
IF EIBCALEN = 0 THEN DO;
   EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
   CALL WRITE_ERROR_MESSAGE;
   EXEC CICS ABEND ABCODE('LGCA') NODUMP;
END;

/* Initialize success state */
CA_RETURN_CODE = '00';

There is no post-LINK return-code check in LGIPOL01 itself — the outcome is surfaced entirely through the shared CA_RETURN_CODE field written by LGIPDB01.

5. LGUPOL01 — Update Policy

5.1 Purpose

LGUPOL01 is the business-logic front-end for updating existing insurance policies. It supports three policy types — Endowment, House, and Motor — each with a per-type minimum COMMAREA length check. It delegates the actual DB2 UPDATE to LGUPDB01.

5.3 Policy-Type Minimum COMMAREA Length Requirements

LGUPOL01 enforces per-policy-type minimum COMMAREA lengths before delegating to LGUPDB01. This is the key differentiator from LGIPOL01 and LGDPOL01, which use a single fixed header check.

CA_REQUEST_ID Policy Type Header Data Length Minimum Total
01UEND Endowment 28 bytes 124 bytes 152 bytes
01UHOU House 28 bytes 130 bytes 158 bytes
01UMOT Motor 28 bytes 137 bytes 165 bytes
PLI 
/* Policy-type routing with COMMAREA length validation */
SELECT (CA_REQUEST_ID);
   WHEN ('01UEND') DO;
      WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_ENDOW_LEN;
      IF EIBCALEN < WS_REQUIRED_CA_LEN THEN DO;
         CA_RETURN_CODE = '98';
         EXEC CICS RETURN;
      END;
   END;
   WHEN ('01UHOU') DO;
      WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_HOUSE_LEN;
      IF EIBCALEN < WS_REQUIRED_CA_LEN THEN DO;
         CA_RETURN_CODE = '98';
         EXEC CICS RETURN;
      END;
   END;
   WHEN ('01UMOT') DO;
      WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_MOTOR_LEN;
      IF EIBCALEN < WS_REQUIRED_CA_LEN THEN DO;
         CA_RETURN_CODE = '98';
         EXEC CICS RETURN;
      END;
   END;
   OTHERWISE DO;
      CA_RETURN_CODE = '99';
   END;
END;

5.4 OTHERWISE Branch Behaviour

A key distinction in LGUPOL01: when CA_REQUEST_ID is unrecognised, CA_RETURN_CODE is set to '99' but execution does not stop — it falls through to UPDATE_POLICY_DB2_INFO and LGUPDB01 is still called. This allows the back-end program to perform its own validation against the error state.

6. LGDPOL01 — Delete Policy

6.1 Purpose

LGDPOL01 is the business-logic front-end for deleting insurance policies. It supports all four policy types — Endowment, House, Commercial, and Motor — routing them through a single WHEN clause. It normalises CA_REQUEST_ID to uppercase before routing and delegates deletion to LGDPDB01, which exploits DB2 foreign-key cascade semantics to remove both the parent POLICY row and the policy-type-specific child row in a single operation.

6.3 Request Identifier Routing

Unlike LGUPOL01, which has separate WHEN clauses per policy type, LGDPOL01 consolidates all four valid delete requests into a single WHEN clause. This reflects that all policy types share the same delete logic at the orchestration level:

PLI 
/* Normalize to uppercase first */
CA_REQUEST_ID = UPPERCASE(CA_REQUEST_ID);

SELECT (CA_REQUEST_ID);
   WHEN ('01DEND', '01DHOU', '01DCOM', '01DMOT') DO;
      CALL DELETE_POLICY_DB2_INFO;
      IF CA_RETURN_CODE > 0 THEN DO;
         EXEC CICS RETURN;
      END;
   END;
   OTHERWISE DO;
      CA_RETURN_CODE = '99';
   END;
END;

EXEC CICS RETURN;

Note the UPPERCASE() normalization — LGDPOL01 is the only program in this layer that explicitly case-normalises the request ID, making it tolerant of mixed-case input.

6.4 DB2 Cascade Delete

The DELETE_POLICY_DB2_INFO internal procedure passes the full COMMAREA to LGDPDB01:

PLI 
DELETE_POLICY_DB2_INFO: PROC;
   EXEC CICS LINK PROGRAM(LGDPDB01)
                  COMMAREA(COMM_AREA)
                  LENGTH(32500);
END DELETE_POLICY_DB2_INFO;

LGDPDB01 deletes the parent POLICY row, and DB2 foreign-key cascade rules automatically remove the child row from ENDOWMENT, HOUSE, MOTOR, or COMMERCIAL — no separate child delete is needed at the application level.

Policy VSAM Back-End Programs Covers the VSAM KSDS (KSDSPOLY) access layer for insurance policies: LGAPVS01 (write new 64-byte policy record with composite key), LGIPVS01 (GTEQ browse for policy lookup), LGUPVS01 (read-update / rewrite with abend on failure), and LGDPVS01 (delete by composite key), including key structure, CICS file commands, response-code handling, and abend codes.
