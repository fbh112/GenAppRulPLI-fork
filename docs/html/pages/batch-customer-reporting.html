Batch Customer Reporting

1. Overview

Batch Customer Reporting is a set of three non-CICS PL/I programs in the GenApp insurance application. They produce customer report lines from data held in the DB2 CUSTOMER table.

Program Role Summary
LGBATCH Batch driver Reads customer numbers from the CUSTIN file and queries DB2 for each one. It calls LGBATCHF to format each result and writes the line to CUSTRPT.
LGBATCHF Formatting subroutine Takes a customer number and a pointer to the shared COMMAREA. It builds a human-readable line such as Customer 0000000042 is John Smith.
LGBATDB2 Test driver Looks up one hard-coded customer (number 1) in DB2, calls LGBATCHF, and displays the resulting line on the console.

All three programs share the LGCMAREA communication area layout. It is a pointer-based structure laid over a 32,500-byte character buffer (BATCH_COMM_AREA). The programs use it outside CICS to pass DB2 data between the driver and the formatter.

Key characteristics:

  • LGBATCH is a production-style batch loop. It handles file open failures, end-of-file, and three SQL outcomes: found, not found, and error.
  • LGBATCHF is a pure formatting routine. It does no DB2, file, CICS or MQ I/O.
  • LGBATDB2 is a diagnostic harness. It processes exactly one customer and has no SQL error handling.
  • LGBATCHF is loaded dynamically with FETCH and called with a fixed three-argument interface: ENTRY(PIC '9999999999', PTR, CHAR(80)).

3. Batch Driver: LGBATCH

3.1 Purpose

LGBATCH is declared as Proc Options(Main) and takes no parameters. It reads a list of customer numbers from CUSTIN and queries DB2 for each one. For each customer it calls LGBATCHF and writes one 80-byte line to CUSTRPT. It sets a status code in CA_RETURN_CODE after each lookup.

3.2 Files

DD / File Organisation Record size Direction Content
CUSTIN Sequential, fixed block 10 Input One 10-digit customer number per record (PIC '9999999999')
CUSTRPT Sequential, fixed block 80 Output One formatted report line per input record

3.3 Processing Flow

FETCH LGBATCHF] B --> C[ON UNDEFINEDFILE CUSTIN
Open CUSTIN and CUSTRPT] C --> D{CUSTIN open failed?} D -- Yes --> E[DISPLAY message
PLIRETC 16
STOP] D -- No --> F[ON ENDFILE CUSTIN sets FI_EOF

WRITE_ERROR_MESSAGE] K --> N[CALL LGBATCHF
WRITE CUSTRPT_LINE] L --> N M --> N N --> O[READ next CUSTIN record] O --> G G -- No --> P[CLOSE CUSTIN and CUSTRPT] P --> Q([RETURN])

3.4 Procedures

Procedure Responsibility
Main body Sets up the COMMAREA pointer and fetches LGBATCHF. Registers the condition handlers, opens both files, and runs the read and process loop. Closes the files and returns.
PROCESS_RECORD Converts CUSTIN_CUSTNUMBER to the integer host variable DB2_CUSTOMERNUMBER_INT. Calls GET_CUSTOMER_INFO and LGBATCHF, then writes CUSTRPT_LINE.
GET_CUSTOMER_INFO Sets EM_SQLREQ to ' SELECT CUSTOMER'. Runs the single-row SELECT and evaluates SQLCODE.
WRITE_ERROR_MESSAGE Fills the in-memory ERROR_MSG structure with the SQLCODE, date and time. It is never written to any output.

The conversion in PROCESS_RECORD is needed because the DB2 CUSTOMERNUMBER column is an integer and the input field is a picture. The range is therefore limited to a 31-bit signed integer.

3.5 SQLCODE to Return Code Mapping

SQLCODE CA_RETURN_CODE Meaning Action
0 00 Customer found COMM_AREA fields populated
100 01 Customer not found Processing continues; COMM_AREA retains the previous customer’s data
Any other 90 Unexpected SQL error WRITE_ERROR_MESSAGE builds ERROR_MSG in memory; processing continues

The SELECT evaluation:

PLI 
SELECT (SQLCODE);
  WHEN (0)   CA_RETURN_CODE = '00';
  WHEN (100) CA_RETURN_CODE = '01';
  OTHERWISE  DO;
               CA_RETURN_CODE = '90';
               CALL WRITE_ERROR_MESSAGE;
             END;
END;

4. Formatting Subroutine: LGBATCHF

4.1 Purpose

LGBATCHF is a statically called PL/I subroutine with no OPTIONS(MAIN). Its entry is Proc(CUSTNUMBER, COMM_PTR, LS_LINE). It builds one report line from the customer number and the first words of the first and last names. It does no DB2, file, CICS or MQ I/O.

4.2 Name Token Extraction

The routine takes only the text before the first blank in each name field. This mirrors the COBOL idiom STRING ... DELIMITED BY SPACE. The same logic runs for CA_FIRST_NAME (10 characters) and CA_LAST_NAME (20 characters). Both fields share the one POS work variable (FIXED BIN(15)).

INDEX(field,' ') result Token value
0 (no blank) Entire field
1 (leading blank) Empty string
> 1 SUBSTR(field, 1, POS-1)

4.3 Processing Flow

graph TD A([Entry: CUSTNUMBER, COMM_PTR, LS_LINE]) --> B[COMM_AREA_PTR = COMM_PTR] B --> C[POS = INDEX of blank in CA_FIRST_NAME] C --> D{POS} D -- 0 --> E[FIRST_TOKEN = full field] D -- 1 --> F[FIRST_TOKEN = empty] D -- greater than 1 --> G[FIRST_TOKEN = SUBSTR 1 to POS-1] E --> H[POS = INDEX of blank in CA_LAST_NAME] F --> H G --> H H --> I{POS} I -- 0 --> J[LAST_TOKEN = full field] I -- 1 --> K[LAST_TOKEN = empty] I -- greater than 1 --> L[LAST_TOKEN = SUBSTR 1 to POS-1] J --> M[Build LS_LINE] K --> M L --> M M --> N[DISPLAY trace to SYSOUT] N --> O([RETURN])

4.4 Line Construction and Trace

The line is built by concatenation, and a trace message is always written to SYSOUT:

PLI 
LS_LINE = 'Customer ' || CUSTNUMBER || ' is ' ||
          FIRST_TOKEN || ' ' || LAST_TOKEN;

DISPLAY('LGBATCHF WAS HERE... ' || LS_LINE);

The fixed text takes 23 characters ('Customer ' 9, the number 10, ' is ' 4). The longest possible name part is 10 + 1 + 20 = 31 characters. The total is at most 54 characters, so the 80-character line never truncates the data.

4.5 Formatting Examples

CUSTNUMBER CA_FIRST_NAME CA_LAST_NAME LS_LINE (trimmed)
0000000042 John Smith Customer 0000000042 is John Smith
0000001234 Jacqueline Vandenberghe (20-character field) Customer 0000001234 is Jacqueline Vandenberghe
0000009999 ' J ' Doe Customer 0000009999 is Doe (empty first token gives a double space)

5. Test Driver: LGBATDB2

5.1 Purpose

LGBATDB2 exercises the DB2-to-report pipeline without CICS and without file I/O. It always processes customer number 1. It has no loop, no input file and no output file.

5.2 Processing Flow

SELECT INTO COMM_AREA fields] G --> H[CUSTIN_CUSTNUMBER = DB2_CUSTOMERNUMBER_INT] H --> I[CALL LGBATCHF] I --> J[DISPLAY CUSTRPT_LINE] J --> K([RETURN])

6. Data Model

Both drivers read the same DB2 table. They select nine columns, keyed by CUSTOMERNUMBER.

erDiagram CUSTOMER { int CUSTOMERNUMBER "Key - WHERE predicate" string FIRSTNAME "length 10 - CA_FIRST_NAME" string LASTNAME "length 20 - CA_LAST_NAME" string DATEOFBIRTH "length 10 - CA_DOB" string HOUSENAME "length 20 - CA_HOUSE_NAME" string HOUSENUMBER "length 4 - CA_HOUSE_NUM" string POSTCODE "length 8 - CA_POSTCODE" string PHONEMOBILE "length 20 - CA_PHONE_MOBILE" string PHONEHOME "length 20 - CA_PHONE_HOME" string EMAILADDRESS "length 100 - CA_EMAIL_ADDRESS" }

Both drivers use the same single-row query. Each places the results directly into the pointer-based COMM_AREA fields.

PLI 
EXEC SQL SELECT FIRSTNAME, LASTNAME, DATEOFBIRTH, HOUSENAME,
                HOUSENUMBER, POSTCODE, PHONEMOBILE, PHONEHOME,
                EMAILADDRESS
         INTO :CA_FIRST_NAME, :CA_LAST_NAME, :CA_DOB, :CA_HOUSE_NAME,
              :CA_HOUSE_NUM, :CA_POSTCODE, :CA_PHONE_MOBILE,
              :CA_PHONE_HOME, :CA_EMAIL_ADDRESS
         FROM CUSTOMER
         WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUMBER_INT;

The COMM_AREA is a union-style structure (COMM_AREA UNION BASED(COMM_AREA_PTR)) laid over the 32,500-byte buffer. Within it, the customer, policy and customer-security request layouts are mutually exclusive overlays.

7. Error Handling

7.1 Error Handling by Program

Condition LGBATCH LGBATCHF LGBATDB2
CUSTIN cannot be opened ON UNDEFINEDFILE shows 'FILE STATUS AT OPEN CUSTIN', calls PLIRETC(16) and issues STOP n/a n/a
End of CUSTIN ON ENDFILE sets FI_EOF = '1'B and the loop ends n/a n/a
CUSTRPT cannot be opened or written Not handled n/a n/a
SQLCODE 100 (not found) CA_RETURN_CODE = '01'; continues with stale data n/a Not checked; continues with unpopulated or stale data
Other SQL error CA_RETURN_CODE = '90'; ERROR_MSG built in memory only n/a Not checked
Blank in name fields n/a POS guards (0, 1, greater than 1) n/a
Null or short COMM_PTR n/a Not checked n/a

The startup ON UNDEFINEDFILE handler in LGBATCH:

PLI 
ON UNDEFINEDFILE(CUSTIN) BEGIN;
   DISPLAY('FILE STATUS AT OPEN CUSTIN');
   CALL PLIRETC(16);
   STOP;
END;

7.2 Known Limitations

  • Stale data on not-found: LGBATCH does not reinitialise the COMMAREA between records. After SQLCODE 100 or an SQL error, LGBATCHF still runs and writes a line using the previous customer’s name fields. LGBATCHF does not inspect CA_RETURN_CODE.
  • Unreported SQL errors: ERROR_MSG holds EM_SQLRC, EM_DATE, EM_TIME, EM_CUSNUM, EM_POLNUM and EM_SQLREQ. It is never written to a file, queue or log. The batch run does not abort on SQL errors.
  • Unguarded output file: There is no UNDEFINEDFILE handler for CUSTRPT and no trap for write errors.
  • Test driver gaps: LGBATDB2 ignores SQLCODE after the SELECT and does not check CA_RETURN_CODE. It has no ON conditions, so any runtime condition ends in the default system handling.
  • Unconditional trace: LGBATCHF always issues a DISPLAY, so the job log gets one trace line per customer.

8. Constraints and Dependencies

8.1 Data and Interface Constraints

  • CUSTIN must be fixed-block with exactly 10-byte records. Each record is a 10-digit numeric picture.
  • CUSTRPT must be fixed-block with 80-byte records.
  • Customer numbers must fit in FIXED BIN(31) (0 to 2,147,483,647) for the DB2 lookup.
  • The CUSTOMER table must have a unique CUSTOMERNUMBER, because the query is a single-row SELECT INTO.
  • The LGBATCHF call must match ENTRY(PIC '9999999999', PTR, CHAR(80)) in argument type, length and order.
  • COMM_AREA_PTR must be set to ADDR(BATCH_COMM_AREA) before any COMM_AREA field is referenced. LGBATCHF must be fetched before it is called.
  • In LGBATCHF, first-name extraction must finish before last-name extraction begins, because POS is shared.
  • LGBATCHF needs only about 48 bytes of valid storage behind COMM_PTR (CA_FIRST_NAME at offset 18 and CA_LAST_NAME at offset 28).
  • EM_SQLRC is PIC '+(5)9', so the SQLCODE it can show is limited to ±99999.

8.2 Runtime Dependencies

Dependency Needed by Notes
DB2 subsystem, precompile, bind and plan or package LGBATCH, LGBATDB2 Both include SQLCA via EXEC SQL INCLUDE SQLCA
LGCMAREA include All three Defines COMM_AREA; expanded at compile time

9. Examples

9.1 Customer Found (LGBATCH)

Input record in CUSTIN: 0000000042.

  1. DB2_CUSTOMERNUMBER_INT is set to 42.
  2. The SELECT returns SQLCODE 0, so CA_RETURN_CODE is '00' and the CA_* fields are filled.
  3. LGBATCHF formats the line and the driver writes it to CUSTRPT.

Line produced by LGBATCHF:

CODE 
Customer 0000000042 is John Smith

9.2 Customer Not Found (LGBATCH)

Input record in CUSTIN: 0000009999, with no matching row.

  1. The SELECT returns SQLCODE 100 and CA_RETURN_CODE is set to '01'.
  2. The COMMAREA is not refreshed, so LGBATCHF still runs.
  3. The line for the missing customer carries the previous customer’s name.

If the previous customer was John Smith, the line is:

CODE 
Customer 0000009999 is John Smith

9.3 Unexpected SQL Error (LGBATCH)

Input record: 0000000007, with a DB2 error such as SQLCODE -911.

  1. CA_RETURN_CODE is set to '90' and WRITE_ERROR_MESSAGE fills ERROR_MSG in memory.
  2. Processing continues. A report line is written using whatever COMMAREA data is present.

The in-memory ERROR_MSG is illustrative only. Nothing writes it out:

CODE 
20250101 143022  LGBATCH CNUM=0000000007 PNUM=0000000000 SELECT CUSTOMER SQLCODE=  -911

9.4 Test Driver Run (LGBATDB2)

Customer 1 exists in the table. The console output is:

CODE 
LGBATDB2 SQLCode : 0
LGBATDB2 SQLState: 00000
LGBATCHF WAS HERE... Customer 0000000001 is John Smith
Customer 0000000001 is John Smith

The LGBATCHF WAS HERE... line is the trace from LGBATCHF. The last line is the driver’s DISPLAY(CUSTRPT_LINE).

If customer 1 is missing, the startup display still shows the initial values. SQLCODE +100 (SQLSTATE 02000) is not checked by the program. LGBATCHF receives unpopulated COMMAREA fields, so its line carries no usable name data.
