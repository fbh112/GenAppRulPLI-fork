Program Inventory

GenApp is a PL/I-based insurance application running on z/OS under CICS and batch environments. It manages customers and insurance policies (Motor, Endowment, House, Commercial) through a layered architecture spanning presentation, orchestration, DB2 persistence, and VSAM persistence tiers. This inventory documents all 35 source programs and 4 include files, classifying each by role, transaction ID, primary domain, and complexity.

1. Overview

The GenApp PL/I application is an insurance policy management system hosted on IBM z/OS. It supports online (CICS) and batch processing modes, and is organized around two primary business domains:

  • Customer Management — Add, Inquire, and Update customer records
  • Policy Management — Add, Delete, Inquire, and Update policies of four types: Motor, Endowment, House, and Commercial

Each business operation is handled by a consistent three-tier call chain:

  1. Presentation Layer — CICS BMS terminal handlers (transaction-mapped menus)
  2. Orchestration Layer — Policy or customer orchestrators that validate and route requests
  3. Backend Layer — Dedicated DB2 SQL programs and/or VSAM I/O programs

Batch programs operate independently of CICS and access DB2 and sequential files directly. Utility programs provide shared infrastructure services (TS queues, statistics, web service exposure, setup).

2. System Architecture

GenApp follows a strict layered architecture. Terminal-facing CICS programs handle BMS map I/O, pass a COMMAREA to orchestrators, which in turn delegate to DB2 and VSAM backend programs. Batch programs operate as a separate tier with direct DB2 and file access.

3. Menu / Presentation Layer

The five presentation-layer programs handle CICS BMS map interaction and manage terminal I/O. Each program uses %INCLUDE SSMAP for BMS map structures and %INCLUDE LGCMAREA for the COMMAREA. They accept DFHEIPTR and COMM_AREA_PTR as procedure parameters to support reentrant execution.

A typical CICS BMS interaction in PL/I uses the EXEC CICS SEND MAP and EXEC CICS RECEIVE MAP commands with the map structure included via %INCLUDE SSMAP:

PLI 
%INCLUDE SSMAP;
%INCLUDE LGCMAREA;

LGTESTP1: PROCEDURE(DFHEIPTR, COMM_AREA_PTR) OPTIONS(MAIN REENTRANT);

    /* Receive input from terminal */
    EXEC CICS RECEIVE MAP('SSMAPO')
              MAPSET('SSMAP')
              INTO(SSMAPI);

    /* Link to appropriate orchestrator based on user action */
    IF CA_REQUEST_ID = 'LPOL' THEN
        EXEC CICS LINK PROGRAM('LGAPOL01')
                  COMMAREA(CA_DATA)
                  LENGTH(32500);

    /* Send updated map back to terminal */
    EXEC CICS SEND MAP('SSMAPO')
              MAPSET('SSMAP')
              FROM(SSMAPO)
              ERASE;
END LGTESTP1;

A representative batch DB2 cursor loop in PL/I:

PLI 
%INCLUDE SQLCA;

DCL CUSTOMER_CURSOR CURSOR FOR
    SELECT CUSTOMERNUM, FIRSTNAME, LASTNAME
    FROM   CUSTOMER
    ORDER BY CUSTOMERNUM;

EXEC SQL OPEN CUSTOMER_CURSOR;

FETCH_LOOP:
DO WHILE (SQLCODE = 0);
    EXEC SQL FETCH CUSTOMER_CURSOR
             INTO :WS_CUST_NUM, :WS_FIRST_NAME, :WS_LAST_NAME;
    IF SQLCODE = 0 THEN
        CALL LGBATCHF(WS_CUSTOMER_RECORD);
END;

EXEC SQL CLOSE CUSTOMER_CURSOR;

11. Include Files

Include files are shared PL/I structures compiled into each program at pre-processing time using the %INCLUDE directive. They define the COMMAREA contract, BMS map layouts, business rule interfaces, and the SQL Communication Area.

File Used By Purpose
plinc/LGCMAREA.inc All CICS programs COMMAREA structure definition — CA_REQUEST_ID, CA_RETURN_CODE, customer and policy data fields
plinc/SSMAP.inc LGTESTP1–4, LGTESTC1 BMS map structures for terminal screens
plinc/LGCMARER.inc LGAPOL01 → LGAPBR01 Business rule request area structure for the external rules engine
plinc/SQLCA.inc All DB2 programs SQL Communication Area — SQLCODE, SQLERRM, and related diagnostic fields

The COMMAREA structure (from LGCMAREA.inc) is the primary data contract between all CICS layers:

PLI 
%INCLUDE LGCMAREA;

/* LGCMAREA defines the following key fields: */
DCL 1 CA_DATA,
      2 CA_REQUEST_ID     CHAR(6),   /* e.g. 'LPADD ', 'LPINQ ' */

Statistics & Monitoring Explains the GenApp statistics pipeline: LGASTAT1 (event-processing adapter that increments named counters per transaction type and outcome) and LGWEBST5 (self-rescheduling CICS statistics collector that harvests counters every minute, computes deltas, and writes results to TSQs for dashboard consumption), covering counter naming conventions, TSQ layout, and the SSST transaction scheduling loop.
