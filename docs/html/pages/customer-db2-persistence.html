Customer DB2 & Security Persistence

This page documents the back-end DB2 data access layer of the insurance application. It covers inserting, querying and updating customer records in the CUSTOMER table, and persisting credential data in the CUSTOMER_SECURE table. Four CICS-hosted Enterprise PL/I programs implement it: LGACDB01, LGACDB02, LGICDB01 and LGUCDB01. Each is linked to by a front-end orchestrator and communicates only through a CICS COMMAREA.

1. Overview

1.1 Purpose

The persistence layer isolates all customer-related DB2 access behind small, single-purpose programs. Each program does the following:

  • Validates the inbound COMMAREA.
  • Performs one DB2 operation.
  • Maps the DB2 outcome to a two-character CA_RETURN_CODE.
  • Logs unexpected failures to a transient data queue through the shared LGSTSQ utility.

1.2 Programs at a Glance

Program Operation DB2 Table DB2 Statement Downstream LINKs
LGACDB01 Add customer CUSTOMER INSERT LGACVS01 (VSAM), LGACDB02 (security)
LGACDB02 Add customer security record CUSTOMER_SECURE INSERT LGSTSQ (errors only)
LGICDB01 Inquire customer CUSTOMER singleton SELECT LGSTSQ (errors only)
LGUCDB01 Update customer CUSTOMER UPDATE LGUCVS01 (VSAM), LGSTSQ (errors only)

1.3 Key Characteristics

  • LINK-only execution. The programs are called with EXEC CICS LINK and depend entirely on a populated COMMAREA.
  • Shared COMMAREA layout. All four programs overlay the COMM_AREA structure from the LGCMAREA include (plinc/LGCMAREA.inc). Its raw buffer is CHAR(32500).
  • Dual-store consistency. Add and update operations mirror the change to a VSAM store (LGACVS01, LGUCVS01) after the DB2 work.
  • Resilient customer numbering. LGACDB01 takes customer numbers from a CICS named counter. If the counter is unavailable, it falls back to a DB2 identity column.
  • Uniform diagnostics. All programs share an identical WRITE_ERROR_MESSAGE routine and the same abend, LGCA, for a missing COMMAREA.

The orchestrators sit above the DB2 programs and are the only entry points. LGACDB01 is the only program that coordinates other persistence programs. It creates the customer row, mirrors it to VSAM, and then chains to LGACDB02 to create the initial credential row.

2.2 Component Responsibilities

Component Responsibility
LGACDB01 Allocates a customer number, inserts the CUSTOMER row, returns the new number, and triggers the VSAM mirror and security record creation.
LGACDB02 Routes on CA_REQUEST_ID = '02ACUS' and inserts one CUSTOMER_SECURE row.
LGICDB01 Reads nine customer attributes into the COMMAREA by customer number.
LGUCDB01 Updates the nine mutable customer attributes by customer number, then mirrors the change to VSAM.
LGSTSQ Shared logger that writes the formatted error message and a COMMAREA snapshot to a TD queue.
LGCMAREA Shared COMMAREA layout (header, customer, policy and security views).

2.3 Common Program Skeleton

All four programs follow the same structure:

graph TD A([LINK from orchestrator]) --> B[Capture EIBTRNID, EIBTRMID, EIBTASKN] B --> C{EIBCALEN = 0?} C -- Yes --> D[WRITE_ERROR_MESSAGE
ABEND LGCA NODUMP] C -- No --> E[CA_RETURN_CODE = 00
Save length and pointer] E --> F[Program-specific validation and DB2 call] F --> G[Map SQLCODE to CA_RETURN_CODE] G --> H[EXEC CICS RETURN]

Each program starts with the same prologue, shown here in PL/I:

PLI 
LGUCDB01: Proc(COMM_AREA_PTR) Options(Main);
  ...
  WS_TRANSID = EIBTRNID;
  WS_TERMID  = EIBTRMID;
  WS_TASKNUM = EIBTASKN;
  IF ( EIBCALEN = 0 ) THEN DO;
     EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
     CALL WRITE_ERROR_MESSAGE;
     EXEC CICS ABEND ABCODE('LGCA') NODUMP;
  END;
  CA_RETURN_CODE = '00';

CUSTOMER holds the personal and contact details of each customer. CUSTOMERNUMBER is the key used by every program in this layer.

3.3 CUSTOMER_SECURE Table

CUSTOMER_SECURE stores the credential data for a customer.

Column COMMAREA Field Notes
customerNumber CA_CUSTOMER_NUM Converted to FIXED BIN(31) (DB2_CUSTOMERNUM_INT).
customerPass CA_CUSTSECR_PASS CHAR(32), an MD5 checksum.
state_indicator CA_CUSTSECR_STATE CHAR(1). 'N' means a new record.
pass_changes CA_CUSTSECR_COUNT CHAR(4), converted to FIXED BIN(31) (DB2_CUSTOMERCNT_INT).

4. Communication Area Contract

4.1 Size and Layout Rules

  • A COMMAREA is mandatory. EIBCALEN = 0 causes an LGCA abend with no dump.
  • LGACDB01 and LGICDB01 require at least 90 bytes: an 18-byte header/trailer plus a 72-byte customer section.
  • LGUCDB01 and LGACDB02 do not perform the length check.
  • The customer key is always converted from PIC '9999999999' to a FIXED BIN(31) host variable, which limits it to 2,147,483,647.

4.2 Return Codes by Program

Code LGACDB01 LGACDB02 LGICDB01 LGUCDB01
00 Customer added Security row added Customer found Update succeeded
01 – – Not found (SQLCODE 100) or SQLCODE -913 Not found (SQLCODE 100)
90 DB2 INSERT failed – Unexpected DB2 error Unexpected DB2 error
98 COMMAREA < 90 bytes DB2 INSERT failed COMMAREA < 90 bytes –
99 – Unrecognized request ID – –

The code 98 means different things in different programs. In LGACDB01 and LGICDB01 it means “COMMAREA too short”. In LGACDB02 it means “DB2 error”.

5.3 Customer Number Allocation

OBTAIN_CUSTOMER_NUMBER requests the next value from the CICS named counter GENACUSTNUM in pool GENA:

  • Counter available. DB2_CUSTOMERNUM_INT receives LASTCUSTNUM and LGAC_NCS stays 'ON'.
  • Counter unavailable. LGAC_NCS is set to 'NO' and DB2_CUSTOMERNUM_INT is set to 0.

The two paths are mutually exclusive. The caller can never supply the customer number. The counter name and pool are hardcoded literals.

5.4 DB2 INSERT Strategies

INSERT_CUSTOMER supplies all ten columns in both paths. The statements below are shown in outline.

Counter path (LGAC_NCS = 'ON'):

PLI 
EXEC SQL INSERT INTO CUSTOMER
   ( CUSTOMERNUMBER, FIRSTNAME, LASTNAME, DATEOFBIRTH, HOUSENAME,
     HOUSENUMBER, POSTCODE, PHONEMOBILE, PHONEHOME, EMAILADDRESS )
   VALUES ( :DB2_CUSTOMERNUM_INT, :CA_FIRST_NAME, :CA_LAST_NAME, :CA_DOB,
            :CA_HOUSE_NAME, :CA_HOUSE_NUM, :CA_POSTCODE,
            :CA_PHONE_MOBILE, :CA_PHONE_HOME, :CA_EMAIL_ADDRESS );

Identity fallback path. CUSTOMERNUMBER is DEFAULT, so DB2 generates it:

PLI 
EXEC SQL INSERT INTO CUSTOMER ( ... )
   VALUES ( DEFAULT, :CA_FIRST_NAME, ... , :CA_EMAIL_ADDRESS );

IF SQLCODE = 0 THEN
   EXEC SQL SET :DB2_CUSTOMERNUM_INT = IDENTITY_VAL_LOCAL();

After either successful INSERT, the new number is returned to the caller with CA_CUSTOMER_NUM = DB2_CUSTOMERNUM_INT. A non-zero SQLCODE sets CA_RETURN_CODE = '90', calls WRITE_ERROR_MESSAGE and returns immediately, so no VSAM or security processing happens.

5.5 Downstream Calls

After the INSERT, LGACDB01 links to LGACVS01 and then to LGACDB02. The first call passes the original COMMAREA with LENGTH(225). The second passes a separate CDB2AREA:

CDB2AREA Field Value
D2_CUSTOMER_NUM DB2_CUSTOMERNUM_INT (the newly assigned number)
D2_REQUEST_ID '02ACUS'
D2_CUSTSECR_PASS Fixed initial hash 5732fec825535eeafb8fac50fee3a8aa
D2_CUSTSECR_COUNT '0000'
D2_CUSTSECR_STATE 'N'
  • Every new customer starts with the same hardcoded initial credential value and a “new” state.
  • The LGACVS01 call has no conditional guard beyond the earlier early-return on INSERT failure.
  • LGACDB01 does not explicitly test D2_RETURN_CODE after the LGACDB02 link. It only re-checks CA_RETURN_CODE, so a security-insert failure is logged by LGACDB02 but not surfaced in the caller’s return code.

6. Customer Security Persistence (LGACDB02)

6.1 Processing Flow

graph TD A([LINK from LGACDB01]) --> B{EIBCALEN = 0?} B -- Yes --> C[Log NO COMMAREA RECEIVED
ABEND LGCA] B -- No --> D[CA_RETURN_CODE = 00] D --> E{CA_REQUEST_ID} E -- 02ACUS --> F[Convert customer num and count
to FIXED BIN 31] F --> G[INSERT_CUSTOMER_PASSWORD] G --> H{SQLCODE = 0?} H -- No --> I[RC 98
log error and RETURN] H -- Yes --> J([RETURN RC 00]) E -- Other --> K[RC 99 and RETURN]

6.2 Request Routing

A PL/I SELECT routes on CA_REQUEST_ID. Only '02ACUS' (Add Customer Security) is recognized. Any other value sets return code 99 and returns without touching DB2 and without writing a log entry.

PLI 
SELECT (CA_REQUEST_ID);
  WHEN ('02ACUS') DO;
     DB2_CUSTOMERNUM_INT = CA_CUSTOMER_NUM;
     DB2_CUSTOMERCNT_INT = CA_CUSTSECR_COUNT;
     CALL INSERT_CUSTOMER_PASSWORD;
  END;
  OTHERWISE DO;
     CA_RETURN_CODE = '99';
     EXEC CICS RETURN;
  END;
END;

6.3 The Security INSERT

INSERT_CUSTOMER_PASSWORD labels the request as ' INSERT SECURITY' and inserts exactly one row per call. The statement is shown in outline:

PLI 
EXEC SQL INSERT INTO CUSTOMER_SECURE
   ( customerNumber, customerPass, state_indicator, pass_changes )
   VALUES ( :DB2_CUSTOMERNUM_INT, :CA_CUSTSECR_PASS,
            :CA_CUSTSECR_STATE, :DB2_CUSTOMERCNT_INT );

IF SQLCODE ¬= 0 THEN DO;
   CA_RETURN_CODE = '98';
   CALL WRITE_ERROR_MESSAGE;
   EXEC CICS RETURN;
END;
  • Failures such as duplicate keys, with SQLCODE -803 for example, are not retried.
  • The password is silently truncated to 32 characters by its CHAR(32) declaration.
  • A non-numeric CA_CUSTSECR_COUNT would raise a PL/I conversion condition.

7.2 Singleton SELECT

GET_CUSTOMER_INFO reads the nine customer columns directly into the COMMAREA fields. The statement is shown in outline:

PLI 
EM_SQLREQ = ' SELECT CUSTOMER';
EXEC SQL SELECT FIRSTNAME, LASTNAME, DATEOFBIRTH, HOUSENAME, HOUSENUMBER,
                POSTCODE, PHONEMOBILE, PHONEHOME, EMAILADDRESS
           INTO :CA_FIRST_NAME, :CA_LAST_NAME, :CA_DOB, :CA_HOUSE_NAME,
                :CA_HOUSE_NUM, :CA_POSTCODE, :CA_PHONE_MOBILE,
                :CA_PHONE_HOME, :CA_EMAIL_ADDRESS
           FROM CUSTOMER
          WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUMBER_INT;

SELECT (SQLCODE);
  WHEN (0)         CA_RETURN_CODE = '00';
  WHEN (100, -913) CA_RETURN_CODE = '01';
  OTHERWISE DO;
     CA_RETURN_CODE = '90';
     CALL WRITE_ERROR_MESSAGE;
     EXEC CICS RETURN;
  END;
END;

SQLCODE 100 (no row) and -913 (deadlock/timeout) both map to '01'. Callers cannot tell a missing customer from a transient resource conflict. Neither case writes an error log entry.

8. Customer Update (LGUCDB01)

8.1 Sequence of Operations

sequenceDiagram participant Orch as LGUCUS01 participant UC as LGUCDB01 participant DB2 participant VS as LGUCVS01 participant LOG as LGSTSQ Orch->>UC: LINK with COMMAREA UC->>UC: EIBCALEN check, convert customer number UC->>DB2: UPDATE CUSTOMER WHERE CUSTOMERNUMBER DB2-->>UC: SQLCODE alt SQLCODE = 100 UC->>UC: CA_RETURN_CODE = 01 else SQLCODE other than 0 UC->>UC: CA_RETURN_CODE = 90 UC->>LOG: LINK ERROR_MSG and CA_ERROR_MSG end UC->>VS: LINK COMMAREA length 225 UC-->>Orch: RETURN with CA_RETURN_CODE

8.2 The UPDATE Statement

All nine mutable columns are updated in a single statement. The caller must supply values for every field, because partial updates are not supported:

SQL 
UPDATE CUSTOMER
  SET FIRSTNAME=:CA_FIRST_NAME, LASTNAME=:CA_LAST_NAME, DATEOFBIRTH=:CA_DOB,
      HOUSENAME=:CA_HOUSE_NAME, HOUSENUMBER=:CA_HOUSE_NUM, POSTCODE=:CA_POSTCODE,
      PHONEMOBILE=:CA_PHONE_MOBILE, PHONEHOME=:CA_PHONE_HOME,
      EMAILADDRESS=:CA_EMAIL_ADDRESS
WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT;

8.3 Result Handling

  • SQLCODE 0. CA_RETURN_CODE stays '00'.
  • SQLCODE 100. CA_RETURN_CODE is '01'. This is treated as a business condition and nothing is logged.
  • Any other non-zero SQLCODE. CA_RETURN_CODE is '90' and WRITE_ERROR_MESSAGE is called.

The EXEC CICS LINK PROGRAM(LGUCVS01) COMMAREA(COMM_AREA) LENGTH(225) is unconditional. It runs even when the DB2 update returned '01' or '90', so VSAM processing is not gated on the DB2 outcome.

9. Error Handling and Diagnostics

9.1 Shared WRITE_ERROR_MESSAGE Routine

Every program contains an identical diagnostic routine:

sequenceDiagram participant P as Program participant CICS participant LOG as LGSTSQ participant TDQ as TD Queue P->>P: EM_SQLRC = SQLCODE P->>CICS: ASKTIME ABSTIME(WS_ABSTIME) P->>CICS: FORMATTIME MMDDYYYY(WS_DATE) TIME(WS_TIME) P->>LOG: LINK COMMAREA(ERROR_MSG) LOG->>TDQ: Write formatted error record opt EIBCALEN greater than 0 P->>LOG: LINK COMMAREA(CA_ERROR_MSG) up to 90 bytes LOG->>TDQ: Write COMMAREA snapshot end
PLI 
EM_SQLRC = SQLCODE;
EXEC CICS ASKTIME ABSTIME(WS_ABSTIME);
EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME) MMDDYYYY(WS_DATE) TIME(WS_TIME);
EM_DATE = WS_DATE;  EM_TIME = WS_TIME;
EXEC CICS LINK PROGRAM('LGSTSQ') COMMAREA(ERROR_MSG) LENGTH(STG(ERROR_MSG));

IF ( EIBCALEN > 0 ) THEN DO;
   IF ( EIBCALEN < 91 ) THEN
      CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
   ELSE
      CA_DATA = LEFT(COMM_AREA_RAW, 90);
   EXEC CICS LINK PROGRAM('LGSTSQ') COMMAREA(CA_ERROR_MSG)
        LENGTH(STG(CA_ERROR_MSG));
END;

9.2 Error Message Content

Field Content
EM_DATE / EM_TIME Timestamp from FORMATTIME (date as MMDDYYYY)
Program name LGACDB01, LGACDB02, LGICDB01 or LGUCDB01
EM_CUSNUM Customer number (pre-loaded in LGICDB01 and LGUCDB01)
EM_SQLREQ ' INSERT CUSTOMER', ' INSERT SECURITY', ' SELECT CUSTOMER' or ' UPDATE CUST '
EM_SQLRC The SQLCODE

The CA_ERROR_MSG record is prefixed with 'COMMAREA=' and carries at most 90 bytes of the raw COMMAREA.

9.3 Eye-Catchers

Each program initializes WS_EYECATCHER with a literal such as 'LGACDB01------WS' or 'LGACDB02------WS'. This lets support staff locate the program’s working storage in a storage dump. Each program also captures EIBTRNID, EIBTRMID and EIBTASKN in WS_HEADER.

9.4 Which Conditions Are Logged

Condition Logged to TDQ? Result
No COMMAREA Yes Abend LGCA
COMMAREA too short (LGACDB01, LGICDB01) No RC 98
SQLCODE 100 (inquire/update) No RC 01
SQLCODE -913 (inquire) No RC 01
Unexpected SQLCODE Yes RC 90 (LGACDB01, LGICDB01, LGUCDB01) or 98 (LGACDB02)
Unknown request ID (LGACDB02) No RC 99

10. Design Constraints and Considerations

Area Constraint
Customer number integrity Never taken from the COMMAREA on add. It comes from the named counter or the DB2 identity column.
Key range Customer numbers are FIXED BIN(31) in DB2 host variables, so the maximum is 2,147,483,647.
Field widths Fixed CHAR lengths silently truncate longer values.
Diagnostic dump At most 90 bytes of the COMMAREA are logged.
Fixed link lengths LGACVS01 and LGUCVS01 are linked with LENGTH(225). LGACDB02 is linked with a 32,500-byte CDB2AREA.
Initial credentials All new customers share the same hardcoded initial password hash, count = '0000' and state = 'N'.
Ordering on add Number allocation, then CUSTOMER INSERT, then VSAM mirror, then security INSERT.
Ordering on update DB2 UPDATE, then an unconditional VSAM update.
Single-row operations No cursors or loops. Each invocation handles one customer.

11. Examples

11.1 Successful Add with Named Counter

  • Input: CA_REQUEST_ID = '01ACUS', first name John, last name Smith, EIBCALEN >= 90.
  • Processing:
    • The counter returns 1000042.
    • The explicit-number INSERT succeeds.
    • LGACVS01 and LGACDB02 are linked.
  • Output: CA_RETURN_CODE = '00', CA_CUSTOMER_NUM = 1000042.

11.2 Add with Named Counter Unavailable

  • Processing:
    • GET COUNTER returns a non-NORMAL response, so LGAC_NCS = 'NO'.
    • The INSERT uses DEFAULT for CUSTOMERNUMBER.
    • IDENTITY_VAL_LOCAL() returns, for example, 1000043.
  • Output: CA_RETURN_CODE = '00', CA_CUSTOMER_NUM = 1000043.

11.3 Add Rejected for a Short COMMAREA

  • Input: EIBCALEN = 50.
  • Output: CA_RETURN_CODE = '98'. No counter call, DB2 call or LINK is made.

11.4 Security Record Insert

  • Input: CA_REQUEST_ID = '02ACUS', CA_CUSTOMER_NUM = 0000012345, CA_CUSTSECR_PASS = '5f4dcc3b5aa765d61d8327deb882cf99', CA_CUSTSECR_STATE = 'N', CA_CUSTSECR_COUNT = '0000'.
  • Output: A row (12345, '5f4dcc3b…', 'N', 0) is inserted into CUSTOMER_SECURE and CA_RETURN_CODE = '00'.
  • Failure variant: If customer 12345 already exists, DB2 returns a duplicate-key code such as -803. The program returns CA_RETURN_CODE = '98' and logs the error with the COMMAREA snapshot.
  • Unknown request: CA_REQUEST_ID = '01INQC' returns '99' with no DB2 access.

11.5 Inquiry Outcomes

Scenario Input Result
Found CA_CUSTOMER_NUM = 0000000042, EIBCALEN = 90 RC 00, nine fields populated
Not found CA_CUSTOMER_NUM = 9999999999 RC 01, fields unchanged
Short COMMAREA EIBCALEN = 50 RC 98, no DB2 access

11.6 Update Outcomes

Scenario Input Result
Success CA_CUSTOMER_NUM = 0000000042, new details RC 00, then LGUCVS01 linked
Not found CA_CUSTOMER_NUM = 0000099999 RC 01, no log entry, LGUCVS01 still linked
DB2 error SQLCODE such as -803 or -904 RC 90, entry written to the TD queue via LGSTSQ, LGUCVS01 still linked
