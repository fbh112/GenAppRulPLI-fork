Error Logging Utility (LGSTSQ)

LGSTSQ is a shared CICS Enterprise PL/I diagnostic logging utility within the GenApp application suite. It provides centralized, timestamped, and region-tagged error recording services. It accepts diagnostic message strings passed either via a communication area (COMMAREA) from calling application programs or directly through terminal input from 3270 visual display units.

When invoked, LGSTSQ interrogates the runtime environment, constructs a standardized diagnostic record prefixed with the CICS System Identifier (SYSID), and writes the message dual-target to both the standard CICS Transient Data Queue (CSMT) for system log consolidation and an application Temporary Storage Queue (GENAERRS or dynamic GENAnnnn).

1. Overview

LGSTSQ functions as the common logging backbone for GenApp application modules (such as policy management, customer inquiries, and commercial processing). By delegating message emission to LGSTSQ, calling programs decouple operational logging mechanics from core business transactions.

Key capabilities of LGSTSQ include:

  • Dual Destination Dispatching: Unconditionally writes log entries to the CSMT Transient Data Queue (TDQ) for operational audit trails and a Temporary Storage Queue (TSQ) for application review.
  • Dynamic Queue Routing: Analyzes message prefixes to dynamically route output from the default GENAERRS TSQ to custom four-character partitioned queues (GENAnnnn) via an inline Q=nnnn syntax.
  • Context Awareness: Interrogates the CICS Execute Interface Block (EIB) and system attributes using EXEC CICS ASSIGN commands to dynamically ascertain the calling execution path (linked program vs. interactive terminal).
  • Fault-Tolerant Non-Blocking I/O: Employs NOSUSPEND and RESP exception handling protocols across all CICS primitives to ensure that diagnostics or storage depletion never impede or abend core business transactions.

2.1 Component Interaction Description

  1. Ingestion Layer: LGSTSQ operates in dual-mode. Batch-like online tasks and CICS application modules pass data across the standard pointer-based COMMAREA interface (COMM_AREA_PTR). Alternatively, operators can invoke the utility transaction directly from an interactive 3270 terminal.
  2. Processing Core: The procedure determines its runtime execution state using EXEC CICS ASSIGN INVOKINGPROG. It extracts the payload, strips transaction routing directives (like transaction codes or Q=nnnn dynamic queue modifiers), and measures byte lengths.
  3. Queue Destinations: Messages are formatted with the local region’s 4-byte SYSID and written to CSMT (TDQ) and GENAERRS / GENAnnnn (TSQ). For terminal-originated executions, a trailing screen erasure and keyboard unlock are dispatched.

3. Data Flow and Execution Logic

3.1 Detailed Processing Flow

The utility follows a deterministic, sequential execution model that resolves invocation sources, normalizes lengths, overrides queue targets, writes to storage subsystems, and performs clean exits.

3.2 Processing Steps

3.2.1 Initialization and Context Capture

The utility clears output structures (WRITE_MSG and WS_RECV) to blanks and interrogates CICS runtime properties:

  • EXEC CICS ASSIGN SYSID(WRITE_MSG_SYSID): Captures the 4-character local CICS region name.
  • EXEC CICS ASSIGN STARTCODE(WS_STARTCODE): Identifies task initiation type.
  • EXEC CICS ASSIGN PRINSYSID(WS_PRINSYSID): Evaluates multi-region operation (MRO) principal system IDs.
  • EXEC CICS ASSIGN INVOKINGPROG(WS_INVOKEPROG): Identifies if the program was called via EXEC CICS LINK.

3.2.2 Input Mode Detection

  • Program Link Path (WS_INVOKEPROG is not blank): WS_FLAG is set to 'C'. Message text is populated from COMMA_DATA (via pointer COMM_AREA_PTR), and WS_RECV_LEN is set to EIBCALEN.
  • Terminal Path (WS_INVOKEPROG is blank): EXEC CICS RECEIVE reads the terminal stream. WS_FLAG is set to 'R'. The 5-byte transaction ID prefix is discarded, WS_RECV_DATA is transferred into WRITE_MSG_MSG, and length is adjusted by subtracting 5.

3.2.3 Queue Routing and Payload Trimming

The default TSQ target is configured to 'GENAERRS'. If WRITE_MSG_MSG starts with the literal string 'Q=':

  1. Characters 3 through 6 are extracted and concatenated with 'GENA' to form dynamic TSQ destination GENAnnnn.
  2. The remaining payload from position 8 onward (length 83) is extracted via buffer TEMPO and moved back to WRITE_MSG_MSG, stripping the command token.
  3. WS_RECV_LEN is decremented by 7.

3.2.4 Message Assembly and Queue Dispatch

The write length WS_RECV_LEN is increased by 5 to account for the 4-byte SYSID plus the 1-byte delimiter space (FILLER_X). Output records are dispatched:

  1. TDQ Output: EXEC CICS WRITEQ TD QUEUE('CSMT') writes the message to the regional CICS log.
  2. TSQ Output: EXEC CICS WRITEQ TS QUEUE(STSQ) NOSUSPEND writes the message to the default or dynamically overridden TSQ.

3.2.5 Termination

If WS_FLAG equals 'R', EXEC CICS SEND TEXT FROM(FILLER_X) ERASE FREEKB is issued to clear the display screen and unlock the terminal keyboard. Control is returned cleanly via EXEC CICS RETURN.

4. Interface and Data Structures

4.1 Interface Parameters & Working Fields

Field Identifier Data Type I/O Type Purpose / Description
COMM_AREA_PTR POINTER Input Parameter pointer addressing the caller’s COMMAREA structure.
COMMA_DATA CHAR(90) Input 90-byte input message text mapped over COMM_AREA_PTR.
EIBCALEN FIXED BIN(15) Input Execute Interface Block field reporting input COMMAREA length.
WS_INVOKEPROG CHAR(8) Runtime Invoking program identifier retrieved via CICS ASSIGN.
WRITE_MSG_SYSID CHAR(4) Output Prefix Local CICS region identifier prepended to all output logs.
STSQ CHAR(8) Control Target TSQ name (defaults to 'GENAERRS', dynamic: 'GENAnnnn').
STDQ_NAME CHAR(4) Control Target TDQ name, constant 'CSMT'.
WS_RECV CHAR(79) Input Buffer Structure for raw 3270 input (5-byte TranID + 74-byte data).
WRITE_MSG CHAR(95) Composite Buffer Full formatted output buffer (SYSID + space + message text).
WS_RESP FIXED BIN(31) Internal CICS command response code capture field.

4.2 Composite Record Layout (WRITE_MSG)

The 95-byte formatted output buffer written to both queues exhibits the following byte layout:

CODE 
+--------------------+--------------+-------------------------------------------------------------+
| WRITE_MSG_SYSID    | FILLER_X     | WRITE_MSG_MSG                                               |
| (4 Bytes - SYSID)  | (1 Byte - ' ')| (90 Bytes - Formatted Application Message Text)            |
+--------------------+--------------+-------------------------------------------------------------+

5. Technical Constraints & Design Rules

5.1 Buffer and Field Bounds

  • Maximum Message Length: Caller payloads are bound to a maximum of 90 bytes (CHAR(90)). Invocations exceeding this limit are truncated during PL/I assignment.
  • Terminal Constraints: Interactive inputs are constrained to 74 bytes of message payload after the initial 5-byte transaction prefix is stripped.
  • Queue Write Boundaries: WS_RECV_LEN controls the dynamic slice written to both queues. The hard structural maximum is bounded by WRITE_MSG (95 bytes).

5.2 Dynamic Queue Overrides

  • Strict Format Matching: Dynamic routing requires an exact case-sensitive uppercase match on SUBSTR(WRITE_MSG_MSG, 1, 2) = 'Q='.
  • Namespace Conformance: Suffix parameters replace bytes 5–8 of the queue name, ensuring all temporary queues remain scoped to the GENA namespace (GENAnnnn).

5.3 Exception Handling and Resiliency

  • NOSUSPEND TSQ Writes: If the CICS Temporary Storage subsystem is constrained or out of auxiliary space, NOSUSPEND ensures the record is dropped without suspending or abending the caller’s transaction thread.
  • Suppression via RESP: Every CICS command includes RESP(WS_RESP) to prevent CICS default exception trapping, ensuring zero task abends during error logging phases.

6. Execution Examples

6.1 Example 1: Standard Application Call (Default Queue)

Inbound State:

  • Invoking Program: LGSICVP (WS_INVOKEPROG = 'LGSICVP')
  • COMMAREA Payload: "Policy not found for customer 1234567890"
  • EIBCALEN: 42
  • System SYSID: GENL

Processing Summary:

  1. WS_INVOKEPROG is non-blank; sets WS_FLAG = 'C'.
  2. Message evaluated; no Q= prefix detected; STSQ remains 'GENAERRS'.
  3. Length computed: 42 (EIBCALEN) + 5 (SYSID prefix) = 47.
  4. Dispatched to TDQ CSMT and TSQ GENAERRS.

Output Buffer:

CODE 
GENL Policy not found for customer 1234567890

6.2 Example 2: Application Call with Dynamic Queue Override

Inbound State:

  • Invoking Program: LGSICVP (WS_INVOKEPROG = 'LGSICVP')
  • COMMAREA Payload: "Q=0042Policy limit exceeded for account 99"
  • EIBCALEN: 43
  • System SYSID: GENL

Processing Summary:

  1. WS_INVOKEPROG is non-blank; sets WS_FLAG = 'C'.
  2. Prefix Q= detected at bytes 1–2. Suffix 0042 extracted; STSQ set to 'GENA0042'.
  3. Message trimmed of first 7 bytes ("Q=0042" removed); effective message length reduced by 7 (43 - 7 = 36).
  4. Final length computed: 36 + 5 = 41.
  5. Dispatched to TDQ CSMT and TSQ GENA0042.

Output Buffer:

CODE 
GENL Policy limit exceeded for account 99

6.3 Example 3: Direct Terminal Invocation

Inbound State:

  • Invoking Program: Blank (WS_INVOKEPROG = ' ')
  • Terminal String Entered: "LGSQ Account 888 is invalid" (Total length: 30)
  • System SYSID: GENL

Processing Summary:

  1. WS_INVOKEPROG is blank; enters terminal processing path.
  2. EXEC CICS RECEIVE captures terminal buffer; sets WS_FLAG = 'R'.
  3. First 5 bytes ("LGSQ ") stripped; message length adjusted (30 - 5 = 25).
  4. Default STSQ used ('GENAERRS'). Total write length adjusted (25 + 5 = 30).
  5. Dispatched to TDQ CSMT and TSQ GENAERRS.
  6. WS_FLAG = 'R' triggers EXEC CICS SEND TEXT with ERASE and FREEKB to reset the terminal display.

Output Buffer:

CODE 
GENL Account 888 is invalid
