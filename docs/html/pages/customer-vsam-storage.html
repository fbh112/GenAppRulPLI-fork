Customer VSAM Data Services

Customer VSAM Data Services provide the core transactional file-handling infrastructure for customer data within the General Insurance Application (GenApp). Operating directly on the CICS-managed Key-Sequenced Data Set (KSDS) file KSDSCUST, this service suite provides record creation, exclusive record locking and updates, and pseudo-random customer key resolution. These services maintain synchronization across dual-store architectures, enforce transaction boundaries, and ensure robust error logging through dedicated transient diagnostic queues.

1. Overview

1.1 Purpose and Scope

The Customer VSAM Data Services layer isolates direct VSAM KSDS dataset operations behind standardized CICS interfaces. Whether maintaining dual-store parity alongside relational databases (DB2) or serving direct online queries and batch simulations, these modular PL/I programs encapsulate all record access patterns, locking semantics, and integrity verifications for the KSDSCUST cluster.

1.2 Program Portfolio Summary

The customer VSAM layer comprises three core operational modules:

  • LGACVS01 (Add Customer VSAM Service): Performs direct keyed record insertion into KSDSCUST. It is typically invoked by business orchestrators (such as LGACDB01) to write an exact image of the inbound communication area (COMMAREA), ensuring that newly generated customer records are mirrored to VSAM.
  • LGUCVS01 (Update Customer VSAM Service): Implements an update lifecycle using exclusive record locking. It executes an EXEC CICS READ ... UPDATE command followed by an EXEC CICS REWRITE, persisting customer demographic and policy modifications while preventing concurrent write corruption.
  • LGICVS01 (Random Customer Key Resolution Service): Resolves valid customer keys from KSDSCUST for synthetic workloads, tests, or interactive lookups. It serializes customer range control blocks stored in a CICS Temporary Storage Queue (GENACNTL), calculates pseudo-random keys using task entropy, and executes a Greater-Than-or-Equal (GTEQ) generic search against the KSDS file.

3. VSAM Record Insertion Service (LGACVS01)

3.1 Functionality and Invocation Contract

LGACVS01 receives customer demographic and policy records via the CICS Communication Area (COMMAREA) and writes the record directly to the KSDSCUST VSAM KSDS file. It serves as the primary VSAM mirror module during customer creation.

  • Invoking Program: Typically called via EXEC CICS LINK from DB2 orchestrator LGACDB01.
  • Target File: CICS File Definition KSDSCUST.
  • Primary Key (RIDFLD): CA_CUSTOMER_NUM (10-digit numeric).
  • Record Length: Derived dynamically at runtime from EIBCALEN.

3.2 Processing Logic and Write Operations

  1. Length Acquisition: Upon entry, LGACVS01 reads the inbound COMMAREA length from the Execute Interface Block (EIBCALEN) and stores it in WS_Commarea_Len.
  2. KSDS Keyed Insertion: The program issues an explicit EXEC CICS WRITE FILE operation:
    • Data is sourced from CA_CUSTOMER_NUM, which represents the start of the persistent payload within COMM_AREA.
    • Key length is fixed at 10 bytes.
    • Primary response is captured in WS_RESP.
  3. Response Verification:
    • If WS_RESP = DFHRESP(NORMAL), control returns cleanly to the caller with CA_RETURN_CODE unaltered.
    • If WS_RESP ≠ DFHRESP(NORMAL) (e.g., DUPREC or file disabled), the program enters its error handling routine.

3.4 Error Handling and Diagnostic Dispatch (LGV0)

When a write failure occurs:

  • CA_RETURN_CODE is set to '80'.
  • Secondary response code EIBRESP2 is stored into WS_RESP2.
  • Internal routine WRITE_ERROR_MESSAGE is invoked:
    • System time is retrieved using EXEC CICS ASKTIME and formatted via EXEC CICS FORMATTIME.
    • The ERROR_MSG structure is populated with timestamp, program literal (LGACVS01), customer ID (EM_CUSNUM), RESP (EM_RESPRC), and RESP2 (EM_RESP2RC).
    • EXEC CICS LINK PROGRAM('LGSTSQ') writes the message to the diagnostic queue.
    • A second call to LGSTSQ transmits up to 90 bytes of COMM_AREA_RAW prefixed with 'COMMAREA='.
  • Task abnormal termination is triggered via EXEC CICS ABEND ABCODE('LGV0') NODUMP.

3.5 Code Examples and Data Layout

The core file-write operation within LGACVS01 is implemented as follows:

PL1 
/* Capture COMMAREA length from CICS EIB */
 WS_Commarea_Len = EIBCALEN;

 /* Write record directly to KSDSCUST */
 EXEC CICS WRITE FILE('KSDSCUST')
      FROM(CA_Customer_Num)
      LENGTH(WS_Commarea_Len)
      RIDFLD(CA_Customer_Num)
      KEYLENGTH(10)
      RESP(WS_RESP);

 IF WS_RESP ^= DFHRESP(NORMAL) THEN
   DO;
     WS_RESP2 = EIBRESP2;
     CA_RETURN_CODE = '80';
     CALL WRITE_ERROR_MESSAGE;
     EXEC CICS ABEND ABCODE('LGV0') NODUMP;
     EXEC CICS RETURN;
   END;

4. VSAM Customer Update Service with Exclusive Locking (LGUCVS01)

4.1 Functionality and Dual-Stage Update Model

LGUCVS01 manages in-place updates to existing customer demographic data. To prevent lost updates and maintain serialization in high-concurrency environments, it executes a strict two-stage process: read-for-update lock acquisition followed by record rewriting.

4.2 Exclusive Lock Acquisition (READ UPDATE) and Data Rewrite (REWRITE)

  1. Length Initialization: Captures EIBCALEN into WS_Commarea_Len and WS_Commarea_LenF.
  2. Read-for-Update (Phase 1):
    • Issues EXEC CICS READ FILE('KSDSCUST') INTO(WS_Customer_Area) UPDATE.
    • Specifies RIDFLD(CA_CUSTOMER_NUM) with KEYLENGTH(10).
    • CICS places an exclusive record enqueue on the target KSDS record.
    • If the record does not exist or cannot be read (WS_RESP ≠ DFHRESP(NORMAL)), the program sets CA_RETURN_CODE = '81', logs diagnostics via LGSTSQ, and abends with code LGV1.
  3. Record Rewrite (Phase 2):
    • Upon successful read lock acquisition, issues EXEC CICS REWRITE FILE('KSDSCUST') FROM(CA_CUSTOMER_NUM) LENGTH(WS_Commarea_LenF).
    • Rewrites the record using updated fields passed in the COMMAREA.
    • Releases the exclusive CICS record lock.
    • If the rewrite fails (WS_RESP ≠ DFHRESP(NORMAL)), the program sets CA_RETURN_CODE = '82', logs diagnostics via LGSTSQ, and abends with code LGV2.

4.4 Diagnostic Logging and Distinct Failure Signals (LGV1, LGV2)

LGUCVS01 differentiates between read failures and rewrite failures using dedicated return codes and CICS user abend codes:

Failure Phase CA_RETURN_CODE CICS Abend Code Description
Read for Update '81' LGV1 Target customer key not found (NOTFND) or file locked/inaccessible.
Rewrite '82' LGV2 Record lock lost, I/O error, or invalid record length during rewrite.

4.5 Code Examples and COMMAREA Mapping

The two-phase update routine in LGUCVS01 is implemented as follows:

PL1 
/* Phase 1: Read with exclusive update lock */
 EXEC CICS READ FILE('KSDSCUST')
      INTO(WS_Customer_Area)
      LENGTH(WS_Commarea_Len)
      RIDFLD(CA_Customer_Num)
      KEYLENGTH(10)
      UPDATE
      RESP(WS_RESP);

 IF WS_RESP ^= DFHRESP(NORMAL) THEN
   DO;
     WS_RESP2 = EIBRESP2;
     CA_RETURN_CODE = '81';
     CALL WRITE_ERROR_MESSAGE;
     EXEC CICS ABEND ABCODE('LGV1') NODUMP;
     EXEC CICS RETURN;
   END;

 /* Phase 2: Rewrite updated COMMAREA data */
 EXEC CICS REWRITE FILE('KSDSCUST')
      FROM(CA_Customer_Num)
      LENGTH(WS_Commarea_LenF)
      RESP(WS_RESP);

 IF WS_RESP ^= DFHRESP(NORMAL) THEN
   DO;
     WS_RESP2 = EIBRESP2;
     CA_RETURN_CODE = '82';
     CALL WRITE_ERROR_MESSAGE;
     EXEC CICS ABEND ABCODE('LGV2') NODUMP;
     EXEC CICS RETURN;
   END;

5. Random Customer Key Resolution Service (LGICVS01)

5.1 Invocation Modes and Context Resolution

LGICVS01 supports both batch/programmatic calling and interactive terminal usage. Upon invocation, it determines execution context via CICS system inquiries:

PL1 
EXEC CICS ASSIGN SYSID(WS_SYSID) RESP(WS_RESP);
 EXEC CICS ASSIGN STARTCODE(WS_STARTCODE) RESP(WS_RESP);
 EXEC CICS ASSIGN INVOKINGPROG(WS_INVOKEPROG) RESP(WS_RESP);

 IF SUBSTR(WS_STARTCODE, 1, 1) = 'D' | WS_INVOKEPROG ^= ' ' THEN
   DO;
     WS_FLAG = 'C'; /* COMMAREA Mode */
     WS_COMMAREA = COMMA_DATA_H;
     WS_RECV_LEN = EIBCALEN;
   END;
 ELSE
   DO;
     WS_FLAG = 'R'; /* Terminal RECEIVE Mode */
     EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN) RESP(WS_RESP);
     WS_COMMAREA = WS_RECV_DATA;
     WS_RECV_LEN = WS_RECV_LEN - 5;
   END;

5.2 Control Queue Serialization (GENACNTL ENQ/DEQ)

The permissible range of customer numbers is maintained in the GENACNTL Temporary Storage Queue. To avoid race conditions during concurrent initialization or read operations, access is serialized using EXEC CICS ENQ and DEQ commands.

5.3 Boundary Evaluation and Pseudo-Random Key Computation

Once WS_CUST_LOW and WS_CUST_HIGH are extracted (defaulting to 1000001 if not found), the program calculates a pseudo-random key. It seeds the PL/I RANDOM function using the current CICS task number (EIBTASKN), providing variation across distinct task executions:

$\text{WS_RANDOM_NUMBER} = \lfloor \text{RANDOM}(\text{EIBTASKN}) \times (\text{WS_CUST_HIGH} - \text{WS_CUST_LOW}) + \text{WS_CUST_LOW} \rfloor$

5.4 Nearest Key Resolution via READ GTEQ

The calculated random customer number might not correspond to an existing record in the KSDS cluster. LGICVS01 performs a Greater-Than-or-Equal (GTEQ) read:

PL1 
EXEC CICS READ FILE('KSDSCUST')
      INTO(CA_AREA)
      LENGTH(F82)            /* 225 bytes */
      RIDFLD(WRITE_MSG_HIGH) /* Calculated Random Key */
      KEYLENGTH(F10)         /* 10 bytes */
      RESP(WS_RESP)
      GTEQ;

 IF WS_RESP = DFHRESP(NORMAL) THEN
   DO;
     /* Replace random seed with actual customer key found */
     WRITE_MSG_HIGH = CA_CUSTOMER_NUM;
   END;
  • If RESP = NORMAL, CA_CUSTOMER_NUM holds the nearest existing customer record key $\ge$ the generated key.
  • If RESP ≠ NORMAL (e.g., generated key is higher than any record in the file), WRITE_MSG_HIGH retains the generated key value as a fallback.

5.6 Code Examples and Output Dispatching

Depending on the initial invocation mode (WS_FLAG), the resolved key is either placed into the caller’s COMMAREA or transmitted to the 3270 terminal:

PL1 
SELECT (WS_FLAG);
   WHEN ('C')
     DO;
       COMMA_DATA_H    = WRITE_MSG_H;        /* 'HIGH CUSTOMER=' */
       COMMA_DATA_HIGH = WRITE_MSG_HIGH;     /* Resolved 10-digit Key */
       COMMA_DATA_FILL = (60)' ';            /* Clear filler */
     END;
   OTHERWISE
     DO;
       /* Display directly on 3270 screen */
       EXEC CICS SEND TEXT
            FROM(WRITE_MSG_H)
            LENGTH(24)
            WAIT
            ERASE
            TERMINAL
            FREEKB;
     END;
 END;

 EXEC CICS RETURN;

6. Shared Data Interfaces, Constraints, and Error Handling Standards

6.1 COMMAREA Structure (LGCMAREA) and Buffer Constraints

The primary customer data interface is governed by %INCLUDE LGCMAREA, defining a 32,500-byte structure (COMM_AREA_RAW). Individual customer fields are constrained as follows:

CA_RETURN_CODE PIC '99' 2 2-digit status code returned to caller
CA_CUSTOMER_NUM PIC '9999999999' 10 10-digit primary customer key (RIDFLD)
CA_FIRST_NAME CHAR(10) 10 Customer given name
CA_LAST_NAME CHAR(20) 20 Customer family name
CA_DOB CHAR(10) 10 Date of birth (YYYY-MM-DD)
CA_HOUSE_NAME CHAR(20) 20 Residential property name

CA_POLICY_DATA CHAR(32267) 32,267 Raw payload for associated policy data

6.2 Temporary Storage Queue Control (GENACNTL)

  • Queue Identification: CICS TS Queue name is fixed as 'GENACNTL'.
  • Item 1 (Eyecatcher): Length 20 bytes ('**** GENAPP CNTL').
  • Item 2 (Low Bound): Length 23 bytes ('LOW CUSTOMER=' + 10-digit value).
  • Item 3 (High Bound): Length 24 bytes ('HIGH CUSTOMER=' + 10-digit value).
  • Concurrency Protection: All access must be bounded by EXEC CICS ENQ RESOURCE('GENACNTL') and EXEC CICS DEQ RESOURCE('GENACNTL').

6.3 Standardized Error Logging Protocol (LGSTSQ)

When file operations in LGACVS01 or LGUCVS01 encounter non-normal conditions, diagnostics are dispatched to LGSTSQ via two sequential EXEC CICS LINK calls:

  1. Structured Error Header (ERROR_MSG):
    • Timestamp generated via EXEC CICS ASKTIME and EXEC CICS FORMATTIME.
    • Populates Program ID, Customer ID (EM_CUSNUM), primary response code (EM_RESPRC), and secondary response code (EM_RESP2RC).
  2. Data Payload Excerpt (CA_ERROR_MSG):
    • Transmits a diagnostic snapshot of the inbound COMMAREA prefixed with 'COMMAREA='.
    • Length is bounded: if EIBCALEN < 91, extracts EIBCALEN characters; if EIBCALEN \ge 91, truncates to 90 characters to prevent buffer overflow.
