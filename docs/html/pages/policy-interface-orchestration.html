Policy Presentation & Business Orchestration

1. Overview

The Policy Presentation and Business Orchestration subsystem within the General Insurance Application (GenApp) provides terminal user interfaces and core coordination services for managing policy lifecycles. It spans four distinct insurance product lines: Motor, Endowment, House, and Commercial property.

The subsystem follows a decoupled, three-tier enterprise mainframe architecture:

  1. Presentation Layer: CICS Basic Mapping Support (BMS) interactive menu programs (LGTESTP1, LGTESTP2, LGTESTP3, and LGTESTP4) executing under transaction IDs SSP1, SSP2, SSP3, and SSP4. These handle terminal input/output, user validation, conversational state transitions, and screen repainting.
  2. Business Orchestration Layer: Headless CICS dispatchers (LGIPOL01, LGAPOL01, LGUPOL01, and LGDPOL01) that act as domain orchestrators. They validate incoming request payloads, enforce buffer length contracts, optionally invoke decision engines (such as IBM Operational Decision Manager rules), and coordinate downstream database persistence.
  3. Data Persistence Layer: Backend database programs (e.g., LGIPDB01, LGAPDB01, LGUPDB01, and LGDPDB01) that execute embedded SQL against Db2 policy and customer tables.

Communication across all layers is standardized using a 32,500-byte shared Communication Area (COMMAREA) structure mapped by the LGCMAREA copybook.

2. System Architecture

2.1 Multi-Tier Architecture & Orchestration Layer

The presentation tier interacts with terminal operators via 3270 data streams mapped into symbolic BMS structures (SSMAP). Upon receiving user commands, the presentation programs populate the standard COMM_AREA structure and invoke the appropriate business orchestrator program via EXEC CICS LINK.

The business orchestrators validate input lengths, manage decision rules, and route requests to Db2 database access modules. In failure scenarios, presentation and orchestration modules coordinate transactional rollbacks (EXEC CICS SYNCPOINT ROLLBACK) and emit diagnostic snapshots to CICS Transient Data Queues (TDQ) via LGSTSQ.

3. Presentation Layer & BMS Menu Transactions

3.1 Motor Policy Transaction (SSP1 / LGTESTP1)

LGTESTP1 manages interactive operations for Motor insurance policies using BMS map SSMAPP1 in mapset SSMAP.

Primary Responsibilities

  • Cold Start Detection: Evaluates EIBCALEN = 0. Allocates a local BASE_COMM_AREA, initializes output fields (ENP1CNOO, ENP1PNOO, ENP1VALO, ENP1CCO, ENP1ACCO, ENP1PREO) to zeros, and renders the initial blank map using EXEC CICS SEND MAP('SSMAPP1') ERASE.
  • Option Routing:
    • Option '1' (Inquire): Populates CA_REQUEST_ID = '01IMOT', reads keys from ENP1CNOO and ENP1PNOO, and links to LGIPOL01. Displays vehicle attributes (make, model, value, registration, colour, CC, manufacture date, premium, accidents).
    • Option '2' (Add): Populates CA_REQUEST_ID = '01AMOT', maps user input fields (ENP1*I), zeros broker/payment fields, and links to LGAPOL01. Displays new policy ID and message New Motor Policy Inserted.
    • Option '3' (Delete): Populates CA_REQUEST_ID = '01DMOT', links to LGDPOL01, blanks screen details, and sets Motor Policy Deleted.
    • Option '4' (Update): Executes a two-phase flow (Inquire pre-fetch via LGIPOL01, secondary RECEIVE MAP, then update via LGUPOL01 with request '01UMOT').

3.2 Endowment Policy Transaction (SSP2 / LGTESTP2)

LGTESTP2 manages Endowment insurance policies using BMS map SSMAPP2.

Primary Responsibilities

  • Screen Attributes: Captures investment fund name (ENP2FNMI), policy term (ENP2TERI), sum assured (ENP2SUMI), life assured (ENP2LIFI), and investment indicator flags: with-profits (ENP2WPRI), managed fund (ENP2MANI), and equities (ENP2EQUI).
  • Operation Routing:
    • Option '1': Inquire via LGIPOL01 with CA_REQUEST_ID = '01IEND'.
    • Option '2': Add via LGAPOL01 with CA_REQUEST_ID = '01AEND'. Displays New Life Policy Inserted.
    • Option '3': Delete via LGDPOL01 with CA_REQUEST_ID = '01DEND'. Clears detail fields and displays Life Policy Deleted.
    • Option '4': Two-phase Update via LGIPOL01 (01IEND) then LGUPOL01 (01UEND). Displays Life Policy Updated.

3.3 House Policy Transaction (SSP3 / LGTESTP3)

LGTESTP3 provides the front-end interface for residential property policies using BMS map SSMAPP3.

Primary Responsibilities

  • Property Field Handling: Captures property type (ENP3TYPI), bedroom count (ENP3BEDI), declared property value (ENP3VALI), house name (ENP3HNMI), house number (ENP3HNOI), and postcode (ENP3HPCI).
  • Operation Routing:
    • Option '1': Inquire via LGIPOL01 with CA_REQUEST_ID = '01IHOU'.
    • Option '2': Add via LGAPOL01 with CA_REQUEST_ID = '01AHOU'.
    • Option '3': Delete via LGDPOL01 with CA_REQUEST_ID = '01DHOU'.
    • Option '4': Two-phase Update via LGIPOL01 (01IHOU) then LGUPOL01 (01UHOU). Displays House Policy Updated.

3.4 Commercial Policy Transaction (SSP4 / LGTESTP4)

LGTESTP4 manages commercial business policies using BMS map SSMAPP4. Unlike the other presentation programs, commercial policy maintenance supports Inquire, Add, and Delete, but does not provide an Update option.

Primary Responsibilities

  • Multi-Search Routing:
    • Inquiry (Option '1') dynamically determines search strategies:
      • Customer Number + Policy Number: sets CA_REQUEST_ID = '01ICOM'
      • Policy Number only: sets CA_REQUEST_ID = '02ICOM'
      • Customer Number only: sets CA_REQUEST_ID = '03ICOM'
      • Postcode present (ENP4HPCO non-blank): overrides all keys to CA_REQUEST_ID = '05ICOM'
  • Peril and Underwriting Management: Captures four distinct risk perils and premium amounts (Fire, Crime, Flood, Weather), property geolocation (latitude/longitude), customer description, property type, underwriting status (ENP4STAO), and rejection reason (ENP4REJO).
  • Operation Routing:
    • Option '2': Add via LGAPOL01 with CA_REQUEST_ID = '01ACOM'.
    • Option '3': Delete via LGDPOL01 with CA_REQUEST_ID = '01DCOM'.

4. Business Orchestration Layer Dispatchers

4.1 Policy Inquiry Dispatcher (LGIPOL01)

LGIPOL01 acts as the business front-end for policy data retrieval across all policy types.

Processing Steps

  1. Invocation Guard: Inspects EIBCALEN. If 0, sets EM_MSG_TEXT = ' NO COMMAREA RECEIVED', logs diagnostics via WRITE_ERROR_MESSAGE, and abends with EXEC CICS ABEND ABCODE('LGCA') NODUMP.
  2. Context Setup: Initializes CA_RETURN_CODE = '00', preserves customer and policy numbers in working storage (EM_CUSNUM, EM_POLNUM).
  3. Database Delegation: Issues EXEC CICS LINK PROGRAM('LGIPDB01') COMMAREA(COMM_AREA) LENGTH(32000).
  4. Completion: Issues EXEC CICS RETURN, allowing the caller to inspect the populated COMM_AREA and CA_RETURN_CODE.

4.2 Policy Addition Dispatcher (LGAPOL01) & ODM Business Rules Integration

LGAPOL01 orchestrates the creation of new insurance policies.

Processing Steps

  1. Validation: Checks EIBCALEN > 0 (abends with LGCA if missing) and verifies that EIBCALEN meets the minimum header length (WS_CA_HEADER_LEN = 28). Sets CA_RETURN_CODE = '98' and exits if length is insufficient.
  2. Business Rules Feature Toggle (ODM Integration):
    • The program defines a configuration toggle BUSINESS_RULES (initialized to 'N').
    • When enabled ('Y') and processing an Endowment addition (CA_REQUEST_ID = '01AEND'), it links to LGAPBR01 (IBM Operational Decision Manager rules wrapper) to validate underwriting rules before database insertion:
      PL1 
      IF ( BUSINESS_RULES = 'Y' ) THEN
       DO;
         IF ( CA_REQUEST_ID = '01AEND' ) THEN
           DO;
             EXEC CICS LINK Program('LGAPBR01')
                            Commarea(COMM_AREA)
                            LENGTH(32500);
           END;
       END;
  3. Database Persistence: Issues EXEC CICS LINK PROGRAM('LGAPDB01') COMMAREA(COMM_AREA) LENGTH(32500).
  4. Return Evaluation: Evaluates CA_RETURN_CODE. If non-zero, immediately returns to propagate backend status to the calling presentation program.

4.3 Policy Update Dispatcher (LGUPOL01) & Two-Phase Update Flows

LGUPOL01 manages update operations for Endowment, House, and Motor policies.

Payload Length Gating

To prevent buffer underruns, LGUPOL01 validates EIBCALEN against specific length thresholds for each policy type:

Request ID Policy Type Required Length Formula Minimum Bytes
'01UEND' Endowment WS_CA_HEADER_LEN (28) + WS_FULL_ENDOW_LEN (124) 152
'01UHOU' House WS_CA_HEADER_LEN (28) + WS_FULL_HOUSE_LEN (130) 158
'01UMOT' Motor WS_CA_HEADER_LEN (28) + WS_FULL_MOTOR_LEN (137) 165
Other Unrecognized Sets CA_RETURN_CODE = '99' N/A

If the buffer is shorter than required, the program sets CA_RETURN_CODE = '98' and returns immediately. If valid, it invokes UPDATE_POLICY_DB2_INFO, issuing EXEC CICS LINK PROGRAM('LGUPDB01') COMMAREA(COMM_AREA_RAW) LENGTH(32500).

4.4 Policy Deletion Dispatcher (LGDPOL01)

LGDPOL01 handles deletion requests across all four policy lines.

Processing Steps

  1. Validation: Verifies EIBCALEN >= 28 (returns 98 if undersized).
  2. Key Normalization: Converts CA_REQUEST_ID to uppercase via the UPPERCASE built-in function.
  3. Request Routing: Validates that CA_REQUEST_ID matches one of '01DEND', '01DHOU', '01DCOM', or '01DMOT'. Unrecognized codes result in CA_RETURN_CODE = '99'.
  4. Database Execution: Calls DELETE_POLICY_DB2_INFO, issuing EXEC CICS LINK PROGRAM('LGDPDB01') COMMAREA(COMM_AREA) LENGTH(32500).
  5. Cascading Semantics: Relies on relational integrity and foreign keys in Db2 to remove child detail rows when the parent POLICY row is deleted.

7. Error Handling, Rollback & Diagnostic Logging

7.1 Input & Guard Validation

The presentation and orchestration tiers apply multi-stage validation checks:

  • Menu Option Enforcement: Presentation menus verify that input matches valid options (1–4). If an invalid character is entered, the program sets ERP*FLDO = 'Please enter a valid option', positions the cursor at the option field using field length attribute OPT*L = -1, and resends the map with the CURSOR option.
  • Entry Buffer Guard: Every module inspects EIBCALEN. A zero length indicates an invalid execution state (e.g., invoked directly without a payload). Presentation modules treat EIBCALEN = 0 as a cold start and display an empty menu. Orchestrator dispatchers log the failure to a TDQ and terminate immediately via EXEC CICS ABEND ABCODE('LGCA') NODUMP.

7.2 Transactional Rollback Protocols

To maintain database consistency across distributed CICS units of work:

  • Add (Option 2) and Delete (Option 3) routines in presentation programs inspect CA_RETURN_CODE following orchestrator links.
  • If CA_RETURN_CODE > 0, the presentation module immediately issues an EXEC CICS SYNCPOINT ROLLBACK before displaying the error map. This reverses uncommitted Db2 insertions or deletions:
PL1 
/* Example Rollback Handling in Presentation Tier (LGTESTP1) */
EXEC CICS LINK PROGRAM('LGAPOL01')
               COMMAREA(COMM_AREA)
               LENGTH(32500);

IF ( CA_RETURN_CODE > 0 ) THEN
  DO;
    EXEC CICS SYNCPOINT ROLLBACK;
    GO TO NO_ADD;
  END;

8. Implementation Code Examples

8.1 Menu Option Dispatching in Presentation Tier (LGTESTP1)

The following PL/I snippet illustrates option selection, request mapping, and pseudo-conversational re-entry within presentation programs:

PL1 
A_GAIN:
  EXEC CICS HANDLE AID CLEAR(CLEARIT) PF3(ENDIT);
  EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);

  EXEC CICS RECEIVE MAP('SSMAPP1')
                 INTO(SSMAPP1I)
                 MAPSET('SSMAP');

  SELECT (ENP1OPTO);
    WHEN ('1') /* Inquire Motor Policy */
      DO;
        CA_REQUEST_ID   = '01IMOT';
        CA_CUSTOMER_NUM = ENP1CNOO;
        CA_POLICY_NUM   = ENP1PNOO;

        EXEC CICS LINK PROGRAM('LGIPOL01')
                       COMMAREA(COMM_AREA)
                       LENGTH(32500);

        IF ( CA_RETURN_CODE > 0 ) THEN
          GO TO NO_DATA;

        /* Map returned details to screen */
        ENP1IDAI = CA_ISSUE_DATE;
        ENP1EDAI = CA_EXPIRY_DATE;
        ENP1CMKI = CA_M_MAKE;
        ENP1CMOI = CA_M_MODEL;
        ENP1VALI = CA_M_VALUE;
        ENP1REGI = CA_M_REGNUMBER;
        ENP1COLI = CA_M_COLOUR;
        ENP1CCI  = CA_M_CC;
        ENP1MANI = CA_M_MANUFACTURED;
        ENP1PREI = CA_M_PREMIUM;
        ENP1ACCI = CA_M_ACCIDENTS;

        EXEC CICS SEND MAP('SSMAPP1')
                       FROM(SSMAPP1O)
                       MAPSET('SSMAP');
        GO TO ENDIT_STARTIT;
      END;

    WHEN ('2') /* Add Motor Policy */
      DO;
        CA_REQUEST_ID   = '01AMOT';
        CA_CUSTOMER_NUM = ENP1CNOI;
        CA_PAYMENT      = 0;
        CA_BROKERID     = 0;
        CA_BROKERSREF   = ' ';

        CA_ISSUE_DATE      = ENP1IDAI;
        CA_EXPIRY_DATE     = ENP1EDAI;
        CA_M_MAKE          = ENP1CMKI;
        CA_M_MODEL         = ENP1CMOI;
        CA_M_VALUE         = ENP1VALI;
        CA_M_REGNUMBER     = ENP1REGI;
        CA_M_COLOUR        = ENP1COLI;
        CA_M_CC            = ENP1CCI;
        CA_M_MANUFACTURED  = ENP1MANI;
        CA_M_PREMIUM       = ENP1PREI;
        CA_M_ACCIDENTS     = ENP1ACCI;

        EXEC CICS LINK PROGRAM('LGAPOL01')
                       COMMAREA(COMM_AREA)
                       LENGTH(32500);

        IF ( CA_RETURN_CODE > 0 ) THEN
          DO;
            EXEC CICS SYNCPOINT ROLLBACK;
            GO TO NO_ADD;
          END;

        ENP1PNOI = CA_POLICY_NUM;
        ENP1CNOI = CA_CUSTOMER_NUM;
        ENP1OPTI = ' ';
        ERP1FLDO = 'New Motor Policy Inserted';

        EXEC CICS SEND MAP('SSMAPP1')
                       FROM(SSMAPP1O)
                       MAPSET('SSMAP');
        GO TO ENDIT_STARTIT;
      END;

    OTHERWISE
      DO;
        ERP1FLDO = 'Please enter a valid option';
        ENP1OPTL = -1; /* Position cursor on option field */
        EXEC CICS SEND MAP('SSMAPP1')
                       FROM(SSMAPP1O)
                       MAPSET('SSMAP')
                       CURSOR;
        GO TO ENDIT_STARTIT;
      END;
  END;

ENDIT_STARTIT:
  EXEC CICS RETURN TRANSID('SSP1')
                   COMMAREA(COMM_AREA);

8.2 Business Rules & Dispatching in Orchestration Tier (LGAPOL01)

The following PL/I snippet illustrates COMMAREA length checking, feature toggle evaluation, database linking, and error logging in LGAPOL01:

PL1 
LGAPOL01: Proc(COMM_AREA_PTR) Options(Main);

  /* Capture CICS EIB Context */
  WS_TRANSID = EIBTRNID;
  WS_TERMID  = EIBTRMID;
  WS_TASKNUM = EIBTASKN;
  WS_CALEN   = EIBCALEN;

  /* Validate Presence of COMMAREA */
  IF ( EIBCALEN = 0 ) THEN
    DO;
      EM_MSG_TEXT = ' NO COMMAREA RECEIVED';
      CALL WRITE_ERROR_MESSAGE;
      EXEC CICS ABEND ABCODE('LGCA') NODUMP;
    END;

  CA_RETURN_CODE = '00';
  EM_CUSNUM      = CA_CUSTOMER_NUM;

  /* Verify Minimum Buffer Length */
  WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_REQUIRED_CA_LEN;
  IF ( EIBCALEN < WS_REQUIRED_CA_LEN ) THEN
    DO;
      CA_RETURN_CODE = '98';
      EXEC CICS RETURN;
    END;

  /* Conditional ODM Business Rule Execution */
  IF ( BUSINESS_RULES = 'Y' ) THEN
    DO;
      IF ( CA_REQUEST_ID = '01AEND' ) THEN
        DO;
          EXEC CICS LINK Program('LGAPBR01')
                         Commarea(COMM_AREA)
                         LENGTH(32500);
        END;
    END;

  /* Delegate Database Persistence */
  EXEC CICS LINK Program('LGAPDB01')
                 Commarea(COMM_AREA)
                 LENGTH(32500);

  IF ( CA_RETURN_CODE > 0 ) THEN
    DO;
      EXEC CICS RETURN;
    END;

  EXEC CICS RETURN;

/* Centralized Diagnostic Error Logger */
WRITE_ERROR_MESSAGE: Proc;
  DCL ABS_TIME FIXED BIN(31);
  DCL TIME1    CHAR(8);
  DCL DATE1    CHAR(10);

  EXEC CICS ASKTIME ABSTIME(ABS_TIME);
  EXEC CICS FORMATTIME ABSTIME(ABS_TIME)
                       MMDDYYYY(DATE1)
                       TIME(TIME1);

  EM_DATE = DATE1;
  EM_TIME = TIME1;

  EXEC CICS LINK PROGRAM('LGSTSQ')
                 COMMAREA(ERROR_MSG)
                 LENGTH(STG(ERROR_MSG));

  IF ( EIBCALEN > 0 ) THEN
    DO;
      IF ( EIBCALEN < 91 ) THEN
        CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
      ELSE
        CA_DATA = LEFT(COMM_AREA_RAW, 90);

      EXEC CICS LINK PROGRAM('LGSTSQ')
                     COMMAREA(CA_ERROR_MSG)
                     LENGTH(STG(CA_ERROR_MSG));
    END;
  RETURN;
END WRITE_ERROR_MESSAGE;

END LGAPOL01;
