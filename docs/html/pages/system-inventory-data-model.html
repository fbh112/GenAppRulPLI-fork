System Program Inventory and Database Table Dependencies

GenApp is a general insurance application running on z/OS that manages customers and insurance policies across four product lines: Motor, Endowment, House, and Commercial. The application is implemented entirely in PL/I and spans 35 programs organized across three online tiers plus a batch layer. All CICS online transactions share a common COMMAREA-based communication contract, while DB2 and VSAM serve as the dual persistence layer — DB2 as the authoritative store, and VSAM as a mirrored index for high-speed key lookup. This page provides a complete program inventory, inter-program linkage map, and DB2 table relational dependency reference across both the policy and customer domains.

1. Overview

The GenApp application exposes CICS online transactions for the full lifecycle management of customers and insurance policies, and includes batch programs for reporting and data extraction. The architecture follows a strict three-tier layering:

  • Tier 1 — Presentation: Five BMS menu programs accept terminal input, present BMS maps, and dispatch requests downstream via EXEC CICS LINK.
  • Tier 2 — Orchestration: Seven business-logic programs validate the COMMAREA and route dynamically to the appropriate backend.
  • Tier 3 — Backend: Sixteen programs handle all physical I/O — eight against DB2 (embedded SQL) and seven against VSAM KSDS datasets, plus one customer-security insert program.
  • Supporting Services: Four cross-cutting CICS programs handle error logging, statistics collection, and environment setup.
  • Batch: Four programs handle offline customer reporting and motor-table extract.

All programs communicate exclusively through a shared COMMAREA structure defined in LGCMAREA.inc. There are no direct inter-program data coupling paths outside this contract.

The three-tier design enforces a clean separation of concerns: presentation programs are entirely free of SQL, orchestrators contain business logic but no file I/O, and backends are pure I/O handlers with no presentation awareness. Supporting services are consumed horizontally across all tiers.

3. Program Inventory

3.1 Tier 1 — Presentation / BMS Menu Programs

Presentation programs receive control directly from CICS transactions. They display BMS maps to the terminal, accept user input, and dispatch to the orchestration tier via EXEC CICS LINK. None of these programs perform any DB2 or VSAM I/O directly.

All five programs share the same entry point signature:

PLI 
Proc(DFHEIPTR, COMM_AREA_PTR) Options(Main, Reentrant)

They use two common includes:

PLI 
%INCLUDE SSMAP;     /* BMS map structures for all screens     */
%INCLUDE LGCMAREA;  /* Shared COMMAREA structure               */
