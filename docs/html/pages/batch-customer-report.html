Batch Customer Reporting

1. Overview

The Batch Customer Reporting pipeline is a set of non-CICS PL/I programs in the GenApp insurance application. They produce customer report lines from DB2 data. Three programs make up the pipeline:

Program Role Description
LGBATCH Main batch driver Reads customer numbers from CUSTIN, queries the DB2 CUSTOMER table for each one, calls LGBATCHF to format a line, and writes the line to CUSTRPT.
LGBATCHF Formatting subroutine Takes a customer number and a pointer to the shared COMMAREA. Builds an 80-character report line from the customer’s first and last name.
LGBATDB2 Standalone test driver Looks up one hard-coded customer (number 1) in DB2, calls LGBATCHF, and displays the resulting line.

The programs share the LGCMAREA COMMAREA layout, which CICS programs in the same application also use. A 32,500-byte working-storage buffer (BATCH_COMM_AREA) backs the layout, and a BASED pointer structure (COMM_AREA) overlays it. The DB2 SELECT fills this structure, and the formatter reads from it.

Key characteristics:

  • Batch only. There are no CICS commands, and LGBATCH and LGBATDB2 are Options(Main) programs.
  • LGBATCH reads sequential files and writes the report.
  • LGBATCHF is a pure formatting routine with no I/O except a diagnostic DISPLAY.
  • LGBATCH and LGBATDB2 both load LGBATCHF dynamically with FETCH.

3. Components

3.1 LGBATCH – Main Batch Driver

3.1.1 Purpose

LGBATCH reads a sequential file of customer numbers and queries DB2 for each number. It calls LGBATCHF to format a line, and writes one 80-character line per input record to CUSTRPT. After each DB2 lookup it sets CA_RETURN_CODE to show the outcome, and it ends normally once the input is exhausted.

3.1.2 Files and Resources

Resource Type Attributes Use
CUSTIN Sequential input ENV(FB RECSIZE(10)), one PIC '9999999999' customer number per record Drives the processing loop
CUSTRPT Sequential output ENV(FB RECSIZE(80)) One report line per customer
CUSTOMER DB2 table Keyed by CUSTOMERNUMBER Customer demographics
LGBATCHF External subroutine ENTRY(PIC '9999999999', PTR, CHAR(80)) Line formatting
SQLCA Include EXEC SQL INCLUDE SQLCA SQL status (SQLCODE)

3.1.3 Internal Procedures

Procedure Responsibility
Main body Sets COMM_AREA_PTR, fetches LGBATCHF, registers condition handlers, opens files, runs the read loop, closes files.
PROCESS_RECORD Converts the customer number to a FIXED BIN(31) host variable. Calls GET_CUSTOMER_INFO, then LGBATCHF, then writes the line.
GET_CUSTOMER_INFO Runs the SELECT … INTO and maps SQLCODE to CA_RETURN_CODE.
WRITE_ERROR_MESSAGE Builds the in-memory ERROR_MSG structure on unexpected SQL errors.

3.1.5 Key Code Elements

The main procedure binds the COMMAREA to its backing store, then loads the formatter. Both steps run before any file I/O:

PLI 
COMM_AREA_PTR = ADDR(BATCH_COMM_AREA);
FETCH LGBATCHF;

If CUSTIN cannot be opened, the program stops with return code 16:

PLI 
ON UNDEFINEDFILE(CUSTIN) BEGIN;
   DISPLAY('FILE STATUS AT OPEN CUSTIN');
   CALL PLIRETC(16);
   STOP;
END;

SQLCODE is evaluated in a SELECT/WHEN/OTHERWISE construct inside GET_CUSTOMER_INFO:

PLI 
SELECT (SQLCODE);
   WHEN (0)   CA_RETURN_CODE = '00';
   WHEN (100) CA_RETURN_CODE = '01';
   OTHERWISE  DO;
      CA_RETURN_CODE = '90';
      CALL WRITE_ERROR_MESSAGE;
   END;
END;

The DB2 query selects nine columns directly into the COMMAREA fields:

PLI 
EXEC SQL SELECT FIRSTNAME, LASTNAME, DATEOFBIRTH, HOUSENAME,
                HOUSENUMBER, POSTCODE, PHONEMOBILE, PHONEHOME,
                EMAILADDRESS
         INTO :CA_FIRST_NAME, :CA_LAST_NAME, :CA_DOB, :CA_HOUSE_NAME,
              :CA_HOUSE_NUM, :CA_POSTCODE, :CA_PHONE_MOBILE,
              :CA_PHONE_HOME, :CA_EMAIL_ADDRESS
         FROM CUSTOMER
         WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUMBER_INT;

The call to the formatter is:

PLI 
CALL LGBATCHF(CUSTIN_CUSTNUMBER, COMM_AREA_PTR, CUSTRPT_LINE);

3.2 LGBATCHF – Report Line Formatter

3.2.1 Purpose

LGBATCHF formats one customer report line. It gets the customer number, a pointer to the COMMAREA, and an 80-character output variable. It keeps the first word (up to the first blank) of the first name and of the last name. It then builds a line of the form Customer <number> is <first> <last>. It performs no DB2, file, CICS, or MQ operations.

3.2.2 Parameters

Parameter Declaration Direction Description
CUSTNUMBER PIC '9999999999' In Customer number to embed in the line
COMM_PTR PTR In Address of the LGCMAREA COMMAREA in the caller’s storage
LS_LINE CHAR(80) Out Receives the formatted report line

The formatter reads only CA_FIRST_NAME (10 characters) and CA_LAST_NAME (20 characters). Other COMMAREA fields, such as CA_DOB, CA_POSTCODE, CA_NUM_POLICIES and CA_PAYMENT, are addressable but not used in the line.

3.2.3 Name Token Extraction

The routine uses INDEX to find the first blank in each name and takes the text before it. This mirrors the COBOL idiom STRING … DELIMITED BY SPACE. The logic is the same for both name fields:

POS = INDEX(field, ' ') Token result
0 (no blank) Entire field
1 (leading blank) Empty string
> 1 SUBSTR(field, 1, POS-1)
graph TD A([Entry: CUSTNUMBER, COMM_PTR, LS_LINE]) --> B["COMM_AREA_PTR = COMM_PTR"] B --> C["POS = INDEX of blank in CA_FIRST_NAME"] C --> D{POS} D -- "0" --> E["FIRST_TOKEN = full field"] D -- "1" --> F["FIRST_TOKEN = empty"] D -- ">1" --> G["FIRST_TOKEN = SUBSTR 1 to POS-1"] E --> H["POS = INDEX of blank in CA_LAST_NAME"] F --> H G --> H H --> I{POS} I -- "0" --> J["LAST_TOKEN = full field"] I -- "1" --> K["LAST_TOKEN = empty"] I -- ">1" --> L["LAST_TOKEN = SUBSTR 1 to POS-1"] J --> M["Compose LS_LINE"] K --> M L --> M M --> N["DISPLAY trace line"] N --> O([RETURN])

3.2.4 Key Code Elements

PLI 
COMM_AREA_PTR = COMM_PTR;

The line is composed by concatenation, and then a trace is displayed:

PLI 
LS_LINE = 'Customer ' || CUSTNUMBER || ' is ' ||
          FIRST_TOKEN || ' ' || LAST_TOKEN;

DISPLAY('LGBATCHF WAS HERE... ' || LS_LINE);

The longest possible line is 54 characters (9 + 10 + 4 + 10 + 1 + 20), so name data is never truncated in the 80-character field.

3.3 LGBATDB2 – Standalone Test Driver

3.3.1 Purpose

LGBATDB2 exercises the DB2-to-formatter path without a file or a loop. It fetches customer number 1, calls LGBATCHF, and displays the result. It is intended for testing and verification, not production runs.

3.3.2 Execution Steps

  1. Set COMM_AREA_PTR to ADDR(BATCH_COMM_AREA).
  2. FETCH LGBATCHF.
  3. DISPLAY the initial SQLCODE and SQLSTATE. No SQL has run yet, so this is only a baseline.
  4. Set DB2_CUSTOMERNUMBER_INT = 1.
  5. Call PROCESS_RECORD. It calls GET_CUSTOMER_INFO, converts the integer to CUSTIN_CUSTNUMBER, calls LGBATCHF, and displays CUSTRPT_LINE.
  6. RETURN.
graph TD A([Start LGBATDB2]) --> B["COMM_AREA_PTR = ADDR BATCH_COMM_AREA"] B --> C["FETCH LGBATCHF"] C --> D["DISPLAY SQLCODE and SQLSTATE"] D --> E["DB2_CUSTOMERNUMBER_INT = 1"] E --> F[PROCESS_RECORD] F --> G[GET_CUSTOMER_INFO
SELECT INTO COMM_AREA fields] G --> H["CUSTIN_CUSTNUMBER = DB2_CUSTOMERNUMBER_INT"] H --> I["CALL LGBATCHF"] I --> J["DISPLAY CUSTRPT_LINE"] J --> K([RETURN])

3.3.3 Differences from LGBATCH

Aspect LGBATCH LGBATDB2

Output Writes CUSTRPT file DISPLAY to SYSOUT
SQLCODE handling Maps to CA_RETURN_CODE 00/01/90 None
Looping DO WHILE (^FI_EOF) None, single pass

6. Data Structures and Entity Relationships

6.1 Shared COMMAREA Storage

All three programs declare the same storage pattern:

  • BATCH_COMM_AREA CHAR(32500) is the physical storage.
  • COMM_AREA, from the LGCMAREA include, is a UNION BASED(COMM_AREA_PTR). It overlays the buffer and exposes the customer request, policy request, and customer-security request layouts.
  • COMM_AREA_PTR = ADDR(BATCH_COMM_AREA) must run before any COMMAREA field is referenced.
  • LGBATCHF sets its own COMM_AREA_PTR = COMM_PTR, so it reads the caller’s storage and does not copy it.

7. Interface Contract

7.1 LGBATCHF Entry Declaration

Callers declare and fetch the formatter as follows. The types and order must match exactly.

PLI 
DCL LGBATCHF ENTRY(PIC '9999999999', PTR, CHAR(80));
...
FETCH LGBATCHF;
...
CALL LGBATCHF(CUSTIN_CUSTNUMBER, COMM_AREA_PTR, CUSTRPT_LINE);
Position Caller variable Type Callee parameter
1 CUSTIN_CUSTNUMBER PIC '9999999999' CUSTNUMBER
2 COMM_AREA_PTR PTR COMM_PTR
3 CUSTRPT_LINE CHAR(80) LS_LINE

7.2 Number Conversions

CUSTOMERNUMBER is an integer in DB2, but LGBATCHF expects a picture field. Each driver therefore converts the number:

  • LGBATCH assigns DB2_CUSTOMERNUMBER_INT = CUSTIN_CUSTNUMBER. Customer numbers must fit in a signed 31-bit integer (up to 2,147,483,647).
  • LGBATDB2 assigns CUSTIN_CUSTNUMBER = DB2_CUSTOMERNUMBER_INT, which gives a 10-digit display form such as 0000000001.

8.2 Known Behaviors

  • Stale data on “not found”: When SQLCODE is 100, the CA_* fields are not refreshed. LGBATCH still calls LGBATCHF, so the line reflects the previous customer’s names. The COMMAREA is not reinitialised between records.
  • SQL errors are not externalised: WRITE_ERROR_MESSAGE fills ERROR_MSG in memory only. Nothing writes it to a file, queue, or log, so it is visible only in a dump.
  • SQL errors do not abort the run: LGBATCH continues with the next record after an error (CA_RETURN_CODE = '90').
  • No CUSTRPT guard: There is no UNDEFINEDFILE(CUSTRPT) handler and no write-error handling.
  • CA_RETURN_CODE is not consulted: LGBATCHF neither reads nor sets it.
  • LGBATDB2 ignores SQLCODE: It displays SQLCODE and SQLSTATE only at startup, before any SQL has run. It never checks the outcome of the SELECT.
  • Unconditional trace: LGBATCHF always issues its DISPLAY trace. The trace appears once per customer in the LGBATCH job log.

8.3 Job-Level Return Codes

Return code Cause
0 Normal completion, implicit
16 CUSTIN could not be opened (CALL PLIRETC(16))

9. Constraints and Dependencies

9.1 Input and Allocation Constraints

  • CUSTIN must be allocated as fixed-block with a 10-byte record. Each record is one 10-digit numeric customer number.
  • CUSTRPT must be allocated and writable as fixed-block with an 80-byte record.
  • The DB2 environment must be available. This means a precompiled and bound program and a valid plan or package.
  • LGBATCHF must be fetchable at runtime, because the FETCH runs before any file open.

9.2 Sequencing Constraints

  1. COMM_AREA_PTR is set before any COMMAREA reference.
  2. LGBATCHF is fetched before it is called.
  3. In LGBATCH, CUSTIN and CUSTRPT are opened, then the ENDFILE handler is registered, then the first read happens, then the loop runs.
  4. The DB2 SELECT always precedes the call to LGBATCHF.
  5. In LGBATCHF, the first-name extraction finishes before the last-name extraction starts, because both reuse the single POS variable.
  6. In LGBATCHF, LS_LINE is fully built before the DISPLAY.

9.3 Data Constraints

Item Constraint
Customer number 10-digit numeric picture; must also fit in FIXED BIN(31) for the DB2 predicate
BATCH_COMM_AREA Exactly 32,500 bytes; COMM_AREA must fit within it
CA_FIRST_NAME / CA_LAST_NAME 10 / 20 characters; longer DB2 values are truncated
Name tokens Only text before the first blank is kept
CUSTRPT_LINE Exactly 80 characters
SQL query Single-row SELECT INTO, so CUSTOMERNUMBER must be unique; no cursor
EM_SQLRC Signed 5-digit picture (±99999)

10. Examples

10.1 Formatter Output – Standard Names

Input to LGBATCHF:

Parameter Value
CUSTNUMBER 0000000042
CA_FIRST_NAME 'John '
CA_LAST_NAME 'Smith '

Resulting LS_LINE (padded with blanks to 80 characters):

CODE 
Customer 0000000042 is John Smith

10.2 Formatter Output – Names That Fill the Field

When INDEX returns 0 for both names, the full field values are used:

CODE 
Customer 0000001234 is Jacqueline Vandenberghe

10.3 Formatter Output – Leading Blank in First Name

When CA_FIRST_NAME starts with a blank, POS = 1 and FIRST_TOKEN is empty. The literal separator ' ' still follows it, so the line has two spaces:

CODE 
Customer 0000009999 is  Doe

10.4 LGBATCH – Customer Found

Input record 0000000042. The SELECT returns SQLCODE = 0, so CA_RETURN_CODE = '00' and the CA_* fields are populated. LGBATCHF formats the line and LGBATCH writes it to CUSTRPT.

Based on the formatter logic in section 3.2, the line written is of the form Customer 0000000042 is John Smith. The LGBATCH example in the source documentation shows a wider layout with date of birth and postcode, but the formatter logic builds only the name sentence.

10.5 LGBATCH – Customer Not Found

Input record 0000009999, with no matching row:

  1. SQLCODE = 100 gives CA_RETURN_CODE = '01'.
  2. The CA_* fields keep the previous customer’s values.
  3. LGBATCHF is still called. The customer number in the line is 0000009999, but the names belong to the previous customer.
CODE 
Customer 0000009999 is John Smith

10.6 LGBATCH – Unexpected SQL Error

Input record 0000000007 and SQLCODE = -911:

  1. CA_RETURN_CODE = '90' and WRITE_ERROR_MESSAGE is called.
  2. ERROR_MSG is built in memory only. An illustrative image of its content:
CODE 
20250101 143022  LGBATCH CNUM=0000000007 PNUM=0000000000 SELECT CUSTOMER SQLCODE=  -911
  1. Processing continues. LGBATCHF is called with whatever COMMAREA data is present.

10.7 LGBATDB2 – Console Output

For a successful lookup of customer 1, the job log shows the startup status lines and the displayed report line. The LGBATCHF trace line also appears, because the formatter always displays it:

CODE 
LGBATDB2 SQLCode : 0
LGBATDB2 SQLState: 00000
LGBATCHF WAS HERE... Customer 0000000001 is John Smith
Customer 0000000001 is John Smith

The startup SQLCODE and SQLSTATE display runs before the SELECT. It therefore shows only the initial SQLCA state and does not reflect the lookup result, including a not-found condition.

11. Operational Notes

Topic Guidance
Running the full report Run LGBATCH with CUSTIN and CUSTRPT DDs allocated, and a DB2 connection available.
Smoke-testing the pipeline Run LGBATDB2. It needs only DB2 access and LGBATCHF, and prints one line to SYSOUT.
Monitoring Check the job step return code for 16. Scan SYSOUT for repeated LGBATCHF WAS HERE... trace lines, which give per-record progress.
Detecting bad lookups CA_RETURN_CODE values 01 and 90 are set in memory but not written to the report. Reconcile CUSTIN and CUSTRPT against the DB2 data to detect not-found customers.
Extending the report LGBATCHF can use other COMMAREA fields (CA_DOB, CA_POSTCODE, CA_EMAIL_ADDRESS, CA_NUM_POLICIES) without changing the interface. The 80-byte limit applies.
