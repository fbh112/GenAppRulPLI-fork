Policy Add

1. Overview

The Policy Add flow creates a new insurance policy in the General Insurance (GenApp) application. It runs as a chain of three CICS PL/I programs that share one 32,500-byte COMMAREA:

Program Role
LGAPOL01 Orchestrator. Validates the COMMAREA, optionally calls the ODM business rules program LGAPBR01 for Endowment adds, then links to LGAPDB01.
LGAPDB01 DB2 insert engine. Applies pricing, discount, surcharge and commission rules, inserts the POLICY row and the policy-type detail row, then links to LGAPVS01.
LGAPVS01 VSAM writer. Writes a compact 64-byte policy record to the KSDS file KSDSPOLY.

The flow handles these request types:

Request ID Policy type
01AEND Endowment
01AHOU House
01AMOT Motor
01ACOM Commercial
01ACLM Claim (in LGAPDB01 only)

The caller learns the outcome from CA_RETURN_CODE in the COMMAREA. On a successful add, the DB2-generated CA_POLICY_NUM and CA_LASTCHANGED are also returned.

The orchestrator holds no data logic. LGAPDB01 owns all DB2 access and business pricing. LGAPVS01 keeps a compact VSAM copy of the policy in step with DB2. All three programs share the error-logging utility LGSTSQ.

2.2 Component Responsibilities

Component Type Responsibility
LGAPOL01 CICS PL/I program COMMAREA presence and length validation, feature-toggled ODM call, delegation to LGAPDB01, return-code propagation
LGAPBR01 CICS program (ODM) Applies business rules to Endowment adds. Disabled by default.
LGAPDB01 CICS PL/I + DB2 Request routing, premium loading, bundling discount, broker commission, inserts into POLICY and detail tables
LGAPVS01 CICS PL/I + VSAM Builds the 21-byte composite key and 43-byte data area, then writes to KSDSPOLY
LGSTSQ CICS utility Writes the error message and a COMMAREA snapshot to a transient data queue
LGCMAREA PL/I include Defines the shared COMM_AREA union (32,500 bytes)

2.3 Shared Includes

  • LGCMAREA defines COMM_AREA, which is based on COMM_AREA_PTR. It has a raw COMM_AREA_RAW overlay and structured sub-groups (CA_ENDOWMENT, CA_HOUSE, CA_MOTOR, CA_COMMERCIAL, CA_CLAIM).
  • LGPOLICY, DCLPOLIC, DCLENDOW and SQLCA are used by LGAPDB01 for DB2 host variables and SQL communication.

4. Orchestration: LGAPOL01

4.1 Processing Steps

  1. Capture EIB fields. EIBTRNID, EIBTRMID, EIBTASKN and EIBCALEN are copied to working storage for diagnostics.
  2. Presence check. If EIBCALEN = 0, the program sets the message ' NO COMMAREA RECEIVED', calls WRITE_ERROR_MESSAGE, and abends with LGCA (NODUMP).
  3. Initialisation. CA_RETURN_CODE is set to '00'. The COMMAREA pointer is saved, and CA_CUSTOMER_NUM is copied to EM_CUSNUM.
  4. Length validation. The required length is WS_CA_HEADER_LEN (28) plus WS_REQUIRED_CA_LEN. If EIBCALEN is shorter, the program sets CA_RETURN_CODE = '98' and returns.
  5. Optional ODM rules. If BUSINESS_RULES = 'Y' and CA_REQUEST_ID = '01AEND', the program links to LGAPBR01.
  6. DB2 insert. The program always links to LGAPDB01.
  7. Return-code check. If CA_RETURN_CODE > 0, the program returns immediately. Otherwise it returns normally with '00'.

4.3 Code Examples

Optional business-rules call. The feature toggle is initialised to 'N', and the statement that would set it to 'Y' is commented out in the source:

PLI 
EXEC CICS LINK Program('LGAPBR01') COMMAREA(COMM_AREA) LENGTH(32500)

Mandatory DB2 call, followed by return-code propagation:

PLI 
EXEC CICS LINK Program('LGAPDB01') COMMAREA(COMM_AREA) LENGTH(32500)
IF CA_RETURN_CODE > 0 THEN DO;
   EXEC CICS RETURN;
END;
EXEC CICS RETURN;

No-COMMAREA handling:

PLI 
EXEC CICS ABEND ABCODE('LGCA') NODUMP

4.4 ODM Feature Toggle

  • BUSINESS_RULES is a compile- or deploy-time switch, not a runtime input.
  • Even when enabled, only 01AEND requests reach LGAPBR01. House, Motor and Commercial adds never do.
  • LGAPOL01 performs no separate status check after the LGAPBR01 call. Any outcome has to be reflected in the shared COMMAREA fields, such as CA_RETURN_CODE.

5. DB2 Insert: LGAPDB01

5.1 Request Routing and Length Check

On entry, LGAPDB01 repeats the EIBCALEN = 0 check (abend LGCA) and sets CA_RETURN_CODE = '00'. It also converts the customer and policy numbers to integer host variables. The first SELECT/WHEN on CA_REQUEST_ID then sets the policy type and the extra required length:

Request ID Policy type (DB2_POLICYTYPE) Added required length
01AEND E WS_FULL_ENDOW_LEN (124)
01AHOU H WS_FULL_HOUSE_LEN (130)
01AMOT M WS_FULL_MOTOR_LEN (137)
01ACOM C none
01ACLM X none
other n/a CA_RETURN_CODE = '99', return

If EIBCALEN is less than the required length (the 28-byte header plus the type-specific length), the program sets CA_RETURN_CODE = '98' and returns.

5.2 Processing Flow

graph TD A([Start LGAPDB01]) --> B{EIBCALEN = 0?} B -- Yes --> C[ABEND LGCA] B -- No --> D[Init host variables, RC = 00] D --> E{Valid request ID?} E -- No --> F[RC = 99, return] E -- Yes --> G{Length OK?} G -- No --> H[RC = 98, return] G -- Yes --> I{Request is 01ACLM?} I -- No --> J[INSERT_POLICY] I -- Yes --> K J --> K{Route by type} K --> K1[INSERT_ENDOW] K --> K2[INSERT_HOUSE] K --> K3[INSERT_MOTOR] K --> K4[INSERT_COMMERCIAL] K --> K5[INSERT_CLAIM] K1 --> L[LINK LGAPVS01] K2 --> L K3 --> L K4 --> L K5 --> L L --> M([EXEC CICS RETURN])

5.3 INSERT_POLICY

INSERT_POLICY runs for every request except 01ACLM. It does the following:

  1. Converts CA_BROKERID and CA_PAYMENT to integers.
  2. Applies the house location loading (section 5.4).
  3. Calls BUNDLING_DISCOUNT (section 5.5) and CALCULATE_COMMISSION (section 5.6).
  4. Inserts the POLICY row with POLICYNUMBER DEFAULT (an identity column) and CURRENT TIMESTAMP for LASTCHANGED.
  5. Evaluates SQLCODE:
    • 0 sets CA_RETURN_CODE = '00'.
    • -530 (referential integrity violation, for example a non-existent customer) sets '70', logs, and returns without an abend.
    • Any other non-zero value sets '90', logs, and returns without an abend.
  6. Retrieves the generated key with SET :DB2_POLICYNUM_INT = IDENTITY_VAL_LOCAL() and copies it to CA_POLICY_NUM.
  7. Selects LASTCHANGED from POLICY into CA_LASTCHANGED.

600000-699999?} B -- Yes --> C[Loading by property value

5.4 House Premium Loading

This rule applies only to 01AHOU requests whose postcode falls in the range 600000–699999. The surcharge is added to DB2_PAYMENT_INT:

Property value Surcharge
over 10,000,000 and under 15,000,000 +20%
over 15,000,000 and under 20,000,000 +40%
over 20,000,000 +50%

5.5 Bundling Discount

BUNDLING_DISCOUNT counts the customer’s currently active policies of type 'M' or 'H'. If the count is greater than 2, DB2_PAYMENT_INT is reduced by 15%. A non-zero SQLCODE sets CA_RETURN_CODE = '90', logs the error, and abends with LGSQ to force backout.

5.6 Broker Commission

CALCULATE_COMMISSION counts the broker’s active policies (ISSUEDATE/EXPIRYDATE bracketing the current date) and derives WS_COMMISSION as a percentage of DB2_PAYMENT_INT:

Active broker policies Commission rate
0 0%
1 1%
2 2%
3 3%
4 4%
5 or more 5%

5.7 Policy-Type Insert Procedures

Procedure Table Pricing or special logic
INSERT_ENDOW ENDOWMENT If WS_VARY_LEN = EIBCALEN - WS_REQUIRED_CA_LEN is greater than 0, the excess bytes go into the PADDINGDATA VARCHAR. Otherwise the column is omitted.
INSERT_HOUSE HOUSE Converts value and bedrooms to integers.
INSERT_MOTOR MOTOR Applies accident-based premium loading (below).
INSERT_COMMERCIAL COMMERCIAL Applies peril surcharges via VALIDATE_PREV_PERIL (below).
INSERT_CLAIM CLAIM Calls UPDATE_BROKER_COMM (below) before the insert.

Motor accident loading is applied to CA_M_PREMIUM:

Accidents Multiplier
0–2 ×1.00
3–5 ×1.20
6–8 ×1.50
more than 8 ×3.00

Commercial peril surcharge. VALIDATE_PREV_PERIL sums FLOODPERIL and WEATHERPERIL over active commercial policies with the same ZIPCODE. A sum greater than 3 sets WS_FLOOD_FLG or WS_WEATHER_FLG to 'Y', and the matching premium is increased by 15% before the insert.

Claim commission penalty. UPDATE_BROKER_COMM counts the policy’s claims where YEAR(CLAIMDATE) = YEAR(CURRENT DATE). If the count is greater than 3, it executes:

SQL 
UPDATE POLICY SET COMMISSION = (COMMISSION / 2)
 WHERE POLICYNUMBER = :DB2_C_Policynum_INT

For claims, CA_POLICY_NUM is an input and must reference an existing policy.

5.8 Hand-off to VSAM

After the DB2 work, LGAPDB01 links to LGAPVS01 and then returns:

PLI 
EXEC CICS LINK PROGRAM('LGAPVS01') COMMAREA(COMM_AREA) LENGTH(32500)
EXEC CICS RETURN

6. VSAM Write: LGAPVS01

6.1 Purpose and Record Layout

LGAPVS01 writes one 64-byte record to the KSDS KSDSPOLY. The record consists of a 21-byte composite key and a 43-byte policy data area.

graph LR subgraph WF_POLICY_INFO [WF_POLICY_INFO - 64 bytes] subgraph KEY [WF_POLICY_KEY - 21 bytes] K1[WF_REQUEST_ID
1 byte] K2[WF_CUSTOMER_NUM
10 bytes] K3[WF_POLICY_NUM
10 bytes] end subgraph DATA [WF_POLICY_DATA - 43 bytes union] D1[C: postcode, status, customer] D2[E: flags, fund name, life assured] D3[H: type, bedrooms, value, postcode, name] D4[M: make, model, value, reg number] end end

6.2 Processing Steps

  1. Store EIBCALEN. Set WF_Request_ID from the 4th character of CA_REQUEST_ID, and copy the customer and policy numbers into the key.
  2. SELECT (WF_REQUEST_ID) copies the matching fields:
    • 'C' copies CA_B_Postcode, CA_B_Status and CA_B_Customer.
    • 'E' copies the three flags, the fund name and the life assured.
    • 'H' copies the property type, bedrooms, value, postcode and house name.
    • 'M' copies the make, model, value and registration number.
    • OTHERWISE blanks WF_Policy_Text. Unknown types are not rejected, and the write still proceeds.
  3. Reassign WF_Policy_Num from CA_POLICY_NUM, so the key holds the DB2-generated number.
  4. Write the record:
PLI 
EXEC CICS WRITE FILE('KSDSPOLY')
     FROM(WF_POLICY_INFO)
     LENGTH(64)
     RIDFLD(WF_POLICY_KEY)
     KEYLENGTH(21)
     RESP(WS_RESP);
  1. If WS_RESP is not DFHRESP(NORMAL), capture EIBRESP2 in WS_RESP2 and set CA_RETURN_CODE = '80'. Then call WRITE_ERROR_MESSAGE and issue EXEC CICS RETURN.

6.3 VSAM Flow

flowchart TD A([Start]) --> B[Build key from COMMAREA] B --> C{Type = C, E, H or M?} C -- Yes --> D[Copy type-specific data] C -- No --> E[Blank policy text] D --> F[Refresh policy number] E --> F F --> G[WRITE FILE KSDSPOLY] G --> H{RESP normal?} H -- Yes --> I([Return]) H -- No --> J[RC = 80
Log via LGSTSQ] J --> I

Some fields are truncated when moved into the working record. CA_E_LIFE_ASSURED (31 characters) goes into a 30-character field, and CA_B_Customer (255 characters) goes into a 31-character field.

7. Communication Area Contract

7.1 Key Fields

Field Description
CA_REQUEST_ID 6-character operation code. It selects the policy type.
CA_RETURN_CODE 2-digit outcome code.
CA_CUSTOMER_NUM 10-digit customer.
CA_POLICY_NUM 10-digit policy number. It is returned from the DB2 identity for adds, and is an input for claims.
CA_ISSUE_DATE, CA_EXPIRY_DATE 10-character policy dates.
CA_BROKERID, CA_BROKERSREF Broker ID (10 digits) and reference (10 characters).
CA_PAYMENT 6-digit base premium.
CA_LASTCHANGED Timestamp, returned from DB2.
CA_ENDOWMENT, CA_HOUSE, CA_MOTOR, CA_COMMERCIAL, CA_CLAIM Type-specific unions.
COMM_AREA_RAW 32,500-byte raw overlay, used for error snapshots.

7.2 Return Codes

Code Set by Meaning
00 LGAPOL01, LGAPDB01 Success
70 LGAPDB01 Referential integrity violation (SQLCODE -530)
80 LGAPVS01 VSAM write failed
90 LGAPDB01 Other SQL error
98 LGAPOL01, LGAPDB01 COMMAREA too short
99 LGAPDB01 Unrecognised request ID

LGAPOL01 does not translate return codes. It passes LGAPDB01’s result (including 80 from LGAPVS01, set while LGAPDB01 is still running) back to the caller.

9. Error Handling

9.1 Strategy by Program

Program Condition Response
LGAPOL01 No COMMAREA Log, then abend LGCA (NODUMP)
LGAPOL01 COMMAREA too short RC = 98, return
LGAPDB01 Policy INSERT failure RC = 70 or 90, log, return (no abend, since nothing needs backout yet)
LGAPDB01 SQL failure after the POLICY insert, or in a supporting query RC = 90, log, abend LGSQ (NODUMP) to back out the unit of work
LGAPVS01 WRITE FILE RESP not NORMAL RC = 80, log RESP and RESP2, return

9.2 Diagnostic Logging

Each program has a WRITE_ERROR_MESSAGE routine that does the following:

  1. It issues ASKTIME and FORMATTIME to timestamp the message.
  2. It links to LGSTSQ with ERROR_MSG, which holds the program name, customer number, policy number, SQL request label and SQLCODE. In LGAPVS01, RESP and RESP2 replace the SQL fields.
  3. If EIBCALEN > 0, it links to LGSTSQ a second time with up to 90 bytes of the raw COMMAREA (CA_ERROR_MSG, prefixed COMMAREA=).
PLI 
EXEC CICS LINK PROGRAM('LGSTSQ')
     COMMAREA(ERROR_MSG) LENGTH(STG(ERROR_MSG));
IF EIBCALEN > 0 THEN DO;
   IF EIBCALEN < 91 THEN CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
   ELSE CA_DATA = LEFT(COMM_AREA_RAW, 90);
   EXEC CICS LINK PROGRAM('LGSTSQ')
        COMMAREA(CA_ERROR_MSG) LENGTH(STG(CA_ERROR_MSG));
END;

LGAPDB01 sets EM_SQLREQ to a label such as ' INSERT POLICY', ' INSERT ENDOW ' or 'BUNDLE DISCNT ' before each SQL statement. The failing operation can therefore be identified from the log.

10. Worked Examples

10.1 Motor Policy with Accident Loading

Input (abridged):

Field Value
CA_REQUEST_ID 01AMOT
CA_CUSTOMER_NUM 0000001234
CA_PAYMENT 001200
CA_M_PREMIUM 000800
CA_M_ACCIDENTS 000004
  • LGAPOL01 validates the COMMAREA, skips the business rules (not an Endowment request), and links to LGAPDB01.
  • LGAPDB01 inserts the POLICY row with POLICYTYPE = 'M'. With fewer than 3 active motor and house policies, the payment stays at 1200. Commission is taken from the broker’s active-policy tier.
  • With 4 accidents (the 3–5 band), the premium is 800 × 1.20 = 960. That value goes into MOTOR.
  • LGAPVS01 writes the record with key 'M' || customer || policy.
  • The result is CA_RETURN_CODE = '00' and a populated CA_POLICY_NUM.

10.2 House Policy with Surcharge and Bundling Discount

Input: 01AHOU, CA_PAYMENT = 2000, CA_H_VALUE = 12000000, CA_H_POSTCODE = 650000. The customer already has 3 active motor and house policies, and the broker has 5 active policies.

Step Result
Postcode and value loading (+20%) 2000 → 2400
Bundling discount (−15%) 2400 → 2040
Commission (5% tier) 2040 × 0.05 = 102

POLICY and HOUSE rows are written, followed by the VSAM record.

10.3 Endowment with Business Rules Disabled

For 01AEND, BUSINESS_RULES = 'N', so LGAPBR01 is not called. LGAPOL01 links straight to LGAPDB01, which inserts into POLICY and ENDOWMENT. The final CA_RETURN_CODE is '00'.

10.4 COMMAREA Too Short

A request such as 01AHOU with EIBCALEN below the required minimum returns CA_RETURN_CODE = '98'. No business-rules call, DB2 insert or VSAM write occurs.

10.5 Claim Triggering Commission Halving

Input: 01ACLM for existing policy 0000007891, which already has 3 claims this year.

  • INSERT_POLICY is skipped.
  • UPDATE_BROKER_COMM counts the claims, finds more than 3, and halves the policy’s commission.
  • The CLAIM row is inserted.

10.6 VSAM Write Failure

If KSDSPOLY already holds a record with the same key (a duplicate), the write returns a non-NORMAL RESP. LGAPVS01 sets CA_RETURN_CODE = '80' and logs the RESP and RESP2 codes plus a COMMAREA snapshot via LGSTSQ. LGAPOL01 then sees a non-zero return code and returns it to the caller.

11. Constraints and Operational Notes

  • COMMAREA size. All LINK calls pass the full 32,500-byte area. Error snapshots are capped at 90 bytes.
  • Sequencing. LGAPBR01 (when enabled) always runs before LGAPDB01. The POLICY insert always precedes the detail insert, because the detail table needs the generated policy number as its foreign key.
  • Unit of work. An LGSQ abend backs out the POLICY row when a later insert fails.
  • VSAM tolerance. LGAPVS01 does not reject unknown request types, and it has no EIBCALEN = 0 guard. It relies on being called from LGAPDB01 after validation.
  • Field limits. Numeric fields are fixed-width. Examples are CA_PAYMENT (6 digits, maximum 999,999), CA_H_VALUE (8 digits) and CA_E_TERM (2 digits).
  • VSAM link on failure. LGAPDB01 links to LGAPVS01 unconditionally on its normal path. Failures inside the detail inserts abend before that point.
