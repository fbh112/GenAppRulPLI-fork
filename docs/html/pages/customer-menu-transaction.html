Customer Maintenance Menu (SSC1)

1. Overview

LGTESTC1 is a CICS PL/I program that implements the interactive customer maintenance menu of the General Insurance (GenApp) application. It runs under CICS transaction SSC1 and presents the BMS map SSMAPC1 (mapset SSMAP) to terminal users.

The menu supports three customer operations:

Option Operation Backend Program Request ID
1 Customer Inquiry LGICUS01 01ICUS
2 Customer Add LGACUS01 01ACUS
4 Customer Update LGUCUS01 01UCUS

The program does not access customer data directly. It collects screen input and passes it to the backend programs with EXEC CICS LINK, using a shared 32,500-byte communication area (COMM_AREA, defined by the LGCMAREA include).

After a successful add, the program updates the GENACNTL temporary storage (TS) queue, which tracks the highest assigned customer number. The update is protected by EXEC CICS ENQ and EXEC CICS DEQ on the resource GENACNTL.

Errors from the backend programs are shown in the on-screen error field ERRFLDO. PF3 ends the transaction and CLEAR redisplays a blank menu.

Key characteristics:

  • Pseudo-conversational design: Each interaction ends with EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA).
  • Data cleansing: Null bytes are translated to spaces and the postcode is uppercased before add and update.
  • Centralised error handling: NO_DATA, NO_ADD and NO_UPD all converge on ERROR_OUT, which displays the message and resets state.
  • Serialised control queue: WRITE_GENACNTL guards the GENACNTL queue with ENQ/DEQ.

2. System Architecture

2.1 Component Overview

The architecture has four layers. The terminal and BMS map form the presentation layer. LGTESTC1 is the control layer. The backend programs are the data-access layer. The GENACNTL TS queue and the ENQ resource are the control state.

graph TD U[Terminal User] -->|Transaction SSC1| P[LGTESTC1 PL/I Program] P <-->|SEND MAP / RECEIVE MAP| M[BMS Map SSMAPC1 - Mapset SSMAP] P -->|LINK 01ICUS| I[LGICUS01 Inquiry] P -->|LINK 01ACUS| A[LGACUS01 Add] P -->|LINK 01UCUS| UP[LGUCUS01 Update] P <-->|COMMAREA 32500 bytes| C[COMM_AREA - LGCMAREA] P -->|WRITE_GENACNTL| W[Internal Procedure] W -->|ENQ / DEQ| E[Resource GENACNTL] W -->|READQ / WRITEQ TS| Q[(TS Queue GENACNTL)]

2.2 Components and Responsibilities

Component Type Responsibility
SSC1 CICS transaction Owning transaction ID, re-initiated on each pseudo-conversational return
LGTESTC1 PL/I program Menu control, option dispatch, data mapping, error display
SSMAP / SSMAPC1 BMS mapset / map Customer screen; symbolic structures SSMAPC1I and SSMAPC1O
LGCMAREA Include Defines the COMM_AREA UNION (32,500 bytes)
LGICUS01 Backend program Retrieves a customer by number
LGACUS01 Backend program Inserts a new customer and returns the assigned number
LGUCUS01 Backend program Updates customer details
GENACNTL TS queue and ENQ resource Holds LOW CUSTOMER= and HIGH CUSTOMER= control records

The %INCLUDE SSMAP expansion also declares the maps SSMAPP1 to SSMAPP5. They are not used in this program’s logic. A call to an initialisation program, ADDIPGM1, is commented out in the source.

2.3 COMMAREA Structure

COMM_AREA is a UNION, so the same 32,500 bytes can be addressed in different ways.

graph TD CA[COMM_AREA - 32500 bytes] --> RAW[COMM_AREA_RAW CHAR 32500] CA --> HDR[Header Fields] CA --> REQ[Request-specific area] HDR --> RID[CA_REQUEST_ID CHAR 6] HDR --> RC[CA_RETURN_CODE PIC 99] HDR --> CN[CA_CUSTOMER_NUM PIC 9999999999] REQ --> INIT[CA_REQUEST_INITIALISER CHAR 32482] REQ --> CR[CA_CUSTOMER_REQUEST fields] CR --> F1[CA_FIRST_NAME / CA_LAST_NAME / CA_DOB] CR --> F2[CA_HOUSE_NAME / CA_HOUSE_NUM / CA_POSTCODE] CR --> F3[CA_PHONE_HOME / CA_PHONE_MOBILE / CA_EMAIL_ADDRESS]

3. Inputs

3.1 BMS Screen Input

The program receives data with the following call:

PLI 
EXEC CICS RECEIVE MAP('SSMAPC1')
                  INTO(SSMAPC1I)
                  ASIS TERMINAL
                  MAPSET('SSMAP');
Field Length Use
ENT1OPTO 1 Menu option; drives the SELECT dispatch
ENT1CNOO 10 Customer number for inquiry and the update pre-fetch
ENT1CNOI 10 Customer number re-read in the update path after the second RECEIVE MAP
ENT1FNAI 10 First name
ENT1LNAI 20 Last name
ENT1DOBI 10 Date of birth
ENT1HNMI 20 House name
ENT1HNOI 4 House number
ENT1HPCI 8 Postcode
ENT1HP1I 20 Home phone
ENT1HP2I 20 Mobile phone
ENT1HMOI 27 Email address

3.2 COMMAREA and Entry Parameters

  • DFHEIPTR is the first procedure parameter. It gives the CICS preprocessor addressability to the EIB.
  • COMM_AREA_PTR is the second parameter and points to the COMMAREA.
  • When EIBCALEN = 0 (first invocation), the program points COMM_AREA_PTR at the local BASE_COMM_AREA.
  • On later invocations, the pointer addresses the COMMAREA returned by EXEC CICS RETURN.

3.3 TS Queue Input

WRITE_GENACNTL reads the GENACNTL queue into READ_MSG (CHAR(80)). It tests the first 13 characters of each item for 'HIGH CUSTOMER'.

4. Processing Logic

4.1 Overall Control Flow

flowchart TD START([Transaction SSC1 starts]) --> CHK{EIBCALEN = 0?} CHK -->|Yes| INIT[Initialise maps and COMMAREA, ENT1CNOO = 0000000000, SEND MAP ERASE] CHK -->|No| AGAIN INIT --> AGAIN[A_GAIN: HANDLE AID and MAPFAIL, RECEIVE MAP] AGAIN --> SEL{SELECT ENT1OPTO} SEL -->|1| INQ[Customer Inquiry] SEL -->|2| ADD[Customer Add] SEL -->|4| UPD[Customer Update] SEL -->|OTHERWISE| INV[Invalid option message] INQ --> RET[ENDIT_STARTIT: RETURN TRANSID SSC1] ADD --> RET UPD --> RET INV --> RET AGAIN -.PF3 / MAPFAIL.-> ENDIT[ENDIT: Transaction ended] AGAIN -.CLEAR.-> CLR[CLEARIT: MAPONLY] CLR --> RET

4.2 Program Entry and Initialisation

On the first invocation (EIBCALEN = 0):

  • COMM_AREA_PTR is set to ADDR(BASE_COMM_AREA).
  • SSMAPC1I and SSMAPC1O are cleared to spaces.
  • CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER are reset.
  • ENT1CNOO is preset to '0000000000'.
  • The map is sent with ERASE.

On later invocations, this block is skipped and control goes directly to A_GAIN.

4.3 Screen Input and AID Handling

Before the map is received, three handlers are registered:

PLI 
EXEC CICS HANDLE AID CLEAR(CLEARIT);
EXEC CICS HANDLE AID PF3(ENDIT);
EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);
  • CLEAR goes to CLEARIT.
  • PF3 goes to ENDIT.
  • MAPFAIL goes to ENDIT.

4.4 Option Dispatch

The value of ENT1OPTO drives a PL/I SELECT statement.

  • '1' runs the inquiry.
  • '2' runs the add.
  • '4' runs the update.
  • OTHERWISE runs the invalid option handling.

4.5 Option 1 — Customer Inquiry

The program sets CA_REQUEST_ID to '01ICUS' and loads CA_CUSTOMER_NUM from ENT1CNOO. It then links to LGICUS01 with the full 32,500-byte COMMAREA.

  • If CA_RETURN_CODE > 0, control goes to NO_DATA.
  • On success, the returned fields are copied to the screen structure and the map is sent.
  • Control then goes to ENDIT_STARTIT.
sequenceDiagram participant User participant LGTESTC1 participant LGICUS01 User->>LGTESTC1: Option 1 + customer number LGTESTC1->>LGTESTC1: CA_REQUEST_ID = 01ICUS LGTESTC1->>LGICUS01: LINK COMMAREA(32500) LGICUS01-->>LGTESTC1: Customer data + CA_RETURN_CODE alt CA_RETURN_CODE = 0 LGTESTC1-->>User: SEND MAP with customer details else CA_RETURN_CODE > 0 LGTESTC1-->>User: No data was returned. end LGTESTC1->>LGTESTC1: RETURN TRANSID SSC1

The field mapping from COMMAREA to screen is:

COMMAREA Screen
CA_FIRST_NAME ENT1FNAI
CA_LAST_NAME ENT1LNAI
CA_DOB ENT1DOBI
CA_HOUSE_NAME ENT1HNMI
CA_HOUSE_NUM ENT1HNOI
CA_POSTCODE ENT1HPCI
CA_PHONE_HOME ENT1HP1I
CA_PHONE_MOBILE ENT1HP2I
CA_EMAIL_ADDRESS ENT1HMOI

4.6 Option 2 — Customer Add

The program sets CA_REQUEST_ID to '01ACUS' and CA_CUSTOMER_NUM to 0. It copies all screen fields into the COMMAREA, then cleanses the data before linking:

PLI 
COMM_AREA_RAW = TRANSLATE(COMM_AREA_RAW,' ','00'X);
CA_POSTCODE   = UPPERCASE(CA_POSTCODE);

It then links to LGACUS01.

  • Failure (CA_RETURN_CODE > 0): EXEC CICS SYNCPOINT ROLLBACK is issued and control goes to NO_ADD.
  • Success:
    • WRITE_GENACNTL is called.
    • The new CA_CUSTOMER_NUM is copied to ENT1CNOI.
    • ENT1OPTI is cleared.
    • ERRFLDO is set to 'New Customer Inserted'.
    • The map is sent.
sequenceDiagram participant User participant LGTESTC1 participant LGACUS01 participant TSQ as GENACNTL TS Queue User->>LGTESTC1: Option 2 + customer details LGTESTC1->>LGTESTC1: Copy fields, TRANSLATE nulls, UPPERCASE postcode LGTESTC1->>LGACUS01: LINK (01ACUS) LGACUS01-->>LGTESTC1: CA_CUSTOMER_NUM + CA_RETURN_CODE alt CA_RETURN_CODE > 0 LGTESTC1->>LGTESTC1: SYNCPOINT ROLLBACK LGTESTC1-->>User: Error Adding Customer else Success LGTESTC1->>TSQ: WRITE_GENACNTL (ENQ, update, DEQ) LGTESTC1-->>User: New Customer Inserted end

4.7 Option 4 — Customer Update (Two-Phase)

Phase 1: fetch and display

  • CA_REQUEST_ID is set to '01ICUS' and the customer number is loaded from ENT1CNOO.
  • LGICUS01 is linked.
  • If CA_RETURN_CODE > 0, control goes to NO_DATA.
  • Otherwise the current data is mapped to the screen and sent.

Phase 2: receive edits and update

  • A second EXEC CICS RECEIVE MAP is issued in the same task. There is no pseudo-conversational break between the display and the re-read.
  • CA_REQUEST_ID is set to '01UCUS'.
  • CA_CUSTOMER_NUM is refreshed from ENT1CNOI.
  • All fields are copied to the COMMAREA, and the null translation and postcode uppercase steps are applied.
  • LGUCUS01 is linked.
  • If CA_RETURN_CODE > 0, control goes to NO_UPD.
  • On success, ERRFLDO is set to 'Customer details updated' and the map is sent.
sequenceDiagram participant User participant LGTESTC1 participant LGICUS01 participant LGUCUS01 User->>LGTESTC1: Option 4 + customer number LGTESTC1->>LGICUS01: LINK (01ICUS) LGICUS01-->>LGTESTC1: Current customer data LGTESTC1-->>User: SEND MAP (data for review) User->>LGTESTC1: RECEIVE MAP (edited data) LGTESTC1->>LGTESTC1: Copy, TRANSLATE, UPPERCASE LGTESTC1->>LGUCUS01: LINK (01UCUS) LGUCUS01-->>LGTESTC1: CA_RETURN_CODE LGTESTC1-->>User: Customer details updated

4.8 Invalid Option

For any other option value, OTHERWISE sets the following:

  • ERRFLDO = 'Please enter a valid option'
  • ENT1OPTL = -1, which positions the cursor on the option field

The map is sent with CURSOR, and control goes to ENDIT_STARTIT.

4.9 Error Handling Labels

graph TD ND[NO_DATA: No data was returned.] --> EO[ERROR_OUT] NA[NO_ADD: Error Adding Customer] --> EO NU[NO_UPD: Error Updating Customer] --> EO EO --> S1[SEND MAP with error text] S1 --> S2[Clear SSMAPC1I / SSMAPC1O] S2 --> S3[Reset COMM_AREA_RAW, request ID, return code, customer number, initialiser] S3 --> ES[ENDIT_STARTIT]

4.10 Terminal Session Control

Label Action
ENDIT_STARTIT EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA) keeps the pseudo-conversation alive
ENDIT Sends 'Transaction ended' with ERASE FREEKB, then does a plain EXEC CICS RETURN
CLEARIT Clears SSMAPC1I, sends the map with MAPONLY, then returns with TRANSID('SSC1')

4.11 WRITE_GENACNTL — TS Queue Maintenance

WRITE_GENACNTL is an internal procedure. It is called only after a successful add.

  1. Serialise: It issues EXEC CICS ENQ RESOURCE(STSQ_NAME), where STSQ_NAME is 'GENACNTL'.
  2. Initialise: It sets WS_FLAG_TSQH = 'Y' and WS_ITEM_COUNT = 1.
  3. Read item 1, then loop with READQ TS NEXT while WS_RESP = 0.
  4. Match: If the first 13 characters are 'HIGH CUSTOMER', it:
    • sets WRITE_MSG_HIGH to CA_CUSTOMER_NUM;
    • clears the flag;
    • rewrites the item with LENGTH(24);
    • forces WS_RESP = 99 to leave the loop.
  5. Create if missing: If the flag is still 'Y', it writes three new items with NOSUSPEND:
    • the header record (20 bytes);
    • the LOW CUSTOMER= record (23 bytes);
    • the HIGH CUSTOMER= record (24 bytes).
  6. Release: It issues EXEC CICS DEQ RESOURCE(STSQ_NAME).
flowchart TD A([WRITE_GENACNTL]) --> B[ENQ RESOURCE GENACNTL] B --> C[WS_FLAG_TSQH = Y, WS_ITEM_COUNT = 1] C --> D[READQ TS ITEM 1] D --> E{RESP = NORMAL?} E -->|Yes| F[Loop: READQ TS NEXT, increment WS_ITEM_COUNT] F --> G{First 13 chars = HIGH CUSTOMER?} G -->|Yes| H[Set WRITE_MSG_HIGH, clear flag, REWRITE ITEM, WS_RESP = 99] G -->|No| I{WS_RESP = 0?} I -->|Yes| F I -->|No| J H --> J{WS_FLAG_TSQH = Y?} E -->|No| J J -->|Yes| K[WRITEQ header, LOW, HIGH records] J -->|No| L K --> L[DEQ RESOURCE GENACNTL] L --> M([Return])

The queue contents after initialisation are:

Item Record Length
1 **** GENAPP CNTL (WRITE_MSG_E) 20
2 LOW CUSTOMER= + number (WRITE_MSG_L) 23
3 HIGH CUSTOMER= + number (WRITE_MSG_H) 24

PLI 
EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA);

This statement runs at ENDIT_STARTIT and CLEARIT. It passes the request ID, return code, customer number and customer detail fields to the next task.

5.3 LINK Outputs

5.4 Side Effects

  • TS queue: WRITEQ TS QUEUE('GENACNTL') updates the control records.
  • ENQ/DEQ: The enqueue on GENACNTL can block other tasks that request the same resource.

7. Constraints

7.1 Input and Option Constraints

  • Only options '1', '2' and '4' are accepted. Anything else, including '3', '5'–'9' and non-numeric characters, goes to the OTHERWISE branch.
  • CA_CUSTOMER_NUM is PIC '9999999999'. The program does no numeric validation of ENT1CNOO before passing it to the backend.
  • On add, the customer number is forced to 0. The backend assigns the number.

7.2 COMMAREA Constraints

  • Each LINK uses a fixed LENGTH(32500), which matches COMM_AREA_RAW.
  • EIBCALEN = 0 is tested at entry so the program never runs against an uninitialised COMMAREA.

7.3 Data Cleansing Constraints

  • TRANSLATE(COMM_AREA_RAW,' ','00'X) is applied to add and update only. It is not applied to inquiry.
  • UPPERCASE(CA_POSTCODE) is applied to add and update only.

7.4 Backend and Sequencing Constraints

  • Every LINK is followed by a CA_RETURN_CODE > 0 check (PIC '99').
  • Only the add path issues a SYNCPOINT ROLLBACK.
  • An update always starts with an inquiry. A customer that cannot be found cannot be updated.
  • WRITE_GENACNTL runs only after a confirmed successful add.

7.5 TS Queue Constraints

  • The record lengths are fixed at 20, 23 and 24 bytes.
  • The HIGH CUSTOMER record is found by exact match on the first 13 characters.
  • New items are written with NOSUSPEND.
  • All queue access is wrapped in ENQ/DEQ.

7.6 Field Width Constraints

Screen field COMMAREA field Width
ENT1FNAI CA_FIRST_NAME 10
ENT1LNAI CA_LAST_NAME 20
ENT1DOBI CA_DOB 10
ENT1HNMI CA_HOUSE_NAME 20

ENT1HP1I CA_PHONE_HOME 20

Email addresses are limited to the 27 characters the map can carry.

8. Error Handling

Condition Detection Response
Inquiry fails (option 1 or the option 4 pre-fetch) CA_RETURN_CODE > 0 after LGICUS01 GO TO NO_DATA
Add fails CA_RETURN_CODE > 0 after LGACUS01 SYNCPOINT ROLLBACK, then NO_ADD
Update fails CA_RETURN_CODE > 0 after LGUCUS01 NO_UPD
Invalid option OTHERWISE branch Message, cursor on option field
No COMMAREA EIBCALEN = 0 Initialise and display the menu
PF3 HANDLE AID PF3(ENDIT) End the transaction
CLEAR HANDLE AID CLEAR(CLEARIT) Blank map, stay in SSC1
MAPFAIL HANDLE CONDITION MAPFAIL(ENDIT) End the transaction
TS read not normal WS_RESP check Fall back to creating the control records

Notes:

  • ERROR_OUT shows the message, then clears both map structures, COMM_AREA_RAW, CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER. It then returns via ENDIT_STARTIT. The next invocation therefore starts with a clean COMMAREA.
  • The update path has no explicit rollback in this program.

9. Examples

9.1 Inquiry (Option 1)

Input Value
ENT1OPTO 1
ENT1CNOO 0000000042
PLI 
CA_REQUEST_ID   = '01ICUS';
CA_CUSTOMER_NUM = ENT1CNOO;
EXEC CICS LINK PROGRAM('LGICUS01') COMMAREA(COMM_AREA) LENGTH(32500);

The screen is refreshed with the customer’s name, date of birth, address, phones and email. If LGICUS01 returns a non-zero code, the message No data was returned. is shown.

9.2 Add (Option 2)

Field Value
ENT1OPTO 2
ENT1FNAI Jane
ENT1LNAI Doe
ENT1DOBI 1995-03-22
ENT1HNMI Rose Cottage
ENT1HNOI 10
ENT1HPCI ec1a 1bb
ENT1HP1I 01234567890
ENT1HP2I 07911123456
ENT1HMOI jane.doe@example.com

The postcode is uppercased to EC1A 1BB. After a successful link to LGACUS01, WRITE_GENACNTL updates the queue. The screen shows the new customer number (for example 0000000099) and New Customer Inserted. On failure, the program rolls back and shows Error Adding Customer.

9.3 Update (Option 4)

Input Value
ENT1OPTO 4
ENT1CNOO 0000000099
  1. LGICUS01 is linked and the current data is displayed.
  2. The user edits the data, and a second RECEIVE MAP reads it.
  3. CA_REQUEST_ID is set to '01UCUS', then null translation and postcode uppercasing are applied.
  4. LGUCUS01 is linked, and the screen shows Customer details updated.

If the inquiry fails, the screen shows No data was returned.. If the update fails, it shows Error Updating Customer.

9.4 Invalid Option

Input Value
ENT1OPTO 9
PLI 
ERRFLDO  = 'Please enter a valid option';
ENT1OPTL = -1;

The screen shows Please enter a valid option, and the cursor is placed on the option field.

9.5 GENACNTL Queue Contents After Initialisation

The first successful add on an empty queue, with customer number 0000000099, produces:

TEXT 
Item 1: **** GENAPP CNTL    
Item 2: LOW CUSTOMER=0000000099
Item 3: HIGH CUSTOMER=0000000099

Later adds rewrite only item 3 (the HIGH CUSTOMER= record) with the latest customer number.
