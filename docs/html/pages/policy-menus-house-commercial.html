Policy CICS Menus — House & Commercial

1. Overview

This page documents two interactive BMS terminal programs in the General Insurance application. Both are PL/I programs and use the CICS pseudo-conversational pattern.

Program Transaction Map Mapset Business Area
LGTESTP3 SSP3 SSMAPP3 SSMAP House insurance policies
LGTESTP4 SSP4 SSMAPP4 SSMAP Commercial property insurance policies

Each program shows a single-screen menu. The operator types a one-character option, and the program routes the request to a back-end policy service with EXEC CICS LINK. The programs do no SQL or file I/O of their own. They build a shared 32,500-byte COMMAREA, set a six-character CA_REQUEST_ID, link to a back-end program, and check CA_RETURN_CODE.

Supported operations

Option House (LGTESTP3) Commercial (LGTESTP4)
1 Inquire (LGIPOL01) Inquire (LGIPOL01), with four search strategies
2 Add (LGAPOL01) Add (LGAPOL01)
3 Delete (LGDPOL01) Delete (LGDPOL01)
4 Update (LGIPOL01 then LGUPOL01) Not supported

Common behaviour

  • First entry: when EIBCALEN = 0, the program initialises the COMMAREA and the map, then sends a blank screen.
  • Keys: PF3 ends the transaction and CLEAR resets the screen.
  • Empty receive: a MAPFAIL condition ends the transaction.
  • Failed writes: a failed add, delete or update ends in SYNCPOINT ROLLBACK, an on-screen message and a reset of the COMMAREA.

2. System Architecture

2.1 Component Overview

Each menu program sits between the terminal and the back-end policy services. The BMS mapset SSMAP and the shared COMMAREA layout LGCMAREA are included at compile time through %INCLUDE.

The diagram shows the following:

  • Both menus share the same mapset, the same COMMAREA layout and the same inquire, add and delete back-end programs.
  • Only the house menu uses LGUPOL01.
  • All data store access goes through the back-end programs.

Component Role

2.3 Pseudo-Conversational Lifecycle

Neither program holds CICS resources while the operator is thinking. After each screen interaction the task ends with EXEC CICS RETURN TRANSID(...) COMMAREA(COMM_AREA). CICS restarts the same transaction on the next AID key and passes the COMMAREA back in.

stateDiagram-v2 [*] --> FirstEntry: EIBCALEN = 0 FirstEntry --> WaitInput: Init COMMAREA, SEND MAP ERASE, RETURN TRANSID WaitInput --> Dispatch: Enter pressed, RECEIVE MAP Dispatch --> WaitInput: Success or error, SEND MAP, RETURN TRANSID WaitInput --> Cleared: CLEAR pressed Cleared --> WaitInput: SEND MAP MAPONLY, RETURN TRANSID WaitInput --> Ended: PF3 or MAPFAIL Ended --> [*]: SEND TEXT Transaction ended, RETURN

3. Shared Design Elements

3.1 Communication Area (COMMAREA)

Both programs declare COMM_AREA from LGCMAREA. It is 32,500 bytes long, and every EXEC CICS LINK passes LENGTH(32500).

Field Type Purpose
CA_REQUEST_ID CHAR(6) Operation code that tells the back-end program what to do
CA_RETURN_CODE PIC '99' Result set by the back end. Zero is success, and greater than zero is failure
CA_CUSTOMER_NUM PIC '9999999999' Customer identifier
CA_POLICY_NUM PIC '9999999999' Policy identifier. Returned by the add service
CA_ISSUE_DATE / CA_EXPIRY_DATE CHAR(10) Policy dates
CA_REQUEST_INITIALISER CHAR(32482) Overlay used to blank the request-specific area

The request-specific area is a union. The house menu uses the CA_HOUSE member and the commercial menu uses CA_COMMERCIAL.

3.2 Request ID Catalogue

Request ID Program Operation Back end
01IHOU LGTESTP3 Inquire house policy (also the update pre-fetch) LGIPOL01
01AHOU LGTESTP3 Add house policy LGAPOL01
01DHOU LGTESTP3 Delete house policy LGDPOL01
01UHOU LGTESTP3 Update house policy LGUPOL01
01ICOM LGTESTP4 Inquire by customer and policy LGIPOL01
02ICOM LGTESTP4 Inquire by policy only LGIPOL01
03ICOM LGTESTP4 Inquire by customer only LGIPOL01
05ICOM LGTESTP4 Inquire by postcode LGIPOL01
01ACOM LGTESTP4 Add commercial policy LGAPOL01
01DCOM LGTESTP4 Delete commercial policy LGDPOL01

3.3 Common Program Skeleton

Both programs follow the same skeleton: a first-entry guard, A_GAIN, a SELECT on the option field, and a set of terminal labels.

Label Purpose
A_GAIN Registers AID and condition handlers, receives the map and dispatches on the option
ENDIT_STARTIT RETURN TRANSID('SSPx') COMMAREA(COMM_AREA), the normal pseudo-conversational exit
ENDIT Sends Transaction ended with ERASE FREEKB, then does a plain RETURN
CLEARIT Blanks SSMAPPxI, sends the map with MAPONLY, then returns with the transaction ID
NO_ADD Return code 70 gives Customer does not exist. Any other code gives the generic add error
NO_DELETE Sets the delete error message
NO_UPD Sets the update error message (house only)
NO_DATA Sets No data was returned.
ERROR_OUT Sends the map with the error message, resets state, then goes to ENDIT_STARTIT

The handler setup common to both programs looks like this:

CODE 
EXEC CICS HANDLE AID CLEAR(CLEARIT) PF3(ENDIT)
EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT)
EXEC CICS RECEIVE MAP('SSMAPP3') INTO(SSMAPP3I) MAPSET('SSMAP')

(LGTESTP4 uses SSMAPP4 and SSMAPP4I.)

4.3 Option Details

Option Request ID Success message Failure label
1 Inquire 01IHOU None; the policy fields are shown NO_DATA
2 Add 01AHOU New House Policy Inserted NO_ADD (after rollback)
3 Delete 01DHOU House Policy Deleted NO_DELETE (after rollback)
4 Update 01IHOU, then 01UHOU House Policy Updated NO_DATA or NO_UPD

Inquire and delete read the keys from the output map fields ENP3CNOO and ENP3PNOO. Add takes the customer number and policy details from the input fields (ENP3*I). It also zeroes CA_PAYMENT and CA_BROKERID and blanks CA_BROKERSREF, so the operator cannot supply payment or broker data.

4.4 Update Sequence (Two-Phase)

Option 4 does an inquire, lets the operator edit, then updates. The pre-fetch and the update happen in one task, with a second RECEIVE MAP between them.

sequenceDiagram participant U as Operator participant P as LGTESTP3 participant I as LGIPOL01 participant X as LGUPOL01 U->>P: Option 4 + customer + policy P->>I: LINK CA_REQUEST_ID=01IHOU I-->>P: House data, RC=0 P-->>U: SEND MAP with current values U->>P: RECEIVE MAP with edits P->>X: LINK CA_REQUEST_ID=01UHOU X-->>P: RC alt RC = 0 P-->>U: House Policy Updated else RC > 0 P-->>U: Error Updating House Policy via ERROR_OUT end P->>P: RETURN TRANSID SSP3

Unlike add and delete, a failed update does not issue SYNCPOINT ROLLBACK. The inquire phase is read-only, so it needs none.

4.5 Code Examples

Inquire request set-up and link:

CODE 
CA_REQUEST_ID  = '01IHOU';
CA_CUSTOMER_NUM = ENP3CNOO;
CA_POLICY_NUM   = ENP3PNOO;
EXEC CICS LINK PROGRAM('LGIPOL01') COMMAREA(COMM_AREA) LENGTH(32500);
IF CA_RETURN_CODE > 0 THEN GO TO NO_DATA;

Add failure handling, with NO_ADD choosing the message:

CODE 
IF CA_RETURN_CODE > 0 THEN DO;
   EXEC CICS SYNCPOINT ROLLBACK;
   GO TO NO_ADD;
END;

NO_ADD:
   SELECT (CA_RETURN_CODE);
      WHEN (70)  ERP3FLDO = 'Customer does not exist';
      OTHERWISE  ERP3FLDO = 'Error Adding House Policy';
   END;
   GO TO ERROR_OUT;

Invalid option handling:

CODE 
OTHERWISE DO;
   ERP3FLDO = 'Please enter a valid option';
   ENP3OPTL = -1;
   EXEC CICS SEND MAP('SSMAPP3') FROM(SSMAPP3O) MAPSET('SSMAP') CURSOR;
   GO TO ENDIT_STARTIT;
END;

The screen fields are shorter than the matching COMMAREA fields (25 versus 255 characters for address, customer, property type and reject reason). The operator can see and enter only the first 25 characters of each.

5.2 Inquiry Search Strategy

For option 1 the program selects CA_REQUEST_ID from the keys the operator supplied. A non-blank postcode overrides the other keys.

A key counts as “not provided” when it is spaces or '0000000000'. If no key and no postcode is given, no routing guard applies and the request ID keeps its earlier value. The back end decides how to respond.

6. Error Handling

6.1 Strategy

Both programs use the same error strategy:

  1. Validate the option. An unknown option gets a message, a cursor on the option field and no back-end call.
  2. Check CA_RETURN_CODE after every LINK. Any value greater than zero is a failure.
  3. Roll back writes. Add and delete failures issue EXEC CICS SYNCPOINT ROLLBACK before the error label. Inquiry failures do not. LGTESTP3 also does not roll back after an update failure.
  4. Send one message. Every failure ends at ERROR_OUT, which sends the map with the message in ERP3FLDO or ERP4FLDO.
  5. Reset state. ERROR_OUT blanks SSMAPPxI and COMM_AREA_RAW. It also resets CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER. This stops stale data from reaching the next cycle.
graph LR A[LINK returns] --> B{CA_RETURN_CODE > 0?} B -- No --> S[Success path] B -- Yes --> C{Write operation?} C -- Yes --> D[SYNCPOINT ROLLBACK] C -- No --> E D --> E[NO_ADD / NO_DELETE / NO_UPD / NO_DATA
set message] E --> F[ERROR_OUT
SEND MAP, reset COMMAREA] F --> G[ENDIT_STARTIT]

The diagram shows that rollback applies only to write operations. The update path in LGTESTP3 is an exception: NO_UPD is reached without a rollback.

6.2 Return Code Interpretation

Return code Context Meaning to the menu
0 Any Success
70 Add (house and commercial) Customer does not exist
Other > 0 Add Generic add error
Other > 0 Delete Generic delete error
Other > 0 Update (house) Generic update error
Any > 0 Inquire No data was returned.

6.3 Attention Keys and Conditions

Event Handler Result
PF3 ENDIT Transaction ended is sent with ERASE FREEKB, then a plain RETURN ends the task
CLEAR CLEARIT The input area is blanked and the map is sent with MAPONLY. The transaction restarts through RETURN TRANSID
MAPFAIL ENDIT The transaction ends cleanly

7. Constraints and Design Notes

7.1 Data Size and Format

  • The COMMAREA is fixed at 32,500 bytes on every LINK. A mismatch with a back-end program would cause a LENGERR condition.
  • CA_REQUEST_INITIALISER is 32,482 bytes (6 + 2 + 10 + 32,482 = 32,500).
  • ERP3FLDO and ERP4FLDO are 40 characters, so every message fits within that.
  • Dates are CHAR(10). The menus do not validate their format. The back-end programs do that.
  • Numeric COMMAREA fields are pictured as digits only, for example PIC '9999999999' for keys and PIC '99999999' for premiums.

7.2 Behavioural Constraints

Constraint LGTESTP3 LGTESTP4
Valid options 1, 2, 3, 4 1, 2, 3
Update supported Yes, via pre-fetch and a second RECEIVE MAP No
Inquiry search keys Customer and policy Customer and policy, policy, customer, or postcode
Delete key validation Back end Back end. No blank or zero gate in the menu
Broker and payment input Not user-supplied (zeroed) Not applicable
Reentrancy Not specified Compiled Options(Main, Reentrant)
Transaction ID Hard-coded SSP3 Hard-coded SSP4

7.3 Initialisation

  • On first entry the numeric screen fields are preset to zeros ('0000000000' for customer and policy numbers). In LGTESTP3, value and bedrooms are also preset to '00000000' and '000'.
  • The request-specific area CA_REQUEST_INITIALISER is blanked on first entry and after every error.

8. Worked Examples

8.1 House: Inquire (Option 1)

Input Value
Customer (ENP3CNOO) 0000000001
Policy (ENP3PNOO) 0000000042
Option 1

The program sets CA_REQUEST_ID = '01IHOU' and links to LGIPOL01. On CA_RETURN_CODE = 0, the screen shows the returned values: issue date, expiry date, property type, bedrooms, value, house name, house number and postcode.

8.2 House: Add for a Non-Existent Customer

Input Value
Customer (ENP3CNOI) 9999999999
Option 2
  1. LGAPOL01 returns CA_RETURN_CODE = 70.
  2. The program issues SYNCPOINT ROLLBACK.
  3. NO_ADD sets Customer does not exist.
  4. ERROR_OUT sends the map and resets the COMMAREA.

8.3 Commercial: Inquire by Customer and Policy

Input Value
Option 1
Customer (ENP4CNOO) 0000000042
Policy (ENP4PNOO) 0000000007
Postcode (ENP4HPCO) blank

Both keys are present, so CA_REQUEST_ID = '01ICOM'. LGIPOL01 is called, and on success all CA_B_* fields and dates are copied to the map and displayed.

8.4 Commercial: Add (Option 2)

Input Value
Option 2
Customer (ENP4CNOO) 0000000042
Issue and expiry dates 2024-06-01 and 2025-05-31
Address 5 Commerce Park
Postcode M1 1AE
Fire peril and premium 0001 and 00002000

8.5 Commercial: Delete with an Error

Input Value
Option 3
Customer 0000000099
Policy 0000000003

8.6 Invalid Option (Both Menus)

An option such as 9 falls to OTHERWISE. The message is Please enter a valid option, the cursor is placed on the option field with ENP3OPTL or ENP4OPTL set to -1, and no back-end program is called.
