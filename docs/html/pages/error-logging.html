Error Logging (LGSTSQ)

1. Overview

LGSTSQ is the shared error-message logging utility of the GenApp PL/I application. It is a small CICS PL/I program. It takes a text message of up to 90 bytes and writes it to two CICS destinations:

  • The Transient Data Queue CSMT. This is the standard CICS message log, used for operational visibility.
  • A Temporary Storage Queue. It defaults to GENAERRS. A caller can redirect it to GENAnnnn by starting the message with Q=nnnn.

Every record starts with the 4-character CICS SYSID, so each entry identifies the region that produced it.

The message can arrive in one of two ways:

  • By program link. Another GenApp program passes it in a COMMAREA. Nearly every CICS program in the application does this on error: the orchestrators, the DB2 backends and the VSAM backends.
  • From a terminal. An operator types it directly. The program then clears the screen after logging.

This page covers:

  • the LGSTSQ utility itself
  • the message conventions callers follow
  • the invocation modes
  • the queue-override mechanism
  • the length arithmetic
  • the behaviour of the program when something goes wrong

2. System Architecture

2.1 Position in the GenApp Architecture

GenApp has three tiers: BMS menus, orchestrators, and DB2/VSAM backends. LGSTSQ is a cross-cutting supporting service. Programs in the orchestration and backend tiers call it with EXEC CICS LINK whenever they need to record a diagnostic. It does not call any other program and does not touch DB2 or VSAM.

2.3 Internal Structure

The program is a single monolithic PL/I procedure with no internal subroutines or labelled paragraphs. It runs from top to bottom in six functional blocks.

and message trimming] C --> D[4. WRITEQ TD to CSMT] D --> E[5. WRITEQ TS to STSQ
NOSUSPEND] E --> F[6. Optional SEND TEXT
then RETURN]

3. Inputs and Invocation Modes

3.1 Inputs

Input Source Description
COMM_AREA_PTR Procedure parameter Pointer to the caller’s COMMAREA, based on the COMMA structure
COMMA_DATA COMMAREA 90-byte message text used for program-linked calls
EIBCALEN EIB Length of the supplied COMMAREA
WS_RECV / WS_RECV_DATA EXEC CICS RECEIVE Terminal input: 5-byte transaction ID followed by 74 bytes of data
WRITE_MSG_SYSID ASSIGN SYSID 4-character region identifier
WS_STARTCODE ASSIGN STARTCODE How the task was started
WS_PRINSYSID ASSIGN PRINSYSID System that owns the principal facility
WS_INVOKEPROG ASSIGN INVOKINGPROG Calling program name. A non-blank value means the program was linked to.

3.2 Invocation Modes

LGSTSQ tells how it was started from the INVOKINGPROG value. The two paths are mutually exclusive.

Aspect Called by program (WS_FLAG = 'C') From terminal (WS_FLAG = 'R')
Detection WS_INVOKEPROG non-blank WS_INVOKEPROG blank
Message source COMMA_DATA (COMMAREA) WS_RECV_DATA (after EXEC CICS RECEIVE)
Initial length WS_RECV_LEN = EIBCALEN Received length minus 5 (tranid)
Terminal response None SEND TEXT with ERASE and FREEKB

4.2 Sequence of Operations

The sequence below shows a program-linked call, the most common case.

sequenceDiagram participant Caller as Calling Program participant LOG as LGSTSQ participant CICS as CICS Services participant TD as TDQ CSMT participant TS as TSQ GENAERRS / GENAnnnn Caller->>LOG: EXEC CICS LINK PROGRAM(LGSTSQ) COMMAREA(msg) LOG->>CICS: ASSIGN SYSID / STARTCODE / PRINSYSID / INVOKINGPROG CICS-->>LOG: Region and invoker information LOG->>LOG: INVOKINGPROG not blank, so WS_FLAG = C LOG->>LOG: Check for Q=nnnn prefix and adjust length LOG->>TD: WRITEQ TD CSMT (SYSID + message) LOG->>TS: WRITEQ TS STSQ NOSUSPEND (SYSID + message) LOG->>CICS: EXEC CICS RETURN CICS-->>Caller: Control returned

The terminal-initiated variant adds a RECEIVE at the start and a SEND TEXT at the end:

sequenceDiagram participant Op as Terminal Operator participant LOG as LGSTSQ participant TD as TDQ CSMT participant TS as TSQ Op->>LOG: Transaction ID + message text LOG->>LOG: ASSIGN calls (INVOKINGPROG blank) LOG->>Op: EXEC CICS RECEIVE (tranid + data) LOG->>LOG: WS_FLAG = R, strip tranid, check Q= LOG->>TD: WRITEQ TD CSMT LOG->>TS: WRITEQ TS NOSUSPEND LOG->>Op: SEND TEXT (1 blank byte, ERASE, FREEKB) LOG->>LOG: EXEC CICS RETURN

4.3 Step-by-Step Description

  1. Initialization. WRITE_MSG and WS_RECV are set to blanks so no stale data reaches the log.
  2. Environment capture. Four ASSIGN commands run unconditionally. SYSID is stored directly in the record prefix.
  3. Invocation detection. The program branches on WS_INVOKEPROG, as described in section 3.2.
  4. Queue override check. The queue name defaults to GENAERRS. If the message begins with Q=, the next four characters replace the last four characters of the name, and the 7-byte prefix is removed from the message.
  5. Length adjustment. 5 bytes are added for the SYSID plus the blank separator.
  6. TDQ write. The record goes to CSMT.
  7. TSQ write. The same record goes to the selected TSQ with NOSUSPEND.
  8. Terminal response. This happens only for terminal invocations.
  9. Return. EXEC CICS RETURN always runs last.

5. Message Record Layout and Conventions

5.1 Log Record Structure

Every entry written to either queue has the same shape.

graph LR A[WRITE_MSG_SYSID
4 bytes] --> B[FILLER_X
1 blank byte] --> C[WRITE_MSG_MSG
up to 90 bytes]
Field Length Content
WRITE_MSG_SYSID 4 CICS region identifier from ASSIGN SYSID
FILLER_X 1 Blank separator
WRITE_MSG_MSG 90 Message text, with any Q=nnnn prefix removed

The structure is at most 95 bytes. The LENGTH given to the queue writes decides how many bytes are actually recorded.

5.2 Diagnostic Message Conventions

The other GenApp programs follow these conventions when they call LGSTSQ:

  • Single call point. Programs in every tier link to LGSTSQ with a COMMAREA holding the message text. No caller name is hardcoded in the logger.
  • 90-byte ceiling. Message text is truncated by PL/I character assignment if it is longer than 90 bytes.
  • Region stamp. The logger adds the SYSID, so callers do not need to include the region name.
  • Optional routing prefix. A caller can start the text with Q=nnnn to send the message to the TSQ GENAnnnn. The prefix is stripped before logging.
  • Dual visibility. Operators see the message on CSMT. Application support reads it from the TSQ.

5.3 Queue-Name Override (Q=nnnn)

The override changes only the TSQ destination. CSMT is always written.

Message text STSQ used Text logged
Policy not found... GENAERRS Policy not found...
Q=0042Policy limit exceeded... GENA0042 Policy limit exceeded...

The rules are:

  • The check is strict. Positions 1–2 must be exactly Q= in upper case. A lowercase q= or a leading space bypasses the override.
  • Positions 3–6 are taken verbatim and placed in positions 5–8 of STSQ. They are not validated.
  • The prefix occupies 7 bytes, so the message text starts at byte 8.

Relevant logic:

PLI 
STSQ = 'GENAERRS';
If SUBSTR(WRITE_MSG_MSG,1,2) = 'Q=' Then Do;
   SUBSTR(STSQ,5,4)  = SUBSTR(WRITE_MSG_MSG,3,4);
   TEMPO             = SUBSTR(WRITE_MSG_MSG,8,83);
   WRITE_MSG_MSG     = TEMPO;
   WS_RECV_LEN       = WS_RECV_LEN - 7;
End;
WS_RECV_LEN = WS_RECV_LEN + 5;

5.4 Length Arithmetic

WS_RECV_LEN is the number of bytes written to each queue. It is calculated as follows:

Step Called by program From terminal
Initial value EIBCALEN Length returned by RECEIVE
Strip tranid – − 5
Strip Q=nnnn prefix (if present) − 7 − 7
Add SYSID + blank + 5 + 5

6. CICS Commands Used

Command Purpose
EXEC CICS ASSIGN SYSID Obtain the region identifier used as the record prefix
EXEC CICS ASSIGN STARTCODE Record how the task was started
EXEC CICS ASSIGN PRINSYSID Identify the principal facility’s owning system
EXEC CICS ASSIGN INVOKINGPROG Decide between link and terminal invocation
EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN) Read terminal input (terminal path only)
EXEC CICS WRITEQ TD QUEUE(CSMT) Write to the system message log
EXEC CICS WRITEQ TS QUEUE(STSQ) NOSUSPEND Write to the application error queue without waiting
EXEC CICS SEND TEXT FROM(FILLER_X) TERMINAL WAIT ERASE LENGTH(1) FREEKB Clear the screen and unlock the keyboard (terminal path only)
EXEC CICS RETURN End the task

The terminal response is always one blank byte. No formatted output is sent.

7. Dependencies

7.1 Runtime Requirements

  • CICS region. Every operation uses the EXEC CICS interface.
  • Execute Interface Block. EIBCALEN supplies the COMMAREA length.
  • CSMT TDQ. It must be defined to the region.
  • A transaction definition for LGSTSQ. This is needed only for terminal use.
  • A 3270 or compatible terminal. It is needed only for terminal invocation.

7.2 Related Programs

Program Relationship
All orchestrators and backends (for example LGAPOL01, LGAPDB01, LGACVS01) Link to LGSTSQ to log errors
LGSETUP Deletes and recreates the GENAERRS TS queue during environment setup

LGSTSQ uses no DB2 tables and no VSAM files.

8. Constraints

8.1 Size and Length

  • COMMA_DATA, WRITE_MSG_MSG and TEMPO are all CHAR(90).
  • WS_RECV is 79 bytes: a 5-byte tranid and 74 bytes of data. Terminal messages therefore carry at most 74 usable characters.
  • WS_RECV_LEN starts at 80. It is not bounds-checked, so unusually short input could produce a negative or oversized length.

8.2 Ordering

  • The ASSIGN calls must run before the invocation branch.
  • The message must be populated before the override check and the queue writes.
  • The WRITEQ TD always precedes the WRITEQ TS. Both use the same buffer and length.
  • SEND TEXT follows both writes, and RETURN is always last.

8.3 Invocation

  • A caller must supply a COMMAREA. If INVOKINGPROG is non-blank and no COMMAREA is present, dereferencing COMM_AREA_PTR can cause an abend.
  • Link-invoked callers never receive a screen response.

9. Error Handling

LGSTSQ is itself the error logger. It is designed never to abend and never to block the calling transaction.

graph TD A[CICS command issued
with RESP WS_RESP] --> B{Command fails?} B -- No --> C[Continue] B -- Yes --> D[WS_RESP set
No abend, no check] D --> C C --> E[WRITEQ TS with NOSUSPEND:
storage unavailable means write skipped] E --> F[EXEC CICS RETURN always reached]
Mechanism Behaviour
RESP(WS_RESP) on every command Suppresses default CICS condition handling, so a failed command does not abend the task
WS_RESP never inspected Failures are silently absorbed and processing continues
NOSUSPEND on WRITEQ TS The write is dropped rather than waiting if temporary storage is unavailable, so TSQ logging is best-effort
No NOSUSPEND on WRITEQ TD Behaves normally, but its errors are also absorbed by RESP
Conditional SEND TEXT Terminal I/O is issued only when WS_FLAG = 'R'
Override fallback Without Q=, the default GENAERRS is used
No ABEND, no ON units, no retry There is no recursive error reporting

The practical consequence is that a caller’s transaction is never held up or abended by a logging problem. The cost is that a failed log write can go unnoticed.

10. Examples

10.1 Called by Another Program (No Override)

Input: invoker LGSICVP, SYSID GENL, EIBCALEN = 42, COMMAREA "Policy not found for customer 1234567890".

  • WS_FLAG = 'C'
  • The message does not start with Q=, so STSQ = 'GENAERRS'
  • WS_RECV_LEN = 42 + 5 = 47
  • Both queues are written, and there is no terminal send
CODE 
GENL Policy not found for customer 1234567890

10.2 Called by Another Program (With Q=nnnn Override)

Input: COMMAREA "Q=0042Policy limit exceeded for account 99", SYSID GENL, EIBCALEN = 43.

  • Q= is detected, so STSQ = 'GENA0042'
  • The text is trimmed to Policy limit exceeded for account 99
  • WS_RECV_LEN = 43 − 7 = 36, then 36 + 5 = 41
  • CSMT and GENA0042 are written
CODE 
GENL Policy limit exceeded for account 99

10.3 Invoked from a Terminal

Input: the operator types LGSQ Account 888 is invalid, and 30 bytes are received. SYSID is GENL.

  • INVOKINGPROG is blank, so WS_FLAG = 'R'
  • The message is taken from WS_RECV_DATA
  • WS_RECV_LEN = 30 − 5 = 25, then 25 + 5 = 30
  • CSMT and GENAERRS are written
  • SEND TEXT clears the screen
CODE 
GENL Account 888 is invalid

10.4 Summary of Outcomes

Scenario TSQ target Record length Terminal send
Link, no override GENAERRS EIBCALEN + 5 No
Link, Q=0042 GENA0042 EIBCALEN − 7 + 5 No
Terminal, no override GENAERRS received − 5 + 5 Yes
