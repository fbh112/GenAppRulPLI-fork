Customer Presentation & Business Orchestration

1. Overview

The Customer Presentation & Business Orchestration layer of the General Insurance (GenApp) application has two parts:

  • Presentation tier. LGTESTC1 runs under CICS transaction SSC1. It is an interactive BMS terminal menu (map SSMAPC1, mapset SSMAP) that lets an operator inquire about, add, and update customers.
  • Business orchestration tier. Three CICS PL/I programs are reached through EXEC CICS LINK and a shared 32,500-byte COMMAREA (LGCMAREA):
    • LGICUS01 handles inquiry.
    • LGACUS01 handles customer addition and lifecycle administration.
    • LGUCUS01 handles update.

The data-access work is delegated to further programs, such as LGICDB01, LGUCDB01, LGACDB02 and LGACVS01. Each orchestrator validates its input, decides where to route the request, and reports errors through the shared logging utility LGSTSQ.

Program Role Request ID Key downstream targets
LGTESTC1 BMS menu, transaction SSC1 Sets 01ICUS, 01ACUS, 01UCUS LGICUS01, LGACUS01, LGUCUS01, TS queue GENACNTL
LGICUS01 Customer inquiry orchestrator 01ICUS LGICDB01, or AAAAAAAA when MQHIT= is found in the GENAWMQC queue
LGACUS01 Customer onboarding and policy lifecycle Sets 01ICUS, 02OCUS, 02UCUS, 02DCUS by action code LGACVS01, LGACDB02, DB2 CUSTOMER and POLICY, CICS named counter
LGUCUS01 Customer update orchestrator 01UCUS LGUCDB01

2. System Architecture

2.1 Component Architecture

graph TD U[Terminal User] --> M[BMS Map SSMAPC1 / Mapset SSMAP] M --> T[LGTESTC1 - Transaction SSC1] T -->|LINK 01ICUS| I[LGICUS01 Inquiry Orchestrator] T -->|LINK 01ACUS| A[LGACUS01 Add / Lifecycle Orchestrator] T -->|LINK 01UCUS| UP[LGUCUS01 Update Orchestrator] T -->|ENQ / WRITEQ| TS[(TS Queue GENACNTL)] I -->|MQHIT absent| IDB[LGICDB01 DB2 Inquiry] I -->|MQHIT= found| ALT[AAAAAAAA Alternate MQ Path] I -->|read| MQC[(TS Queue GENAWMQC)] A --> CTR[CICS Named Counter GENACUSTNUM / GENA] A --> DB[(DB2 CUSTOMER / POLICY)] A -->|LINK| VS[LGACVS01 VSAM Add] A -->|LINK| SEC[LGACDB02 Customer Security] UP -->|LINK| UDB[LGUCDB01 DB2 Update] I -.errors.-> LOG[LGSTSQ Error Logger] A -.errors.-> LOG UP -.errors.-> LOG LOG --> TDQ[(Transient Data Queue)]

The presentation tier holds no business rules beyond input shaping. It sets the request ID, copies screen fields into the COMMAREA, and interprets CA_RETURN_CODE. The orchestrators own validation and routing.

2.2 Layer Responsibilities

Layer Component Responsibilities
Presentation LGTESTC1 Screen send and receive, option dispatch, data cleansing, pseudo-conversational control, GENACNTL high-water mark
Orchestration LGICUS01, LGACUS01, LGUCUS01 COMMAREA validation, request-ID checks, routing, return-code mapping, error logging
Data access LGICDB01, LGUCDB01, LGACDB02, LGACVS01 DB2 and VSAM operations, security record creation
Cross-cutting LGSTSQ Writes the formatted error message and a COMMAREA snapshot to a TDQ

2.3 Shared COMMAREA Contract

Every program shares the COMM_AREA UNION (32,500 bytes) from LGCMAREA. Its main fields are:

Field Type Meaning
CA_REQUEST_ID CHAR(6) Operation selector
CA_RETURN_CODE PIC ‘99’ Outcome: 00 success, 70, 90, 98, 99 errors
CA_CUSTOMER_NUM PIC ‘9999999999’ Customer key
CA_FIRST_NAME / CA_LAST_NAME CHAR(10) / CHAR(20) Customer name
CA_DOB CHAR(10) Date of birth
CA_HOUSE_NAME / CA_HOUSE_NUM / CA_POSTCODE CHAR(20) / CHAR(4) / CHAR(8) Address
CA_PHONE_HOME / CA_PHONE_MOBILE CHAR(20) Phone numbers
CA_EMAIL_ADDRESS CHAR(100) Email address
COMM_AREA_RAW CHAR(32500) Byte-level overlay of the whole area

3. Interactive Menu: LGTESTC1 (Transaction SSC1)

3.1 Pseudo-Conversational Control Flow

On the first invocation EIBCALEN = 0. The program points COMM_AREA_PTR at a local base area, clears both map structures, presets ENT1CNOO to '0000000000', and sends the map with ERASE. Every later invocation goes straight to A_GAIN, where AID handlers are registered and the map is received.

PL1 
EXEC CICS HANDLE AID CLEAR(CLEARIT);
EXEC CICS HANDLE AID PF3(ENDIT);
EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);
EXEC CICS RECEIVE MAP('SSMAPC1') INTO(SSMAPC1I) ASIS TERMINAL MAPSET('SSMAP');
graph TD S[SSC1 started] --> C{EIBCALEN = 0?} C -->|Yes| INIT[Init COMMAREA and maps, SEND MAP ERASE] C -->|No| AG[A_GAIN] INIT --> AG AG --> RCV[HANDLE AID/CONDITION, RECEIVE MAP] RCV --> SEL{SELECT ENT1OPTO} SEL -->|1| OP1[Inquiry] SEL -->|2| OP2[Add] SEL -->|4| OP4[Update] SEL -->|OTHERWISE| INV[Invalid option message] OP1 --> RET[ENDIT_STARTIT: RETURN TRANSID SSC1] OP2 --> RET OP4 --> RET INV --> RET RCV -->|PF3 / MAPFAIL| END[ENDIT: Transaction ended] RCV -->|CLEAR| CLR[CLEARIT: SEND MAPONLY, RETURN TRANSID SSC1]

3.2 Menu Options

Option Operation Request ID Backend
1 Customer inquiry 01ICUS LGICUS01
2 Customer add 01ACUS LGACUS01
4 Customer update (two-phase) 01ICUS, then 01UCUS LGICUS01, then LGUCUS01
Other Rejected with “Please enter a valid option” none none

3.3 Option 1: Customer Inquiry

The program loads CA_CUSTOMER_NUM from the screen and links to LGICUS01. A non-zero return code goes to NO_DATA. Otherwise the returned fields are mapped back to the screen and the map is sent.

PL1 
CA_REQUEST_ID   = '01ICUS';
CA_CUSTOMER_NUM = ENT1CNOO;
EXEC CICS LINK PROGRAM('LGICUS01') COMMAREA(COMM_AREA) LENGTH(32500);
IF CA_RETURN_CODE > 0 THEN GO TO NO_DATA;
ENT1FNAI = CA_FIRST_NAME;
ENT1LNAI = CA_LAST_NAME;
/* ... DOB, address, phones, email ... */
EXEC CICS SEND MAP('SSMAPC1') MAPSET('SSMAP');
GO TO ENDIT_STARTIT;

3.4 Option 2: Customer Add

The add path sets CA_CUSTOMER_NUM = 0 and copies the screen fields into the COMMAREA. It then applies two cleansing steps before the link:

  • TRANSLATE replaces null bytes in the whole area with spaces.
  • UPPERCASE forces the postcode to upper case.
PL1 
COMM_AREA_RAW = TRANSLATE(COMM_AREA_RAW,' ','00'X);
CA_POSTCODE   = UPPERCASE(CA_POSTCODE);
EXEC CICS LINK PROGRAM('LGACUS01') COMMAREA(COMM_AREA) LENGTH(32500);
IF CA_RETURN_CODE > 0 THEN DO;
   EXEC CICS SYNCPOINT ROLLBACK;
   GO TO NO_ADD;
END;
CALL WRITE_GENACNTL;

On success the screen shows the new customer number and the message 'New Customer Inserted'.

3.5 Option 4: Customer Update (Two-Phase)

Update is a verify-then-modify sequence inside a single task activation.

sequenceDiagram participant User participant LGTESTC1 participant LGICUS01 participant LGUCUS01 participant LGUCDB01 User->>LGTESTC1: Option 4 + customer number LGTESTC1->>LGICUS01: LINK (01ICUS) LGICUS01-->>LGTESTC1: Current customer data LGTESTC1-->>User: SEND MAP with existing data User->>LGTESTC1: Edited fields (second RECEIVE MAP) LGTESTC1->>LGTESTC1: TRANSLATE nulls, UPPERCASE postcode LGTESTC1->>LGUCUS01: LINK (01UCUS) LGUCUS01->>LGUCDB01: LINK full COMMAREA LGUCDB01-->>LGUCUS01: Updated, return code LGUCUS01-->>LGTESTC1: CA_RETURN_CODE LGTESTC1-->>User: Customer details updated

If the inquiry step fails, the update is never attempted. A failure of the update itself goes to NO_UPD.

3.6 Error Handling and Session Control

Label Message in ERRFLDO Trigger
NO_DATA No data was returned. Inquiry (option 1 or the option 4 pre-fetch) returned a non-zero code
NO_ADD Error Adding Customer LGACUS01 returned a non-zero code (after SYNCPOINT ROLLBACK)
NO_UPD Error Updating Customer LGUCUS01 returned a non-zero code
OTHERWISE Please enter a valid option Option not 1, 2 or 4 (cursor set with ENT1OPTL = -1)

All three error labels branch to ERROR_OUT. It sends the map, clears both map structures and the COMMAREA, and returns through ENDIT_STARTIT.

Label Behaviour
ENDIT_STARTIT EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA)
ENDIT Sends Transaction ended with ERASE FREEKB, then a plain RETURN (PF3 or MAPFAIL)
CLEARIT Sends the map with MAPONLY, then returns with TRANSID('SSC1') (CLEAR key)

3.7 GENACNTL Temporary Storage Queue Maintenance

After a successful add, WRITE_GENACNTL records the highest customer number. It brackets the work with ENQ and DEQ on GENACNTL:

  1. Read item 1, then browse with READQ TS NEXT.
  2. If an item begins with HIGH CUSTOMER, rewrite it (24 bytes) with the new number.
  3. If no such item exists, write three new items: a header (20 bytes), LOW CUSTOMER= (23 bytes) and HIGH CUSTOMER= (24 bytes).
graph TD A[ENQ GENACNTL] --> B[Flag = Y, item = 1] B --> C[READQ TS ITEM 1] C --> D{Normal?} D -->|Yes| E[Loop READQ NEXT] E --> F{First 13 chars = HIGH CUSTOMER?} F -->|Yes| G[REWRITE item with new number, flag cleared, exit loop] F -->|No| E D -->|No| H{Flag still Y?} G --> H H -->|Yes| I[WRITEQ header, LOW, HIGH] H -->|No| J[DEQ GENACNTL] I --> J

4. Inquiry Orchestration: LGICUS01

LGICUS01 is the front door for customer lookup. It does no database work itself. After validating the COMMAREA, it scans the GENAWMQC TS queue for a record starting with MQHIT=. This acts as a runtime routing switch.

graph TD A[Entry] --> B{EIBCALEN = 0?} B -->|Yes| C[WRITE_ERROR_MESSAGE, ABEND LGCA NODUMP] B -->|No| D[CA_RETURN_CODE = 00, CA_NUM_POLICIES = 0] D --> E{EIBCALEN < 90?} E -->|Yes| F[CA_RETURN_CODE = 98, RETURN] E -->|No| G[GET_CUSTOMER_INFO] G --> H[Read GENAWMQC items, look for MQHIT=] H --> I{MQ_HIT = 0?} I -->|Yes| J[LINK LGICDB01] I -->|No| K[LINK AAAAAAAA] J --> L[RETURN] K --> L

The minimum length is the customer length (72) plus the header and trailer length (18), which is 90 bytes. If the control queue is missing or unreadable, MQ_HIT stays 0 and the request quietly takes the DB2 path.

5. Customer Update Orchestration: LGUCUS01

LGUCUS01 is a gatekeeper with a strict request-ID check.

  1. It captures the EIB identity fields (EIBTRNID, EIBTRMID, EIBTASKN).
  2. If EIBCALEN = 0, it logs NO COMMAREA RECEIVED and abends with LGCA.
  3. It initialises CA_RETURN_CODE = '00' and CA_NUM_POLICIES = 0.
  4. If CA_REQUEST_ID is not '01UCUS', it sets CA_RETURN_CODE = '99' and returns without any update.
  5. Otherwise it links to LGUCDB01 with the full 32,500-byte COMMAREA.
PL1 
UPDATE_CUSTOMER_INFO: PROC;
  EXEC CICS LINK PROGRAM(LGUCDB01)
       COMMAREA(COMM_AREA)
       LENGTH(32500);
END UPDATE_CUSTOMER_INFO;
graph TD A[Start LGUCUS01] --> B{EIBCALEN = 0?} B -->|Yes| C[Log error, ABEND LGCA] B -->|No| D{CA_REQUEST_ID = 01UCUS?} D -->|No| E[CA_RETURN_CODE = 99, RETURN] D -->|Yes| F[LINK LGUCDB01] F --> G[RETURN]

6. Customer Onboarding and Lifecycle: LGACUS01

6.1 Action Dispatch

LGACUS01 validates the COMMAREA the same way (abend LGCA if absent, return code 98 if shorter than 18 + 72 = 90 bytes). It then dispatches on ACTION_CODE.

PL1 
SELECT;
  WHEN (ACTION_CODE = '1') DO;
      CA_REQUEST_ID = '01ICUS';
      CALL ONBOARD_CUSTOMER;
  END;
  WHEN (ACTION_CODE = '2') DO;
      CA_REQUEST_ID = '02OCUS';
      CALL OFFER_CUSTOMER;
  END;
  WHEN (ACTION_CODE = '3') DO;
      CA_REQUEST_ID = '02UCUS';
      CALL TRANSFER_CUSTOMER;
  END;
  WHEN (ACTION_CODE = '4') DO;
      CA_REQUEST_ID = '02DCUS';
      CALL DELETE_CUSTOMER;
  END;
  OTHERWISE;
END;

Important behaviour: In the PL/I port, ACTION_CODE is initialised to '0' and never changed. At runtime the OTHERWISE branch is always taken, so after validation the program performs no business operation. This is a documented artifact of porting from COBOL. The branches below describe the intended design.

Action Procedure Request ID Purpose
1 ONBOARD_CUSTOMER 01ICUS Register customer and security profile
2 OFFER_CUSTOMER 02OCUS Issue a policy to an existing customer
3 TRANSFER_CUSTOMER 02UCUS Insert a transferred policy
4 DELETE_CUSTOMER 02DCUS Delete a policy

6.2 Customer Onboarding

graph TD A[ONBOARD_CUSTOMER] --> B[GET COUNTER GENACUSTNUM pool GENA] B --> C{Counter OK?} C -->|Yes| D[INSERT CUSTOMER with counter value] C -->|No| E[LGAC_NCS = NO, INSERT CUSTOMER with DEFAULT] E --> F[SET number = IDENTITY_VAL_LOCAL] D --> G{SQLCODE = 0?} F --> G G -->|No| H[CA_RETURN_CODE = 90, log, RETURN] G -->|Yes| I[CA_CUSTOMER_NUM = number] I --> J[LINK LGACVS01 VSAM, length 225] J --> K[LINK LGACDB02 security, request 02ACUS] K --> L{CA_RETURN_CODE = 00?} L -->|No| M[RETURN with error] L -->|Yes| N[RETURN success]

The customer number comes from a CICS named counter (pool GENA, counter GENACUSTNUM). If the counter is unavailable, the program silently falls back to the DB2 identity column. The security record starts in the clean state:

PL1 
D2_CUSTOMER_NUM    = DB2_CUSTOMERNUM_INT;
D2_REQUEST_ID      = '02ACUS';
D2_CUSTSECR_COUNT  = '0000';
D2_CUSTSECR_STATE  = 'N';

EXEC CICS LINK PROGRAM(LGACDB02)
     COMMAREA(CDB2AREA)
     LENGTH(32500);

6.3 Policy Issuance, Transfer and Deletion

All three policy procedures are guarded by CA_REQUEST_ID ^= '01ACLM', so claim requests never trigger them.

PL1 
IF (CA_REQUEST_ID ^= '01ACLM') THEN
  CALL INSERT_CUSTOMER_POLICY;

Offer and transfer share the same insert and outcome mapping:

PL1 
SELECT (SQLCODE);
  WHEN (0)    CA_RETURN_CODE = '00';
  WHEN (-530) DO;
      CA_RETURN_CODE = '70';
      CALL WRITE_ERROR_MESSAGE;
      EXEC CICS RETURN;
  END;
  OTHERWISE DO;
      CA_RETURN_CODE = '90';
      CALL WRITE_ERROR_MESSAGE;
      EXEC CICS RETURN;
  END;
END;

After a successful insert, the program reads IDENTITY_VAL_LOCAL() into CA_POLICY_NUM. It then selects LASTCHANGED into CA_LASTCHANGED.

Deletion removes a POLICY row only when both CUSTOMERNUMBER and POLICYNUMBER match. The source comment says SQLCODE 100 is also treated as success. The code checks SQLCODE <> 0, so any non-zero code, including 100, results in return code 90.

graph TD A[Policy request] --> B{CA_REQUEST_ID = 01ACLM?} B -->|Yes| C[Skip] B -->|No| D{Action} D -->|Offer / Transfer| E[INSERT POLICY DEFAULT number, CURRENT TIMESTAMP] D -->|Delete| F[DELETE POLICY by customer AND policy number] E --> G{SQLCODE} G -->|0| H[00 - get policy number and LASTCHANGED] G -->|-530| I[70 - customer not found] G -->|other| J[90 - SQL error] F --> K{SQLCODE = 0?} K -->|Yes| L[Success] K -->|No| J

8. Return Codes and Validation Summary

8.1 Return Codes by Program

Code Meaning Set by
00 Success All orchestrators
70 Referential integrity violation (SQLCODE -530) LGACUS01
90 SQL or system error LGACUS01
98 COMMAREA shorter than the 90-byte minimum LGICUS01, LGACUS01
99 Invalid request ID (not 01UCUS) LGUCUS01

8.2 Validation and Guard Rules

Rule Where Effect
Missing COMMAREA (EIBCALEN = 0) LGICUS01, LGACUS01, LGUCUS01 Log, then ABEND LGCA NODUMP
COMMAREA too short LGICUS01, LGACUS01 Return code 98
Request ID must be 01UCUS LGUCUS01 Otherwise return code 99
Claim requests (01ACLM) excluded LGACUS01 policy procedures Operation skipped
Option must be 1, 2 or 4 LGTESTC1 Invalid option message
Null bytes become spaces, postcode upper-cased LGTESTC1 add and update Applied before the link
Rollback on add failure LGTESTC1 SYNCPOINT ROLLBACK before NO_ADD

8.3 Field-Width Considerations

The map email field ENT1HMOI is 27 characters. The COMMAREA field CA_EMAIL_ADDRESS is 100 characters. Through this menu only 27 characters of an email address can be entered or displayed.

9. Error Logging

LGICUS01, LGACUS01 and LGUCUS01 each have a WRITE_ERROR_MESSAGE procedure. It does the following:

  1. It calls ASKTIME and FORMATTIME to get the date and time.
  2. It fills ERROR_MSG with the date, time, program name, customer number, policy number, SQL request label and SQLCODE.
  3. It links to LGSTSQ to write that record to the TDQ.
  4. If EIBCALEN > 0, it links to LGSTSQ a second time. This call writes up to 90 bytes of the raw COMMAREA, prefixed COMMAREA=.
sequenceDiagram participant Program as Orchestrator participant CICS participant LGSTSQ participant TDQ Program->>CICS: ASKTIME / FORMATTIME CICS-->>Program: Date and time Program->>LGSTSQ: LINK ERROR_MSG LGSTSQ->>TDQ: Write formatted message Program->>LGSTSQ: LINK CA_ERROR_MSG (up to 90 bytes) LGSTSQ->>TDQ: Write COMMAREA snapshot

In practice, LGUCUS01 and LGICUS01 log only the missing-COMMAREA case. LGACUS01 logs every DB2 failure. An invalid request ID in LGUCUS01 and a short COMMAREA return a code to the caller without logging.

10.3 Update Request ID Mismatch

When LGUCUS01 receives CA_REQUEST_ID = '01ICUS', it returns CA_RETURN_CODE = '99' and never calls LGUCDB01. The menu program avoids this case by always setting 01UCUS before the update link.

10.4 Short COMMAREA

An EIBCALEN of 10 against the 90-byte minimum gives CA_RETURN_CODE = '98'. The program returns immediately with no downstream calls.

10.5 Invalid Menu Option

Option 9 takes the OTHERWISE branch. The map is resent with Please enter a valid option and the cursor on the option field. The transaction stays alive through RETURN TRANSID('SSC1').
