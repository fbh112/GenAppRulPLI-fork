Policy VSAM (KSDSPOLY) Programs

This page documents the four Enterprise PL/I CICS programs that maintain and query the KSDSPOLY policy VSAM KSDS file. LGAPVS01 adds records, LGUPVS01 updates them, LGDPVS01 deletes them, and LGIPVS01 does a generic GTEQ browse. All four share one 21-byte composite key, one COMMAREA layout, and one error-logging pattern that calls LGSTSQ.

1. Overview

1.1 Purpose

KSDSPOLY is a VSAM key-sequenced dataset that holds insurance policies of four types:

  • Commercial (C)
  • Endowment (E)
  • House (H)
  • Motor (M)

It is the VSAM counterpart to the DB2-based policy programs; for example, LGDPVS01 mirrors LGDPDB01. Each program does one job against the file and reports the result through a return code or message.

1.2 Program Summary

Program Operation CICS File Command Return Codes / Result Failure Behaviour
LGAPVS01 Add policy WRITE FILE CA_RETURN_CODE = '80' on failure Log, then EXEC CICS RETURN
LGUPVS01 Update policy READ ... UPDATE, then REWRITE '81' (read failure), '82' (rewrite failure) Log, then ABEND (LGV3 / LGV4, NODUMP)
LGDPVS01 Delete policy DELETE '81' on failure Log, then EXEC CICS RETURN
LGIPVS01 Generic GTEQ browse READ ... GENERIC GTEQ 'Policy Key=' or 'Policy Bad=' (sentinel 13) Error text returned to the COMMAREA or terminal

1.3 Key Characteristics

  • Composite key. The 21-byte key is request type (1) + customer number (10) + policy number (10).
  • Fixed record. Each record is 64 bytes: a 21-byte key plus a 43-byte policy-type-specific data area.
  • Policy type. The type comes from the 4th character of CA_REQUEST_ID.
  • Explicit response handling. Every CICS file command is issued with RESP, and the program tests it against DFHRESP(NORMAL).
  • No DB2. None of the four programs use SQL.

2.3 Build and Runtime Environment

The documentation for LGUPVS01 lists these build settings:

  • Enterprise PL/I for z/OS V52
  • Compile with SYSTEM(CICS),PP(MACRO,CICS)
  • Link-edit with MAP,RENT,COMPAT(PM5)
  • Deploy to the CICSLOAD library

All four programs run only under CICS.

3. KSDSPOLY Record and Composite Key Structure

3.1 Composite Key (WF_POLICY_KEY)

Component Length Source
WF_REQUEST_ID 1 4th character of CA_REQUEST_ID (C, E, H, M)
WF_CUSTOMER_NUM 10 CA_CUSTOMER_NUM
WF_POLICY_NUM 10 CA_POLICY_NUM
Total 21 Passed as RIDFLD with KEYLENGTH(21)

The same assignments appear in the add, update and delete programs:

PLI 
WF_Request_ID   = SUBSTR(CA_Request_ID,4,1);
WF_Policy_Num   = CA_Policy_Num;
WF_Customer_Num = CA_Customer_Num;

3.2 Record Layout

erDiagram KSDSPOLY_RECORD ||--|| WF_POLICY_KEY : "has 21-byte key" KSDSPOLY_RECORD ||--|| WF_POLICY_DATA : "has 43-byte data (UNION)" WF_POLICY_KEY { char WF_REQUEST_ID "1 byte" char WF_CUSTOMER_NUM "10 bytes" char WF_POLICY_NUM "10 bytes" } WF_POLICY_DATA ||--o| COMMERCIAL : "type C" WF_POLICY_DATA ||--o| ENDOWMENT : "type E" WF_POLICY_DATA ||--o| HOUSE : "type H" WF_POLICY_DATA ||--o| MOTOR : "type M" COMMERCIAL { char WF_B_POSTCODE "8" num WF_B_STATUS "status" char WF_B_CUSTOMER "31" } ENDOWMENT { char WF_E_WITH_PROFITS "1" char WF_E_EQUITIES "1" char WF_E_MANAGED_FUND "1" char WF_E_FUND_NAME "10" char WF_E_LIFE_ASSURED "30" } HOUSE { char WF_H_PROPERTY_TYPE "15" num WF_H_BEDROOMS "3 digits" num WF_H_VALUE "8 digits" char WF_H_POSTCODE "8" char WF_H_HOUSE_NAME "name" } MOTOR { char WF_M_MAKE "15" char WF_M_MODEL "15" num WF_M_VALUE "6 digits" char WF_M_REGNUMBER "7" }

WF_POLICY_DATA is a PL/I UNION. The commercial, endowment, house and motor overlays share the same storage, so only the overlay for the active policy type is populated. LGAPVS01 writes the 64-byte WF_POLICY_INFO (key + data) with LENGTH(64).

3.3 Field Mapping Between COMMAREA and Record

Type COMMAREA → Record fields
Commercial (C) CA_B_Postcode, CA_B_Status, CA_B_Customer → WF_B_*
Endowment (E) CA_E_WITH_PROFITS, CA_E_EQUITIES, CA_E_MANAGED_FUND, CA_E_FUND_NAME, CA_E_LIFE_ASSURED → WF_E_*
House (H) CA_H_PROPERTY_TYPE, CA_H_BEDROOMS, CA_H_VALUE, CA_H_POSTCODE, CA_H_HOUSE_NAME → WF_H_*
Motor (M) CA_M_MAKE, CA_M_MODEL, CA_M_VALUE, CA_M_REGNUMBER → WF_M_*
Other WF_Policy_Text is set to blanks. No rejection and no error code.

3.4 Truncation on Assignment

The COMMAREA fields are wider than the stored fields in some cases, so PL/I truncates them on assignment:

  • CA_B_Customer is 255 characters. Only 31 are stored.
  • CA_E_LIFE_ASSURED is 31 characters. Only 30 are stored.
  • In LGUPVS01, CA_H_HOUSE_NAME is 20 characters but only 9 are retained in the VSAM record.

4. Add Policy: LGAPVS01

4.1 Processing Flow

flowchart TD A([Start]) --> B[Capture EIBCALEN
Build key fields] B --> C{WF_REQUEST_ID} C -- C --> D1[Copy commercial data] C -- E --> D2[Copy endowment data] C -- H --> D3[Copy house data] C -- M --> D4[Copy motor data] C -- other --> D5[Blank WF_Policy_Text] D1 --> E[Re-assign WF_Policy_Num] D2 --> E D3 --> E D4 --> E D5 --> E E --> F[EXEC CICS WRITE FILE KSDSPOLY
LENGTH 64 / KEYLENGTH 21] F --> G{RESP = NORMAL?} G -- Yes --> H([Return]) G -- No --> I[WS_RESP2 = EIBRESP2
CA_RETURN_CODE = 80] I --> J[WRITE_ERROR_MESSAGE] J --> K([EXEC CICS RETURN])

4.2 Behaviour

  1. The program saves EIBCALEN and builds the three key components.
  2. A SELECT (WF_REQUEST_ID) block fills the matching policy-data overlay.
  3. WF_Policy_Num is assigned again from CA_Policy_Num just before the write.
  4. A CICS WRITE FILE('KSDSPOLY') writes the 64-byte record.
  5. If RESP is not NORMAL, the program does the following:
    • It saves EIBRESP2.
    • It sets CA_RETURN_CODE = '80'.
    • It calls WRITE_ERROR_MESSAGE.
    • It issues EXEC CICS RETURN.

Key statements:

PLI 
SELECT (WF_Request_ID);
  WHEN ('C') ...   /* commercial fields */
  WHEN ('E') ...   /* endowment fields  */
  WHEN ('H') ...   /* house fields      */
  WHEN ('M') ...   /* motor fields      */
  OTHERWISE  WF_Policy_Text = ' ';
END;
WF_Policy_Num = CA_Policy_Num;

The write command, with the options as documented:

PLI 
EXEC CICS WRITE FILE('KSDSPOLY')
     FROM(WF_Policy_Info)
     LENGTH(64)
     RIDFLD(WF_Policy_Key)
     KEYLENGTH(21)
     RESP(WS_RESP);

4.3 Add Sequence

sequenceDiagram participant Caller participant LGAPVS01 participant KSDSPOLY participant LGSTSQ Caller->>LGAPVS01: COMMAREA (request id, customer, policy, type data) LGAPVS01->>LGAPVS01: Build 21-byte key, populate union LGAPVS01->>KSDSPOLY: WRITE FILE (64 bytes) alt RESP = NORMAL KSDSPOLY-->>LGAPVS01: OK LGAPVS01-->>Caller: Return (return code unchanged) else Failure (e.g. DUPREC) KSDSPOLY-->>LGAPVS01: Non-normal RESP LGAPVS01->>LGSTSQ: LINK ERROR_MSG LGAPVS01->>LGSTSQ: LINK CA_ERROR_MSG (COMMAREA snapshot) LGAPVS01-->>Caller: CA_RETURN_CODE = 80 end

5. Update Policy: LGUPVS01

5.1 Processing Flow

flowchart TD A([Start]) --> B[Build key and populate policy data
same SELECT logic as add] B --> C[EXEC CICS READ FILE KSDSPOLY UPDATE
RIDFLD WF_Policy_Key KEYLENGTH 21] C --> D{READ RESP NORMAL?} D -- No --> E[CA_RETURN_CODE = 81
WRITE_ERROR_MESSAGE
ABEND LGV3 NODUMP] D -- Yes --> F[EXEC CICS REWRITE FILE KSDSPOLY
FROM WF_Policy_Info LENGTH 64] F --> G{REWRITE RESP NORMAL?} G -- No --> H[CA_RETURN_CODE = 82
WRITE_ERROR_MESSAGE
ABEND LGV4 NODUMP] G -- Yes --> I([RETURN])

5.2 Behaviour

  • The program builds the key and policy data exactly as LGAPVS01 does. The SELECT block ends with the same re-assignment of WF_Policy_Num.
  • READ ... UPDATE locks the record. The record image goes into the 1024-byte buffer WS_FileIn, and the length used on the READ is the COMMAREA length.
  • A READ failure sets return code 81 and abends with LGV3. The REWRITE is never attempted.
  • REWRITE writes a fixed 64 bytes from WF_Policy_Info, using WS_Commarea_LenF, which is initialised to 64. A REWRITE failure sets return code 82 and abends with LGV4.
  • Both abends use NODUMP, and each is followed by EXEC CICS RETURN.
  • On success the program issues a plain RETURN and leaves CA_RETURN_CODE unchanged.

5.3 Update Sequence

sequenceDiagram participant Caller participant LGUPVS01 participant KSDSPOLY participant LGSTSQ Caller->>LGUPVS01: COMMAREA with new policy data LGUPVS01->>KSDSPOLY: READ UPDATE (21-byte key) alt READ fails LGUPVS01->>LGSTSQ: LINK (error + COMMAREA snapshot) LGUPVS01-->>Caller: RC 81, ABEND LGV3 else READ ok LGUPVS01->>KSDSPOLY: REWRITE (64 bytes) alt REWRITE fails LGUPVS01->>LGSTSQ: LINK (error + COMMAREA snapshot) LGUPVS01-->>Caller: RC 82, ABEND LGV4 else REWRITE ok LGUPVS01-->>Caller: Return normally end end

6. Delete Policy: LGDPVS01

6.1 Processing Flow

flowchart TD A([Start]) --> B[WS_Commarea_Len = EIBCALEN
Build 21-byte key] B --> C[EXEC CICS DELETE FILE KSDSPOLY
RIDFLD WF_Policy_Key KEYLENGTH 21] C --> D{RESP = NORMAL?} D -- Yes --> E([RETURN]) D -- No --> F[WS_RESP2 = EIBRESP2
CA_RETURN_CODE = 81] F --> G[WRITE_ERROR_MESSAGE] G --> H([EXEC CICS RETURN])

6.2 Behaviour

The program is single-purpose: build the key, delete, and log if the delete fails.

PLI 
EXEC CICS Delete File('KSDSPOLY')
     Ridfld(WF_Policy_Key)
     KeyLength(21)
     Resp(WS_RESP);

If (WS_RESP <> DFHRESP(NORMAL)) Then Do;
   WS_RESP2 = EIBRESP2;
   CA_RETURN_CODE = '81';
   Call WRITE_ERROR_MESSAGE;
   EXEC CICS RETURN;
End;
  • Only the 4th character of CA_REQUEST_ID contributes to the key.
  • There is no browse, retry or alternate access path.
  • The documentation notes that EM_POLNUM exists in ERROR_MSG, but no assignment to it appears in the code shown. The logged policy number may therefore be blank.

7. Generic GTEQ Browse: LGIPVS01

7.1 Dual Invocation Modes

LGIPVS01 is the only program that works with a partial key. It can be called with EXEC CICS LINK and a COMMAREA, or started from a terminal. It decides which at startup:

PLI 
/* ASSIGN SYSID, STARTCODE, INVOKINGPROG, each with RESP(WS_RESP) */
IF SUBSTR(WS_STARTCODE,1,1) = 'D' | WS_INVOKEPROG ^= ' ' THEN ...  /* COMMAREA, WS_FLAG='C' */
ELSE ...                                                           /* RECEIVE,  WS_FLAG='R' */
Mode Condition Input Source WS_RECV_LEN
COMMAREA (WS_FLAG = 'C') Start code begins with D, or invoking program is not blank COMMA_DATA_TEXT (11) + COMMA_DATA_KEY (21) Set to 10
Terminal (WS_FLAG = 'R') Otherwise EXEC CICS RECEIVE into WS_RECV (5-char tran id + 74-char data) Reduced by 6 after the receive

7.2 Processing Flow

7.3 Browse Read

The read statement as documented:

PLI 
EXEC CICS READ FILE('KSDSPOLY')
     INTO(CA_AREA) LENGTH(F64)
     RIDFLD(PART_KEY) KEYLENGTH(F11)
     GENERIC GTEQ
     RESP(WS_RESP);
  • PART_KEY is an 11-byte partial key: PART_KEY_TYPE (1) + PART_KEY_NUM (10).
  • GENERIC with GTEQ positions to the first record whose key is greater than or equal to the partial key.
  • After the read, the program checks that the record belongs to the requested type: if CA_POLICY_TYPE ^= PART_KEY_TYPE, it reports failure. A GTEQ read can land on a record of a later policy type.
  • It issues one read only. There is no further browse iteration.

7.4 Output Message

Outcome WRITE_MSG_TEXT Key field
Success 'Policy Key=' WRITE_MSG_KEY_CH = CA_POLICY_TYPE ‖ CA_CUSTOMER_NUM
Failure 'Policy Bad=' WRITE_MSG_CUSTNUM = 13, WRITE_MSG_POLNUM = 13

The terminal path uses SEND TEXT FROM(WRITE_MSG) TERMINAL WAIT ERASE LENGTH(80) FREEKB. The COMMAREA path clears COMMA_DATA, then copies the label into COMMA_DATA_TEXT and the key into COMMA_DATA_KEY.

7.5 Browse Sequence (COMMAREA Mode)

sequenceDiagram participant Caller participant LGIPVS01 participant KSDSPOLY Caller->>LGIPVS01: LINK with COMMAREA ("Policy Key=" + key) LGIPVS01->>LGIPVS01: ASSIGN STARTCODE / INVOKINGPROG LGIPVS01->>LGIPVS01: Build PART_KEY (11 bytes) LGIPVS01->>KSDSPOLY: READ GENERIC GTEQ (KEYLENGTH 11) KSDSPOLY-->>LGIPVS01: 64-byte record or non-normal RESP LGIPVS01->>LGIPVS01: Compare record type with requested type LGIPVS01-->>Caller: COMMAREA updated (Policy Key= / Policy Bad=)

8. Return Codes

8.1 Return Code Summary

Program Condition CA_RETURN_CODE / Result Abend
LGAPVS01 WRITE FILE RESP ≠ NORMAL '80' None (EXEC CICS RETURN)
LGUPVS01 READ UPDATE RESP ≠ NORMAL '81' LGV3 (NODUMP)
LGUPVS01 REWRITE RESP ≠ NORMAL '82' LGV4 (NODUMP)
LGDPVS01 DELETE RESP ≠ NORMAL '81' None (EXEC CICS RETURN)
LGIPVS01 Type mismatch or RESP ≠ NORMAL 'Policy Bad=' with 13 / 13 None
All Success Return code is not set; the caller’s value is left unchanged None

81 is used by two programs with different meanings. In LGUPVS01 it means the read failed, and in LGDPVS01 it means the delete failed. Callers must interpret it together with the program that was invoked.

8.2 Return Code Flow

flowchart LR ADD[LGAPVS01 write fails] --> R80[80] UPDR[LGUPVS01 read fails] --> R81[81 + ABEND LGV3] UPDW[LGUPVS01 rewrite fails] --> R82[82 + ABEND LGV4] DEL[LGDPVS01 delete fails] --> R81D[81] INQ[LGIPVS01 no match] --> BAD["Policy Bad= / 13"]

9. Error Logging Pattern

9.1 WRITE_ERROR_MESSAGE

LGAPVS01, LGUPVS01 and LGDPVS01 each contain an internal WRITE_ERROR_MESSAGE procedure that runs only on a file failure. It does the following:

  1. It calls EXEC CICS ASKTIME ABSTIME(WS_ABSTIME).
  2. It calls EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME) MMDDYYYY(WS_DATE) TIME(WS_TIME).
  3. It fills ERROR_MSG and links to LGSTSQ.
  4. If EIBCALEN > 0, it logs up to 90 bytes of the raw COMMAREA through CA_ERROR_MSG.

9.2 ERROR_MSG Contents

Field Content
EM_DATE / EM_TIME Formatted timestamp (MM/DD/YYYY, HH:MM:SS)
Program literal LGAPVS01, LGUPVS01 or LGDPVS01
EM_CUSNUM CA_Customer_Num
EM_POLNUM Policy number (present in the layout; see section 6.2 for the LGDPVS01 caveat)
Operation text Write file KSDSPOLY, Re-write KSDSPOLY, or Delete file KSDSPOLY
EM_RESPRC / EM_RESP2RC WS_RESP / WS_RESP2

The operation text in LGUPVS01 always says “Re-write KSDSPOLY”, even when the failure is on the READ.

9.3 COMMAREA Snapshot Logic

The snapshot is capped at 90 bytes:

PLI 
IF (EIBCALEN > 0) THEN DO;
   IF (EIBCALEN < 91) THEN
      CA_Data = LEFT(COMM_AREA_RAW,EIBCALEN);
   ELSE
      CA_Data = LEFT(COMM_AREA_RAW,90);
   EXEC CICS LINK PROGRAM('LGSTSQ')
        COMMAREA(CA_ERROR_MSG) ...;
END;

CA_ERROR_MSG carries the literal prefix COMMAREA= followed by CA_Data.

9.4 Logging Sequence

sequenceDiagram participant Prog as LGAPVS01 / LGUPVS01 / LGDPVS01 participant CICS participant LGSTSQ Prog->>CICS: ASKTIME Prog->>CICS: FORMATTIME (MMDDYYYY, TIME) Prog->>LGSTSQ: LINK COMMAREA(ERROR_MSG) opt EIBCALEN > 0 Prog->>Prog: CA_Data = LEFT(COMM_AREA_RAW, min(EIBCALEN, 90)) Prog->>LGSTSQ: LINK COMMAREA(CA_ERROR_MSG) end Prog->>CICS: RETURN (LGUPVS01: ABEND first)

10. Constraints and Design Considerations

10.1 Key and Record Constraints

  • The key is always 21 bytes, and a different KEYLENGTH would cause a CICS error. The browse uses 11 bytes.
  • Records are fixed at 64 bytes (LENGTH(64)) on add and update. The browse also reads 64 bytes.
  • The file name KSDSPOLY is hard-coded in every program.
  • CA_CUSTOMER_NUM and CA_POLICY_NUM are PIC '9999999999'. They are moved into CHAR(10) key fields.

10.2 Validation Gaps

  • An unrecognised policy type is not rejected on add or update. The data area is blanked, and a key-only record can still be written or rewritten.
  • None of the programs check EIBCALEN = 0 before using the COMMAREA, unlike the usual LGCA abend convention in the wider application.
  • LGIPVS01 does not validate the policy-type character or the numeric content of PART_KEY_NUM. Non-numeric input would cause a PL/I conversion error.
  • LGIPVS01 terminal input must be long enough to remain valid after the length is reduced by 6.

10.3 Ordering Rules

  • The key must be built, and the policy data populated, before any file command.
  • For LGUPVS01, a successful READ UPDATE must come before the REWRITE. The program enforces this by abending on a read failure.
  • Time and date services are used only on the error path.

10.4 Diagnostic Limits

  • At most 90 bytes of COMMAREA are logged.
  • RESP2 is captured only on failure.
  • COMM_AREA_RAW is declared as 32,500 characters. A larger COMMAREA would overflow the declared overlay.

11. Examples

11.1 Add a Motor Policy (Success)

Field Value
CA_REQUEST_ID '01AMOT'
CA_CUSTOMER_NUM '0000001234'
CA_POLICY_NUM '0000009901'
CA_M_MAKE / CA_M_MODEL 'TOYOTA' / 'COROLLA'
CA_M_VALUE / CA_M_REGNUMBER '015000' / 'AB12CDE'

The 4th character is M, so the motor fields are copied. The resulting key is 'M' ‖ '0000001234' ‖ '0000009901'. The write returns NORMAL and CA_RETURN_CODE is untouched.

11.2 Add with Duplicate Key (Failure)

The input is the same as in 11.1, but a record with the same key already exists.

  • WS_RESP is non-normal (for example DUPREC).
  • CA_RETURN_CODE is set to '80'.
  • LGSTSQ receives the timestamped error and up to 90 bytes of COMMAREA.

11.3 Update an Endowment Policy (Success)

Field Value
CA_REQUEST_ID '01UEOW'
CA_CUSTOMER_NUM '0000002222'
CA_POLICY_NUM '0000007777'
Endowment fields with-profits Y, equities N, managed fund Y, fund GROWTH01, life assured JANE SMITH

READ UPDATE finds the record under key 'E0000002222' ‖ '0000007777'. REWRITE replaces the 64-byte record, and no return code is set.

11.4 Update of a Missing Record

For CA_REQUEST_ID = '01UHSE' with customer and policy numbers '9999999999', the READ UPDATE fails. CA_RETURN_CODE is set to '81', the error is logged, and the task abends with LGV3.

11.5 Delete (Success and Failure)

The key is built from the COMMAREA:

CODE 
WF_REQUEST_ID   = '0'          (1 byte  - 4th char of CA_REQUEST_ID)
WF_CUSTOMER_NUM = '0000012345' (10 bytes)
WF_POLICY_NUM   = '0000098765' (10 bytes)
Total key       = 21 bytes

If the record exists, DELETE returns NORMAL and the program returns without changing CA_RETURN_CODE. If the record is missing (for example NOTFND), CA_RETURN_CODE is set to '81' and the error and a COMMAREA snapshot go to LGSTSQ.

11.6 Browse via LINK (Success)

Input COMMAREA:

Field Value
COMMA_DATA_TEXT 'Policy Key='
COMMA_DATA_KEY 'E0000000010'

PART_KEY_TYPE is 'E' and PART_KEY_NUM is 0000000010. The GTEQ read returns a record with CA_POLICY_TYPE = 'E' and CA_CUSTOMER_NUM = '0000000010'. The types match, so the COMMAREA is returned with COMMA_DATA_TEXT = 'Policy Key=' and COMMA_DATA_KEY = 'E0000000010'.

11.7 Browse from a Terminal (No Match)

The operator enters data starting with M9999999990. The GTEQ read returns a record whose type is not M, or a non-normal RESP. The program sets WRITE_MSG_TEXT = 'Policy Bad=' and both numeric subfields to 13. It then sends the 80-byte message to the terminal with ERASE, FREEKB and WAIT.
