Customer VSAM Programs

1. Overview

The Customer VSAM Programs are a set of three CICS-hosted PL/I programs. They maintain and query the KSDSCUST VSAM Key-Sequenced Data Set in the insurance General Application (GenApp). KSDSCUST holds the customer master records. The 10-digit customer number (CA_CUSTOMER_NUM) is the record key.

Program Function Primary CICS file command Failure signal
LGACVS01 Add a new customer record WRITE FILE('KSDSCUST') CA_RETURN_CODE='80', ABEND LGV0
LGUCVS01 Update an existing customer record READ ... UPDATE, then REWRITE CA_RETURN_CODE='81' or '82', ABEND LGV1 or LGV2
LGICVS01 Randomly select a valid customer number READ ... GTEQ No abend; falls back to the raw random number

Key characteristics:

  • All three programs access KSDSCUST only through CICS file control. None of them uses DB2.
  • LGACVS01 and LGUCVS01 follow the same error pattern:
    • They test RESP against DFHRESP(NORMAL).
    • On failure they set a return code and write diagnostics through LGSTSQ.
    • They then end the task with ABEND ... NODUMP.
  • LGICVS01 has a different role. It uses a temporary storage queue, GENACNTL, to hold the customer-number range, and it serializes access to that queue with ENQ/DEQ.
  • All three share the COMMAREA layout from the LGCMAREA include. LGICVS01 uses its own smaller 84-byte COMMA_DATA view.

2.2 Shared Data Structures

The programs use the following structures:

  • COMM_AREA is the LGCMAREA include, based on COMM_AREA_PTR. LGACVS01 and LGUCVS01 use it. It contains:
    • CA_REQUEST_ID
    • CA_RETURN_CODE
    • CA_CUSTOMER_NUM
    • the CA_REQUEST_SPECIFIC overlay
    • COMM_AREA_RAW, a 32,500-byte raw view
  • COMMA_DATA is used by LGICVS01. It is 84 bytes:
    • COMMA_DATA_H, 14 bytes
    • COMMA_DATA_HIGH, a 10-digit field
    • COMMA_DATA_FILL, 60 bytes
  • ERROR_MSG and CA_ERROR_MSG are the diagnostic structures that LGACVS01 and LGUCVS01 pass to LGSTSQ.

GENACNTL does not hold customer data. It holds the lower and upper bounds that LGICVS01 uses to generate a key for a GTEQ read against KSDSCUST.

3. LGACVS01 – Add Customer

3.1 Purpose

LGACVS01 writes a new customer record to KSDSCUST. The record is the whole COMMAREA, starting at CA_CUSTOMER_NUM. The customer number is also the record key. If the write fails, the program does the following:

  1. It sets CA_RETURN_CODE to '80'.
  2. It logs two diagnostic messages through LGSTSQ.
  3. It abends the task with LGV0.

3.2 Inputs and Outputs

Category Item Description
Input CA_CUSTOMER_NUM Record key and start of the record image
Input EIBCALEN Length of the record written (copied to WS_Commarea_Len)
Input CA_FIRST_NAME, CA_LAST_NAME, CA_DOB, address, phone, email, CA_POLICY_DATA Customer demographic data written to the file
Output KSDSCUST record New keyed record
Output CA_RETURN_CODE '80' on write failure; unchanged on success
Output ERROR_MSG, CA_ERROR_MSG Diagnostics sent to LGSTSQ on failure
Output ABEND LGV0 Raised on failure, with NODUMP

3.3 Processing Flow

graph TD A([Start LGACVS01]) --> B[WS_Commarea_Len = EIBCALEN] B --> C[EXEC CICS WRITE FILE KSDSCUST
RIDFLD = CA_CUSTOMER_NUM] C --> D{{WS_RESP = NORMAL?}} D -- Yes --> E([RETURN to caller]) D -- No --> F[WS_RESP2 = EIBRESP2] F --> G[CA_RETURN_CODE = 80] G --> H[WRITE_ERROR_MESSAGE] H --> I[EXEC CICS ABEND LGV0 NODUMP] I --> J[EXEC CICS RETURN]

3.4 Code Example – The WRITE Command

The main write uses the following parameters:

PLI 
EXEC CICS WRITE FILE('KSDSCUST')
              FROM(CA_Customer_Num)
              LENGTH(WS_Commarea_Len)
              RIDFLD(CA_Customer_Num)
              KEYLENGTH(10)
              RESP(WS_RESP);

If WS_RESP is not DFHRESP(NORMAL), the error path is:

PLI 
WS_RESP2 = EIBRESP2;
CA_RETURN_CODE = '80';
CALL WRITE_ERROR_MESSAGE;
EXEC CICS ABEND ABCODE('LGV0') NODUMP;
EXEC CICS RETURN;

4. LGUCVS01 – Update Customer

4.1 Purpose

LGUCVS01 updates an existing customer record. It reads the record with UPDATE intent, which gives the task exclusive control of the record. It then rewrites the record with the COMMAREA data.

4.2 Inputs and Outputs

Category Item Description
Input CA_CUSTOMER_NUM KSDS key for the READ UPDATE, and start of the REWRITE image
Input EIBCALEN Copied to WS_Commarea_Len and WS_Commarea_LenF
Input Customer fields New data to persist (name, DOB, postcode, phones, email, and so on)
Output Updated KSDSCUST record Result of REWRITE
Output CA_RETURN_CODE '81' for read failure, '82' for rewrite failure
Output ABEND LGV1 / LGV2 One abend code per failing operation

4.3 Processing Flow

graph TD A([Start LGUCVS01]) --> B[Capture EIBCALEN
WS_Commarea_Len / LenF] B --> C[READ FILE KSDSCUST UPDATE
INTO WS_Customer_Area] C --> D{{RESP = NORMAL?}} D -- No --> E[CA_RETURN_CODE = 81
WRITE_ERROR_MESSAGE] E --> F[ABEND LGV1 NODUMP] D -- Yes --> G[REWRITE FILE KSDSCUST
FROM CA_CUSTOMER_NUM] G --> H{{RESP = NORMAL?}} H -- No --> I[CA_RETURN_CODE = 82
WRITE_ERROR_MESSAGE] I --> J[ABEND LGV2 NODUMP] H -- Yes --> K([RETURN to caller])

4.4 Code Examples

The READ with update intent:

PLI 
EXEC CICS READ FILE('KSDSCUST')
             INTO(WS_Customer_Area)
             LENGTH(WS_Commarea_Len)
             RIDFLD(CA_Customer_Num)
             KEYLENGTH(10)
             UPDATE
             RESP(WS_RESP);

The REWRITE:

PLI 
EXEC CICS REWRITE FILE('KSDSCUST')
               FROM(CA_Customer_Num)
               LENGTH(WS_Commarea_LenF)
               RESP(WS_RESP);

5. LGICVS01 – Random Customer Selection

5.1 Purpose

LGICVS01 returns a valid customer number chosen at random from KSDSCUST. It does this in five steps:

  1. It reads the permitted customer-number range from the GENACNTL TS queue. If the control records are missing, it creates them with defaults of 1000001.
  2. It generates a pseudo-random number within that range, seeded with the CICS task number.
  3. It reads KSDSCUST with GTEQ to find the nearest real key.
  4. It checks how it was invoked. If it was started by LINK or a start code beginning with 'D', it returns the result in the COMMAREA. Otherwise it sends the result to the terminal.
  5. It issues EXEC CICS RETURN.

5.2 Invocation Modes

Mode Condition WS_FLAG Output
COMMAREA STARTCODE starts with 'D' or INVOKINGPROG is not blank 'C' COMMA_DATA fields
Terminal Otherwise (EXEC CICS RECEIVE reads input) 'R' SEND TEXT of WRITE_MSG_H

5.3 Processing Flow

RANDOM EIBTASKN] N --> O[READ KSDSCUST GTEQ] O --> P{{RESP = NORMAL?}} P -- Yes --> Q[Use actual CA_CUSTOMER_NUM] P -- No --> R[Keep random number] Q --> S{{WS_FLAG}} R --> S S -- C --> T[Populate COMMA_DATA] S -- other --> U[SEND TEXT to terminal] T --> V([RETURN]) U --> V

5.4 GENACNTL Control Queue

The queue holds up to three kinds of record:

Record Length Content Written when
Eyecatcher 20 **** GENAPP CNTL Item 1 could not be read
LOW CUSTOMER 23 LOW CUSTOMER= plus a 10-digit value No LOW record was found
HIGH CUSTOMER 24 HIGH CUSTOMER= plus a 10-digit value No HIGH record was found

The writes use NOSUSPEND, and ENQ/DEQ on the queue name serialize access. This prevents two tasks from both finding a record missing and writing duplicates.

5.5 Code Examples

The random key calculation:

PLI 
WS_RANDOM_NUMBER = FLOOR(RANDOM(EIBTASKN) *
                   FLOAT(WS_CUST_HIGH - WS_CUST_LOW) + WS_CUST_LOW);

The GTEQ read, which returns the nearest key at or above the random value:

PLI 
EXEC CICS READ FILE('KSDSCUST')
             INTO(CA_AREA)
             LENGTH(F82)
             RIDFLD(WRITE_MSG_HIGH)
             KEYLENGTH(F10)
             RESP(WS_RESP)
             GTEQ;

The result dispatch:

PLI 
SELECT (WS_FLAG);
  WHEN ('C') DO;
    COMMA_DATA_H    = WRITE_MSG_H;
    COMMA_DATA_HIGH = WRITE_MSG_HIGH;
    COMMA_DATA_FILL = (60)' ';
  END;
  OTHERWISE
    EXEC CICS SEND TEXT FROM(WRITE_MSG_H) LENGTH(24)
                        WAIT ERASE TERMINAL FREEKB;
END;

6. Shared Error Handling (LGACVS01 and LGUCVS01)

6.1 WRITE_ERROR_MESSAGE Procedure

Both programs contain an internal WRITE_ERROR_MESSAGE procedure. It does the following:

  1. ASKTIME and FORMATTIME produce WS_DATE (MMDDYYYY) and WS_TIME.
  2. It fills ERROR_MSG with the date, time, customer number (EM_CUSNUM), EM_RESPRC (from WS_RESP) and EM_RESP2RC (from WS_RESP2).
  3. EXEC CICS LINK PROGRAM('LGSTSQ') sends ERROR_MSG.
  4. If EIBCALEN > 0, it copies up to 90 bytes of COMM_AREA_RAW into CA_Data and links to LGSTSQ again.
PLI 
EXEC CICS LINK PROGRAM('LGSTSQ')
               COMMAREA(ERROR_MSG)
               LENGTH(STG(ERROR_MSG));

IF EIBCALEN > 0 THEN DO;
  IF EIBCALEN < 91 THEN
    CA_Data = LEFT(COMM_AREA_RAW, EIBCALEN);
  ELSE
    CA_Data = LEFT(COMM_AREA_RAW, 90);
  EXEC CICS LINK PROGRAM('LGSTSQ')
                 COMMAREA(CA_ERROR_MSG)
                 LENGTH(STG(CA_ERROR_MSG));
END;
graph TD A[Entry] --> B[ASKTIME / FORMATTIME] B --> C[Populate ERROR_MSG] C --> D[LINK LGSTSQ with ERROR_MSG] D --> E{{EIBCALEN > 0?}} E -- No --> H[Return] E -- Yes --> F{{EIBCALEN < 91?}} F -- Yes --> G1[CA_Data = LEFT EIBCALEN] F -- No --> G2[CA_Data = LEFT 90] G1 --> I[LINK LGSTSQ with CA_ERROR_MSG] G2 --> I I --> H

6.2 Return Codes and Abend Codes

Program Failing operation CA_RETURN_CODE ABEND code
LGACVS01 WRITE 80 LGV0
LGUCVS01 READ UPDATE 81 LGV1
LGUCVS01 REWRITE 82 LGV2
LGICVS01 READ GTEQ none none

All the abends use NODUMP. The diagnostics written to LGSTSQ are therefore the main record of the failure.

6.3 LGICVS01 Error Behaviour

LGICVS01 does not log or abend. It tests RESP after each command and recovers.

  • If the TS queue is absent, it recreates the control records.
  • If the GTEQ read does not return NORMAL, it returns the raw random number. This can happen when the number is above the highest key.
  • The writes to GENACNTL use NOSUSPEND. The program does not check whether they succeeded.

7. Dependencies and Constraints

7.1 Common Dependencies

  • A CICS runtime with the file KSDSCUST defined. It must be a KSDS with a 10-byte key.
  • The LGCMAREA include, for LGACVS01 and LGUCVS01.
  • The CICS program LGSTSQ, which LGACVS01 and LGUCVS01 use for error logging.
  • The GENACNTL TS queue, which LGICVS01 uses.

7.2 Key Constraints

Area Constraint
Key CA_CUSTOMER_NUM is PIC '9999999999' and is used with KEYLENGTH(10).
Size The COMMAREA view (COMM_AREA_RAW) is at most 32,500 bytes.
Duplicates LGACVS01 fails on a duplicate key, because a KSDS requires unique keys.
Update order LGUCVS01 must READ UPDATE before it REWRITEs.
Read buffer LGUCVS01 reads into a 1,024-byte buffer, WS_Customer_Area.
Record size LGICVS01 reads into a 225-byte CA_AREA, so it assumes a record of that length.
Diagnostics The COMMAREA snapshot in the logs is limited to 90 bytes.
Random seed LGICVS01 uses the task number as its seed.

8. Examples

8.1 Add Customer – Success

Input COMMAREA: CA_CUSTOMER_NUM=0000000042, CA_REQUEST_ID=ACUST0, CA_RETURN_CODE=00.

  1. LGACVS01 writes the record with key 0000000042.
  2. CICS returns NORMAL.
  3. CA_RETURN_CODE stays 00, and no error messages are logged.

8.2 Add Customer – Duplicate Key

The key 0000000042 already exists.

  1. The WRITE returns a non-NORMAL response such as DUPREC.
  2. CA_RETURN_CODE is set to 80.
  3. LGSTSQ receives two messages:
    • the structured error line
    • a COMMAREA= snapshot of the first 90 bytes
  4. The task abends with LGV0.

8.3 Update Customer – Record Not Found

Customer 0000009999 does not exist.

  1. READ UPDATE fails.
  2. CA_RETURN_CODE is set to 81.
  3. The error is logged.
  4. The task abends with LGV1. The REWRITE is never attempted.

8.4 Update Customer – Rewrite Failure

Customer 0000000007 is read successfully, but the REWRITE fails.

  1. CA_RETURN_CODE is set to 82.
  2. The error is logged.
  3. The task abends with LGV2.

8.5 Random Selection via LINK, With No Existing Queue

  1. INVOKINGPROG='LGICUS01', so WS_FLAG is 'C'.
  2. The GENACNTL queue does not exist, so the program writes the eyecatcher, LOW CUSTOMER=0001000001 and HIGH CUSTOMER=0001000001.
  3. The random number is 1000001, because the range has zero width.
  4. A GTEQ read finds key 0001000050.
  5. The COMMAREA is returned as shown below:
Field Value
COMMA_DATA_H HIGH CUSTOMER=
COMMA_DATA_HIGH 0001000050
COMMA_DATA_FILL 60 spaces

8.6 Random Selection From a Terminal

The queue holds LOW CUSTOMER=0001000001 and HIGH CUSTOMER=0001009999. The program computes a random number of 1005482. A GTEQ read returns key 0001005500, and the terminal shows:

CODE 
HIGH CUSTOMER=0001005500
