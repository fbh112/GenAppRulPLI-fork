Customer Update

1. Overview

The Customer Update application changes an existing customer’s personal and contact details in the GenApp general insurance system. It runs as a chain of three CICS-hosted Enterprise PL/I programs. Together they keep two data stores consistent: the DB2 CUSTOMER table and the VSAM KSDS file KSDSCUST.

Program Role Data store / resource
LGUCUS01 Entry point and orchestrator. Validates the COMMAREA and request ID, then delegates. None (no direct data access)
LGUCDB01 DB2 update. Runs a single SQL UPDATE on the CUSTOMER table, then links to the VSAM program. DB2 CUSTOMER table
LGUCVS01 VSAM update. Reads the customer record for update, then rewrites it. VSAM KSDS KSDSCUST
LGSTSQ (shared utility) Writes diagnostic messages and COMMAREA dumps to a CICS queue. CICS queue

Key behaviours:

  • Single request code: only request ID 01UCUS is accepted. Anything else is rejected with return code 99.
  • Shared COMMAREA: all programs use the LGCMAREA layout, up to 32,500 bytes. It carries the customer number, the updated details and the return code.
  • Return codes: 00 means success. 01 means customer not found in DB2. 90 means an unexpected DB2 error. 99 means invalid request ID. 81 and 82 mean a VSAM read or rewrite failure.
  • Diagnostics: errors are timestamped and sent to LGSTSQ, together with up to 90 bytes of the raw COMMAREA.

2. System Architecture

2.1 Component Architecture

LGUCUS01 is the only program the caller talks to. It validates the request and hands the full COMMAREA to LGUCDB01. LGUCDB01 updates DB2 and then calls LGUCVS01 to mirror the change in VSAM. All three programs use LGSTSQ for error logging.

2.2 Component Responsibilities

Component Responsibilities
LGUCUS01 Captures EIB fields (EIBTRNID, EIBTRMID, EIBTASKN). Abends with LGCA if no COMMAREA is present. Initialises CA_RETURN_CODE to 00 and CA_NUM_POLICIES to 0. Validates CA_REQUEST_ID = '01UCUS'. Links to LGUCDB01.
LGUCDB01 Converts CA_CUSTOMER_NUM to the integer host variable DB2_CUSTOMERNUM_INT. Updates nine columns in one SQL statement. Maps SQLCODE to return codes. Links to LGUCVS01.
LGUCVS01 Reads KSDSCUST with UPDATE intent, keyed by CA_CUSTOMER_NUM with a key length of 10. Rewrites the record. Sets 81 or 82 and abends (LGV1 or LGV2) on failure.
LGSTSQ Shared logging utility called by all three programs via EXEC CICS LINK.

4. Component Details

4.1 LGUCUS01 — Entry Point

4.1.1 Processing Steps

  1. Copy EIBTRNID, EIBTRMID and EIBTASKN into working storage for diagnostics.
  2. If EIBCALEN = 0, set EM_MSG_TEXT to ' NO COMMAREA RECEIVED', call WRITE_ERROR_MESSAGE, and issue EXEC CICS ABEND ABCODE('LGCA') NODUMP.
  3. Set CA_RETURN_CODE = '00' and CA_NUM_POLICIES = 0. Save the COMMAREA length and pointer. Copy CA_CUSTOMER_NUM into EM_CUSNUM.
  4. If CA_REQUEST_ID is not '01UCUS', set CA_RETURN_CODE = '99' and return immediately. No error message is logged for this case.
  5. Otherwise call UPDATE_CUSTOMER_INFO, then issue EXEC CICS RETURN.

4.1.2 Delegation to the DB2 Program

UPDATE_CUSTOMER_INFO contains one synchronous link that passes the full 32,500-byte COMMAREA:

PLI 
EXEC CICS LINK PROGRAM(LGUCDB01)
               COMMAREA(COMM_AREA)
               LENGTH(32500);

The request ID check that guards this call:

PLI 
IF CA_REQUEST_ID ^= '01UCUS' THEN DO;
   CA_RETURN_CODE = '99';
   EXEC CICS RETURN;
END;

4.2 LGUCDB01 — DB2 Update

4.2.1 Processing Steps

  1. Capture the EIB fields and apply the same missing-COMMAREA guard as LGUCUS01. This abends with LGCA.
  2. Set CA_RETURN_CODE = '00'. Convert the 10-digit CA_CUSTOMER_NUM to the FIXED BIN(31) host variable DB2_CUSTOMERNUM_INT.
  3. Call UPDATE_CUSTOMER_INFO, which sets EM_SQLREQ to ' UPDATE CUST ' and runs the SQL UPDATE.
  4. Link to LGUCVS01 with a 225-byte COMMAREA.
  5. Issue EXEC CICS RETURN.

4.2.2 The SQL Update

All nine customer columns are updated in one statement. The row is selected by customer number:

SQL 
UPDATE CUSTOMER
  SET FIRSTNAME=:CA_FIRST_NAME, LASTNAME=:CA_LAST_NAME, DATEOFBIRTH=:CA_DOB,
      HOUSENAME=:CA_HOUSE_NAME, HOUSENUMBER=:CA_HOUSE_NUM, POSTCODE=:CA_POSTCODE,
      PHONEMOBILE=:CA_PHONE_MOBILE, PHONEHOME=:CA_PHONE_HOME,
      EMAILADDRESS=:CA_EMAIL_ADDRESS
WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT;

4.2.3 SQLCODE Mapping

SQLCODE Meaning CA_RETURN_CODE Error logged?
0 Row updated 00 No
100 No matching customer 01 No (expected business condition)
Other Unexpected DB2 error 90 Yes, via WRITE_ERROR_MESSAGE

4.2.4 Link to the VSAM Program

PLI 
EXEC CICS LINK PROGRAM(LGUCVS01)
               COMMAREA(COMM_AREA)
               LENGTH(225);

The link is unconditional. LGUCVS01 is called whatever the DB2 outcome was, including 01 and 90.

4.3 LGUCVS01 — VSAM Rewrite

4.3.1 Processing Steps

  1. Copy EIBCALEN into WS_Commarea_Len and WS_Commarea_LenF.
  2. Read the customer record with an exclusive update lock:
PLI 
EXEC CICS READ FILE('KSDSCUST')
               INTO(WS_Customer_Area)
               RIDFLD(CA_CUSTOMER_NUM)
               KEYLENGTH(10)
               UPDATE
               RESP(WS_RESP);
  1. If WS_RESP is not DFHRESP(NORMAL), save EIBRESP2 in WS_RESP2 and set CA_RETURN_CODE = '81'. Then call WRITE_ERROR_MESSAGE, issue EXEC CICS ABEND ABCODE('LGV1') NODUMP, and issue EXEC CICS RETURN.
  2. Rewrite the record from the COMMAREA data, starting at CA_CUSTOMER_NUM:
PLI 
EXEC CICS REWRITE FILE('KSDSCUST')
               FROM(CA_CUSTOMER_NUM)
               LENGTH(WS_Commarea_LenF)
               RESP(WS_RESP);
  1. If the rewrite fails, set CA_RETURN_CODE = '82', log the error, and abend with LGV2.
  2. On success the program returns, leaving CA_RETURN_CODE as it was.

6. Error Handling

6.1 Return Code and Abend Summary

Condition Program CA_RETURN_CODE Abend Logged via LGSTSQ
No COMMAREA (EIBCALEN = 0) LGUCUS01 / LGUCDB01 n/a LGCA (NODUMP) Yes
Invalid request ID LGUCUS01 99 None No
Customer not found (SQLCODE 100) LGUCDB01 01 None No

6.2 Error Logging Flow

WRITE_ERROR_MESSAGE exists in each program, and all copies follow the same pattern. The date and time are formatted first, and then LGSTSQ is linked up to twice. The first call carries ERROR_MSG. The second carries a COMMAREA dump, but only when a COMMAREA exists.

graph TD A[Error detected] --> B[Save SQLCODE or RESP/RESP2] B --> C[EXEC CICS ASKTIME] C --> D[EXEC CICS FORMATTIME
date and time] D --> E[Populate ERROR_MSG] E --> F[LINK LGSTSQ with ERROR_MSG] F --> G{EIBCALEN > 0?} G -- No --> H([Return]) G -- Yes --> I{EIBCALEN < 91?} I -- Yes --> J[CA_DATA = first EIBCALEN bytes] I -- No --> K[CA_DATA = first 90 bytes] J --> L[LINK LGSTSQ with CA_ERROR_MSG
COMMAREA= prefix] K --> L L --> H

The code pattern used for the 90-byte cap:

PLI 
EXEC CICS LINK PROGRAM('LGSTSQ')
               COMMAREA(ERROR_MSG)
               LENGTH(STG(ERROR_MSG));

IF EIBCALEN > 0 THEN DO;
   IF EIBCALEN < 91 THEN
      CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
   ELSE
      CA_DATA = LEFT(COMM_AREA_RAW, 90);
   EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(CA_ERROR_MSG)
                  LENGTH(STG(CA_ERROR_MSG));
END;

7. Constraints and Design Considerations

7.1 COMMAREA Constraints

  • A COMMAREA must be present. The EIBCALEN = 0 check is the first logic executed in LGUCUS01 and in LGUCDB01.
  • The maximum COMMAREA size is 32,500 bytes, and LGUCUS01 passes all of it to LGUCDB01.
  • LGUCDB01 forwards only the first 225 bytes to LGUCVS01. The VSAM program sees nothing beyond that.
  • LGUCVS01 uses EIBCALEN as the I/O length. It reads into a CHAR(1024) buffer, so records larger than 1,024 bytes would overflow it.

7.2 Sequencing Rules

  • The request ID is validated before any update is attempted.
  • DB2 is updated before VSAM. Both are only reached for a valid 01UCUS request.
  • In LGUCVS01, a successful READ ... UPDATE must precede the REWRITE. If the read fails, the rewrite is never attempted.
  • Error logging always runs before an abend. Within the logger, ASKTIME runs before FORMATTIME.

7.3 Data Constraints

  • The customer number is exactly 10 numeric digits. It is the DB2 key, after conversion to integer, and also the 10-byte VSAM key.
  • The DB2 update is all-or-nothing across nine fields. There is no partial update, so the caller must supply every field.
  • The diagnostic COMMAREA dump is capped at 90 bytes (CA_DATA is CHAR(90)). The message text is capped at 63 characters (EM_MSG_TEXT).

7.4 Consistency Observations

The following behaviours come directly from the program logic. Take them into account when you maintain or extend the flow:

  • Unconditional VSAM link. LGUCDB01 links to LGUCVS01 even after a DB2 01 or 90 result. The VSAM file may therefore be touched when the DB2 update did not succeed.
  • Abends hide the return code. LGUCVS01 sets 81 or 82 but then abends with NODUMP. The caller is therefore more likely to see an abend (LGV1 or LGV2) than the return code.
  • Overwritten DB2 return code. On a successful VSAM step the return code is left as LGUCDB01 set it, so a DB2 01 or 90 still reaches the caller.
  • Record scope. LGUCVS01 rewrites from CA_CUSTOMER_NUM onward, with a length derived from EIBCALEN. When it is invoked by LGUCDB01 with a 225-byte COMMAREA, that length is 225.

8. Usage Examples

8.1 Valid Update (Happy Path)

Input COMMAREA:

Field Value
CA_REQUEST_ID 01UCUS
CA_CUSTOMER_NUM 0000001234
CA_FIRST_NAME John
CA_LAST_NAME Smith
CA_POSTCODE SW1A 1AA
CA_EMAIL_ADDRESS john.smith@example.com

Flow:

  1. LGUCUS01 accepts the request and sets CA_RETURN_CODE = '00'.
  2. LGUCDB01 runs the SQL UPDATE and gets SQLCODE 0.
  3. LGUCVS01 reads and rewrites the KSDSCUST record.
  4. The caller receives CA_RETURN_CODE = '00'.

8.2 Invalid Request ID

With CA_REQUEST_ID = '01ICUS' (an inquiry code), LGUCUS01 sets CA_RETURN_CODE = '99' and returns. Neither LGUCDB01 nor LGUCVS01 is invoked, no data changes, and nothing is logged.

8.3 Customer Not Found in DB2

With CA_CUSTOMER_NUM = '0000099999' and no matching row, the SQL UPDATE returns SQLCODE 100. LGUCDB01 sets CA_RETURN_CODE = '01' without logging. It still links to LGUCVS01, and the caller receives 01 unless the VSAM step abends.

8.4 Unexpected DB2 Error

If the UPDATE fails with, for example, -803 or -904, LGUCDB01 sets CA_RETURN_CODE = '90'. It writes the date, time, LGUCDB01, customer number and SQLCODE to the queue through LGSTSQ, followed by up to 90 bytes of the COMMAREA. It then continues to the VSAM link.

8.5 VSAM Read Failure

If customer 0000009999 is not in KSDSCUST, the READ ... UPDATE returns a non-normal RESP. LGUCVS01 captures EIBRESP2, sets CA_RETURN_CODE = '81' and logs the failure. It then abends with LGV1 and never attempts the rewrite.

8.6 VSAM Rewrite Failure

If the read succeeds but the rewrite fails (for example, a file disabled or an I/O error), LGUCVS01 sets CA_RETURN_CODE = '82', logs the error, and abends with LGV2.

8.7 Missing COMMAREA

If LGUCUS01 is invoked with EIBCALEN = 0, it writes ' NO COMMAREA RECEIVED' to the queue through LGSTSQ with a timestamp and the program name. It then abends with LGCA and no dump, and no update is attempted.
