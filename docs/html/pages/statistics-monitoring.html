Statistics & Monitoring

1. Overview

The Statistics & Monitoring subsystem of the GenApp insurance application is built on three CICS PL/I programs. Together they count business transactions, turn the counts into per-interval rates, and publish the results for dashboards. All state is held in CICS named counters and Temporary Storage Queues (TSQs). The subsystem uses no DB2 tables.

Program Role Trigger Main resources touched
LGSETUP Counter initialisation: creates or resets the counter pool and the TSQs Operator-entered terminal transaction (LGSE) Counters in pool GENA; TSQs GENACNTL, GENASTAT, GENASTRT, GENAERRS
LGASTAT1 Event-processing adapter that classifies each business event by request type and outcome and updates the matching named counter Event-processing (EP) adapter channel, or a COMMAREA call Channel containers DFHEP.DATA.00001 and DFHEP.DATA.00002; counter pool GENA; TSQ GENASTRT
LGWEBST5 Periodic harvester that reads the counters, calculates deltas and stores snapshots for dashboards Self-scheduling transaction SSST, every minute Counter pool GENA; rate TSQs GENA…V

Counter names follow a single convention across all three programs:

CODE 
GENA + <6-char request id> + <2-char outcome>      e.g. GENA01ICUS00, GENA01AMOT99
  • Outcome 00 means success.
  • Outcome 99 means any failure. LGASTAT1 collapses every non-zero return code into 99.

2.2 Component Responsibilities

Layer Component Responsibility
Initialisation LGSETUP Deletes and recreates the counters at zero. Seeds GENACUSTNUM. Rebuilds the GENACNTL control records. Purges the other TSQs.
Capture LGASTAT1 Reads the request id and return code from the EP channel, or from the COMMAREA as a fallback. Normalises both and builds the counter name. Records the first-use timestamp in GENASTRT.
Aggregation LGWEBST5 Reads 17 success counters, 17 error counters and GENACUSTNUM. Computes new, old and delta values. Rolls up totals by operation type. Reschedules itself.
Storage Named counters (pool GENA) Hold the cumulative counts.
Storage TSQs Hold control data, the startup marker, and the three-item snapshot (new, old, delta) for each metric.

3. Counter Initialisation (LGSETUP)

3.1 Purpose and Invocation

LGSETUP is a terminal-driven utility that tears down and rebuilds the GenApp statistics environment. The operator can optionally supply a high customer number after the transaction id:

CODE 
LGSE 0000000050

If nothing follows the transaction id, LASTCUSTNUM keeps its default of 11. The lower bound FRSTCUSTNUM is fixed at 1.

3.2 Initialisation Flow

graph TD A([Start LGSETUP]) --> B[RECEIVE terminal input
max 80 bytes] B --> C{{Input length greater than 5}} C -- Yes --> D[LASTCUSTNUM = data after transaction id] C -- No --> E[Keep default LASTCUSTNUM = 11] D --> F[DELETEQ GENAERRS, GENASTRT,
GENASTAT, GENACNTL] E --> F F --> G[WRITEQ GENACNTL x3
label, LOW, HIGH] G --> H[DELETE then DEFINE COUNTER
GENACUSTNUM value LASTCUSTNUM] H --> I[Loop 1 to 36:
DELETE then DEFINE COUNTER value 0] I --> J[SEND TEXT HIGH CUSTOMER record] J --> K([RETURN])

3.3 Resources Created or Reset

Resource Action Resulting state
GENAERRS, GENASTRT, GENASTAT DELETEQ TS Queues removed.
GENACNTL DELETEQ TS, then three WRITEQ TS calls with NOSUSPEND 20-byte label **** GENAPP CNTL , 23-byte LOW CUSTOMER=0000000001, 24-byte HIGH CUSTOMER=0000000011 (or the supplied value).
GENACUSTNUM (pool GENA) DELETE COUNTER, then DEFINE COUNTER Seeded with LASTCUSTNUM.
36 statistics counters (pool GENA) DELETE COUNTER, then DEFINE COUNTER All set to 0.

Deleting GENASTRT matters for LGASTAT1. The next event it processes sees QIDERR and stamps a new statistics start time (see section 4.4).

3.4 Code Example: Counter Reset Loop

PLI 
/* Reset every statistics counter in pool GENA to zero */
DO COUNTER_IDX = 1 TO COUNTER_COUNT;
   EXEC CICS DELETE COUNTER(COUNTER_NAME(COUNTER_IDX))
        POOL(GENAPOOL) RESP(WS_RESP);
   EXEC CICS DEFINE COUNTER(COUNTER_NAME(COUNTER_IDX))
        POOL(GENAPOOL) VALUE(ZERO_VALUE) RESP(WS_RESP);
END;

EXEC CICS SEND TEXT FROM(WRITE_MSG_H) TERMINAL
     WAIT ERASE LENGTH(24) FREEKB;
EXEC CICS RETURN;

3.5 Behavioural Notes

  • Every CICS command uses RESP(WS_RESP), but the response is never tested. A non-existent queue or counter on delete is therefore tolerated silently. A failed define or write is also silent, so the environment can be left partly initialised.
  • COUNTER_COUNT (36) must be kept in step with the COUNTER_TABLE contents by hand.
  • A non-numeric override value causes a PL/I conversion error at runtime. No range or format validation is coded.
  • Counter names are 16-character blank-padded strings in the GENA pool.

4. Event Counting (LGASTAT1)

4.1 Purpose

LGASTAT1 is the event-processing adapter target. For each business event it builds a counter name, GENA<request><type>, and issues EXEC CICS GET COUNTER against pool GENA. The counter value is returned in TRANCOUNT. Request types and outcomes are normalised first, so related variants share one counter.

4.2 Inputs and Source Precedence

Priority Source Request id (6 chars) Return code (2 chars)
1 CICS channel containers DFHEP.DATA.00001 into WS_DATA_REQ DFHEP.DATA.00002 into WS_DATA_RC
2 COMMAREA (only if EIBCALEN > 0) CA_REQUEST_ID CA_RETURN_CODE
– Neither available Immediate EXEC CICS RETURN, nothing is counted

Only the RESP of the second GET CONTAINER is evaluated.

4.3 Processing Sequence

sequenceDiagram participant CICS as CICS / EP Adapter participant P as LGASTAT1 participant TS as TSQ GENASTRT participant C as Counter Pool GENA CICS->>P: Invoke (channel or COMMAREA) P->>P: Build WS_HEADER (eyecatcher LGASTAT1------WS) P->>CICS: GET CONTAINER DFHEP.DATA.00001 P->>CICS: GET CONTAINER DFHEP.DATA.00002 alt Containers NORMAL P->>P: Use channel request id and return code else Not NORMAL and EIBCALEN = 0 P-->>CICS: RETURN (no counting) else Not NORMAL and COMMAREA present P->>P: Use CA_REQUEST_ID and CA_RETURN_CODE end P->>TS: READQ TS GENASTRT alt QIDERR (first use) P->>CICS: ASKTIME / FORMATTIME P->>TS: WRITEQ TS date + time (16 bytes) end P->>P: Normalise request id and outcome P->>C: GET COUNTER GENA POOL(GENA) C-->>P: TRANCOUNT P-->>CICS: RETURN

4.4 First-Use Timestamp in GENASTRT

The queue holds one 16-byte record, WS_QAREA:

  • an 8-character date
  • a 2-character separator
  • a 6-character time

If READQ TS returns QIDERR, the program gets the time with ASKTIME and FORMATTIME and writes the record. This marks when statistics collection began. Later invocations read the queue but do not rewrite it.

4.5 Counter Normalisation Rules

The rules consolidate variants so that counts are not fragmented across many keys.

Condition Result Business meaning
GENACOUNTER = '02ACUS' '01ACUS' Add-customer variants counted together.
GENACOUNTER is '02ICOM', '03ICOM' or '05ICOM' '01ICOM' Inquire-commercial variants counted together.
GENATYPE ^= '00' '99' Every failure falls into one bucket.
PLI 
IF GENACOUNTER = '02ACUS' THEN GENACOUNTER = '01ACUS';
IF GENACOUNTER = '02ICOM' | GENACOUNTER = '03ICOM' | GENACOUNTER = '05ICOM'
   THEN GENACOUNTER = '01ICOM';
IF GENATYPE ^= '00' THEN GENATYPE = '99';

EXEC CICS GET COUNTER(GENACOUNT_STR) POOL(GENAPOOL)
     VALUE(TRANCOUNT) RESP(WS_RESP);
EXEC CICS RETURN;

GENACOUNT_STR is a 16-character BASED overlay of GENACOUNT. Its layout is 'GENA' (4), GENACOUNTER (6), GENATYPE (2) and four trailing blanks. Because it is an overlay, the normalisation must run before the GET COUNTER call.

graph TD A[Raw request id + return code] --> B{{Request id = 02ACUS}} B -- Yes --> B1[01ACUS] B -- No --> C{{02ICOM, 03ICOM or 05ICOM}} B1 --> C C -- Yes --> C1[01ICOM] C -- No --> D{{Return code not 00}} C1 --> D D -- Yes --> D1[Outcome = 99] D -- No --> E[Outcome = 00] D1 --> F[Counter name GENA + id + outcome + 4 blanks] E --> F

4.6 Worked Examples

Scenario Inputs Counter used
Channel input, successful motor inquiry 01IMOT / 00 GENA01IMOT00
COMMAREA fallback, failed add customer 02ACUS / 01 GENA01ACUS99. The request id is remapped, the outcome becomes 99, and GENASTRT is created if missing.
No channel and no COMMAREA – None. The program returns silently.

4.7 Behavioural Notes

  • The program’s stated purpose is that each invocation increments the matching counter through GET COUNTER. One passage in the program notes describes the call as a read of the current value. Treat the call as the single point where the event is counted. Operationally, the counter named GENA<id><00|99> should rise once per event.
  • All EXEC CICS commands use RESP and none abend the task. A missing counter is not handled explicitly.
  • The COMM_AREA structure comes from the shared include LGCMAREA.inc. COMM_AREA_RAW is limited to 32,500 bytes.

5. Periodic Harvesting (LGWEBST5)

5.1 Purpose

LGWEBST5 runs under transaction SSST and reschedules itself every minute. On each run it does the following:

  1. Computes the elapsed seconds since the previous run.
  2. Reads GENACUSTNUM and 17 success and 17 error counters.
  3. Persists a new / old / delta triple for each counter into its own TSQ.
  4. Rolls the success counts up by operation type: Inquire, Add, Update and Delete.

5.2 Self-Scheduling Harvest Cycle

sequenceDiagram participant CICS participant W as LGWEBST5 (SSST) participant I as GENA000V participant Pool as Counter Pool GENA participant R as Rate TSQs CICS->>W: Start task W->>CICS: ASKTIME / FORMATTIME W->>I: TRAN_RATE_INTERVAL: READQ item 1 (old HHMMSS) W->>I: DELETEQ, WRITEQ HHMMSS, WRITEQ elapsed seconds W->>CICS: START TRANSID SSST AFTER MINUTES 1 W->>Pool: QUERY COUNTER GENACUSTNUM W->>R: TRAN_RATE_COUNTS GENAX05V loop I = 1 to 17 W->>Pool: QUERY COUNTER CT_SUCCESS(I) W->>W: Add to COUNTSUCCESS and per-operation total W->>R: TRAN_RATE_COUNTS GENA + CT_CODE(I) + V W->>Pool: QUERY COUNTER CT_ERROR(I) W->>W: Add to COUNTERRORS end W->>R: TRAN_RATE_COUNTS GENAX00V to GENAX04V (totals) W-->>CICS: RETURN

5.3 Flow Overview

graph TD A([Start LGWEBST5]) --> B[Capture EIB fields
ASKTIME / FORMATTIME] B --> C[CALL TRAN_RATE_INTERVAL
updates GENA000V, schedules SSST] C --> D[Zero six accumulators] D --> E[QUERY COUNTER GENACUSTNUM
TRAN_RATE_COUNTS GENAX05V] E --> F[Loop I = 1 to 17] F --> G[Success counter
route by CT_OPS I / A / U / D] G --> H[TRAN_RATE_COUNTS for GENA code V] H --> I[Error counter into COUNTERRORS] I --> J{{More counters}} J -- Yes --> F J -- No --> K[Write totals GENAX00V to GENAX04V] K --> L([RETURN])

5.4 Interval Tracking: TRAN_RATE_INTERVAL

The GENA000V queue holds two items:

Item Content
1 Previous run time, HHMMSS (6 chars)
2 Elapsed seconds between the previous and current run
  • If the read of item 1 does not return NORMAL (first run), the old time defaults to 120000.
  • The queue is deleted and rewritten.
  • Both times are converted to seconds since midnight as HH*3600 + MM*60 + SS.
  • The elapsed value is ABS(new - old).
  • The next run is scheduled with the following command:
PLI 
EXEC CICS START TRANSID('SSST') AFTER MINUTES(1) RESP(WS_RESP);

ABS() prevents negative values at midnight, but the interval is then wrong. For example, 235500 followed by 000100 gives 86040 seconds instead of 360. If the task fails before the START is issued, the self-scheduling chain stops.

5.5 Snapshot Maintenance: TRAN_RATE_COUNTS

This reusable routine maintains a three-item TSQ for any metric:

graph LR A[READQ item 1
previous new value] -->|NORMAL| B[ORATEVAL = item 1] A -->|Error / first run| C[ORATEVAL = 0] B --> D[DELETEQ TS] C --> D D --> E[WRITEQ item 1 = NRATEVAL] E --> F[WRITEQ item 2 = ORATEVAL] F --> G[WRITEQ item 3 = DRATEVAL
ABS NRATEVAL - ORATEVAL]
PLI 
/* Delta calculation for one counter (illustrative) */
DRATEVAL = ABS(NRATEVAL - ORATEVAL);

Each of NRATEVAL, ORATEVAL and DRATEVAL is PIC '999999999', which is 9 digits. A value above 999,999,999 overflows silently.

5.6 Queue Catalogue

TSQ Content Items
GENA000V Interval timing 1 = previous HHMMSS, 2 = elapsed seconds
GENAX05V GENACUSTNUM customer sequence value 1 = new, 2 = old, 3 = delta
GENA<code>V (17 queues, for example GENA100V) One per success counter in CT_SUCCESS 1 = new, 2 = old, 3 = delta
GENAX00V Total successes (COUNTSUCCESS) 1 = new, 2 = old, 3 = delta
GENAX01V Total inquires (COUNTINQ) 1 = new, 2 = old, 3 = delta
GENAX02V Total adds (COUNTADD) 1 = new, 2 = old, 3 = delta
GENAX03V Total updates (COUNTUPD) 1 = new, 2 = old, 3 = delta
GENAX04V Total deletes (COUNTDEL) 1 = new, 2 = old, 3 = delta

COUNTERRORS is accumulated but is not written to any queue.

5.7 Operation Routing

CT_SUCCESS, CT_ERROR, CT_CODE and CT_OPS are parallel static arrays, so the index I must stay aligned across all four.

PLI 
DO I = 1 TO 17;
   EXEC CICS QUERY COUNTER(CT_SUCCESS(I)) POOL(GENAPOOL)
        VALUE(COUNTVAL) RESP(WS_RESP);
   COUNTSUCCESS = COUNTSUCCESS + COUNTVAL;
   SELECT (SUBSTR(CT_OPS,I,1));
      WHEN ('I') COUNTINQ = COUNTINQ + COUNTVAL;
      WHEN ('A') COUNTADD = COUNTADD + COUNTVAL;
      WHEN ('U') COUNTUPD = COUNTUPD + COUNTVAL;
      WHEN ('D') COUNTDEL = COUNTDEL + COUNTVAL;
   END;
   WS_TSQNAME = 'GENA' || CT_CODE(I) || 'V';
   NRATEVAL   = COUNTVAL;
   CALL TRAN_RATE_COUNTS;
   EXEC CICS QUERY COUNTER(CT_ERROR(I)) POOL(GENAPOOL)
        VALUE(COUNTVAL) RESP(WS_RESP);
   COUNTERRORS = COUNTERRORS + COUNTVAL;
END;

This code is a representative sketch of the documented logic. SELECT has no OTHERWISE clause, so any other character in CT_OPS raises a PL/I error.

5.8 Worked Example: Two Consecutive Runs

Run GENA01ICUS00 GENA100V item 1 (new) item 2 (old) item 3 (delta)
First (no TSQ) 50 000000050 000000000 000000050
Second (about 60 s later) 75 000000075 000000050 000000025

Dashboards read item 3 to show transactions per interval. They use GENA000V item 2 to normalise this into a per-second rate.

7. Operational Considerations

7.1 Deployment Prerequisites

  • The named counter pool GENA must be defined in the CICS region.
  • Transaction SSST must be defined and must reference program LGWEBST5. A transaction such as LGSE must be defined for LGSETUP.
  • The EP adapter configuration must populate DFHEP.DATA.00001 and DFHEP.DATA.00002 for LGASTAT1.
  • LGSETUP must be run before the first harvest cycle. Otherwise the counters do not exist and LGWEBST5 silently carries forward stale COUNTVAL values.

7.2 Recommended Startup Order

graph LR A[1. Run LGSE
reset counters and queues] --> B[2. Enable EP adapter
LGASTAT1 starts counting] B --> C[3. Start SSST once
LGWEBST5 self-schedules] C --> D[4. Dashboards read rate TSQs]

7.3 Known Limitations

Area Limitation
Counter set mismatch LGSETUP defines 36 statistics counters. LGWEBST5 harvests 17 success counters, 17 error counters and GENACUSTNUM. Keep the three counter lists consistent.
Midnight crossing ABS() gives a wrong interval for the first run after midnight.
First-run interval A missing GENA000V defaults the old time to 120000, so the first interval is not meaningful.
Missing counters QUERY COUNTER failures are ignored in LGWEBST5, and GET COUNTER failures are ignored in LGASTAT1.
Rate field width 9-digit picture fields overflow silently.
Date formats LGASTAT1 writes DDMMYYYY to GENASTRT. LGWEBST5 formats dates as MM/DD/YYYY. Consumers must not assume a common format.
Global queues Queue names are static, so concurrent instances share the same queues.
Error visibility All three programs use RESP without branching on most results. Failures are not reported, and the harvest chain stops silently if the START fails.

7.4 Summary of Error-Handling Patterns

Program Pattern
LGSETUP Passive RESP capture. Best-effort delete and define. Terminal confirmation is the only completion signal.
LGASTAT1 Channel-to-COMMAREA fallback. Graceful return when no input exists. QIDERR drives first-use initialisation. Normalisation prevents lookups of undefined counters.
LGWEBST5 Defaults for missing history (ORATEVAL = 0, WS_OLDV = '120000'). ABS() guards deltas. Other failures are ignored.
