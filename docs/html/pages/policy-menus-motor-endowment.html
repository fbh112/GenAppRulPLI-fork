Policy CICS Menus — Motor & Endowment

1. Overview

The Policy CICS Menus are two interactive, BMS-driven terminal programs written in PL/I. They give operators a front end for maintaining insurance policies in the GenApp General Insurance application:

Program Transaction BMS Map (Mapset SSMAP) Policy Type
LGTESTP1 SSP1 SSMAPP1 Motor
LGTESTP2 SSP2 SSMAPP2 Endowment (life)

Both programs offer the same four menu options, selected with a one-character option field:

Option Operation Backend program linked
1 Inquire LGIPOL01
2 Add LGAPOL01
3 Delete LGDPOL01
4 Update (inquire, then edit, then update) LGIPOL01, then LGUPOL01

Both programs are screen-handling and routing layers only. They do the following:

  • Receive input from a BMS map.
  • Load a shared 32,500-byte COMM_AREA.
  • Set a six-character CA_REQUEST_ID that tells the backend which operation to run.
  • Call the backend with EXEC CICS LINK.
  • Show the result or an error message.
  • Return to CICS pseudo-conversationally under their own transaction ID.

Neither program issues SQL. All DB2 access happens in the linked backend programs.

2.1 Component Overview

Endowment Menu] P1 --- M1[BMS Map SSMAPP1

The menus sit at the top of a layered design:

  1. Presentation layer: the BMS maps SSMAPP1 and SSMAPP2, both in mapset SSMAP.
  2. Menu layer: LGTESTP1 and LGTESTP2. They do option routing, COMM_AREA population, and error display.
  3. Orchestrator layer: LGIPOL01, LGAPOL01, LGDPOL01 and LGUPOL01. These are shared by both policy types and select the policy type from CA_REQUEST_ID.
  4. Data layer: DB2 backend programs. These are called by the orchestrators, not by the menus.

2.2 Shared Resources

Resource Description
LGCMAREA copybook Defines the 32,500-byte COMM_AREA. It is expanded inline in each program.
SSMAP copybook Defines the BMS I/O structures SSMAPC1, SSMAPP1 to SSMAPP5. It is expanded inline.
DFHEIPTR The EIB pointer, passed as the first procedure parameter.
COMM_AREA_PTR The pointer to the COMMAREA, passed as the second parameter.

2.3 Request ID Matrix

CA_REQUEST_ID is set immediately before each LINK. The backends use it to decide the operation and policy type.

Operation Motor (LGTESTP1) Endowment (LGTESTP2)
Inquire 01IMOT 01IEND
Add 01AMOT 01AEND
Delete 01DMOT 01DEND
Update 01UMOT 01UEND

3. Pseudo-Conversational Lifecycle

Both programs use the same control skeleton. They differ only in transaction ID, map, and field prefix (ENP1…/ERP1… for motor, ENP2…/ERP2… for endowment).

SEND MAP ERASE] C -- No --> AG INIT --> AG[A_GAIN:
HANDLE AID and CONDITION] AG --> RX[RECEIVE MAP] RX --> SEL{SELECT option} SEL -- 1 --> OP1[Inquire] SEL -- 2 --> OP2[Add] SEL -- 3 --> OP3[Delete] SEL -- 4 --> OP4[Update] SEL -- Other --> BAD[Invalid option message

3.1 First-Time Entry

When EIBCALEN = 0, no COMMAREA was passed, so this is the first invocation. The program does the following:

  • It points COMM_AREA_PTR at local storage, BASE_COMM_AREA.
  • It clears the output map.
  • It resets CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER.
  • It sets the numeric display fields to zeros.
  • It sends the map with ERASE.
PLI 
/* LGTESTP1 – first-time entry (conceptual excerpt) */
Exec CICS SEND MAP ('SSMAPP1')
          MAPSET('SSMAP')
          ERASE;

For the motor map, the initial defaults are:

Field Value
ENP1CNOO '0000000000'
ENP1PNOO '0000000000'
ENP1VALO '000000'
ENP1CCO '00000'
ENP1ACCO '000000'
ENP1PREO '000000'

3.2 Attention-Key and Condition Handling

At A_GAIN, each program registers handlers before receiving the map:

PLI 
Exec CICS HANDLE AID CLEAR(CLEARIT) PF3(ENDIT);
Exec CICS HANDLE CONDITION MAPFAIL(ENDIT);
Exec CICS RECEIVE MAP('SSMAPP1') INTO(SSMAPP1I) MAPSET('SSMAP');
Event Target Result
PF3 ENDIT Sends the end message and returns with no TRANSID. The session ends.
MAPFAIL (Enter with no data) ENDIT Same as PF3.
CLEAR CLEARIT Repaints the map with MAPONLY and returns with the TRANSID. The session continues.

3.3 Return Paths

PLI 
/* Continue the conversation */
Exec CICS RETURN TRANSID('SSP1') COMMAREA(COMM_AREA);

/* Terminate */
Exec CICS SEND TEXT FROM(MSGEND) ERASE FREEKB;
Exec CICS RETURN;

The end message is 'Transaction ended'. In LGTESTP1 it is padded to 'Transaction ended '.

4.2.1 Option 1 — Inquiry

The program takes the customer and policy keys from the output overlays ENP1CNOO and ENP1PNOO. It links to LGIPOL01 and, on success, copies the returned CA_* fields into the map and re-sends it.

PLI 
CA_REQUEST_ID   = '01IMOT';
CA_CUSTOMER_NUM = ENP1CNOO;
CA_POLICY_NUM   = ENP1PNOO;
Exec CICS LINK PROGRAM('LGIPOL01')
               COMMAREA(COMM_AREA)
               LENGTH(32500);
If CA_RETURN_CODE > 0 Then Go To NO_DATA;

4.2.2 Option 2 — Add

The program uses ENP1CNOI for the customer number. It zeroes or blanks the payment and broker fields, because the screen has no input for them. It then copies all the motor fields from the map into CA_MOTOR and links to LGAPOL01. On a non-zero return code it rolls back and branches to NO_ADD. On success it echoes the new customer and policy numbers, clears the option field, and shows 'New Motor Policy Inserted'.

PLI 
CA_REQUEST_ID = '01AMOT';
/* ... map ENP1*I fields to CA_* motor fields ... */
Exec CICS LINK PROGRAM('LGAPOL01')
               COMMAREA(COMM_AREA)
               LENGTH(32500);
If CA_RETURN_CODE > 0 Then Do;
   Exec CICS Syncpoint Rollback;
   Go To NO_ADD;
End;

4.2.3 Option 3 — Delete

The program links to LGDPOL01 with '01DMOT'. On failure it rolls back and goes to NO_DELETE. On success it blanks the detail fields (dates, make, model, value, registration, colour, CC, manufactured) and shows 'Motor Policy Deleted'.

4.2.4 Option 4 — Update (Two Phases)

Update is a read-before-write sequence inside a single task dispatch:

  1. Phase A: It sets 01IMOT and links to LGIPOL01. A failure goes to NO_DATA. On success it sends the populated map.
  2. Wait for edits: It issues a second EXEC CICS RECEIVE MAP in the same task.
  3. Phase B: It sets 01UMOT, copies the edited fields into the COMMAREA, and links to LGUPOL01. A failure goes to NO_UPD. On success it shows 'Motor Policy Updated'.

4.2.5 Invalid Option

PLI 
ERP1FLDO = 'Please enter a valid option';
ENP1OPTL = -1;           /* position cursor on option field */
Exec CICS SEND MAP('SSMAPP1') MAPSET('SSMAP') CURSOR;

8. Error Handling

8.1 Error Routing

Every LINK is followed by a check of CA_RETURN_CODE. A value above zero diverts to an error label. Each label sets a message in the message field (ERP1FLDO or ERP2FLDO) and falls into the common ERROR_OUT routine.

Label Trigger Motor message Endowment message
NO_ADD (RC = 70) Customer missing Customer does not exist Customer does not exist
NO_ADD (other) Add failed Error Adding Motor Policy Error Adding Life Policy
NO_UPD Update failed Error Updating Motor Policy Error Updating Life Policy
NO_DELETE Delete failed Error Deleting Motor Policy Error Deleting Life Policy
NO_DATA Inquiry failed No data was returned. No data was returned.
PLI 
NO_ADD:
  Select (CA_RETURN_CODE);
    When (70)  ERP1FLDO = 'Customer does not exist';
    Otherwise  ERP1FLDO = 'Error Adding Motor Policy';
  End;
  Go To ERROR_OUT;

8.2 Common ERROR_OUT

graph LR E1[NO_ADD] --> EO E2[NO_UPD] --> EO E3[NO_DELETE] --> EO E4[NO_DATA] --> EO EO[ERROR_OUT:
SEND MAP with message] --> RS[Reset map and
COMM_AREA_RAW] RS --> RT[ENDIT_STARTIT:
RETURN TRANSID]

ERROR_OUT does three things:

  1. It sends the map with the error text.
  2. It blanks the output map, COMM_AREA_RAW, CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER.
  3. It returns with the transaction ID, so the user can retry with a clean state.

8.3 Rollback Policy

Operation Rollback on failure?
Inquire No (read-only)
Add Yes: EXEC CICS SYNCPOINT ROLLBACK
Delete Yes: EXEC CICS SYNCPOINT ROLLBACK
Update No explicit rollback in the menu

9. Constraints and Design Notes

  • Option values: only '1' to '4' are accepted. Anything else produces Please enter a valid option with the cursor on the option field.
  • COMMAREA size: the size is fixed at 32,500 bytes (COMM_AREA_RAW CHAR(32500)) and is used on every LINK. Backends reject a wrong length.
  • Field widths: values wider than the field are truncated silently by PL/I assignment. For example, the screen’s life-assured field is 25 characters, while the COMMAREA field is 31.
  • Payment and broker data: CA_PAYMENT, CA_BROKERID and CA_BROKERSREF are hard-coded to zero or blank on add and update, because the screens have no inputs for them.
  • Update sequencing: the update cannot proceed unless the preceding inquiry succeeds.
  • State between cycles: state survives pseudo-conversational cycles only through the COMMAREA passed on RETURN.
  • Terminating keys: PF3 and MAPFAIL end the session. CLEAR resets the screen but keeps the session alive.
  • Return code discrimination: only RC 70 on add gets a specific message. All other failures use generic messages.
  • Unused maps: both programs declare the other SSMAP map structures through the shared copybook, but they do not use them.
