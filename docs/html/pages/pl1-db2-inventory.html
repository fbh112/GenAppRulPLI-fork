PL/I Program & DB2 Table Inventory

1. Overview

GenApp is a general insurance application running on IBM z/OS, implemented entirely in Enterprise PL/I. It supports CICS online transactions for managing customers and insurance policies across four product lines — Motor, Endowment, House, and Commercial — and includes batch programs for reporting and data extraction.

This inventory serves as the authoritative reference matrix for:

  • Change-impact assessment — identifying which programs are affected by a schema or logic change
  • Test scoping — determining the full set of programs to test when a DB2 table or shared service is modified
  • Migration planning — understanding data ownership, access patterns, and inter-program dependencies before modernisation

The application comprises 35 PL/I programs (plus 6 shared include files) organised into a strict three-tier architecture:

Tier Role Programs
Tier 1 Presentation / BMS Menu 5
Tier 2 Orchestration / Business Logic 7
Tier 3 — DB2 DB2 Backend I/O 8
Tier 3 — VSAM VSAM Backend I/O 7
Supporting Cross-cutting CICS Services 4
Batch Batch Main + Subroutines 4
Total 35

2. System Architecture

2.1 Three-Tier Layering

The application enforces a clean separation of concerns across three tiers. Tier 1 programs handle all terminal I/O via BMS maps. Tier 2 programs contain business logic and route requests dynamically via EXEC CICS LINK. Tier 3 programs perform all physical I/O — either against DB2 tables or VSAM KSDS datasets.

3.2 Tier 2 — Orchestration / Business Logic Programs

These programs validate the COMMAREA, apply business rules, and dispatch dynamically to the appropriate backend program using EXEC CICS LINK with a program name variable. They hold no direct DB2 or VSAM dependencies themselves — with the notable exception of LGACUS01, which performs its own direct DB2 inserts before delegating VSAM mirroring.

The following sequence diagram illustrates the typical end-to-end flow for a policy Add operation, from terminal input through all three tiers:

Attribute Value

Special note: LGACUS01 is the only orchestrator that directly executes SQL — it inserts both a CUSTOMER and a POLICY row itself before calling downstream programs for VSAM mirroring and security record creation. This makes it a cross-domain program straddling both the Customer and Policy ownership boundaries.

SQL 
/* Embedded SQL in LGACUS01 — Tier 2 orchestrator */
EXEC SQL
    INSERT INTO CUSTOMER
        (CUSTOMERID, FIRSTNAME, LASTNAME, ...)
    VALUES
        (:WS-CUSTOMERID, :WS-FIRSTNAME, :WS-LASTNAME, ...);

EXEC SQL
    INSERT INTO POLICY
        (POLICYID, CUSTOMERID, POLICYTYPE, ...)
    VALUES
        (:WS-POLICYID, :WS-CUSTOMERID, :WS-POLICYTYPE, ...);

3.3 Tier 3 — Backend DB2 Programs

These programs perform all embedded SQL operations. They communicate entirely via COMMAREA and return results to the calling orchestrator. Each program also calls LGSTSQ on any SQL error.

3.3.1 LGAPDB01 — Add Policy (DB2)

Attribute Value
Type CICS — DB2 Backend
Entry Proc(COMM_AREA_PTR) Options(Main)
Calls (CICS LINK) LGAPVS01, LGSTSQ
DB2 Tables POLICY (INSERT), ENDOWMENT (INSERT), HOUSE (INSERT), MOTOR (INSERT), COMMERCIAL (INSERT), CLAIM (INSERT)
VSAM Via LGAPVS01 → KSDSPOLY

LGAPDB01 is the most database-intensive program in the application, writing to six tables in a single request path. A representative code pattern for policy-type routing:

PLI 
/* LGAPDB01 — route INSERT by policy type */
SELECT (CA_POLICY_TYPE);
  WHEN ('E')  EXEC SQL INSERT INTO ENDOWMENT  VALUES (...);
  WHEN ('H')  EXEC SQL INSERT INTO HOUSE      VALUES (...);
  WHEN ('M')  EXEC SQL INSERT INTO MOTOR      VALUES (...);
  WHEN ('C')  EXEC SQL INSERT INTO COMMERCIAL VALUES (...);
  WHEN ('L')  EXEC SQL INSERT INTO CLAIM      VALUES (...);
END;

3.3.2 LGIPDB01 — Inquire Policy (DB2)

3.4 Tier 3 — Backend VSAM Programs

These programs handle all CICS File Control operations against two VSAM KSDS datasets: KSDSPOLY for policy records and KSDSCUST for customer records. They are invoked by DB2 backend programs to maintain a parallel VSAM image of every DB2 write, providing a dual-persistence strategy.

3.5 Supporting CICS Programs

These programs provide cross-cutting infrastructure services consumed by programs across all tiers.

3.5.1 LGSTSQ — Error Message Logger

Attribute Value
Type CICS — Shared Service
Entry Proc(COMM_AREA_PTR) Options(Main)
Role Centralised error writer — up to 90 bytes of message text received via COMMAREA, written to CSMT TDQ and GENAERRS TSQ
TDQ / TSQ CSMT (TDQ write), GENAERRS (TSQ write)
DB2 None

Called by virtually every CICS program on any error condition. Its consistent usage across all three tiers means it must be treated as a critical shared dependency in any migration or refactoring effort.

3.5.2 LGASTAT1 — Statistics Counter Update

Attribute Value
Type CICS — Event Processing Adapter
Entry Proc(COMM_AREA_PTR) Options(Main)
Role Reads request ID and return code from DFHEP channel or COMMAREA, then increments named counter GENA<request><rc> in the GENA pool
Named Counters GENA pool (increment)
TS Queues GENASTRT (read)

3.5.3 LGWEBST5 — Statistics Collector

Attribute Value
Type CICS — Statistics Daemon
Entry Proc Options(Main) (no COMMAREA)
Role Queries GENA named counters, computes per-minute transaction rates, stores delta values in GENA<code>V TS queues, and re-starts itself every minute via transaction SSST
Named Counters GENA pool (QUERY)
TS Queues GENA<code>V (read/write)

3.5.4 LGSETUP — GenApp Environment Setup

Attribute Value
Type CICS — Administrative Utility
Entry Proc Options(Main) (no COMMAREA)
Role One-time initialisation — deletes and recreates GENAERRS / GENASTRT TS queues and all 36 named transaction counters in the GENA pool
Named Counters GENA pool — 36 counters (define/reset)
TS Queues GENAERRS, GENASTRT (DELETE), GENACNTL (WRITE)

3.6 Batch Programs

These programs run outside CICS with no EXEC CICS statements. They use embedded SQL directly against DB2 via the DB2 batch attachment facility.

3.6.1 LGBATCH — Batch Customer Report

Attribute Value
Type Batch — Main
Entry Proc Options(Main)
Static CALL LGBATCHF
DB2 Tables CUSTOMER (SELECT)
Input Files CUSTIN (sequential, FB/10)
Output Files CUSTRPT (sequential, FB/80)

Reads customer numbers sequentially from CUSTIN, selects each customer from DB2, and writes a formatted 80-byte report line to CUSTRPT via LGBATCHF.
