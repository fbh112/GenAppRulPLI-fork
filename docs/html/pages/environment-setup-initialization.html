Environment Setup & Queue Management

This page documents the GenApp environment reset and configuration program, LGSETUP. It is a CICS PL/I program that rebuilds the CICS runtime infrastructure the insurance application depends on. It reinitialises the temporary storage queues (control, statistics, start, errors), publishes the customer number range, and resets the named counter pool GENA.

1. Overview

1.1 Purpose

LGSETUP initialises or re-initialises the GenApp insurance application environment. An operator runs it from a terminal, usually with the transaction ID LGSE, and can optionally supply a high customer number. The program then does the following:

  • Deletes and recreates the GenApp temporary storage (TS) queues: control (GENACNTL), statistics (GENASTAT), start (GENASTRT) and errors (GENAERRS).
  • Writes the environment label and the customer number range (low and high) into the control queue.
  • Deletes and redefines the named customer-number counter GENACUSTNUM in pool GENA, seeded with the configured upper bound.
  • Resets the 36 transaction statistics counters to zero. They cover insert, add, delete and update operations for customer, motor, endowment, house and commercial policies.

Every later GenApp transaction then starts from a clean, consistent state.

1.2 Key Characteristics

Characteristic Detail
Language / runtime PL/I, LGSETUP: Proc Options(Main), under CICS

3. Inputs

3.1 Terminal Input

Field Description
WS_RECV 80-byte buffer filled by EXEC CICS RECEIVE.
WS_RECV_TRANID The 5-character transaction ID portion.
WS_RECV_DATA The 74-character data portion. It may carry the high customer number, for example LGSE 0000000011.
WS_RECV_LEN Initialised to 80. After the receive it holds the actual length entered.

3.2 Optional Operator Parameter

LASTCUSTNUM is initialised to 11 but can be overridden at runtime. If WS_RECV_LEN is greater than 5, the trailing data is converted and assigned to LASTCUSTNUM. That value sets the upper bound written to the control queue and the initial value of the GENACUSTNUM counter.

4. Processing Flow

4.1 End-to-End Flow

FRSTCUSTNUM / LASTCUSTNUM] I --> J[WRITEQ TS: environment label - 20 bytes] J --> K[WRITEQ TS: low customer - 23 bytes] K --> L[WRITEQ TS: high customer - 24 bytes] L --> M[DELETE COUNTER GENACUSTNUM] M --> N[DEFINE COUNTER GENACUSTNUM
VALUE = LASTCUSTNUM] N --> O[COUNTER_IDX = 1] O --> P{COUNTER_IDX <= 36?} P -- Yes --> Q[DELETE COUNTER name] Q --> R[DEFINE COUNTER name VALUE 0] R --> S[Increment COUNTER_IDX] S --> P P -- No --> T[SEND TEXT: high customer record] T --> U([EXEC CICS RETURN])

4.2 Sequence of Operations

sequenceDiagram participant Op as Operator participant LG as LGSETUP participant TS as CICS TS Queues participant NC as Named Counter Pool GENA Op->>LG: LGSE [high customer number] LG->>LG: RECEIVE, apply optional override LG->>TS: DELETEQ GENAERRS, GENASTRT, GENASTAT, GENACNTL LG->>TS: WRITEQ GENACNTL (label, low, high) LG->>NC: DELETE then DEFINE GENACUSTNUM (VALUE LASTCUSTNUM) loop 36 statistics counters LG->>NC: DELETE COUNTER LG->>NC: DEFINE COUNTER VALUE 0 end LG-->>Op: SEND TEXT HIGH CUSTOMER=nnnnnnnnnn LG->>LG: EXEC CICS RETURN

4.3 Step-by-Step Description

  1. Receive terminal input. EXEC CICS RECEIVE reads up to 80 characters into WS_RECV.
  2. Optional override. If WS_RECV_LEN > 5, the program subtracts 5 and converts the data portion into LASTCUSTNUM. Otherwise the default of 11 stands.
  3. Delete the TS queues. Four DELETEQ TS calls purge GENAERRS, GENASTRT, GENASTAT and GENACNTL.
  4. Rebuild the control queue. The low and high fields are stamped, then three WRITEQ TS ... NOSUSPEND calls write the records.
  5. Reset the customer counter. GENACUSTNUM is deleted and redefined with VALUE(LASTCUSTNUM).
  6. Reset the statistics counters. A loop over 36 entries deletes each counter and redefines it at zero.
  7. Confirm to the terminal. SEND TEXT shows the high customer record.
  8. Return. EXEC CICS RETURN ends the task.

5. Temporary Storage Queue Management

5.1 Queue Inventory

Variable Queue Purpose Action
STSQ_NAME GENACNTL Control queue holding environment label and customer range Deleted, then rebuilt with 3 records
STSQ_STAT GENASTAT Transaction statistics queue Deleted
STSQ_STRT GENASTRT Start queue Deleted
STSQ_ERRS GENAERRS Error queue Deleted

All four names are declared CHAR(8) STATIC, so they cannot change at runtime.

5.2 Queue Lifecycle

stateDiagram-v2 [*] --> Existing: Prior run state Existing --> Deleted: DELETEQ TS Deleted --> Rebuilt: WRITEQ TS (GENACNTL only) Deleted --> Absent: GENAERRS, GENASTRT, GENASTAT Rebuilt --> [*] Absent --> [*]

5.3 Control Queue Records

The control queue GENACNTL receives three fixed-length records:

Record Field Length Content
1 WRITE_MSG_E 20 '**** GENAPP CNTL '
2 WRITE_MSG_L + WRITE_MSG_LOW 23 'LOW CUSTOMER=' followed by the 10-digit value of FRSTCUSTNUM (always 1)
3 WRITE_MSG_H + WRITE_MSG_HIGH 24 'HIGH CUSTOMER=' followed by the 10-digit value of LASTCUSTNUM

Consumers of GENACNTL must parse records at these exact lengths.

5.4 Code Examples: Queue Operations

Input reception and the optional override:

PLI 
EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN) RESP(WS_RESP)

If WS_RECV_LEN > 5, the program takes SUBSTR(WS_RECV_DATA,1,WS_RECV_LEN-5) and assigns it to LASTCUSTNUM.

Queue deletion, shown for the error queue:

PLI 
EXEC CICS DELETEQ TS QUEUE(STSQ_ERRS) RESP(WS_RESP)

Control queue write:

PLI 
EXEC CICS WRITEQ TS QUEUE(STSQ_NAME) FROM(WRITE_MSG_H)
          NOSUSPEND LENGTH(24)

6. Customer Number Range and Named Counters

6.1 Customer Number Range

Item Declaration Behaviour
FRSTCUSTNUM FIXED BIN(31) INIT(1) Fixed low boundary, never modified
LASTCUSTNUM FIXED BIN(31) INIT(11) High boundary. The default can be overridden from terminal input.
WRITE_MSG_LOW, WRITE_MSG_HIGH PIC '9999999999' 10-digit unsigned display fields

6.2 Named Counter Pool GENA

Every counter lives in the pool named by GENAPOOL, which is CHAR(8) STATIC INIT('GENA').

graph TD POOL[Pool GENA] --> CUST[GENACUSTNUM
seeded with LASTCUSTNUM] POOL --> STATS[36 statistics counters
seeded with 0] STATS --> OPS[Operations:
Insert, Add, Delete, Update] STATS --> ENT[Entities:
Customer, Motor, Endowment,
House, Commercial] STATS --> OUT[Outcomes:
00 success / 99 failure]

Counter names are fixed 16-character strings, padded with blanks. Examples from the table are GENA01ICUS00, GENA01ICUS99, GENA01IMOT99 and GENA01UCUS99.

6.3 Code Examples: Counter Operations

Customer number counter reset:

PLI 
EXEC CICS DELETE COUNTER(GENACOUNT) POOL(GENAPOOL) RESP(WS_RESP)
EXEC CICS DEFINE COUNTER(GENACOUNT) POOL(GENAPOOL)
          VALUE(LASTCUSTNUM) RESP(WS_RESP)

Statistics counter reset loop:

PLI 
DO COUNTER_IDX = 1 TO COUNTER_COUNT;
   EXEC CICS DELETE COUNTER(COUNTER_NAME(COUNTER_IDX))
             POOL(GENAPOOL) RESP(WS_RESP);
   EXEC CICS DEFINE COUNTER(COUNTER_NAME(COUNTER_IDX))
             POOL(GENAPOOL) VALUE(ZERO_VALUE) RESP(WS_RESP);
END;

The loop is driven by COUNTER_COUNT (FIXED BIN(15) STATIC INIT(36)). ZERO_VALUE is FIXED BIN(31) INIT(0).

7. Outputs and Terminal Confirmation

7.1 Summary of Outputs

Output Resource Result
Control queue records GENACNTL Label, low and high customer records
Purged queues GENAERRS, GENASTRT, GENASTAT Emptied
Customer counter GENACUSTNUM in GENA Defined with LASTCUSTNUM
Statistics counters 36 counters in GENA Defined with 0
Terminal text Operator screen HIGH CUSTOMER=nnnnnnnnnn

7.2 Code Example: Terminal Confirmation

PLI 
EXEC CICS SEND TEXT FROM(WRITE_MSG_H) TERMINAL WAIT ERASE
          LENGTH(24) FREEKB

ERASE clears the screen, WAIT holds until the output completes, and FREEKB releases the keyboard. Only the high customer record is echoed to the screen. The label and low records are written to the queue only.

8. Dependencies

8.1 CICS Services

Service Commands Use
Transaction manager / terminal RECEIVE, SEND TEXT, RETURN Input, confirmation and task end
Temporary Storage DELETEQ TS, WRITEQ TS Queue purge and control queue rebuild
Named Counter DELETE COUNTER, DEFINE COUNTER Counter reset in pool GENA

The named counter pool GENA must be available in CICS.

8.2 Runtime and Internal Configuration

  • Operator input. The optional high customer number after the transaction ID, for example LGSE 0000000011.
  • FRSTCUSTNUM. Hardcoded to 1.
  • LASTCUSTNUM. Defaults to 11 and can be overridden from terminal input.
  • COUNTER_TABLE / COUNTER_ARRAY. The static list of 36 counter identifiers.

9. Constraints

9.1 Input and Data Constraints

  • The receive buffer is fixed at 80 bytes (5 for the transaction ID and 74 for data), and longer input is truncated.
  • The override is validated by length only. No format or range check is applied before conversion to FIXED BIN(31), so non-numeric input causes a PL/I conversion error at runtime. Values beyond about 2.1 billion overflow.
  • The display fields are 10-digit unsigned pictures.

9.2 Counter and Queue Constraints

  • Exactly 36 statistics counters are processed. COUNTER_COUNT must be updated by hand if the table changes.
  • GENACUSTNUM starts at LASTCUSTNUM, not at 1 or 0.
  • Queue names and record lengths are hardcoded (20, 23 and 24 bytes).
  • The control queue writes use NOSUSPEND.

9.3 Ordering Constraints

graph LR R[1. RECEIVE and override] --> D[2. Delete 4 TS queues] D --> W[3. Write GENACNTL records] W --> CU[4. Reset GENACUSTNUM] CU --> ST[5. Reset 36 statistics counters] ST --> SD[6. SEND TEXT] SD --> RT[7. RETURN]

The input is received first because every later step depends on the final LASTCUSTNUM. The queues are deleted before the control queue is rewritten, so no stale records remain. The terminal confirmation comes last, so the operator sees it only after the reset is complete.

10. Error Handling

10.1 Passive Response Capture

Every EXEC CICS command specifies RESP(WS_RESP), which suppresses the default condition handling. The program never tests WS_RESP. It has no IF WS_RESP checks, no EXEC CICS ABEND, and no PL/I ON condition handlers.

10.2 Error Behaviour Summary

Scenario Behaviour
Only the transaction ID entered LASTCUSTNUM stays at 11.
Queue does not exist (for example QIDERR) The failure is absorbed and the reset continues.
Counter does not exist on delete The failure is ignored and DEFINE COUNTER proceeds.
WRITEQ TS fails (NOSUSPEND) The failure is recorded in WS_RESP but not acted on, so the control queue may be incomplete.
Counter pool unavailable Execution continues in a partially initialised state.
Terminal display Acts as an implicit completion signal. If it is missing, the setup did not finish.

10.3 Error Flow

graph TD CMD[EXEC CICS command with RESP WS_RESP] --> RESP[Response stored in WS_RESP] RESP --> NOCHK[No test of WS_RESP] NOCHK --> NEXT[Continue to next operation] NEXT --> END[SEND TEXT and RETURN]

11. Usage Examples

11.1 Default Setup (No High Customer Number)

Input: LGSE (transaction ID only).

  • WS_RECV_LEN is 5, so the override branch is not taken.
  • LASTCUSTNUM stays at 11.
  • All four queues are deleted, and GENACNTL is rebuilt with these records:
CODE 
**** GENAPP CNTL    
LOW CUSTOMER=0000000001
HIGH CUSTOMER=0000000011
  • GENACUSTNUM is redefined with VALUE(11).
  • All 36 statistics counters are redefined with VALUE(0).

Terminal output:

CODE 
HIGH CUSTOMER=0000000011

11.2 Custom High Customer Number

Input: LGSE 0000000050 (15 characters).

  • WS_RECV_LEN is 15, which is greater than 5, so the override branch is taken.
  • The length is adjusted to 10, and LASTCUSTNUM is set from SUBSTR(WS_RECV_DATA, 1, 10), giving 50.
  • GENACNTL is rebuilt with LOW CUSTOMER=0000000001 and HIGH CUSTOMER=0000000050.
  • GENACUSTNUM is redefined with VALUE(50).
  • All 36 statistics counters are reset to 0.

Terminal output:

CODE 
HIGH CUSTOMER=0000000050

Any program that reads GENACNTL will see this range as the valid customer number boundaries.

12. Database Access

LGSETUP does not access any Db2 tables. All its external interaction is through CICS Temporary Storage queues and CICS Named Counters, and it contains no EXEC SQL statements.
