Statistics Collection (LGASTAT1 & LGWEBST5)

The statistics collection subsystem in the GenApp insurance application provides operational visibility into real-time business transaction throughput, success rates, and system errors. The pipeline consists of two collaborating CICS PL/I components: LGASTAT1, which acts as an event-driven adapter that classifies, normalizes, and tallies transaction requests and outcomes into CICS named counters, and LGWEBST5, a self-scheduling background daemon that harvests these counters every minute, calculates interval deltas (rates of change), and publishes absolute and rate snapshots to CICS Temporary Storage Queues (TSQs) for consumption by dashboards and monitoring facilities.

1. Overview

The GenApp statistics pipeline delivers continuous monitoring by separating real-time transaction event recording from periodic metric harvesting. This decoupled architecture minimizes runtime overhead on online transactions while ensuring that operational metrics are accurately aggregated and formatted for reporting.

1.1 Role of LGASTAT1 (Real-Time Counter Update)

LGASTAT1 is invoked at the completion of individual business transactions either directly or through CICS Event Processing (EP) adapters. It performs the following primary tasks:

  • Input Ingestion: Accepts a 6-character business request identifier and a 2-character return code from CICS channel containers (DFHEP.DATA.00001 and DFHEP.DATA.00002) or falls back to standard COMMAREA fields (CA_REQUEST_ID, CA_RETURN_CODE).
  • Subsystem Initialization Check: Verifies if the statistics subsystem has been activated in the region by inspecting a CICS Temporary Storage Queue (GENASTRT); if absent, it writes a timestamp recording system startup.
  • Normalization: Remaps variant request identifiers (e.g., consolidating multi-variant inquiry and add operations) and collapses all non-zero return codes into a generic error bucket ('99').
  • Named Counter Lookup: Assembles a normalized 16-character counter key and queries/retrieves the counter from the CICS Named Counter pool GENA.

1.2 Role of LGWEBST5 (Periodic Harvester Daemon)

LGWEBST5 runs asynchronously as CICS transaction SSST. It acts as an autonomous collection daemon:

  • Self-Scheduling Loop: Reschedules itself every 60 seconds via EXEC CICS START TRANSID('SSST') AFTER MINUTES(1).
  • Interval Timing: Reads previous execution timestamps from TSQ GENA000V, computes the elapsed duration in seconds, and updates the timestamp record.
  • Counter Harvesting: Queries 35 separate named counters (1 customer sequence counter, 17 operation success counters, and 17 operation error counters) from pool GENA.
  • Delta and Rate Calculation: Compares current counter readings against prior snapshots stored in dedicated TSQs, computing the exact delta of transactions executed during the preceding minute.
  • Hierarchical Aggregation: Accumulates operational totals across Inquire (I), Add (A), Update (U), and Delete (D) functions, writing individual and summary triples (Current, Previous, Delta) into TSQs.

The system architecture relies on four central architectural pillars:

  1. CICS Event Processing (EP) & Channel Infrastructure: Decouples core business logic from statistics tracking by injecting standard container pairs (DFHEP.DATA.00001 containing the request ID, and DFHEP.DATA.00002 containing the return code).
  2. CICS Named Counter Server (GENA Pool): Provides high-performance, non-blocking, multi-tasking counter repositories across CICS regions without database locking constraints.
  3. CICS Temporary Storage Queues (TSQs): Acts as the intermediate state cache where previous values are retained across intervals and published for display.
  4. CICS Interval Control: Uses asynchronous task creation (START TRANSID) to keep the background collection daemon executing in a reliable, self-renewing loop.

The end-to-end data lifecycle progresses from transaction execution through counter incrementing, periodic harvesting, and final queue persistence.

4. Real-Time Event Classification and Normalization (LGASTAT1)

LGASTAT1 is constructed in PL/I as an inline sequence that maps runtime event descriptors into canonical counter keys.

4.1 Input Ingestion and Fallback Mechanism

LGASTAT1 evaluates two distinct input vectors upon execution:

  1. Primary Input — CICS Channel Containers: The program retrieves two containers from the current channel:
    • DFHEP.DATA.00001 mapped to WS_DATA_REQ (6-character request ID).
    • DFHEP.DATA.00002 mapped to WS_DATA_RC (2-character return code).
  2. Fallback Input — Communication Area (COMMAREA): If container retrieval yields a non-normal response code (e.g., containers absent), LGASTAT1 inspects EIBCALEN. If EIBCALEN > 0, it sources the identifiers from CA_REQUEST_ID and CA_RETURN_CODE. If EIBCALEN = 0, it issues an immediate EXEC CICS RETURN.
PLI 
/* Read input from CICS Event Processing channel containers */
 EXEC CICS GET CONTAINER(WS_CHANNAME1)
           INTO(WS_DATA_REQ)
           RESP(WS_RESP);

 EXEC CICS GET CONTAINER(WS_CHANNAME2)
           INTO(WS_DATA_RC)
           RESP(WS_RESP);

 IF WS_RESP = DFHRESP(NORMAL) THEN DO;
   GENACOUNTER = WS_DATA_REQ;
   GENATYPE    = WS_DATA_RC;
 END;
 ELSE DO;
   IF EIBCALEN = 0 THEN
     EXEC CICS RETURN;
   GENACOUNTER = CA_REQUEST_ID;
   GENATYPE    = CA_RETURN_CODE;
 END;

4.2 Statistics Subsystem Initialization Guard (GENASTRT)

Before processing counter lookups, LGASTAT1 verifies whether the subsystem initialization record exists in Temporary Storage:

  • It issues READQ TS for queue GENASTRT.
  • If DFHRESP(QIDERR) is returned, the program captures the current time using ASKTIME and FORMATTIME and issues WRITEQ TS with record layout WS_QAREA (containing date in DDMMYYYY and time in HH:MM:SS). Subsequent invocations find the queue present and bypass this initialization.

4.3 Counter Key Construction and Normalization Rules

To prevent counter fragmentation across redundant operation codes, LGASTAT1 applies strict normalization rules before key assembly:

Inbound Request Code Normalized Code (GENACOUNTER) Business Operation Description
02ACUS 01ACUS Add Customer (Variant 2 consolidated to Variant 1)
02ICOM, 03ICOM, 05ICOM 01ICOM Inquire Commercial Policy (Variants consolidated)
All other codes Unchanged Retains original 6-character identifier
PLI 
/* Normalise Request Codes */
 IF GENACOUNTER = '02ACUS' THEN 
   GENACOUNTER = '01ACUS';

 IF GENACOUNTER = '02ICOM' | 
    GENACOUNTER = '03ICOM' | 
    GENACOUNTER = '05ICOM' THEN 
   GENACOUNTER = '01ICOM';

 /* Normalise Outcome Codes: Collapse non-zero to '99' */
 IF GENATYPE ^= '00' THEN 
   GENATYPE = '99';

The fully resolved counter structure is 16 bytes:

CODE 
Position:  1 - 4   : Literal 'GENA'
Position:  5 - 10  : GENACOUNTER (6 chars, e.g., '01ICUS')
Position: 11 - 12  : GENATYPE    (2 chars, '00' for success, '99' for error)
Position: 13 - 16  : Padding spaces ('    ')

4.4 Counter Access via Named Counter Server

The program issues EXEC CICS GET COUNTER using pool name 'GENA' and counter name GENACOUNT_STR. This increments and retrieves the tally into TRANCOUNT.

PLI 
EXEC CICS GET COUNTER(GENACOUNT_STR)
           POOL(GENAPOOL)
           VALUE(TRANCOUNT)
           RESP(WS_RESP);

 EXEC CICS RETURN;

5. Periodic Harvesting and Rate Calculation (LGWEBST5)

LGWEBST5 runs asynchronously to harvest counter values, compute delta differences, and record multi-level metrics.

5.1 Self-Sustaining Daemon Lifecycle (SSST)

LGWEBST5 maintains continuous execution by scheduling its own future invocation within the TRAN_RATE_INTERVAL subroutine.

graph TD A[Start LGWEBST5 Task] --> B[Execute ASKTIME / FORMATTIME] B --> C[Call TRAN_RATE_INTERVAL] C --> D[READQ TS GENA000V Item 1] D -->|Success| E[Extract Previous HHMMSS] D -->|QIDERR / Fail| F[Default to 120000] E --> G[DELETEQ TS GENA000V] F --> G G --> H[WRITEQ TS GENA000V Item 1: Current HHMMSS] H --> I[Compute ICOUNTVAL = ABS Current - Old Seconds] I --> J[WRITEQ TS GENA000V Item 2: Elapsed Seconds] J --> K[EXEC CICS START TRANSID 'SSST' AFTER MINUTES 1] K --> L[Proceed to Counter Harvest Loop]
PLI 
TRAN_RATE_INTERVAL: PROC;
   EXEC CICS READQ TS QUEUE(WS_TSQNAME)
             ITEM(WS_TSQITEM)
             INTO(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   IF WS_RESP = DFHRESP(NORMAL) THEN
     WS_OLDV = WS_TSQDATA;
   ELSE
     WS_OLDV = '120000';

   EXEC CICS DELETEQ TS QUEUE(WS_TSQNAME) RESP(WS_RESP);

   WS_HHMMSS = SUBSTR(WS_TIME,1,6);
   WS_TSQDATA = WS_HHMMSS;
   EXEC CICS WRITEQ TS QUEUE(WS_TSQNAME)
             FROM(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   /* Convert timestamps to total seconds since midnight */
   NCOUNTVAL = (HHVAL * 3600) + (MMVAL * 60) + SSVAL;
   OCOUNTVAL = (OHHVAL * 3600) + (OMMVAL * 60) + OSSVAL;
   ICOUNTVAL = ABS(NCOUNTVAL - OCOUNTVAL);
   WS_NEWV   = ICOUNTVAL;

   EXEC CICS WRITEQ TS QUEUE(WS_TSQNAME)
             FROM(WS_NEWV)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   /* Re-schedule the statistics harvester for the next minute */
   EXEC CICS START TRANSID('SSST')
             AFTER MINUTES(1)
             RESP(WS_RESP);
 END TRAN_RATE_INTERVAL;

5.2 Counter Harvesting and Classification Loop

The program defines four parallel arrays of length 17:

  • CT_SUCCESS(17): Success counter names (GENA01ICUS00 through GENA01DCOM00).
  • CT_ERROR(17): Error counter names (GENA01ICUS99 through GENA01DCOM99).
  • CT_CODE(17): TSQ suffix keys (100 through H00).
  • CT_OPS(17): 1-character operation categories (I, A, U, D).

During iteration I = 1 TO 17, the program queries each success counter, maps the count into the appropriate operational bucket, updates the individual TSQ, and queries the corresponding error counter.

PLI 
DO I = 1 TO 17;
   EXEC CICS QUERY COUNTER(CT_SUCCESS(I))
             POOL(GENAPOOL)
             VALUE(COUNTVAL)
             RESP(WS_RESP);

   COUNTSUCCESS = COUNTSUCCESS + COUNTVAL;

   SELECT (SUBSTR(CT_OPS, I, 1));
     WHEN ('I') COUNTINQ = COUNTINQ + COUNTVAL;
     WHEN ('A') COUNTADD = COUNTADD + COUNTVAL;
     WHEN ('U') COUNTUPD = COUNTUPD + COUNTVAL;
     WHEN ('D') COUNTDEL = COUNTDEL + COUNTVAL;
   END;

   WS_TSQNAME = 'GENA' || CT_CODE(I) || 'V';
   NRATEVAL   = COUNTVAL;
   CALL TRAN_RATE_COUNTS;

   EXEC CICS QUERY COUNTER(CT_ERROR(I))
             POOL(GENAPOOL)
             VALUE(COUNTVAL)
             RESP(WS_RESP);

   COUNTERRORS = COUNTERRORS + COUNTVAL;
 END;

5.3 Three-Item TSQ Snapshot and Delta Maintenance (TRAN_RATE_COUNTS)

Every metric queue maintains a 3-item structure:

graph LR subgraph TSQ_Structure [TSQ 3-Item Layout] I1[Item 1: NRATEVAL
Current Value - 9 Digits] I2[Item 2: ORATEVAL
Previous Value - 9 Digits] I3[Item 3: DRATEVAL
Delta ABS New-Old - 9 Digits] end

The TRAN_RATE_COUNTS subroutine executes this sequence:

  1. Read Item 1: Retrieves the previous “new” snapshot. If QIDERR occurs (first run), it defaults ORATEVAL to 0.
  2. Delete Queue: Deletes the TSQ via DELETEQ TS to clear stale items.
  3. Write Item 1: Appends NRATEVAL (the latest value).
  4. Write Item 2: Appends ORATEVAL (the previous value).
  5. Write Item 3: Computes DRATEVAL = ABS(NRATEVAL - ORATEVAL) and appends it.
PLI 
TRAN_RATE_COUNTS: PROC;
   WS_TSQITEM = 1;
   EXEC CICS READQ TS QUEUE(WS_TSQNAME)
             ITEM(WS_TSQITEM)
             INTO(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   IF WS_RESP = DFHRESP(NORMAL) THEN
     ORATEVAL = WS_TSQDATA;
   ELSE
     ORATEVAL = 0;

   EXEC CICS DELETEQ TS QUEUE(WS_TSQNAME) RESP(WS_RESP);

   /* Item 1: New Value */
   WS_TSQDATA = NRATEVAL;
   EXEC CICS WRITEQ TS QUEUE(WS_TSQNAME)
             FROM(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   /* Item 2: Old Value */
   WS_TSQDATA = ORATEVAL;
   EXEC CICS WRITEQ TS QUEUE(WS_TSQNAME)
             FROM(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);

   /* Item 3: Interval Delta */
   DRATEVAL = ABS(NRATEVAL - ORATEVAL);
   WS_TSQDATA = DRATEVAL;
   EXEC CICS WRITEQ TS QUEUE(WS_TSQNAME)
             FROM(WS_TSQDATA)
             LENGTH(WS_TSQLEN)
             RESP(WS_RESP);
 END TRAN_RATE_COUNTS;

5.4 Roll-up and Aggregation Queues

After the iteration loop completes, summary totals are pushed to dedicated aggregate TSQs:

  • GENAX00V: Cumulative successful transactions (COUNTSUCCESS).
  • GENAX01V: Total inquiries across all entities (COUNTINQ).
  • GENAX02V: Total additions across all entities (COUNTADD).
  • GENAX03V: Total updates across all entities (COUNTUPD).
  • GENAX04V: Total deletions across all entities (COUNTDEL).

7. Error Handling, Defensive Programming, and Constraints

7.1 RESP-Based Error Handling and Silent Tolerance

All CICS commands in both LGASTAT1 and LGWEBST5 use explicit RESP(WS_RESP) options. This suppresses default CICS abend handlers and enables structured, programmatic condition checking:

  • Missing TSQs on First Execution: In LGWEBST5, READQ TS commands on GENA000V and GENA<code>V anticipate DFHRESP(QIDERR). When encountered, fallback assignments (WS_OLDV = '120000' and ORATEVAL = 0) prevent arithmetic faults.
  • Silent Tolerance of Auxiliary Failures: DELETEQ TS, WRITEQ TS, and QUERY COUNTER operations capture WS_RESP but intentionally avoid task abends if transient issues occur, allowing the collection loop to continue across remaining queues.
  • Missing Input Handling in LGASTAT1: If channel containers fail to read and EIBCALEN = 0, LGASTAT1 issues an early EXEC CICS RETURN without mutating state.

7.2 Data Type and Structural Constraints

  • 9-Digit Picture Width: Metric counters (NRATEVAL, ORATEVAL, DRATEVAL) are declared as PIC '999999999', restricting maximum values to 999,999,999.
  • Fixed Array Sizing: The internal tables in LGWEBST5 are statically bounded to 17 entries. CT_OPS supports strictly 'I', 'A', 'U', and 'D'.
  • Absolute Value Guards: All rate subtractions use ABS() (e.g., ABS(NRATEVAL - ORATEVAL) and ABS(NCOUNTVAL - OCOUNTVAL)), guarding against negative values if clock anomalies occur.

7.3 Operational Edge Cases

  • Midnight Boundary Crossing: When LGWEBST5 computes the elapsed time interval across midnight (e.g., prior run at 23:59:30 and current run at 00:00:30), ABS(NCOUNTVAL - OCOUNTVAL) computes the absolute numeric difference. While this avoids negative values, it produces an interval anomaly for that single interval.
  • Task Failure in Daemon Chain: If transaction SSST encounters an unhandled failure prior to issuing EXEC CICS START TRANSID('SSST') AFTER MINUTES(1), the self-rescheduling chain ceases and must be manually re-triggered.

8. Practical Execution Examples

8.1 Transaction Event Tallying via LGASTAT1

Scenario: A client submits an “Inquire Motor Policy” request that completes successfully.

  1. Trigger: Event Processing Adapter invokes LGASTAT1 with Channel Container DFHEP.DATA.00001 = '01IMOT' and Container DFHEP.DATA.00002 = '00'.
  2. Channel Read: Both containers read with DFHRESP(NORMAL).
  3. Queue Check: READQ TS QUEUE('GENASTRT') returns NORMAL (queue already exists).
  4. Key Assembly: GENACOUNTER remains '01IMOT'; GENATYPE remains '00'. Key becomes 'GENA01IMOT00 '.
  5. Counter Fetch: EXEC CICS GET COUNTER('GENA01IMOT00 ') POOL('GENA') fetches and increments the tally.

8.2 First-Run Harvest Cycle in LGWEBST5

Scenario: LGWEBST5 executes for the first time after system initialization. No metric TSQs exist.

  1. Interval Setup: READQ TS QUEUE('GENA000V') returns QIDERR. WS_OLDV defaults to '120000'. Current time is 10:00:00. GENA000V is created with Item 1 = '100000' and Item 2 = '007200'. Transaction SSST is scheduled for 10:01:00.
  2. Counter Query: QUERY COUNTER('GENA01ICUS00') returns 120.
  3. Queue Maintenance (TRAN_RATE_COUNTS):
    • READQ TS QUEUE('GENA100V') ITEM(1) returns QIDERR. ORATEVAL defaults to 000000000.
    • DELETEQ TS executes cleanly.
    • WRITEQ TS writes Item 1 = 000000120 (New).
    • WRITEQ TS writes Item 2 = 000000000 (Old).
    • WRITEQ TS writes Item 3 = 000000120 (Delta).
  4. Loop Continuation: Iterates across remaining 16 counters, accumulating totals and populating aggregate queues GENAX00V through GENAX04V.

8.3 Subsequent-Run Rate Calculation in LGWEBST5

Scenario: LGWEBST5 triggers at 10:01:00 for its second scheduled cycle.

  1. Interval Setup: READQ TS QUEUE('GENA000V') successfully retrieves WS_OLDV = '100000'. Current time is 10:01:00. Delta is calculated as 60 seconds (000060). Queue GENA000V is refreshed, and next start is set for 10:02:00.
  2. Counter Query: QUERY COUNTER('GENA01ICUS00') returns 145 (25 new inquiries occurred).
  3. Queue Maintenance (TRAN_RATE_COUNTS):
    • READQ TS QUEUE('GENA100V') ITEM(1) returns 000000120. ORATEVAL becomes 120.
    • DELETEQ TS removes previous 3 items.
    • WRITEQ TS writes Item 1 = 000000145 (New).
    • WRITEQ TS writes Item 2 = 000000120 (Old).
    • WRITEQ TS writes Item 3 = 000000025 (Delta: 25 requests/min).
  4. Aggregate Rollup: Cumulative and operation queues (GENAX00V–GENAX04V) are refreshed with updated interval deltas.
