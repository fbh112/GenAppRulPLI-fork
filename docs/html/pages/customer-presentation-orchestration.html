Customer UI & Business Flow Orchestration

1. Overview

This page documents the interactive customer-maintenance layer of the General Insurance (GenApp) application. It covers the BMS terminal handler LGTESTC1 (CICS transaction SSC1) and the three business entry-point programs it drives: LGICUS01 (customer inquiry), LGACUS01 (customer add) and LGUCUS01 (customer update).

The design splits into two tiers:

  • Presentation tier (LGTESTC1): a pseudo-conversational PL/I program. It sends and receives the BMS map SSMAPC1 from mapset SSMAP. It reads a one-character menu option (1 inquire, 2 add, 4 update). It builds a 32,500-byte COMMAREA and links to the right business program. It also maintains the GENACNTL TS queue after a successful add.
  • Business orchestration tier (LGICUS01, LGACUS01, LGUCUS01): CICS programs that validate the COMMAREA, route the request, and call lower-level DB2/VSAM/security programs. They log errors through LGSTSQ.

The tiers communicate through the shared COMM_AREA structure defined in the LGCMAREA copybook. It carries the request ID, return code, customer number and customer detail fields.

2.2 Shared Communication Area

COMM_AREA is a 32,500-byte UNION (LGCMAREA copybook). COMM_AREA_RAW overlays the whole buffer, so it can be translated or dumped as a unit.

Field Type Purpose
CA_REQUEST_ID CHAR(6) Selects the backend operation (01ICUS, 01ACUS, 01UCUS)
CA_RETURN_CODE PIC ‘99’ Outcome set by the backend (00 is success)
CA_CUSTOMER_NUM PIC ‘9999999999’ 10-digit customer key
CA_FIRST_NAME / CA_LAST_NAME CHAR(10) / CHAR(20) Name
CA_DOB CHAR(10) Date of birth
CA_HOUSE_NAME / CA_HOUSE_NUM / CA_POSTCODE CHAR(20) / CHAR(4) / CHAR(8) Address

CA_REQUEST_INITIALISER CHAR(32482) Request-specific overlay, reset to spaces between transactions

3. Terminal Handler: LGTESTC1 (Transaction SSC1)

3.1 Pseudo-Conversational Lifecycle

LGTESTC1 tests EIBCALEN:

  • EIBCALEN = 0 (first invocation):
    • COMM_AREA_PTR points at a local BASE_COMM_AREA.
    • Both map structures (SSMAPC1I, SSMAPC1O) are cleared to spaces.
    • The COMMAREA fields are initialised.
    • ENT1CNOO is preset to '0000000000'.
    • The map is sent with ERASE.
  • Subsequent invocations: initialisation is skipped and control goes to A_GAIN.

At A_GAIN, the program registers AID and condition handlers, then receives the map:

PLI 
EXEC CICS HANDLE AID CLEAR(CLEARIT);
EXEC CICS HANDLE AID PF3(ENDIT);
EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);
EXEC CICS RECEIVE MAP('SSMAPC1') INTO(SSMAPC1I) ASIS TERMINAL MAPSET('SSMAP');

3.2 Session Control Labels

Label Trigger Behaviour
ENDIT_STARTIT Normal completion of any option EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA) keeps the session alive
ENDIT PF3 or MAPFAIL Sends 'Transaction ended' with ERASE FREEKB, then a plain RETURN
CLEARIT CLEAR key Clears SSMAPC1I, sends MAPONLY, returns with TRANSID('SSC1')

4. Business Flows

4.1 Option 1: Customer Inquiry

LGTESTC1 sets CA_REQUEST_ID = '01ICUS' and loads CA_CUSTOMER_NUM from ENT1CNOO. It then links to LGICUS01 with a fixed 32,500-byte COMMAREA. If CA_RETURN_CODE > 0, control goes to NO_DATA. Otherwise the returned fields are moved to the screen input structure and the map is sent.

PLI 
CA_REQUEST_ID   = '01ICUS';
CA_CUSTOMER_NUM = ENT1CNOO;
EXEC CICS LINK PROGRAM('LGICUS01') COMMAREA(COMM_AREA) LENGTH(32500);
IF CA_RETURN_CODE > 0 THEN GO TO NO_DATA;
ENT1FNAI = CA_FIRST_NAME;
ENT1LNAI = CA_LAST_NAME;
ENT1DOBI = CA_DOB;
