Centralized Error Logging & Diagnostics

1. Overview

1.1 Purpose

Centralized error logging in the application is handled by one reusable CICS PL/I routine, LGSTSQ. Any program can pass it a text message, or an operator can type one at a terminal. It stamps the message with the CICS region identifier (SYSID) and writes it to two destinations:

  • Transient Data Queue CSMT, the standard CICS message log, for system-level operational visibility.
  • Temporary Storage Queue GENAERRS (the default) for application-level error tracking. The queue name can be overridden to GENAnnnn at runtime.

1.2 Key Capabilities

Capability Description
Dual-destination logging Each message goes to the TDQ CSMT and to a TSQ.
Region tagging Every record starts with the 4-character CICS SYSID.
Dual invocation modes The routine runs when linked from another program (COMMAREA) or started from a terminal.
Dynamic queue routing A Q=nnnn prefix in the message redirects the TSQ write to GENAnnnn.
Non-blocking behavior The TSQ write uses NOSUSPEND, and every CICS command uses RESP, so logging never abends or stalls the caller.
No database use The routine uses only CICS queues. It does no DB2 access.

1.3 Scope Note on Diagnostics Content

LGSTSQ is a transport and formatting utility. It does not interpret or format SQLCODEs, response codes, or dump data. It logs whatever text the calling program places in the message (up to 90 bytes). To record diagnostics such as an SQLCODE or an EIBRESP value, the caller builds that text before the call. Section 7 describes this contract.

WRITE_MSG_MSG receives its content from COMMA_DATA or WS_RECV_DATA, depending on the invocation mode. The complete WRITE_MSG record is then written to both queues.

3. Message Record Design

3.1 Record Layout

Every logged entry uses the same record structure:

Field Length Content
WRITE_MSG_SYSID 4 CICS region ID from ASSIGN SYSID
FILLER_X 1 Blank separator
WRITE_MSG_MSG 90 Message text (after any Q=nnnn prefix removal)
Total 95 Maximum record size

The LENGTH operand on the queue writes limits how many of the 95 bytes are actually recorded.

3.2 Length Computation

The length written to both queues is WS_RECV_LEN. It is adjusted as follows:

graph TD A{Invocation mode} -->|Called, WS_FLAG = C| B[WS_RECV_LEN = EIBCALEN] A -->|Terminal, WS_FLAG = R| C[WS_RECV_LEN = received length - 5] B --> D{Message starts with Q=?} C --> D D -->|Yes| E[WS_RECV_LEN = WS_RECV_LEN - 7] D -->|No| F[No change] E --> G[WS_RECV_LEN = WS_RECV_LEN + 5
for SYSID and separator] F --> G G --> H[Length used on WRITEQ TD and WRITEQ TS]

4. Invocation Modes

LGSTSQ chooses its input source at run time by calling EXEC CICS ASSIGN INVOKINGPROG. A non-blank result means another program linked to it. A blank result means a terminal started it.

Aspect Program-linked (WS_FLAG = 'C') Terminal (WS_FLAG = 'R')
Detection WS_INVOKEPROG is not blank WS_INVOKEPROG is blank
Message source COMMA_DATA (COMMAREA) WS_RECV_DATA (after EXEC CICS RECEIVE)
Initial length EIBCALEN Received length minus 5 (transaction ID)
Terminal response None SEND TEXT with ERASE and FREEKB

4.1 Code: Context Gathering

The four context lookups run unconditionally, each capturing its response in WS_RESP. The following is an illustrative reconstruction of the commands:

PLI 
EXEC CICS ASSIGN SYSID(WRITE_MSG_SYSID)        RESP(WS_RESP);
EXEC CICS ASSIGN STARTCODE(WS_STARTCODE)       RESP(WS_RESP);
EXEC CICS ASSIGN PRINSYSID(WS_PRINSYSID)       RESP(WS_RESP);
EXEC CICS ASSIGN INVOKINGPROG(WS_INVOKEPROG)   RESP(WS_RESP);

4.2 Code: Invocation-Mode Branch

PLI 
IF WS_INVOKEPROG ^= ' ' THEN DO;      /* Called by another program */
   WS_FLAG        = 'C';
   WRITE_MSG_MSG  = COMMA_DATA;
   WS_RECV_LEN    = EIBCALEN;
END;
ELSE DO;                              /* Started from a terminal   */
   EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN) RESP(WS_RESP);
   WS_FLAG        = 'R';
   WRITE_MSG_MSG  = WS_RECV_DATA;
   WS_RECV_LEN    = WS_RECV_LEN - 5;
END;

6. Queue Routing

6.1 Transient Data Queue CSMT

  • The name is fixed (STDQ_NAME = 'CSMT'), so every message is written there.
  • The write uses EXEC CICS WRITEQ TD with the WRITE_MSG buffer and length WS_RECV_LEN.
  • It always runs before the TSQ write.
  • It does not use NOSUSPEND.
  • CSMT must exist in the region’s TDQ definitions.

6.2 Temporary Storage Queue GENAERRS / GENAnnnn

  • The default queue name is GENAERRS.
  • The write uses NOSUSPEND, so logging is best-effort.
  • The first four characters (GENA) are fixed. Only positions 5–8 can change.

6.3 Queue Name Override (Q=nnnn)

A message that begins with Q= redirects the TSQ write. The next four characters become the queue suffix.

graph TD A[WRITE_MSG_MSG] --> B{"Bytes 1-2 equal Q= ?"} B -- No --> C[STSQ stays GENAERRS
Message unchanged] B -- Yes --> D["Take bytes 3-6 as suffix nnnn
Place into STSQ positions 5-8"] D --> E["Copy bytes 8-90 to TEMPO
Copy TEMPO back to WRITE_MSG_MSG"] E --> F[WS_RECV_LEN reduced by 7] C --> G[Proceed to queue writes] F --> G
PLI 
STSQ = 'GENAERRS';
IF SUBSTR(WRITE_MSG_MSG,1,2) = 'Q=' THEN DO;
   SUBSTR(STSQ,5,4) = SUBSTR(WRITE_MSG_MSG,3,4);
   TEMPO            = SUBSTR(WRITE_MSG_MSG,8,83);
   WRITE_MSG_MSG    = TEMPO;
   WS_RECV_LEN      = WS_RECV_LEN - 7;
END;
WS_RECV_LEN = WS_RECV_LEN + 5;        /* SYSID + separator */

Routing rules:

  • The Q= match is case-sensitive and must sit in bytes 1–2. Lowercase q= or leading spaces disable the override.
  • The suffix is taken as-is, with no validation.
  • The prefix consumes 7 bytes: Q=, four suffix characters, and one separator byte. Message text starts at byte 8, so callers should leave a blank after nnnn.

7. Diagnostic Content and Caller Contract

LGSTSQ records text only. It performs no formatting, SQLCODE decoding, or dump generation. It is not tied to any particular error type. Diagnostic detail therefore comes from the caller, which should assemble the text in the COMMAREA. Typical content includes a program identifier, a failing operation, an SQLCODE, or an EIBRESP/EIBRESP2 value.

Concern Who handles it
Building the message (program name, SQLCODE, response codes) Calling program
Limiting text to 90 bytes Calling program (excess is truncated by PL/I assignment)
Optionally adding Q=nnnn to select an alternate TSQ Calling program
Prefixing the region ID LGSTSQ
Writing to CSMT and the TSQ LGSTSQ

Because SYSID is prepended, a log entry from region GENL looks like this:

CODE 
GENL <caller-supplied diagnostic text>

8. Error Handling and Resilience

8.1 Design Principle

The logger must never become a failure point. Its error strategy is therefore deliberately minimal.

Mechanism Behavior
RESP(WS_RESP) on every CICS command Suppresses default CICS exception handling (no abend). The response code is stored in WS_RESP.
NOSUSPEND on WRITEQ TS The task is not suspended if temporary storage is unavailable. The message may be lost.
Conditional SEND TEXT Terminal I/O is issued only when WS_FLAG = 'R'.
Invocation-mode detection The COMMAREA is read only when a calling program is detected.
No ABEND, no ON units The program always ends normally with EXEC CICS RETURN.

8.2 Command Pattern

PLI 
EXEC CICS WRITEQ TD QUEUE(STDQ_NAME)
          FROM(WRITE_MSG) LENGTH(WS_RECV_LEN)
          RESP(WS_RESP);

EXEC CICS WRITEQ TS QUEUE(STSQ)
          FROM(WRITE_MSG) LENGTH(WS_RECV_LEN)
          NOSUSPEND RESP(WS_RESP);

IF WS_FLAG = 'R' THEN
   EXEC CICS SEND TEXT FROM(FILLER_X) TERMINAL WAIT
             ERASE LENGTH(1) FREEKB;

EXEC CICS RETURN;

8.3 Known Gaps

  • WS_RESP is populated after each command but never tested. A failed ASSIGN, RECEIVE, or queue write goes unnoticed.
  • WS_RECV_LEN is not bounds-checked. Very short input could produce a negative or oversized length.
  • COMM_AREA_PTR is dereferenced without checking EIBCALEN. A link with no COMMAREA could cause an abend.
  • Messages can be lost silently if the TSQ write fails. The CSMT entry is the more reliable record.

9. Constraints and Limitations

9.1 Size Constraints

Item Limit
COMMAREA message (COMMA_DATA) 90 bytes
Terminal input (WS_RECV) 5-byte transaction ID plus 74 bytes of data
Log record (WRITE_MSG) 95 bytes (4 SYSID + 1 separator + 90 message)
WS_RECV_LEN initial value 80
Terminal response Exactly 1 blank byte

9.2 Sequencing Constraints

  1. All ASSIGN commands run before the invocation-mode branch.
  2. The message is populated, and any Q= prefix handled, before the queue writes.
  3. The TDQ write runs before the TSQ write, and both use the same buffer and length.
  4. The terminal SEND TEXT runs after both queue writes.
  5. EXEC CICS RETURN is the final, unconditional statement.

9.3 Environment Requirements

  • A CICS region with the TDQ CSMT defined.
  • A transaction definition that maps a transaction ID to LGSTSQ, needed only for terminal use.
  • Callers use EXEC CICS LINK and pass a COMMAREA. No caller program name is hard-coded.

10. Examples

10.1 Program-Linked Call, Default Queue

Input: SYSID GENL, invoking program LGSICVP, EIBCALEN = 42, COMMAREA Policy not found for customer 1234567890.

Processing:

  1. WS_FLAG = C and WS_RECV_LEN = 42.
  2. There is no Q= prefix, so STSQ stays GENAERRS.
  3. WS_RECV_LEN = 42 + 5 = 47.
  4. The record is written to CSMT and GENAERRS. No terminal send occurs.

Logged record:

CODE 
GENL Policy not found for customer 1234567890

10.2 Program-Linked Call with Queue Override

Input: COMMAREA starting Q=0042 followed by Policy limit exceeded for account 99, EIBCALEN = 43.

Processing:

  1. Q= is detected, so STSQ = GENA0042.
  2. The 7-byte prefix is stripped, so WS_RECV_LEN = 43 − 7 = 36.
  3. WS_RECV_LEN = 36 + 5 = 41.
  4. The record is written to CSMT and GENA0042.

Logged record:

CODE 
GENL Policy limit exceeded for account 99

The routine always removes 7 bytes. In practice the caller should put a blank after nnnn, as in Q=0042 Policy limit…. Otherwise the first character of the real message is removed.

10.3 Terminal Invocation

Input: The operator enters LGSQ Account 888 is invalid. The received length is 30 and SYSID is GENL.

Processing:

  1. INVOKINGPROG is blank, so RECEIVE runs and WS_FLAG = R.
  2. The message is taken from WS_RECV_DATA, and WS_RECV_LEN = 30 − 5 = 25.
  3. There is no override, so STSQ = GENAERRS.
  4. WS_RECV_LEN = 25 + 5 = 30.
  5. The record is written to CSMT and GENAERRS.
  6. SEND TEXT clears the screen and unlocks the keyboard.

Logged record:

CODE 
GENL Account 888 is invalid

11. Summary

LGSTSQ is the single logging service for the application. It does the following:

  • It accepts messages from programs or terminals.
  • It tags each message with the CICS SYSID.
  • It writes each message to the system log (CSMT) and to an application TSQ (GENAERRS, or GENAnnnn when overridden).
  • It never blocks or abends the calling transaction.

Programs that need richer diagnostics, such as SQLCODEs or response codes, must supply them as text in the COMMAREA. They should also keep the message within the 90-byte limit.
