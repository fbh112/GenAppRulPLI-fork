# GenApp — Motor Domain: Business Rules

> **Domain**: Motor insurance (policy type `M`)  
> **Source programs analysed**: [`LGAPOL01`](../pli/LGAPOL01.pli), [`LGAPDB01`](../pli/LGAPDB01.pli), [`LGIPDB01`](../pli/LGIPDB01.pli), [`LGMOTOUT`](../pli/LGMOTOUT.pli)  
> **Contract definition**: [`plinc/LGCMAREA.inc`](../plinc/LGCMAREA.inc)  
> **DB schema**: [`DDL/db2cre.jcl`](../DDL/db2cre.jcl)  
> **Note**: The Update Policy path calls COBOL program `LGUPDB01` (source absent from workspace); update business rules cannot be fully documented.

## Section 1 — Policy Lifecycle Rules

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-01** | A motor policy request must carry the correct request identifier | `CA_REQUEST_ID = '01AMOT'` | Sets `DB2_POLICYTYPE = 'M'`; size-checks COMMAREA for motor fields. Any other value → RC=99, RETURN | `LGAPDB01` / main flow (line 172) | `CA_REQUEST_ID`, `DB2_POLICYTYPE` | Explicit | Input: `CA_REQUEST_ID='01AMOT'` → proceeds; `CA_REQUEST_ID='01AXXX'` → RC=99 |
| **MOT-02** | COMMAREA must be large enough to carry all motor fields | `EIBCALEN >= WS_CA_HEADER_LEN + WS_FULL_MOTOR_LEN` | If undersized: RC=98, RETURN (caller must retry with a larger commarea) | `LGAPDB01` / main flow (line 193) | `EIBCALEN`, `WS_CA_HEADER_LEN`, `WS_FULL_MOTOR_LEN` | Explicit | COMMAREA < required length → RC=98 |
| **MOT-03** | A motor policy requires a valid parent POLICY row (FK constraint) | `POLICY.CUSTOMERNUMBER` must reference an existing customer | DB2 SQLCODE -530 → RC=70, error logged, RETURN. Any other SQL error → RC=90, error logged, RETURN | `LGAPDB01` / `INSERT_POLICY` (line 304) | `CA_CUSTOMER_NUM`, `DB2_CUSTOMERNUM_INT` | Explicit | Non-existent customer number → SQLCODE=-530 → RC=70 |
| **MOT-04** | Policy number is system-generated, not caller-supplied | `POLICYNUMBER` defined as `GENERATED BY DEFAULT AS IDENTITY (START WITH 1000001, INCREMENT BY 1)` | Db2 assigns the policy number; value is retrieved with `IDENTITY_VAL_LOCAL()` and written back to `CA_POLICY_NUM` | `LGAPDB01` / `INSERT_POLICY` (lines 319–322) | `DB2_POLICYNUM_INT`, `CA_POLICY_NUM` | Explicit | After successful INSERT, `CA_POLICY_NUM` always ≥ 1000001 |
| **MOT-05** | Policy timestamp is captured at insert time | `LASTCHANGED = CURRENT TIMESTAMP` | DB2 sets the timestamp; it is read back immediately and returned to caller in `CA_LASTCHANGED` | `LGAPDB01` / `INSERT_POLICY` (lines 326–331) | `CA_LASTCHANGED`, `POLICY.LASTCHANGED` | Explicit | `CA_LASTCHANGED` contains the exact Db2 insert timestamp |
| **MOT-06** | A motor policy inquiry must match both customer number and policy number | `POLICY.CUSTOMERNUMBER = :CA_CUSTOMER_NUM AND POLICY.POLICYNUMBER = :CA_POLICY_NUM` | SQLCODE=100 (not found) → RC=01. SQLCODE other → RC=90. Match → data populated in COMMAREA | `LGIPDB01` / `GET_MOTOR_DB2_INFO` (lines 592–646) | `CA_CUSTOMER_NUM`, `CA_POLICY_NUM` | Explicit | Wrong customer+policy combination → RC=01 |
| **MOT-07** | Null broker and payment fields are handled gracefully on inquiry | Indicator variables `IND_BROKERID`, `IND_PAYMENT`: if = -1 (null), the field is not moved to COMMAREA | Caller receives only non-null fields; no conversion error on null integers | `LGIPDB01` / `GET_MOTOR_DB2_INFO` (lines 617–622) | `CA_BROKERID`, `CA_PAYMENT`, `IND_BROKERID`, `IND_PAYMENT` | Explicit | BROKERID=NULL in DB → IND_BROKERID=-1 → CA_BROKERID not set |
| **MOT-08** | Motor inquiry marks the end of the policy data block | After populating all fields, writes literal `'FINAL'` into `CA_M_FILLER` positions 1–5 | Caller can detect the end-of-record marker | `LGIPDB01` / `GET_MOTOR_DB2_INFO` (line 640) | `CA_M_FILLER` | Explicit | Successful inquiry → first 5 bytes of `CA_M_FILLER` = `'FINAL'` |

## Section 2 — Motor Premium Calculation Rules

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-P01** | **Accident history surcharge** — low risk (0–2 accidents): no surcharge | `CA_M_ACCIDENTS <= 2` | Premium multiplied by 1.00 (unchanged) | `LGAPDB01` / `INSERT_MOTOR` (lines 522–523) | `CA_M_ACCIDENTS`, `CA_M_PREMIUM` | Explicit | Accidents=2, base premium=1000 → stored premium=1000 |
| **MOT-P02** | **Accident history surcharge** — moderate risk (3–5 accidents): +20% | `CA_M_ACCIDENTS > 2 AND CA_M_ACCIDENTS <= 5` | Premium = base × 1.20 | `LGAPDB01` / `INSERT_MOTOR` (lines 524–525) | `CA_M_ACCIDENTS`, `CA_M_PREMIUM` | Explicit | Accidents=4, base premium=1000 → stored premium=1200 |
| **MOT-P03** | **Accident history surcharge** — high risk (6–8 accidents): +50% | `CA_M_ACCIDENTS > 5 AND CA_M_ACCIDENTS <= 8` | Premium = base × 1.50 | `LGAPDB01` / `INSERT_MOTOR` (lines 526–527) | `CA_M_ACCIDENTS`, `CA_M_PREMIUM` | Explicit | Accidents=7, base premium=1000 → stored premium=1500 |
| **MOT-P04** | **Accident history surcharge** — very high risk (9+ accidents): +200% | `CA_M_ACCIDENTS > 8` | Premium = base × 3.00 | `LGAPDB01` / `INSERT_MOTOR` (lines 528–529) | `CA_M_ACCIDENTS`, `CA_M_PREMIUM` | Explicit | Accidents=9, base premium=1000 → stored premium=3000 |
| **MOT-P05** | **Surcharge stacking** — accident bands are evaluated with independent `IF` statements, not `IF-ELSE` | Each `IF` executes independently; for `CA_M_ACCIDENTS <= 2`, only the ×1.00 rule fires. For any value > 2, multiple `IF` conditions would be evaluated | Only the last matching `IF` condition takes effect on `CA_M_PREMIUM` because each overwrites the previous | `LGAPDB01` / `INSERT_MOTOR` (lines 522–529) | `CA_M_ACCIDENTS`, `CA_M_PREMIUM` | Explicit — **implementation note**: bands are mutually exclusive in the data domain, but the code uses serial `IF`, not `IF-ELSE` | Accidents=4: line 523 fires (×1.00), then line 525 fires (×1.20) — result is correct because the bands are non-overlapping |

## Section 3 — Bundling Discount Rules

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-B01** | **Motor + House bundle discount** — customers with more than 2 active Motor or House policies get 15% off the new policy premium | `COUNT(POLICYNUMBER) > 2` where `POLICYTYPE IN ('M','H')` and policy is currently active (`ISSUEDATE < CURRENT DATE AND EXPIRYDATE > CURRENT DATE`) for the same customer | `DB2_PAYMENT_INT = DB2_PAYMENT_INT - (DB2_PAYMENT_INT * 0.15)` applied before INSERT | `LGAPDB01` / `BUNDLING_DISCOUNT` (lines 339–364) | `DB2_CUSTOMERNUM_INT`, `DB2_PAYMENT_INT`, `WS_CNT_POLICY`, `POLICY.POLICYTYPE`, `POLICY.ISSUEDATE`, `POLICY.EXPIRYDATE` | Explicit | Customer has 3 active Motor/House policies; new motor premium=1000 → discounted to 850 |
| **MOT-B02** | Bundling discount applies to all new policy types, not only Motor | `BUNDLING_DISCOUNT` is called from `INSERT_POLICY` which is called for all non-claim policy types (Endowment, House, Motor, Commercial) | The 15% discount applies to any policy type if the customer has >2 active M/H policies | `LGAPDB01` / `INSERT_POLICY` (line 269) → `BUNDLING_DISCOUNT` | Same as MOT-B01 | Explicit (code), partially inferred (intent) | Customer adds endowment policy; if they have 3 active Motor/House policies → endowment premium also gets 15% off |
| **MOT-B03** | SQL failure during bundling discount check causes ABEND and rollback | `SQLCODE <> 0` | RC=90, error logged, `EXEC CICS ABEND ABCODE('LGSQ')` — causes CICS to back out the POLICY row already inserted | `LGAPDB01` / `BUNDLING_DISCOUNT` (lines 356–362) | `SQLCODE`, `CA_RETURN_CODE` | Explicit | DB2 error during count → CICS ABEND 'LGSQ' → entire transaction backed out |

## Section 4 — Broker Commission Rules

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-C01** | Broker commission is calculated as a percentage of the payment, scaled by the broker's total active policy count | Count of all active policies (any type) brokered by `CA_BROKERID`: 0 policies → 0%; 1 policy → 1%; 2 → 2%; 3 → 3%; 4 → 4%; 5+ → 5% | `WS_COMMISSION` is set and stored in `POLICY.COMMISSION` at INSERT | `LGAPDB01` / `CALCULATE_COMMISSION` (lines 369–401) | `DB2_BROKERID_INT`, `WS_CNT_POLICY`, `WS_COMMISSION`, `DB2_PAYMENT_INT` | Explicit | Broker has 3 active policies; new payment=1000 → commission=30 (3%) |
| **MOT-C02** | Commission is based on the payment **after** any bundling discount has been applied | `BUNDLING_DISCOUNT` is called before `CALCULATE_COMMISSION` inside `INSERT_POLICY` | Commission is calculated on the discounted premium, not the original | `LGAPDB01` / `INSERT_POLICY` (lines 269–272) | `DB2_PAYMENT_INT`, `WS_COMMISSION` | Inferred from call order | Discounted payment=850; broker has 2 policies → commission=17 (2% of 850) |
| **MOT-C03** | Commission is halved when a policy accumulates more than 3 claims in the current year | `COUNT(CLAIMNUMBER) > 3 WHERE YEAR(CLAIMDATE) = YEAR(CURRENT DATE)` for the policy | `UPDATE POLICY SET COMMISSION = (COMMISSION / 2)` | `LGAPDB01` / `UPDATE_BROKER_COMM` (lines 750–785) | `WS_CLM_CNT`, `DB2_C_Policynum_INT`, `POLICY.COMMISSION` | Explicit | Policy has 4 claims this year → commission halved |
| **MOT-C04** | Commission halving SQL failure causes ABEND and rollback | `SQLCODE <> 0` on either the COUNT or the UPDATE | RC=90, ABEND 'LGSQ', transaction backs out | `LGAPDB01` / `UPDATE_BROKER_COMM` (lines 762–783) | `SQLCODE`, `CA_RETURN_CODE` | Explicit | DB2 error → CICS ABEND 'LGSQ' |

## Section 5 — Entity Relationships

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-E01** | A motor policy must belong to exactly one customer | `POLICY.CUSTOMERNUMBER` is a NOT NULL FK referencing `CUSTOMER.customerNumber` with `ON DELETE CASCADE` | Deleting a customer also deletes all their policies, including motor | `DDL/db2cre.jcl` (POLICY table definition) | `POLICY.CUSTOMERNUMBER`, `CUSTOMER.customerNumber` | Explicit (DDL) | Customer deleted → all their MOTOR rows cascade-deleted |
| **MOT-E02** | A MOTOR row must have exactly one POLICY parent | `MOTOR.POLICYNUMBER` is PK + FK to `POLICY.POLICYNUMBER` with `ON DELETE CASCADE` | Deleting a policy also deletes its MOTOR row; a MOTOR row cannot exist without a POLICY | `DDL/db2cre.jcl` (MOTOR table definition) | `MOTOR.POLICYNUMBER`, `POLICY.POLICYNUMBER` | Explicit (DDL) | POLICY deleted → MOTOR row automatically removed |
| **MOT-E03** | A policy can have only one motor sub-type record | MOTOR PK is `POLICYNUMBER` (unique) | Attempting to INSERT a second MOTOR row for the same policy → DB2 unique constraint violation | `DDL/db2cre.jcl` | `MOTOR.POLICYNUMBER` | Explicit (DDL) | Duplicate INSERT for same policyNumber → DB2 error |
| **MOT-E04** | Motor policy inquiry requires both customerNumber and policyNumber | `WHERE POLICY.CUSTOMERNUMBER = :CA_CUSTOMER_NUM AND POLICY.POLICYNUMBER = :CA_POLICY_NUM` | A valid policyNumber with wrong customerNumber returns RC=01 (not found) — prevents cross-customer data leakage | `LGIPDB01` / `GET_MOTOR_DB2_INFO` (lines 592–598) | `CA_CUSTOMER_NUM`, `CA_POLICY_NUM` | Explicit | Correct policyNumber but wrong customerNumber → RC=01 |

| ID | Rule | Conditions | Outcome | Program / Procedure | Data Involved | Explicit / Inferred | Example |
|---|---|---|---|---|---|---|---|
| **MOT-O01** | Batch reads all motor records regardless of policy status | `SELECT … FROM GENASA1.MOTOR FOR READ ONLY` — no WHERE filter | Every row in MOTOR is included in the output, including expired or inactive policies | `LGMOTOUT` / main + `FETCH_MOTOR_ROWS` (lines 89–102, 147–157) | `GENASA1.MOTOR` (all rows) | Explicit | 500 motor policies in DB (active or expired) → 500 records in MOTOROUT |
| **MOT-O02** | Output record is fixed-length 132 bytes, formatted in print layout | FB RECSIZE(132); fields are space-separated PIC/CHAR fields | Every output record is exactly 132 bytes; numeric fields are zero-padded | `LGMOTOUT` / `WRITE_MOTOR_ROW` (lines 177–200) | `WS_MOTOR_LINE`, `MOTOROUT_REC` | Explicit | policyNumber 1000001 stored as `'001000001'`; remaining 13 bytes are spaces |
| **MOT-O03** | Fetch errors set RC=8; the loop continues on SQLCODE=100 (end of data) | `WHEN (100)` → loop termination; `OTHERWISE` → RC=8 via `PLIRETC(8)` | On a fetch error, `WRITE_ERROR_MESSAGE` is called (DISPLAY output), RC=8 is set, but the program does not immediately stop — the DO WHILE condition will re-evaluate | `LGMOTOUT` / `FETCH_MOTOR_ROWS` (lines 159–169) | `SQLCODE`, `WS_ROW_COUNT` | Explicit | Unexpected SQLCODE during fetch → RC=8 set; row count already written rows returned |

| **MOT-O05** | Cursor open failure is fatal and cleans up | `SQLCODE ^= 0` after OPEN MOTOR_CSR | Error logged, `CLOSE FILE(MOTOROUT)`, `PLIRETC(12)`, `RETURN` | `LGMOTOUT` (lines 117–123) | `MOTOR_CSR`, `SQLCODE` | Explicit | DB2 not available → cursor open fails → file closed, RC=12 |

## Section 7 — Error Handling and Return Codes

| Return Code | Set By | Meaning | Recovery |
|---|---|---|---|
| `00` | `LGAPDB01`, `LGIPDB01` | Success | — |
| `01` | `LGIPDB01` | Motor policy not found (customer + policy combination does not exist) | Caller should validate input and retry with correct identifiers |
| `70` | `LGAPDB01` | Invalid customer number — FK violation (SQLCODE=-530) | Caller must ensure customer exists before adding policy |
| `90` | `LGAPDB01`, `LGIPDB01` | Unexpected DB2 error | Check DB2 logs; transaction backed out by CICS ABEND 'LGSQ' |
| `98` | `LGAPDB01`, `LGIPDB01` | COMMAREA too small | Caller must increase COMMAREA length to hold all motor fields |
| `99` | `LGAPDB01` | Unrecognised request ID | Caller must use `'01AMOT'` for add-motor |
| `0` (batch) | `LGMOTOUT` | All rows written successfully | — |
| `8` (batch) | `LGMOTOUT` | DB2 FETCH error during batch run | Check DB2 logs; partial output may exist in MOTOROUT |
| `12` (batch) | `LGMOTOUT` | OPEN failure (file or cursor) | Verify JCL DD allocation and DB2 connectivity |

## Section 8 — Motor Data Model

> These fields must be preserved in the target system.

### MOTOR table (GENASA1.MOTOR)

| Column | Type | Nullable | Business Meaning |
|---|---|---|---|
| `POLICYNUMBER` | INTEGER PK/FK | NO | Unique policy identifier — FK to POLICY; system-generated by POLICY table identity |
| `MAKE` | CHAR(15) | YES | Vehicle manufacturer (e.g. `'FORD'`) |
| `MODEL` | CHAR(15) | YES | Vehicle model (e.g. `'FOCUS'`) |
| `VALUE` | INTEGER | YES | Declared vehicle value in pence/cents |
| `REGNUMBER` | CHAR(7) | YES | Vehicle registration plate |
| `COLOUR` | CHAR(8) | YES | Vehicle colour |
| `CC` | SMALLINT | YES | Engine cubic capacity |
| `YEAROFMANUFACTURE` | DATE | YES | Vehicle year of manufacture |
| `PREMIUM` | INTEGER | YES | Stored premium **after** accident surcharge has been applied |
| `ACCIDENTS` | INTEGER | YES | Number of declared accidents — drives the surcharge calculation |

### COMMAREA Motor fields (CA_MOTOR in LGCMAREA.inc)

| Field | Size | Maps to MOTOR column |
|---|---|---|
| `CA_M_MAKE` | CHAR(15) | MAKE |
| `CA_M_MODEL` | CHAR(15) | MODEL |
| `CA_M_VALUE` | PIC '999999' | VALUE |
| `CA_M_REGNUMBER` | CHAR(7) | REGNUMBER |
| `CA_M_COLOUR` | CHAR(8) | COLOUR |
| `CA_M_CC` | PIC '9999' | CC |
| `CA_M_MANUFACTURED` | CHAR(10) | YEAROFMANUFACTURE |
| `CA_M_PREMIUM` | PIC '999999' | PREMIUM (modified by surcharge before storage) |
